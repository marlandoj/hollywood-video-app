# Character picture performance direction

Owners can save emotion, expression/movement intensity and up to three ordered gesture suggestions for a character in a screenplay scene. Shot direction and take alternatives expose per-character overrides. Blank fields inherit the scene; explicit neutral/natural values reset those fields and an empty gesture list clears additional gesture suggestions. Free-form shot performance notes remain available for timing and nuance.

These settings compile to text in the existing picture prompt. Intensity is a creative choice (restrained, natural or heightened), not a numeric native model parameter. Kling receives the effective character settings through its documented `prompt` field. The current adapters do not expose dedicated semantic emotion, gesture or expression-strength parameters. Synthetic previews retain and display the same intent, but do not demonstrate acting delivery. Owner inspection remains necessary.

The scene editor lives in the voice studio, including when expressive audition generation is disabled. Picture controls are separate from vocal controls. They travel with the scene memory in retained audio takes, but do not change voice synthesis settings. The shot editor shows the compiled saved picture paragraph before generation; each take can have its own overrides. Completed film and take reviews show the original retained picture settings.

Scene memory with picture controls uses `hv-scene-performance/2`; existing records without them retain schema 1 and their original revisions. `ShotDirection.picture` contains character IDs, a reviewed base revision and partial controls. The base revision binds the character name, complete ordered scene source and saved scene-memory revision. Renaming/removing a character or editing that scene intent requires review/rebinding. Generic cast appearance changes remain governed by the existing cast revision and preview/approval workflow. Current character permission is checked by the existing admission and worker boundaries.

At planning, character scene settings and shot fields resolve into one `hv-picture-performance/1` receipt and one prompt paragraph. The receipt retains character names/IDs, the scene source, original memory revisions, effective controls and the declared prompt transport. It does not claim that the generated pixels comply with the direction. Admitted cast and direction snapshots keep earlier requests unchanged. Stored clips, output metadata and manifests retain that receipt; selective reuse includes it in each shot's input hash. Snapshot validation rebuilds the expected receipt from the original job and rejects missing or altered output evidence. Old direction readers reject the new field instead of silently dropping it. No database migration is required.

The existing provider capability and price revisions, endpoints, authorization and accounting paths remain in use. This increment introduces no additional submission, active operator policy or provider key. A closed HTTP fixture verifies exact effective prompt delivery to Kling O3 Standard, including reference transport and audio disabled. Planner/API tests cover precedence, explicit clears, stale bindings, independent take exports, reuse and archive validation. PostgreSQL cases exercise concurrent saves, admission before reservation, and S3 archive restoration of film picture receipts and both providers' retained dialogue performances.

Production acting accuracy, gesture timing, mouth/face quality and provider/licence qualification remain unevaluated. A separate native motion/performance-transfer adapter would require its own supported contract, reviewed source performance media and quality evidence. Multilingual dubbing, narration ducking, and broader P7–P9 work remain open. No paid inference or Zo deployment is claimed.
