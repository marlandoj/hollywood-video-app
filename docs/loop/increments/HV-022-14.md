# HV-022-14 — Two paid admissions never asked the film's own spending cap

epic: HV-022
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

`GET /spend` answers `capUsd: filmCapUsd` and the studio shows that limit at every approval —
"Spent on this film so far: $x of its $40 limit." `assertFilmWithin` is what enforces it, and
picture, current-film and audio takes all call it before they reserve. Two paid paths reached a
reservation without it, by two different routes.

**Lip-sync.** `admitLipSync` has no `assertFilmWithin` at all:

```ts
await this.reserveWithin(tx,cap,input.id,input.stage,policy.heldUsd,monthlyCapUsd,new Date(now),projectId);
```

And no route could have supplied one. `server.ts` computes `filmCapUsd` on one line and, twenty
lines later, builds:

```ts
const lipSyncApi=new LipSyncApi({root:artifactRoot,artifacts,ledger,lipLedger,monthlyBudgetUsd,store:scopedJobs,view:audioJobView});
```

`LipSyncApi`'s context had no field for it. Each pass reserves the policy's held cost, and
`lipsync.ts` allows 32 retained passes per lineage.

**Living-script generation.** `admit`'s living-script branch *does* call `assertFilmWithin` — but the
route called it with three arguments:

```ts
if(ledger instanceof PostgresCostLedger)result=await ledger.admit(projectId,submitted,monthlyBudgetUsd);
```

and `assertFilmWithin` returns immediately when the cap is `undefined`. A re-render off a provider
pool that is not free reserves `costCapUsd`.

Either way: a creator whose film had spent its whole `HV_FILM_SPEND_CAP_USD` was refused every other
render, and admitted for these — bounded only by the $500 monthly program cap. The number the studio
had just shown them was not the number being enforced.

HV-022-13 wrote down that the *vendor* line was missing from `admitLipSync`. The per-film cap is not
named in any increment's gap list.

## What this increment does

- **`admitLipSync` asks the film's cap before it reserves**, with the amount it is about to reserve,
  exactly as the other admissions do.
- **Every admission call in `packages/api/src` names `filmCapUsd`.** The five that reserve `0` —
  editorial, graphics, delivery, sound mixes, dialogue replacement — are unaffected, because
  `assertFilmWithin` returns early on a zero amount; naming it there is what stops the next paid
  render from being admitted without it.
- **Each API module's context *requires* `filmCapUsd`**, so an unwired route is a type error rather
  than a silent omission. Adding the field failed `bun run typecheck` in three test files that build
  these contexts by hand, which is the guarantee doing its job.

## Acceptance criteria

1. **Every admission method that reserves a non-zero amount asks the film's cap**: over `admit`,
   `admitAudio` and `admitLipSync`, each `reserveWithin` whose amount is not the literal `0` sits in
   a method that calls `assertFilmWithin` — and `admitLipSync` asks *before* it reserves, with
   `policy.heldUsd`.
2. **Every admission call in the API names the cap**, with `admitEditSource` — which adds a source to
   the editorial library and reserves nothing — named as the one exception rather than filtered out
   silently.
3. **Each API module that admits requires the cap on its context**, not optionally, and the server
   hands each of them the single `filmCapUsd` it computed.
4. Reverting `packages/api/src/**` and `packages/storage/src/lipsync-ledger.ts` fails all three.

- Tests: `packages/api/test/film-cap-admissions.test.ts`. These are wiring guards, over the source,
  because the defect is wiring: the refusal itself is `assertFilmWithin`, which the other admissions
  already rely on and which `packages/operator/test/film-budget.test.ts` and
  `packages/api/test/film-budget-route.test.ts` cover. Verified: all three fail on the unchanged
  source.

## Known gaps this leaves

- **No end-to-end test admits a lip-sync pass past the cap.** The only suite that reaches
  `admitLipSync` is `packages/storage/test/lipsync.test.ts`, which needs PostgreSQL *and* S3 and skips
  without both; `packages/api/test/film-budget-route.test.ts`, the suite that drives the film cap end
  to end, runs on the local JSON store where `lipLedger` is undefined and the route answers 503
  before admission. The refusal is therefore asserted by construction here rather than by a run.
- **`filmCapUsd` is still optional on the ledger's own signatures.** `admit(…, filmCapUsd?)` and now
  `admitLipSync(…, filmCapUsd?)` both accept `undefined` and silently enforce nothing, which is what
  made the living-script call site's omission invisible. Making it required would touch every caller
  and every test that builds one; the guard above stands in for that.
- **The JSON path has no film cap at admission at all.** `assertFilmBudget` is called separately at
  `server.ts:1548` for dialogue replacement; the local store's `enqueue` does not take a cap, so a
  deployment without PostgreSQL is bounded only by the monthly cap. That is true of every stage, not
  just these two, and predates this.
- **Nothing reconciles the cap with what a film has already reserved elsewhere.** `filmSpend` sums
  this project's events and its own jobs' holds; a job that was admitted and then abandoned holds its
  reservation until `reconcile` runs.
