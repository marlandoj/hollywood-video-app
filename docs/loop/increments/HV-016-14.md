# HV-016-14 — A reopened rough cut left the studio on an empty pitch

epic: HV-016
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

HV-016-09 made the studio rebuild its step from a reopened project link. `index.html` started it
only after the Director's desk had finished its own resume:

    resumeProject(current.token).then(() => studio.resume())

`resumeProject` does not return when the project has been read. For a rough cut that has not been
approved it awaits `reviewAnimatic`, which resolves when the creator presses Approve or Send back in
the desk's animatic panel. For a render still running it awaits `pollJob` until the render ends. The
desk sits behind the Advanced switch, so the creator the studio was built for never pressed either
button, and `studio.resume()` never ran. They saw the pitch with an empty script box. The only action
it offered was to pitch again, which renders and charges again, for a rough cut already paid for.

## What this increment does

- **The studio starts its resume at once.** `resumeProject` sets `project` before its first await,
  and the studio reads the project itself, so it needs nothing else from the desk.
- The desk's resume is unchanged. If it fails, the desk still reports the failure and clears the
  project, as before.

## Acceptance criteria

1. **A rough cut awaiting approval.** Reopening the link resumes the studio to the rough cut, with
   the script and the resumed note. The desk still waits at its own animatic panel, and each of the
   desk and the studio reads the project once.
2. **A link that cannot reopen.** The desk still says *"Your project link is retained. Reload to
   retry."* The studio shows the server's error instead of staying on "Opening your film."
3. Reverting `index.html` fails criteria 1 and 2.

- Tests: `packages/frontend/test/studio-resume-desk.test.js`. It runs `index.html`'s own module
  script with the real studio and stubs for the other panels.

## Known gaps this leaves

- **Two resumes race.** The desk and the studio each read the project. If the creator approves the
  rough cut in the studio while the desk's panel is still waiting, the desk's panel stays open until
  they switch to it or reload. The two panels already disagreed this way before HV-016-09.
- **A late failure clears the project.** If the desk's resume fails after the project was read (a
  failed `pollJob`, for example), it still sets `project = null`, and the studio's next action has no
  project. This was also true before, when the studio had not resumed at all.
