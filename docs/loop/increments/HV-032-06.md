# HV-032-06 — Slow studio routes get two minutes on staging

epic: HV-032
release: 1 "Studio"
gate: none new
spend_usd: 0

## Why

The first titled studio run on staging skipped the titles with 502 "upstream unavailable".

The Editor inspects each editorial source with `GET /api/projects/:id/editorial/sources/:jobId`. On the staging host that takes about 11 seconds, because the cut is read back from S3 and checked. The API's socket idle bound defaults to 10 seconds. Bun closes the connection, and the edge reports "The socket connection was closed unexpectedly".

This was reproduced on the host with curl; the connection was closed after 11.5 seconds. `packages/api/test/http-idle-timeout.test.ts` documents the bound as an operator setting.

## What this increment does

- **Staging's runtime configuration** sets `HV_HTTP_IDLE_TIMEOUT_SECONDS=120` in all three places that write it: `deploy-storage-staging.py` `common()`, `deploy-private-staging.py` and `provision-staging-host.py`.
- The application default stays 10 seconds.
- **Docs:** `docs/STAGING-LOCAL.md`.
- **Operator step:** the running host gets the same line by hand, and the API restarts.

## Acceptance criteria

1. **Every deploy and the provisioned host write the 120-second bound.**
   - Test: `scripts/test_storage_deployment.py` `test_every_deploy_gives_slow_studio_routes_two_minutes`.
2. **A titled studio film completes on staging.** This is shown in the release run.
