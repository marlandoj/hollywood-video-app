# HV-024-05 — The studio said a phrase direction had been dropped, and then said something else

epic: HV-024
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

HV-024-04 stopped one keystroke from silently discarding all sixteen phrase directions on a line. It
kept the ones the edit left standing, dropped the rest, and told the creator how many went:

```js
function retext(text){
  const dropped=phraseEditor.retext(text);
  if(dropped)tell(dropped+" phrase direction"+…+" removed because the words "+…+" changed. …");
}
```

Every path that can reach `retext` reaches `editChanged` immediately afterwards, and `editChanged`
ends with `tell("Review this line's settings before generating an audition.")`:

- `language.onchange` calls `retext(...)` and then `editChanged()` outright;
- `narrationText.oninput` does the same;
- `translation` sits inside the `settings` fieldset, and `settings.addEventListener("input",
  editChanged)` runs after the target's own handler.

So the sentence was written and overwritten on all three paths, every time. HV-024-04's acceptance
criterion 2 — *"editing a word inside one phrase costs that one and reports one"* — was true of the
retention and false of the report, and its headline, *"the studio says so"*, was never made good on.
What the creator actually saw, having just lost a direction, was **"Review this line's settings
before generating an audition."**

Nothing caught it because nothing in this repository mounted the voice studio.
`packages/frontend/test/audio-phrases.test.js` asserts `retainedPhrases` and `editor.retext`'s return
value; `grep "removed because"` across `packages/` matches the source and the docs and no test. The
defect is not inside any function — it is the order in which two handlers for one gesture write to
the same line, and only dispatch can show that.

## What this increment does

- **The count is held rather than announced.** `retext` records how many directions the edit cost and
  calls `editChanged`; `editChanged` says the specific sentence when there is one and the generic
  line when there is not. One thing writes the status for an edit, so no ordering between a property
  handler and a bubbled listener can cover it.
- **The loss outlives the keystroke**, because the direction is still gone. It ends when the draft
  ends: the four places `dirty` goes back to false — discarded, submitted, found already submitted,
  and reloaded — and `fillDefaults`, which is what refills the draft from what was saved.
- **A DOM harness for this panel**, `packages/frontend/test/audio-studio-dom.js`: enough of an
  element to mount `initAudioStudio` on, and a `fire` that runs the target's `on<type>` handler and
  then every `addEventListener` up the tree, which is the order that produced the defect.

## Acceptance criteria

1. **A direction an edit dropped is reported, and the generic line does not write over it** — driven
   through the translation box, which reaches `editChanged` only by bubbling.
2. **It is reported in the plural, and from the narration box too**, which reaches `editChanged` by
   its own handler instead. Two directions lost, two reported.
3. **An edit that costs nothing says nothing about phrases**: typing at the end of a line leaves
   every earlier direction where it was, which is what HV-024-04 is for.
4. **The loss is still reported after an unrelated edit, and not after the draft is discarded.**
5. **The sentence is written in one place**: `retext` no longer calls `tell` at all, and the words
   appear once in the file's code.
6. Reverting `audio-studio.js` fails criteria 1–4 and 5.

- Tests: `packages/frontend/test/audio-studio-dropped-phrases.test.js`. Verified: four of its five
  fail on the unchanged source, and the fifth is the one that needs no phrase to be dropped.

## Known gaps this leaves

- **The notice is still the status line**, so anything else that writes the status — a refresh, an
  error, a scene draft change — clears it, and the creator has no way to ask again what an edit cost.
  A durable list of what this draft has lost would need somewhere to put it.
- **Nothing says *which* directions went**, only how many. `describePhrase` could name them, and the
  editor has thrown away the list by the time the caller is told.
- **The harness is a stub, not a DOM.** It implements the parts of an element this panel touches;
  anything it does not implement throws at the first call rather than behaving as a browser would,
  which is how `removeAttribute` was found. It is honest about that by failing loudly.
- **The rest of the panel is still untested.** This is the first test that mounts it, and it drives
  two of its controls; saving a voice, reviewing a line and the scene performance editor are all
  still covered only by the API tests behind them.
