# HV-039-01 — Raise the palette above WCAG AA and put a gate under it

epic: HV-039
spend_usd: 0

## Goal

Fix the contrast failures that are live in the shipped product today, collapse the duplicated palette that would otherwise let the fix land on one page and miss the other, and leave behind the epic's first automated accessibility assertion.

**What was failing, measured rather than claimed.** Converting each OKLCH token to sRGB and computing the WCAG relative-luminance ratio:

| pair | ratio | required | criterion |
|---|---|---|---|
| primary button label (`--text` on `--accent-strong`) | **3.25:1** | 4.5:1 | 1.4.3 |
| the same label on `:hover`, which repainted the fill with `--accent` | **2.44:1** | 4.5:1 | 1.4.3 |
| text input / select / textarea boundary against the page (`--line` on `--bg`) | **1.71:1** | 3:1 | 1.4.11 |
| the same boundary against a panel (`--line` on `--surface`) | **1.56:1** | 3:1 | 1.4.11 |

Every primary button in both the creator UI and the operator console, and every text control in both, at 16px weight 650 — not WCAG "large text", so 4.5:1 applies. **Nothing in the repository caught any of it: there were zero accessibility assertions across all twelve packages.**

**How this increment was found.** The program-wide re-verification of the pre-loop credit ran one auditor per epic across all 22 epics that had never had the pass `docs/loop/STATUS.md` says the first planner is supposed to run. HV-039 came back `partially-delivered` with eight defects and one BLOCKER, and with a correction to the board in the *other* direction: the delivered UI is not accessibility-naive — `lang`, viewport, landmarks, 3px focus rings that already clear 3:1, `prefers-reduced-motion` in both stylesheets, 34 controls at the 44px target, and real keyboard alternatives to both drag surfaces, which satisfies SC 2.5.7. The status `todo` is right; the empty Evidence column is what understated both the ground covered and the live failures. The four ratios above were recomputed from the tokens before any code was written and match the audit to two decimal places.

## The shape of the repair

**One palette, two readers.** `index.html` and `operator.css` each carried a `:root` block. They agreed on eight tokens by coincidence of maintenance and *disagreed on the name of a ninth*: `--accent-strong` in one file, `--action` in the other, same value, same role — so a contrast fix applied under one name could not reach the other page. `operator.css` also had `--good` for what the creator UI calls `--success`. `packages/frontend/src/tokens.css` is now the declaration; the duplicate names are gone, and a test holds both pages equal to it.

**The primary button fill goes darker, not the label lighter.** `--accent-strong` moves from `oklch(0.61 0.17 262)` to `oklch(0.52 0.17 262)`. That is the widest band that satisfies both criteria at once: the label reaches 4.75:1 (1.4.3 wants 4.5) while the button surface still reaches 3.43:1 against the page and 3.13:1 against a panel (1.4.11 wants 3). Lightening the label instead does not work — `--text` is already `oklch(0.94 …)`, and pure white on the old fill is only 2.91:1.

**The hover state brightens the boundary, not the fill.** `button:hover { background: var(--accent) }` was the single declaration that took the label to 2.44:1, and it was present in *both* files. There is no value of a lighter fill that keeps a light label at 4.5:1 while keeping the button at 3:1 against the page: the band is roughly `L ∈ [0.49, 0.53]`, which is imperceptible as a hover change. So hover now sets `border-color: var(--accent)` on a button that already carries `border: 1px solid transparent` — a visible lighter ring at 6.67:1 against the page, no layout shift, and both states compliant.

**A separate token for anything a person operates.** `--line` is deliberately left at `oklch(0.35 …)`. SC 1.4.11 does not reach a rule between table rows, a section divider or a panel edge, and raising that token to 3:1 turns every hairline in the product into a visible bar. The new `--control-border: oklch(0.53 0.025 275)` clears 3:1 against all three surfaces — 3.67:1 on `--bg`, 3.35:1 on `--surface`, 3.03:1 on `--surface-raised` — and is applied to text inputs, selects, textareas, secondary buttons, button-styled links and the metrics chart axis, the last because 1.4.11 also reaches graphical objects needed to understand content.

**The thresholds are literals in the test, and the conversion happens in the test.** `4.5` and `3.0` are written into `packages/frontend/test/contrast.test.ts`, never read from the stylesheet, so the test cannot pass by agreeing with whatever the palette currently says — the defect family this program has now found seven times. The test converts each OKLCH triple to sRGB with Ottosson's matrices and computes the WCAG ratio itself: no browser, no headless Chrome, no colour library, and no ratio read from a comment or a doc.

## Acceptance criteria

1. **Every token pair the UI relies on clears its WCAG 2.2 AA threshold, computed rather than asserted.** Twenty pairs — ten text pairs at 4.5:1 under SC 1.4.3 and ten boundary, state and graphical-object pairs at 3:1 under SC 1.4.11 — are checked against literal thresholds, with the OKLCH→sRGB conversion and the relative-luminance ratio computed in the test. The parse is sanity-checked (`tokens.size === 12`) so a regex that matched nothing cannot make every assertion vacuous. The two values this increment moved are additionally pinned at the ratios they now reach, so a later edit that stays above threshold but erodes the margin has to be a deliberate change in the test.

2. **The palette is declared once, and no third copy exists.** `tokens.css` holds all twelve tokens. The creator UI's inline block and the operator console's `:root` are asserted equal to it as whole maps, not pair by pair, and a scan of every other `packages/frontend/src/**/*.{css,html,js}` asserts no fourth file declares an OKLCH token.

3. **No boundary of something a person operates is drawn with the decorative separator token, and no hover state repaints a primary button with the foreground accent.** Rules that draw a border on an `input`, `select`, `textarea`, `button`, `summary`, `.secondary` or `.button-link` are checked by selector; `border-bottom` on a row or a `details` element is correctly treated as a separator and left alone. Both files are checked for the `button:hover { background: var(--accent) }` declaration.

4. **No behaviour, route, dependency, frozen path, budget default, account, vendor or migration changes.** The diff is three files plus a new stylesheet, a new test and this doc. Nothing under `docs/legal/**`, `docs/adr/**`, `.github/workflows/**`, `packages/safety/**` or `infra/drizzle/**`; no `package.json` or lockfile entry; no HTTP route, cookie, tracking, account, tier or payment path; no new environment variable. `docs/loop/STATUS.md` and `docs/PROGRAM-EXECUTION.md` are not in the diff; RECORD owns both.

## Demonstrated, not asserted

Six perturbations, each applied on this branch and reverted:

| perturbation | result |
|---|---|
| P1 — restore the old primary button fill (`oklch(0.61 …)`) in all three files | `2 pass / 1 fail` — criterion 1 |
| P2 — restore the hover repaint in the creator UI only | `2 pass / 1 fail` — criterion 3 |
| P3 — draw the operator console's text input boundary with `--line` again | `2 pass / 1 fail` — criterion 3 |
| P4 — fix the fill in `tokens.css` and the creator UI but not the operator console | `2 pass / 1 fail` — criterion 2 |
| P5 — lower `--control-border` to `L = 0.50`, which is 2.91:1 on `--surface-raised` | `2 pass / 1 fail` — criterion 1 |
| P6 — declare a fourth palette at the top of `operator.js` | `2 pass / 1 fail` — criterion 2 |

P4 is the one that matters most: it is exactly the half-fix the duplicated palette invited, and it is the reason criterion 2 exists rather than being folded into criterion 1. P5 is chosen at the boundary — one step of L below threshold — rather than at an obviously wrong value.

## Tests added

- `packages/frontend/test/contrast.test.ts` (new; offline, no browser, no network, no render) — three cases covering criteria 1–3. It is the first accessibility assertion in the repository and `bun test packages test` already picks it up, so it needs no change to the frozen `.github/workflows/**`.

## What this increment does **not** do

- **It does not serve one stylesheet to both pages, and that is a deliberate deviation from the audit's recommendation.** The staging edge (`edge.ts` in the staging runtime, not in this repository) serves only `/`, `/index.html` and `/vendor/hls.min.js` from the frontend, and `infra/Dockerfile.frontend` copies only `index.html` into the nginx image. A `<link rel="stylesheet">` to a second file would 404 in staging and render the creator UI **unstyled** — a worse accessibility outcome than the one being fixed. Serving it is a deployment change to a runtime this increment does not own. Until then the two `:root` blocks are copies that a test holds equal, which closes the drift risk without touching the deployment.
- **It does not fix the `aria-busy` live-region defect.** Five panels set `aria-busy` on an ancestor of their own status live region, which suppresses every screen-reader status and error announcement inside it. That is a separate shape — ARIA semantics, not colour — and it is the natural HV-039-02.
- **It does not reconcile the 2.1-vs-2.2 requirement.** Gate V-020 validates WCAG 2.1 AA while the epic is defined as 2.2 AA, a requirement written in five places where four copies disagree with the fifth. Naming which of the five is authoritative is a decision, not a code change, and it is not made here.
- **It does not address the remaining 1.4.11 surfaces, `placeholder` contrast, or any of the Mobile Review half.** Mobile Review is blocked on HV-029, which has one merged increment and no review-room surface yet.
- **It does not claim WCAG 2.2 AA conformance.** It claims that twenty specific token pairs clear two specific success criteria, computed. Conformance is a statement about the whole product against all of 2.2 AA, no part of which has been audited, and nothing in this diff says otherwise.
