# HV-037-02 — Measured identity similarity, and a paid-pass harness that refuses to spend without a declaration

epic: HV-037
release: 3 "Features"
gate: none new (cites G20-202610031349: Release 3's build order is agreed, and this is the $0 half of its step 9)
spend_usd: 0

## Why

Release 3's build order, step 9, "Benchmark with paid runs": "Measured scores, starting with identity
similarity; one paid pass of the 24-shot corpus per fal video model, about $20, declared". Step 10,
"Routing on measured quality", ranks providers "by the benchmark's scores, never by invented ones",
and the parts table's `HV-037.paid-benchmark` wants the corpus run on the live profile with its record
and spend committed.

Nothing the benchmark records today is a measured picture score:

- **`visualQualityProxy`** (`packages/benchmarks/src/run.ts`) is `min(1, clip bytes / 4096)`, a file
  size, and it is 1 for every clip the mock writes.
- **`continuityAvg`** runs the studio's real comparison (`continuityScore`) over `clip.fingerprint`,
  but the deterministic mock fills that field with a SHA-256 of its prompt, seed and model, not with a
  hash of any picture. So the 0.52 in `baseline.json` is the bit agreement of unrelated digests: a
  measurement of hashing, not of frames.
- **Cost** is $0 by construction, and latency is the mock's ffmpeg time.

And nothing could run the benchmark against a priced provider at all: `runBenchmark` hardwires the mock.

This increment builds the measured score and the harness at $0. It does not run the paid pass. That
pass, about $20, is a later increment that declares its own spend.

## What

**1. A measured identity score, using the comparison the studio already has** (`packages/benchmarks/src/identity.ts`).
No model and no dependency is added. `frameFingerprint` (`packages/generator/src/fal.ts`) is the
studio's 256-bit difference hash: the frame scaled to 17x16 grayscale, one bit per horizontally
adjacent pair. `continuityScore` (`packages/generator/src/index.ts`) is the share of bits two hashes
agree on. The Continuity Supervisor compares shot to shot with this pair. Here it compares a
character's locked reference image to the rendered clip's middle frame.

It is named for what it is: `identity-dhash256-midframe/1`. It measures whole-frame structure. It
is not a face-identity embedding. FULL-SCOPE P2's embedding was never built, as
`packages/planner/src/reference-lock.ts` says. 1 means identical structure, and unrelated pictures
score near 0.5.

- **The frame is hashed from the file on disk.** The score never reads `VideoClip.fingerprint`. A
  test double reports an all-zero fingerprint for every clip, and its frames still score as their
  pixels say.
- **A flat frame is reported, not scored.** A solid colour, which is every frame the mock renders,
  hashes to all zeros. Its "similarity" would only count the reference's zero bits.
- **Which characters a shot shows** = who speaks in it, plus any character its action names as a whole
  word, limited to characters with a reference. In the corpus that is 10 of 24 shots (KEEPER ×6,
  SAILOR ×4). VOICE has no reference. "Two figures" is not guessed at.

**2. A measured pass of the frozen 24-shot corpus** (`packages/benchmarks/src/measured.ts`).
`runMeasuredBenchmark` plans the corpus exactly as `runBenchmark` does (fixture v1.0.0, same sha256).
It renders each eligible shot once at 1280x720 for the shot's own duration and measures each rendered
frame. It writes an `hv-benchmark-measured/1` record with:

- the provider spec, provider and model ids;
- the capability revision, and whether the provider is a synthetic stand-in;
- the reference hashes;
- per shot: characters, references sent, the estimate, the actual cost, latency, clip sha256, frame
  time, frame hash, per-character scores and their mean;
- the aggregate per provider and model: rendered, skipped, failed and flat counts, scored shots,
  identity mean, min and max, and total cost.

A provider that takes references gets the shot's characters' references. A model that requires a
reference cannot render a shot with no locked character, so that shot is skipped and is not given
someone else's face. A priced provider is refused unless a ledger reservation is held. With one, each
shot asks the reservation first, every cost and sunk cost is recorded, and the pass stops when the
reservation can no longer cover a shot.

**3. A reader that refuses invented scores** (`readMeasuredRecord`). This is what step 10 should read.
It recomputes every rendered shot's per-character score from the frame and reference hashes in the
record. It recomputes each shot's mean and the whole aggregate, and refuses any mismatch. It also
refuses a score on a shot that was not rendered. It refuses records from a synthetic provider unless
the caller passes `allowSynthetic`, because a stand-in's picture says nothing about a vendor's.

**4. The paid-pass entry point.**
`bun run benchmark:paid --provider fal:<model> --declared-usd <n> --increment HV-037-NN --references <dir> [--out <file>]`
(`packages/benchmarks/src/paid.ts`). It refuses unless every check below passes, in this order. All of
steps 1–5 run before a provider is constructed or a ledger written.

1. The provider is a paid video model, named in full: `fal:<key of FAL_MODELS>`. Mock, bare `fal`,
   an unknown model and non-video specs are refused.
2. `--declared-usd` is given, in plain dollars above zero. The parser is the studio's `plainDollars`.
3. The increment doc carries `spend_usd:`, enough to cover the declared amount plus anything already
   spent under it (cost events under project `benchmark:<increment>`). The doc must also name the
   provider spec as a whole token. This is CLAUDE.md's rule as written. This doc declares
   `spend_usd: 0`, so the harness refuses to spend under HV-037-02, and a test proves it.
4. The runtime admits the spend:
   - `HV_COST_LEDGER_PATH` is set, and no database ledger URL is, since that ledger's spend would be
     invisible here.
   - The declared amount fits the per-film limit (`HV_FILM_SPEND_CAP_USD`, $40 by default). That
     limit is read under `min(HV_MONTHLY_BUDGET_USD, $500)`, so the program envelope bounds it.
   - `HV_COST_CAP_PER_SHOT_USD` is plain dollars.
5. References are given as `<dir>/<character>.png`, and none is flat. The provider's own capability
   prices the plan through `matchCapability`. The plan is refused if no shot is eligible or if its
   total is above the declaration.
6. The declared amount is reserved against the month's cap with the studio's `CostLedger.reserve`.
   The pass runs under that reservation, and the reservation is released at the end.

Priced offline from each model's capability (a test pins these):

| model | eligible shots | planned |
|---|---|---|
| `fal:kling-v2.5-turbo-pro` | 24 | $8.40 |
| `fal:kling-o3-standard-reference` | 10 (needs a reference) | $2.52 |
| `fal:kling-o3-standard-keyframes` | 0 (needs a first-frame still) | refused |
| `fal:veo3-fast` | 0 (retired) | refused |

The two models that can run cost **$10.92** together. That is under the roadmap's "about $20".

## Acceptance criteria

1. **The identity score is the studio's comparison, measured from pixels.** A reference's hash equals
   `frameFingerprint(png, 0)`, and the similarity equals `continuityScore`. The frame hash in a
   record equals the hash of the clip file at its midpoint, even when the provider reports a false
   fingerprint. Mock frames hash to all zeros and are flagged flat.
   *Test:* `packages/benchmarks/test/measured-identity.test.ts` → "the identity measure is the studio's own comparison, read from pixels" (3 cases).
2. **The score separates a model that holds the reference from one that cannot see it.**
   - On real rendered files, a reference-conditioned stand-in scores at least 0.9 on every scored
     shot. Measured: mean 0.991, min 0.984.
   - A text-only stand-in scores below 0.8 on every scored shot. Measured: mean 0.509, near chance.
   - The gap between the two means is more than 0.2.
   - Both passes score exactly the corpus's 10 character shots.
   *Test:* "a measured pass › separates a model that holds the reference from one that cannot see it", and "which characters a corpus shot shows".
3. **On the mock, the pass measures nothing and says so.** 24 rendered, 24 flat, 0 scored, mean null,
   $0, `synthetic: true`.
   *Test:* "on the mock provider every frame is flat…".
4. **The record carries per-shot scores with provider and model ids**, the fixture version and sha256,
   and the capability revision.
   *Test:* "the record carries per-shot scores…".
5. **Routing cannot read an invented score.** A real record reads back. These are refused:
   - a synthetic record, unless the caller allows it;
   - an edited shot score;
   - an edited aggregate;
   - a score on an unrendered shot;
   - a score on a flat frame;
   - a wrong schema.
   *Test:* "a measured record reaches routing only when its scores follow from its fingerprints" (2 cases).
6. **A paid provider without a declaration is refused before anything is constructed.** Each case
   below asserts four things: the refusal is a `PaidBenchmarkRefusal`, the provider resolver was never
   called, `fetch` (replaced by a spy) was never called, and no ledger file was written.
   - no `--declared-usd`;
   - a malformed amount: `0`, `-5`, `1e3`, `abc`, `20.555`, `Infinity`;
   - no increment, or a missing doc;
   - **this increment's own doc (`spend_usd: 0`)**;
   - a doc that does not name the provider, names only a longer spec, or declares no spend.

   The same refusal holds run as a command: `bun packages/benchmarks/src/paid.ts --provider fal:kling-v2.5-turbo-pro --increment HV-037-02` exits 2 and writes nothing.
   *Test:* `packages/benchmarks/test/paid-harness.test.ts` → "a paid provider without a declaration is refused…" (5 cases) and "run as a command…".
7. **Only a paid video model named in full is admitted.** These are refused: `mock`, an empty spec,
   `anchor-storyboard`, bare `fal`, `fal:no-such-model` and `image:fal`.
   *Test:* "only a paid video model, named in full, is admitted".
8. **The runtime must admit the declared spend.** These are refused:
   - no ledger path;
   - a database ledger URL;
   - $41 against the $40 film limit, or $20 against an operator limit of $15;
   - a malformed monthly or per-shot cap;
   - a film limit above the $500 envelope;
   - a plan priced at $24 against $20 declared;
   - earlier passes under the increment that leave too little;
   - missing or flat references;
   - a month already at $490 of $500, which the ledger's own reservation refuses.

   In every case no shot is rendered, and the ledger is unchanged or never written.
   *Test:* "the runtime must admit the declared spend" (6 cases).
9. **An admitted pass is held by the ledger.** This runs against a local priced stand-in, through an
   injected resolver, on a temporary ledger, with no network.
   - All 24 costs ($6.00) are recorded under `benchmark:<increment>`. The reservation is released.
     The record is written and reads back.
   - A provider that bills $4 against a $0.25 estimate stops after 3 shots under $10 declared. The
     other 21 shots are recorded as skipped, with the reason "declared spend exhausted".
   *Test:* "an admitted pass is held by the ledger" (2 cases).
10. **The pass is priced per fal model, offline**, as in the table above.
    *Test:* "what a paid pass of the corpus would cost…".
11. **The existing gate is untouched and passing.** `baseline.json`, `BENCHMARK_FIELDS`,
    `ANIMATIC_FIELDS` and `scripts/benchmark/compare.ts` are not in the diff.
    `packages/benchmarks/test/benchmark.test.ts` and `metric-classification.test.ts` pass unchanged.

## Declared changes

- Root `package.json` gains one script, `benchmark:paid`. No dependency is added, and `bun.lock` is
  not in the diff.
- **No metric is added to `baseline.json`.** It would have been a gated constant: on the mock every
  frame is flat, so the score is null. Computing it inside `runBenchmark` would also add 24 ffmpeg
  probes to the `totalPipelineMs` that the same-host A/B gates. The measured score lives in its own
  record until a real pass gives it values worth gating.

## Known gaps

- **The paid pass itself is not run.** About $20 was allowed. Priced here, the two runnable models
  come to $10.92. The pass is a later HV-037 increment, and its doc must:
  - declare `spend_usd`;
  - name each `fal:<model>` it runs;
  - commit the corpus's locked reference images, with their sha256;
  - commit the records under `docs/evidence/release-3/` (`HV-037.paid-benchmark`).
- **The corpus has no locked references yet.** The tests use synthetic lavfi patterns (testsrc2,
  mandelbrot), which a text-to-video model cannot be expected to reproduce. The paid increment needs
  real character references for KEEPER and SAILOR. They must be invented characters, never a real
  person, under the consented-casting rules. A mock character sheet from the studio's own sheet stage
  would serve, at $0.
- **The anchored (look-matched) profile cannot be benchmarked yet.** G20 chose
  `kling-o3-standard-keyframes` for the live feature. It needs a first-frame still per shot, and the
  corpus carries none, so the harness refuses it with `frame-anchors`. Benchmarking it needs a frozen
  set of 24 anchor stills. That is a corpus version bump.
- **The reference-conditioned model renders only 10 of 24 shots.** It requires a reference, and 14
  shots have no locked character. Its record says so, shot by shot.
- **The measure is whole-frame structure, not face identity.** A correct face in a wide shot can score
  near chance. Step 10 should treat it as a measured proxy that is honestly named, and should not
  call it identity fidelity. A face-crop or embedding comparison needs a model the repository does not
  have, which would be a G3-class addition.
- **On the staging host the ledger is PostgreSQL**, and this harness records only to the JSON
  `CostLedger`. It refuses to run when a database URL is set rather than spend where the cap cannot
  see it. `BenchmarkLedger` is shaped so that `PostgresCostLedger` satisfies it. Wiring and proving
  that is the paid increment's first task, or the pass runs where the JSON ledger is the program's.
- **A provider that bills past its estimate can overrun the declaration by one shot.** This follows
  the studio's ledger convention: a shot is admitted on its estimate. The stop is proven, but the
  overrun is bounded only by the per-shot cap.
- **`visualQualityProxy` and `continuityAvg` in the deterministic gate are still not measured picture
  scores**, for the reasons in Why. They are left alone, because changing them changes the gated
  baseline. A later increment should rename them or replace them.
- Step 10 (routing on measured quality) is not started. `RoutingStrategy` is still `configured | cost | latency`.
