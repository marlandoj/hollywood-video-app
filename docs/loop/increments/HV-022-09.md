# HV-022-09 — The crew casts from the operator's first vendor

epic: HV-022 (performance: voice, dialogue, lip-sync, ADR)
release: 2 "Voice and crew depth"
gate: G14-202609210000 (ElevenLabs primary, Azure as the fallback)
spend_usd: 0

## Why

The operator's decision was "ElevenLabs primary, Azure behind it": the crew casts the better voice
and keeps the Azure work for when a voice is unavailable. The Sound persona could not act on that —
`castVoices` looked only at Azure's three voices and knew each one's sex from a map in the
repository. With a second vendor authorized, both had to change.

The second vendor's voices are not a fixed list, so their sex cannot be a map here. The account's
own catalogue states it, and that is already evidence the operator captured: the catalogue now
carries the vendor's own label, and nothing in this repository judges a voice by its name.

## What this increment does

- **`hv-audio-policy/4` carries `sex`**, from the account's own `labels.gender`, only for the vendor
  whose catalogue states it, bound into the permission revision like the rest of the evidence.
- **`policyVoiceSex`**: the vendor's stated sex, or Azure's fixed map for an Azure voice.
- **`VOICE_VENDOR_ORDER`** — `["elevenlabs", "azure"]`, the operator's order. `castVoices` builds its
  pool from every authorized, currently valid policy, and for each part casts from the first vendor
  that has a voice fitting the script's stated sex, falling back to the next that does. Azure's
  voices keep their catalogue order, so a film cast on Azure alone is cast exactly as before.
- **`crewVoiceProfile`** builds each vendor's own profile contract — `hv-audio-voice/4` with the
  vendor's settings for ElevenLabs, `hv-audio-voice/2` for Azure — with the crew's brisker pace in
  both.

## Acceptance criteria

1. **With both vendors authorized, the parts go to the first one**, on its own voice contract with
   the crew's pace and the vendor's settings, and the crew's note names the voice it cast.
2. **A part the first vendor cannot fill falls back to the next**, while the parts it can fill stay
   with it.
3. **With only Azure authorized, nothing changes** for films already cast that way.
4. **An expired voice is never cast**, whichever vendor it belongs to.
   - Tests for 1–4: `packages/planner/test/crew-voices.test.ts`.
5. **Nothing else changes.** The crew voice route, catalogue and audio suites pass unchanged.
