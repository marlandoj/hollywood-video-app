# HV-026-05 — The tests nobody typechecked

epic: HV-026
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

`tsconfig.json` included `packages/**/*.ts` and `scripts/**/*.ts` and nothing else. The repository
also has `test/`, `infra/` and `drizzle.config.ts`, and none of them was ever seen by `tsc` —
twenty-one files, including the six suites that read the release evidence and the staging records.
`bun run lint` covers them, but oxlint does not know types, so a change to a shared type could break
them with no signal until the suite ran, and CI's `typecheck` step said nothing.

It did break them. **HV-026-04**, last night, made a quality check's sound measurement nullable to
stop it reporting an unmeasured soundtrack as silence. It updated every reader `tsc` could see and
left `report.sound.meanVolumeDb` standing in `test/picture-qc-check.test.ts` — two errors, hidden by
a glob, in the file that reads the record of the first real film this studio checked.

A critic pass over HV-026-02 also found two claims in that increment's record that were not what its
tests establish. They are corrected here because they are about the same file.

## What this increment does

- **Every TypeScript file in the repository is typechecked**: `test/**/*.ts`, `infra/**/*.ts` and
  `drizzle.config.ts` join the include list. Two errors were waiting there and are fixed.
- **A guard that walks the repository** rather than naming directories: every `.ts` file outside
  `node_modules` must be matched by some pattern in the typechecker's own include list, and every
  pattern must match something — an include naming a directory that no longer exists reads as
  coverage. A new directory is covered the day it appears.
- **`report.sound` is asserted, not asserted past.** A null there would mean no meter ran on that
  film, which is a different record from the one the test is about.
- **The frame-count assertion is no longer brittle.** `framesSampled === durationSec * 30` is only
  an integer when a film's last frame lands exactly on a frame boundary. This film's fourteen
  seconds do; most films' durations do not, and the assertion would have failed the next film
  measured whether or not the check was right.
- **HV-026-02's record gains a Corrections section** naming both: criterion 6 reads as though both
  halves were evidence when one is the record repeating itself, and criterion 5 was asserted in a
  way that would not survive a film of ordinary length.

## Acceptance criteria

1. **`bun run typecheck` covers the whole repository** and passes.
2. **The guard bites**: with the old include list, it names the twenty-one uncovered files. (Shown by
   reverting the config locally; the committed test asserts the covered state.)
3. **An include pattern that matches nothing is refused**, so a stale entry cannot read as coverage.
4. **The guard is asserting over a real walk**: it finds `test/picture-qc-check.test.ts` and more
   than five hundred files before it concludes anything.
5. **The evidence suite still passes**, with the sound reading asserted and the frame count asserted
   to within a frame.

- Tests: `packages/api/test/typecheck-coverage.test.ts` (1, 3, 4), `test/picture-qc-check.test.ts` (5).

## Known gaps this leaves

- **Criterion 2 is shown, not tested.** A test that rewrites `tsconfig.json` to prove the guard
  fails would be a test that edits the repository's own configuration while other suites read it. It
  was run by hand and the result is recorded here: twenty-one files.
- **This says nothing about test *quality*.** Every one of these files is now typechecked; whether
  what they assert is worth asserting is a different question, and the two corrections above are one
  answer to it for one file.
- **`bun run lint` and `bun run typecheck` still have separate ideas of what the repository is.**
  oxlint is given `packages scripts test` on the command line and does not read the tsconfig. They
  agree today because this increment made them; nothing keeps them agreeing.
