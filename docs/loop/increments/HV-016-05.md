# HV-016-05 — The parser deleted the line instead of the span

epic: HV-016
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

A critic pass over `packages/parser` and `packages/safety`.

A Fountain note is `[[…]]` and a boneyard is `/*…*/`. Both mean *this is not part of the film*.
Fountain removes the **span**. This parser asked a predicate about the whole line and, when the
answer was yes, returned before parsing it:

```ts
if (protectedRanges.has(i)) return;
```

So the writer's text on that line went with it:

```
without a note           action = ["She slides the envelope across the bar."]  warnings 0  unparseable 0
with a trailing note     action = []                                           warnings 0  unparseable 0
with an inline boneyard  action = []                                           warnings 0
```

Silently. Nothing in `warnings`, nothing in `unparseable` — which is the one thing this package's own
rule forbids. HV-016-02 refused three constructs specifically because *"a script note nested inside
another put its words in the film while the report said one note was removed — both halves of this
epic's rule broken at once"*. This is the other half, on the commonest construct there is.

### On a scene heading it deleted the scene, and blamed the wrong line

```
INT. BAR - DAY [[needs a rewrite]]

She enters.

EXT. STREET - NIGHT

He follows.
```

```
scenes:      [{heading: "EXT. STREET - NIGHT", action: ["He follows."], dialogue: []}]
warnings:    [{code: "UNPARSEABLE", message: "Unparseable construct at line 3", line: 3}]
unparseable: [{line: 3, text: "She enters."}]
```

The heading was dropped, so `current` stayed null, so the scene's own action was filed as
unparseable. The writer's first scene is gone from the film, and the only diagnostic points at a
line that parses perfectly and names a cause that is not true of it.

### And a boneyard that closes and reopens on one line leaked what the writer cut

The latch was `l.includes("/*") && !l.includes("*/")`. A line holding both fails that test, so the
latch never set — the line itself was dropped by the predicate and **every following line of the
boneyard was parsed as film**:

```
INT. LAB - DAY

Visible action. /* old */ kept /* cut from here

SECRET ACTION THE WRITER DELETED
more deleted material */
```

```
dialogue: [{character: "SECRET ACTION THE WRITER DELETED", lines: ["more deleted material */"]}]
warnings: []
```

Material the writer explicitly cut became a character cue and a spoken line — rendered, voiced and
burned into the captions. That is the exact inverse of what the check exists for.

## What this increment does

- **`scanProtectedSpans(line)` returns what is left**, not whether there was something: the text with
  its notes and closed boneyards taken out, `closedSpans` for whether one was, and `opensBlock` for
  whether the line ends inside a boneyard. The parse loop uses that text.
- **`opensBlock` answers on the last unmatched opener**, not on "contains a closer anywhere", so a
  line that closes one boneyard and opens another is both.
- **A line inside a block comment resumes at its closer**: the text after `*/` is scanned again and
  kept, which is what makes a boneyard a span rather than a mode the file never leaves.
- **A line reduced to nothing is still skipped, not treated as blank.** A blank line ends a speech
  and a whole-line note must not start doing that — it was skipped before and it is skipped now.
- **`holdsProtectedSpan` is defined in terms of the scan**, so the two cannot answer differently, and
  it still means *a note or a **closed** boneyard* — not an unterminated opener, which is the block
  latch's business. HV-016-04's equivalence proof over 87,380 strings and 200,000 seeded ones runs
  against it unchanged and still passes.

## Acceptance criteria

1. **A note beside the writer's text costs the note, not the text** — trailing, inline, and a closed
   boneyard — with the noted parse equal to the unnoted one and nothing in `warnings` or
   `unparseable`.
2. **A note on a scene heading costs the note, not the scene**: both scenes, both actions, and no
   diagnostic about a line that parses.
3. **A boneyard that closes and reopens on one line does not leak what the writer cut**: no cue, no
   speech, the deleted strings absent from the whole result, the kept text kept — and text after the
   closer on a closing line is film again.
4. **A line that was nothing but a note still does not end a speech**, and a genuinely blank line
   still does.
5. **The predicate still answers what it answered**, including the distinction between a closed
   boneyard and an unterminated opener, which is the one that would have been easy to lose.
6. **The whole 200,000 characters the route allows is still one pass**, over five adversarial shapes
   plus the parser end to end — HV-016-04's property, which turning a predicate into a scan is
   exactly the change that could quietly undo.
7. Reverting `index.ts` makes the test file fail to load, because the function it scans with does
   not exist.

- Tests: `packages/parser/test/protected-span-removal.test.ts`, and
  `packages/parser/test/protected-span.test.ts` unchanged.

## Known gaps this leaves

- **Removing a span leaves its whitespace.** `She [[who?]] waits.` becomes `She  waits.` with two
  spaces, and `Visible action. /* old */ kept` becomes `Visible action.  kept`. Fountain says
  nothing about it and the double space reaches the prompt. Collapsing it would mean deciding
  whether `word[[note]]word` is one word or two, which is a choice about the writer's text rather
  than about the span, so it is left alone and said out loud here.
- **A note is still not reported.** Nothing counts how many were removed, the way the Final Draft
  importer counts the parentheticals it drops. A note is *meant* to be removed, so this is a smaller
  gap than the one closed above — but "removed three notes" is information the writer could use, and
  it is not offered.
- **The other findings from the same pass are not here.** A Fountain parenthetical is still pushed
  into the speech and is therefore spoken by the voice vendor and burned into the caption, where the
  Final Draft importer refuses the same construct by name and says why; and an all-caps action line
  is silently reclassified as a character with nothing to say, which the importer's own note then
  misdescribes as "imported as action". Both are proven, both are their own increment.
- **This is Fountain.** The Final Draft importer has its own reader and was not touched.
