# HV-017-14 — Retrying a character sheet whose answer was lost paid for it twice

epic: HV-017
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

"Generate character sheet" posts to `/cast/:id/sheets` with an idempotency key. The server admits
one job per key: a second request with the same key gets the first job back with `admitted: false`.
The panel made a new key on every press (`crypto.randomUUID()`). Suppose the server admitted the
sheet but its answer never arrived, because of a 502 from the proxy or a dropped connection. The
panel said the sheet could not start. Pressing the button again, the one thing the panel invited,
sent a new key and started a second paid sheet.

## What this increment does

- **A retry reuses the key.** The panel keeps the key of a submission whose outcome it does not
  know, together with what that submission asked for (cast version and settings). When the creator
  asks for the same sheet, it sends that key again.
- **Anything else gets a new key, as before**: a different seed, type or scene, or a sheet asked for
  after the last one was answered.

## Acceptance criteria

1. **Lost answer, same sheet.** Pressing Generate again sends the identical body with the same key,
   and the panel reports the sheet queued.
2. **Lost answer, different sheet.** A different seed after a lost answer gets its own key.
3. **Answered sheet.** The same sheet asked for again after its answer arrived gets a new key.
4. Reverting `character-sheets.js` fails criterion 1.

- Tests: `packages/frontend/test/character-sheet-retry.test.js`.

## Known gaps this leaves

- **The key lives only as long as the panel.** Reloading the page after a lost answer forgets the
  key. The sheet the server admitted appears in the panel's history on the next load, so the creator
  can see it before asking again. The history doesn't tell them not to ask again.
