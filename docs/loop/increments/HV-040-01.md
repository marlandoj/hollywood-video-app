# HV-040-01 — Object lifecycle: incomplete multipart upload collection
epic: HV-040
spend_usd: 0

## Goal
Close the "lifecycle policies" gap in the storage pillar. Artifacts already upload as 8 MiB multipart objects (`packages/storage/src/artifacts.ts`), and the PostgreSQL retention sweeper already deletes purged-project prefixes and collects superseded completed objects after a 24-hour grace period (`packages/storage/src/retention.ts`, `scripts/sweep-expired.ts`). Nothing collects multipart uploads that were initiated but never completed, for example after a worker crash or lease loss mid-upload. Those parts are invisible to `ListObjectsV2`, are never referenced by `hv_artifacts` or `hv_archives`, and accumulate in the private bucket indefinitely. This increment adds a bounded, fail-safe hourly pass that aborts stale incomplete uploads under the application's own namespaces, and declares the matching bucket-level lifecycle rule during bucket preparation so the object store enforces the same policy independently. No end-user route changes; no paid provider is touched.

## Acceptance criteria
1. **Stale incomplete uploads are aborted.** `PostgresRetention` gains `collectIncompleteUploads(now = Date.now(), graceMs = 864e5, maxPages = 100)` which lists in-progress multipart uploads under the `v1/` and `archives/` prefixes only, and aborts each upload whose `Initiated` time is older than the grace period, whose project row exists in this database, and whose project has no `queued` or `running` job. It returns `{aborted, retained, supported: true}`. Satisfies FULL-SCOPE §3 P15 Full scope: "Storage: S3-compatible object storage with multipart upload, lifecycle policies, signed short-lived URLs, CDN delivery, regional placement." and the §9 epic register row "HV-040 | Storage and Archive at Scale (PostgreSQL, S3, lifecycle, portable archive)".
2. **Live and foreign work is never touched.** Uploads younger than the grace period, uploads for a project with a queued or running job, and uploads whose key does not parse to a known project in this database (unknown namespace, or another test run's per-run project) are retained and counted, never aborted. The grace period may not be set below one hour and page bounds are validated exactly as `collectOrphans` validates them. Satisfies FULL-SCOPE §3 P15 Full scope "Reliability: … near-zero loss for approved media" and §10 "Evidence before promotion: tests, benchmarks, post-flight evals, gap audits."
3. **The pass is bounded, resumable and idempotent.** Listing uses the store's `key-marker` / `upload-id-marker` continuation and retains the marker across passes in the same process, exactly like the existing `cursors` map for objects. Running the pass a second time immediately after the first aborts nothing further. A failed abort of one upload is counted as `failed`, does not stop the pass, and the next pass retries it. Satisfies the §9 Wave A exit "Staging runs on PostgreSQL + S3 with the existing E2E passing" (the sweeper loop must keep running) and §10 "Evidence before promotion".
4. **An object store without the API degrades truthfully.** If `ListMultipartUploads` returns `NotImplemented` (HTTP 501) or an unsupported-operation error, the pass returns `{aborted: 0, retained: 0, supported: false}` without throwing, the existing object orphan pass still runs, and the sweeper log line records `incompleteUploads: {supported: false}`. Satisfies FULL-SCOPE §10 "Provider independence and versioned adapters" (the S3-compatible contract is not assumed beyond what is verified).
5. **In-repo SigV4 request signing, no new dependency, secrets from the environment only.** Bun's `S3Client` exposes no multipart listing or abort call, so a small `packages/storage/src/s3-requests.ts` signs `GET /{bucket}?uploads&prefix=…` and `DELETE /{bucket}/{key}?uploadId=…` with AWS Signature Version 4 using `node:crypto`, taking endpoint, region, bucket and credentials from the same `HV_S3_*` variables and the same HTTPS-or-loopback endpoint rule as `objectClient()`. No entry is added to any `package.json`. Satisfies FULL-SCOPE §3 P15 "S3-compatible object storage" and CLAUDE.md "Secrets come only from the environment".
6. **Hourly scheduling in the retention sweeper.** `scripts/sweep-expired.ts` runs `collectIncompleteUploads()` on the same hourly cadence as `collectOrphans()` and includes its result in the per-minute JSON status line. A thrown error from the multipart pass is logged as `retention.incomplete_uploads_failed` and does not stop project purge, cache cleanup, S3 deletion or object orphan collection. Satisfies FULL-SCOPE §3 P15 "lifecycle policies" and the reliability sentence cited in criterion 2.
7. **Bucket-level lifecycle rule declared at preparation.** `scripts/prepare-object-bucket.py` puts a lifecycle configuration containing one rule, `AbortIncompleteMultipartUpload` with `DaysAfterInitiation: 1` (matching the 24-hour application grace), reads it back, and prints `"bucketLifecycle": "declared"`. If the store answers `NotImplemented`, `MalformedXML` or an equivalent unsupported-operation error, the script prints `"bucketLifecycle": "unsupported"` and still exits successfully with the public-access block verified exactly as today. It never removes or relaxes the public-access block. Satisfies FULL-SCOPE §3 P15 "lifecycle policies" and §5 "S3 object storage, signed URLs, lifecycle".
8. **No frozen path, budget default, account, vendor or user-facing surface changes.** The diff touches nothing under `docs/legal/**`, `docs/adr/**`, `.github/workflows/**` or `packages/safety/**`, and adds no key, account, tier, cookie or tracking. Satisfies FULL-SCOPE §10 "Free and anonymous for every end user; no billing code reachable." and "Safety refusals expand only."

- `packages/storage/test/s3-requests.test.ts` (offline, always runs): canonical request, string-to-sign and signature for a fixed timestamp and the published AWS SigV4 example credentials (`AKIDEXAMPLE` / `wJalrXUtnFEMI/K7MDENG+bPxRfiCYEXAMPLEKEY`, `20150830T123600Z`) match the expected values; query parameters are sorted and RFC 3986 encoded; the endpoint rule rejects plain HTTP to a non-loopback host; the XML parsers for `ListMultipartUploadsResult` (uploads, `IsTruncated`, `NextKeyMarker`, `NextUploadIdMarker`) and for S3 error bodies (`Code`) are exercised with fixture documents.
- `packages/storage/test/s3-requests.test.ts` (`s3test`, real RustFS in the CI storage lane): create a multipart upload, upload one part, list it under its prefix, abort it, list again and get zero; `Initiated` parses to a finite timestamp.
- `packages/storage/test/incomplete-uploads.test.ts` (`s3test`, per-run database `hv_lifecycle_test_<uuid>` and per-run project ids in the CI bucket, cleaned in `afterAll`): seed (a) a stale upload for an idle project, (b) a fresh upload for the same project, (c) a stale upload for a project with a running job, (d) a stale upload under a key whose project id is not in this database, (e) a stale upload under an unrelated prefix outside `v1/` and `archives/`. With `now = Date.now() + 2 * 864e5`: only (a) is aborted; (b) with real `now` is retained; (c), (d), (e) remain listed after the pass. A second pass aborts nothing. After the running job completes, (c) is aborted on the next pass. Bounds validation throws for `graceMs < 3600e3` and for out-of-range `maxPages`.
- `packages/storage/test/incomplete-uploads.test.ts` (offline, injected client): an abort that throws for one upload is counted as `failed`, the remaining uploads are still aborted, and a repeat pass retries the failed one; a listing that returns HTTP 501 / `NotImplemented` yields `{aborted: 0, retained: 0, supported: false}` without throwing; a truncated listing across two pages resumes from the retained markers and aborts on both pages within `maxPages`.
- `scripts/test_prepare_object_bucket.py` (Python, stubbed boto3 client, registered with the existing `scripts/test_*.py` runs): lifecycle configuration is put with exactly one `AbortIncompleteMultipartUpload` rule of one day and read back; a `NotImplemented` / `MalformedXML` response yields `"bucketLifecycle": "unsupported"` and a zero exit; the public-access block is still put and verified in both cases; a mismatched read-back raises.
- Existing `packages/storage/test/retention.test.ts` and `artifacts.test.ts` continue to pass unchanged, proving completed multipart objects and referenced media are unaffected.

## Out of scope
- Signed short-lived URLs for end-user media delivery, CDN delivery and regional placement (need an edge or CDN vendor; media stays behind the capability proxy; gate G3/G7 territory).
- Off-host or encrypted backup replication, five-minute RPO evidence and disaster-recovery drills (owned by HV-038; the unmerged branch `codex/ZOU-1607-offhost-recovery` holds that work).
- Object versioning, soft delete of objects, changes to the 24-hour object orphan grace, or any change to project retention dates.
- Applying the lifecycle rule to the live staging bucket by hand, changing the public-access block, or editing `.github/workflows/ci.yml`.
- Operator console or diagnostics fields for the new counts (HV-038).
- Any new npm or pip dependency, vendor, account or key.
