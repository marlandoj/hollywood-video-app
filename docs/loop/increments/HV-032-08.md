# HV-032-08 — An idle worker stops reading the whole studio every second

epic: HV-032
release: 1 "Studio"
gate: none new
spend_usd: 0

## Why

During the Release 1 run the staging host got slower as the day went on. Measured on the host while
no job was queued or running:

| Workers | State | CPU |
|---|---|---|
| 1 idle worker | nothing to do | ~1.8 cores |
| 3 idle workers | nothing to do | ~5 cores of 8 |

The poll loop in `runWorker` reconciled reservations like this:

```ts
await context.ledger.reconcile(new Set((await store.all()).filter(j => j.status === "queued" || j.status === "running").map(j => j.id)));
```

`PostgresJobStore.all()` reads every job body in the studio. On staging that is 96 jobs and 8.6 MB
of JSONB — fetched, transferred and parsed about once a second, per worker, only to keep the ids.
The cost grows with every film the studio has ever made.

It is not only waste. With three workers spending five cores on this, the worker that actually had a
film to render was starved: the Release 1 short's `dialogue-replacement` ran for over 30 minutes
(HV-025-06 removed its quadratic permission check, which the starvation had amplified), and the
short's `final` stage lost its lease twice while its shots rendered.

## What this increment does

- **`PostgresJobStore.activeJobIds()`**: `select id from hv_jobs where status in ('queued','running')`.
  No bodies leave the database.
- **`DurableJobStore.activeJobIds()`**: the same set from the JSON store, without copying the jobs.
- **`runWorker`** reconciles from that set.

Reconciliation itself is unchanged: a reservation older than the grace period whose job is no longer
active is still released, by the same code, on the same cadence.

## Acceptance criteria

1. **The idle loop never reads a job body.** A worker started on a store whose only job is `done`
   polls, reconciles from the active ids more than once, and calls `all()` zero times.
   - Test: `packages/queue/test/idle-poll.test.ts`.
2. **The projection is exactly the active jobs.** On PostgreSQL, `activeJobIds()` equals the ids of
   the queued and running jobs from `all()`, and a cancelled job leaves the set.
   - Test: `packages/storage/test/jobs.test.ts`.
3. **Nothing else changes.** The queue worker, fleet and storage job suites pass unchanged.
