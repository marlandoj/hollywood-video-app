# HV-039-07 — The graphics desk rebuilt "Rendered versions" every 1.5 seconds while a render ran

epic: HV-039
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

While a title or credits render runs, `watch` polls its job every 1.5 seconds and then calls
`drawRenders`. `drawRenders` started with `renders.replaceChildren()` and rebuilt the box from
nothing: the Version list, a new `role=status` line and a new **Inspect retained frames** button.
A graphics render runs for tens of seconds, and throughout it:

- **A keyboard user** who had tabbed to Inspect or to the Version list lost focus to the page body
  every 1.5 seconds.
- **An open Version list** closed under the pointer while the creator was choosing from it.
- **A screen reader** got a new live region each time, and its words were written again even when
  nothing had changed. So the progress was read out on every poll, and a creator using one couldn't
  hear anything else in the desk.

## What this increment does

- **The box is built once for a set of renders**, keyed by their ids, and updated in place after
  that. Only the version labels and the status line change.
- **A word is written only when it changes.** A poll that brings the same progress writes nothing.
- A new render, or opening another graphic, changes the set of renders, and the box is built again
  for it, as before.

## Acceptance criteria

1. **Across a progress poll, the box, the Version list, the status line and Inspect are the same
   elements, still on the page**, and the status line shows the new progress.
2. **A poll that changes nothing writes nothing to the status line.** A poll that changes the
   progress writes it once.
3. **An older version chosen during a render stays chosen, in the same list.** When the render
   finishes its label reads "done", and nothing is left polling.
4. Reverting `graphic-studio.js` fails all three.

- Tests: `packages/frontend/test/graphic-renders-poll.test.js`, using the planner's own graphic
  defaults, with the 1.5-second poll run by the test.

## Known gaps this leaves

- **Takes poll the same way.** `takes.js` disables every control in the take panel for each
  2.5-second status check, which drops focus in browsers that move it off a disabled control. That
  fix belongs with the takes desk's own test.
- **Closing the graphics desk** doesn't return focus to the button that opened it (see HV-039-05
  and HV-039-06 for the cast and shot desks).
