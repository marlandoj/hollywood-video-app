# HV-039-06 — Shot direction dropped keyboard focus to the page body after every save

epic: HV-039
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

HV-039-05 fixed the cast desk. The shot-direction desk had the same shape, with a longer way back.
Every change goes through `mutate`, which on success hides the form and calls `render`. `render`
starts with `list.replaceChildren()`. So:

- **Save shot direction** sits in the form that was just hidden.
- **Remove direction for s3** sits in the list that was just rebuilt.
- **Cancel shot edit** hides its own form.
- **Close shot editor** hides the desk.

In each case the browser drops focus to the page body. The desk lists up to 24 shots, grouped by
scene and folded into groups of six, and only the first scene and group are open. A keyboard or
screen-reader user who saved shot 7 had to go back to the top of the page, find the desk, open the
group again and find the shot. No test had ever mounted `direction.js`.

## What this increment does

- **Close** returns focus to the button that opened the desk ("Save screenplay and direct shots").
- **Cancel shot edit** returns focus to the Edit button that started the edit.
- **A successful save or removal** focuses the shot's own row heading. If the row's scene or group
  of six is folded, it is opened first, because focus inside a closed `<details>` goes nowhere a
  person can see. A restore, which covers no single shot, focuses the desk heading.
- **A refused save** leaves focus where it was, because nothing was rebuilt.
- To mount the desk, the test DOM gains `createElementNS`, `createTextNode`, `setCustomValidity`
  and `localName`. The test builds the desk's state from the planner's own defaults and choices,
  the ones the direction route sends, so the viewfinder, camera path and coverage editors fill the
  way they do in a browser.

## Acceptance criteria

1. **Close returns focus to the opener.**
2. **Saving s7, which sits in a folded group of six, focuses s7's row** and that row is visible.
3. **Removing a saved direction focuses that shot's row**, and no longer the removed button.
4. **Cancel returns focus to the Edit button that started the edit.**
5. **A refused save leaves focus on the button that was pressed**, and that button is still on the
   page.
6. Reverting `direction.js` fails criteria 1–4. Removing only the unfolding fails 2 and 3.

- Tests: `packages/frontend/test/direction-focus.test.js`.

## Known gaps this leaves

- **The desk's sub-panels** (take comparison, subject motion and scene cuts) close without
  returning focus to the button that opened them. They have their own controls and their own
  `close`, and each needs its own test.
- **The row heading is not the Edit button.** One Tab from the heading reaches the row's Edit
  button.
- **Reload shot plan** rebuilds the list but keeps its own button, so it isn't affected, and it is
  not changed here.
