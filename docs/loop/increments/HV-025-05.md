# HV-025-05 — Picture edits with graphics render in reasonable time

epic: HV-025
release: 1 "Studio"
gate: none new
spend_usd: 0

## Why

On staging (8 cores), the Editor's titled cut had been running for more than 16 minutes. That cut lays a 4 s title (120 frames, alpha) over the start of an 8 s scored film and adds 6 s of credits (180 frames). The worker's bun process sat at about 66% CPU with 3.2 GB RSS. A 16 s edit in a 2-CPU container took about 15 minutes.

The time was going into the editorial worker's `access()` callback (`packages/queue/src/edit-worker.ts`). Verification calls `access()` before each retained file it hashes. A graphic keeps every frame as a PNG, and each frame is hashed about eight times in one job:

- `verifyOriginal` (the source copy);
- `verifyGraphicMedia` (its file inventory);
- `verifyGraphicBundle` (the receipt).

Those three run twice: once while rendering and again in `verifyPreparedEditSources`. Then `verifyEditMedia` hashes the output inventory, and `verifyPreparedEditSources` hashes the prepared copies.

Each `access()` renewed the lease and then ran the full permission check:

- `assertEditPermission`, which re-validates the plan and replays its edit history;
- re-reading the job and every source carrier;
- `assertEditBindingAvailable`.

That check is large and grows with the graphics' frame receipts, so the job grew roughly with the square of the frame count.

Measured on a 2-CPU container, JSON store:

| Run | Picture-edit job | `access()` / heartbeats | Whole test |
|---|---|---|---|
| CI-size test (6 + 12 graphic frames), before | 55.2 s | 820 (39.5 s inside `access()`, 20.8 s of it in `assertEditPermission`) | 72 s |
| CI-size test, after | 17.5 s | 19 | 34 s |
| Full studio, `HV_STUDIO_E2E=1` (120 + 180 frames), before | 870 s | 4,140 | 977 s |
| Full studio, after | 118 s | 82 | 225 s |

After the fix, the full-size job is about 55 s rendering plus 58 s verifying. Verifying reproduces the whole conform, which is the design. In those 118 s the bun process used about 43 s of CPU, and FFmpeg used the rest.

## What this increment does

- **`packages/queue/src/edit-access.ts`**: `throttledEditAccess(cheap, check, 1000)`.
  - The abort and deadline checks still run on every call.
  - The lease renewal and permission check run at most once a second. `editWorkspaceGuard` already checks the same workspace on the same one-second cadence.
  - A failed check is never remembered as passed, so the next call runs it again.
  - Concurrent callers share one in-flight check. These are the per-file loop and `withEditSourceAccess`'s 2 s timer.
  - `force` always runs the check.
- **`processEditJob`** uses it. The full check is forced:
  - at admission;
  - before a local checkpoint;
  - before completion.

  A PostgreSQL or S3 checkpoint also re-checks permission and every source carrier inside its own fenced transaction (`PostgresArtifactStore.checkpointEdit`).

Every checksum is still verified, per file and per frame. The only change is how often the lease and permission check runs during verification: at least once a second instead of once per file. Revoking a project's permission or taking it down still stops the job within about a second, and always before its checkpoint or completion.

## Acceptance criteria

1. **The lease and permission check runs by time, not per file.** Within the interval, 300 frame checks run it once. It runs again once the interval has passed. A forced check always runs. A failed check is not treated as passed. Concurrent callers share one check. Abort and deadline are checked on every call.
   - Test: `packages/queue/test/edit-access.test.ts`.
2. **The Editor's titled picture edit makes at most about one heartbeat per second.** The CI-size Chrome-gated test counts the job's heartbeats: at most its elapsed seconds plus 8. On the previous code it made 820 heartbeats in 55 s and fails this bound.
   - Test: `packages/api/test/graphics.test.ts`, "the Editor's title and credits render and lay over a scored sound mix that is shared for review" (CI's graphics job).
3. **Nothing else changes.** The editorial, graphics, sound-mix, final-dialogue and studio-anchors API tests and the generator edit and graphic tests pass unchanged.
