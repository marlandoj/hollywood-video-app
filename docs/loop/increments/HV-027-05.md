# HV-027-05 — A creator asks a finished film for a deliverable, and gets one

epic: HV-027
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0 — ffmpeg only, on files a finished job already holds.

depends on: HV-027-04 (PR #177). This branch is cut from it.

## Why

Four increments have ended with *nothing calls this*: the quality check (HV-026-03), the reframes
(HV-027-01), the mezzanine (HV-027-02), and the stage that carries them (HV-027-04). This is the
increment where that stops being true.

## What this increment does

- **`renderDeliveryJob`** copies the film's declared files into a private scratch — one at a time
  through the artifact reader, which checks each file's digest and length as it streams it — and
  hands the master, or the conform directory, to the renderer HV-027-01 and HV-027-02 already built.
  Nothing in the source job is written to.
- **The deliverable is written under the delivery job's own prefix**, replacing whatever a previous
  attempt of *that job* left there. That is the only file it owns, and the path carries the job's own
  identity, so nothing else can be there.
- **`verifyDeliveryMedia`** re-digests the file, re-probes it against the plan, and for a mezzanine
  decodes its frames and compares them with the **conform's own** recorded hashes — the same proof
  the render made, and the only one that says "this is that film".
- **`checkpointDelivery`** on the object-store path retains the one file and checkpoints it under the
  current fence, through `checkpointMedia`, so the verification and the upload are recorded as
  separate phases rather than disappearing into one unspanned call.
- **The worker** takes the same fenced permission re-read every other independent media job takes,
  because the film may have been taken down since admission, and re-verifies a resumed job rather
  than rendering it again.
- **Three routes**, owner-only: the offer list for a film, the request, and the project's own
  deliverables with a link to each finished one. The file is served through the same guarded
  `/artifacts/` path as everything else, under a token minted for that job and no other.

### One thing worth disagreeing with

**A reframe is not verified by reproduction.** Editorial re-runs its whole conform and compares
content hashes; a mezzanine here compares frame hashes against the conform's own record, which costs
one decode. A reframe could only be verified by re-encoding it, which costs a full render to compare
an encoder against itself and says nothing its digest and its probe do not. So it is verified by its
digest and its shape. That is a smaller claim than the one editorial makes, and the code says so
where it is made.

### What a critic pass over this increment found, and what it changed

Six defects, all in code written in this increment or the one under it, all fixed here:

- **The publish transaction checked the lease fence and nothing else.** `PostgresJobStore.mutate`
  loads the project for its `finish`-time permission checks only for the stages named in one list,
  and `delivery` was added to the branches and not to that list — so eight sibling stages re-checked
  their permission at publish and this one did not. A project taken down between the worker's last
  `access()` and its `completeDelivery` would have published anyway. Fixed, and asserted as a
  **totality**: every stage with a `finish&&job.X` branch must be in the gate list, so the next
  stage inherits the guard.
- **The fenced worker re-read dropped the source film on the PostgreSQL path.** The local path
  refused a film rendered again mid-job; production did not. Both do now.
- **The largest copy in the studio ran unguarded.** Every sibling worker reserves free space and
  ticks `access()` through `copyDialogueFiles`; this one did neither, so the workspace guard, the
  deadline and the permission re-read were all suspended for a copy of up to 24 GiB.
- **A flat thirty-minute deadline**, on a job that copies a lossless master and then decodes it
  three times — the exact failure `editRenderTimeoutMs` was written to fix. It grows with the film
  now, and costs more per frame for a mezzanine than for a reframe.
- **A resumed job verified the worker's local cache, not the retained copy.** Under `s3` that is a
  file nobody will be served, and a job resuming on another host had no file to check at all and
  would die `failed` with its deliverable safe in the object store. The retained copy is fetched
  back through the artifact reader first. The local copy is also removed when the job ends, because
  nothing else counted it.
- **The recipe claimed metadata it did not strip.** `-map_metadata -1` leaves ffmpeg's own
  `ENCODER: Lavf60.16.100` on the format, and Matroska writes a per-stream `DURATION` whatever you
  ask. The build version is gone now (`+bitexact`, so a master does not vary with a patch release),
  the recipe says what the file actually carries, and the render **checks** it.

And one claim was narrowed to what the code does: the idempotency key was only ever compared against
a client's request key, so two keys asking for the same deliverable made two jobs. The admission
route now returns the existing job, and the comment says where that is enforced and why a validator
handed one job cannot do it.

## Acceptance criteria

1. **A finished cut is offered its deliverables.** For a 640×360 master: the square is available with
   its output size, the vertical is refused naming the `256-pixel minimum`, and the mezzanine is
   available with an estimate. All three are listed — the refused one is not omitted.
2. **A deliverable is made and served.** Asking for a mezzanine admits a job, the worker renders it,
   and the file is fetched through the artifact path as an attachment, byte for byte the size the
   output records.
3. **The mezzanine is the conform's picture**: FFV1 and `pcm_s24le` at the film's own size, and
   larger than the H.264 master it sits beside.
4. **The reframe is a crop**: H.264 and AAC at 360×360, smaller than the lossless master of the same
   picture, written as `reframe-1x1.mp4`.
5. **The same request key is the same job**, and a different deliverable under that key is refused.
6. **A film that is not this project's finished cut has nothing to deliver** (404), and a kind this
   studio does not make is refused (400).
7. **The token is the job's.** Pointing a deliverable's artifact token at the film's own job is
   unauthorized — the request never reaches the question of whether that file exists.
8. **Both deliverables of one film sit beside it**, each under its own job, both naming the same
   sealed output revision, and the film's offer list shows what has been made of it.
9. **Two request keys asking for the same deliverable are one job.**
10. **The mezzanine carries no build version**: its only format tag is a bit-exact `encoder`, its
    only stream tags are the container's own `DURATION`, and nothing matches `Lavf<digits>`.
11. **Every stage that checks permission at publish is a stage that loads the project** — asserted
    over the source, so the guard is total rather than one more case.
12. **A deliverable's deadline grows with the film**, costs more per frame for a mezzanine than for a
    reframe, and is bounded at both ends.

- Tests: `packages/api/test/delivery-route.test.ts` — one end-to-end case covering 1–9, from a real
  editorial render through the offer list, two deliverables, the worker, and the fetch;
  `packages/generator/test/delivery-mezzanine.test.ts` (10);
  `packages/storage/test/delivery-jobs.test.ts` (11–12).

## Known gaps this leaves, stated rather than implied

- **No frontend.** The routes answer JSON; there is no panel, and the Director's desk does not show
  deliverables.
- **The reframe's placement is centred.** `deliveryReframePlan` takes an anchor and the route does
  not expose it, because nothing yet decides where a vertical frame should sit. A crew persona
  choosing a placement per film is later work.
- **Nothing counts several deliverables of one film together.** A mezzanine is capped at half the
  editorial output budget on its own; three deliverables of the same film are not added up against
  any budget. That question is in `claude/HV-027-04-plan.md`.
- **A single ffmpeg call is killed at twenty minutes**, by the shared subprocess runner, whatever
  the job's own deadline. A film whose lossless picture master takes longer than that to decode
  cannot be delivered as a mezzanine at all, and the failure reads "Sound finishing timed out",
  which names the wrong thing. Neither the ceiling nor the message is this increment's to change,
  and the ceiling has not been measured against a real film.
- **The end-to-end test runs on local storage.** The `s3` path is the same code — the artifact reader
  is what changes — and it is exercised by the object-store suites in CI, but this test does not run
  it. A staging proof run would.
- **The quality check still does not run on a deliverable.** HV-027-01 measured its cuts with it by
  hand in a test; nothing measures a delivered file as part of delivering it. That is a small
  increment now that both halves exist.
- **Burned subtitles and SDH are not built**, and the decision recorded in HV-027-01 — a burned
  deliverable must be terminal and never admissible as a source — is still waiting on a human.
