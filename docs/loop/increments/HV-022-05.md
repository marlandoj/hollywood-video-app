# HV-022-05 — A second voice vendor: the ElevenLabs contract

epic: HV-022 (performance: voice, dialogue, lip-sync, ADR)
release: 2 "Voice and crew depth"
gate: G14-202609210000 (the operator approved ElevenLabs and provisioned its key on the staging host)
spend_usd: 0

## Why

Release 1 shipped with Azure voices. The operator asked why, and the honest answer was that Azure
was the only vendor available to this loop: `CLAUDE.md` forbids adding a vendor, account or key, the
repository already carried Azure and Cartesia adapters, and the operator already had an Azure Speech
resource. He then approved ElevenLabs (G14) and put its key on the staging host himself.

This increment is the contract, not the dispatch. It states what the adapter will ask the service
for, what it refuses before any reservation, and how a word timing is derived from what the service
returns. No request is made, no key is read, and no voice is authorized: a voice becomes castable
only through the operator's own catalogue evidence, in a later increment.

## What this increment does

- **`packages/generator/src/elevenlabs-capability.ts`** — `hv-audio-capability/4`, pinned to
  `eleven_multilingual_v2` and the timestamped endpoint. Two facts are recorded rather than papered
  over: the service returns at most 44.1 kHz PCM while every delivery here is 48 kHz mono, so the
  capability names the fixed ffmpeg resample the adapter will use; and the service aligns
  *characters*, so the alignment basis is `derived-from-provider-character-alignment`.
- **`packages/planner/src/elevenlabs-performance.ts`** — the line controls the service actually
  takes: `speed` (0.7–1.2), `stability`, `similarity`, `exaggeration`, each in steps of 0.01. It has
  no loudness control and no emotion enum, so a line that asks for either is refused here.
- **`hv-audio-voice/4`** and **`hv-audio-line/6`** — the vendor's own profile and plan schemas, so
  an older record can never be read as an ElevenLabs one, with the service's own voice-ID shape
  (twenty URL-safe characters, not a UUID).
- **`packages/generator/src/elevenlabs-request.ts`** — one request built from an admitted plan and
  nothing else, plus `elevenLabsWordTimings`, which folds the character alignment into words and
  refuses a read whose alignment is out of order, past the audio, or wordless.
- The capability joins the registry, so the committed revision pins
  (`docs/evidence/hv019-performance/capability-revision-pins.json`) carry it and any later edit to
  the contract breaks the tripwire.

## Acceptance criteria

1. **An ElevenLabs line compiles to its own contract.** Schema `hv-audio-line/6`, the ElevenLabs
   capability revision, word alignment, a request to the timestamped endpoint with exactly the four
   voice settings, and a request hash that is stable for the same line and different for a different
   read.
   - Test: `packages/planner/test/elevenlabs-contract.test.ts`.
2. **The contract refuses what the service does not do.** Volume, another provider's emotion,
   phoneme alignment, a speed outside 0.7–1.2 or off the 0.01 step, phrase direction, a voice ID the
   service never issues, a mismatched schema and provider, and a line longer than the model takes.
   - Same test.
3. **Word timings are derived or the read is unusable.** Characters fold into words; an alignment
   that is out of order, longer than the audio, shorter than its timings or wordless throws.
   - Same test.
4. **The registry and its pins carry the new capability**, and the conformance suite still passes.
   - Test: `packages/generator/test/performance-conformance.test.ts`.
