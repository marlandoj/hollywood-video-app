# HV-027-04 — The delivery stage, and the durability it has to hold

epic: HV-027
release: 2 "Voice and crew depth"
gate: none new. The migration widens a CHECK constraint and is additive: no row is read, written or
dropped, and the old set is a subset of the new one. It is not a destructive staging migration.
spend_usd: 0 — no provider is touched, and the stage is zero-cost by construction rather than policy.

depends on: HV-027-03 (PR #176). This branch is cut from it.

## Why

Three merged increments end with the same sentence — *nothing calls this*: HV-026-03 (the quality
check), HV-027-01 (the reframes) and HV-027-02 (the mezzanine). All three name the same blocker, and
HV-027-03 settled the design question underneath it. What is left is the wiring, and HV-027-01 listed
it: "a plan field, an output kind, a validator, a worker, a checkpoint, an artifact-permission entry
and signed URLs."

That is about two thousand lines across seventeen files, including a schema migration and the
queue's own durability transitions. It is not one reviewable change, so it is two. **This increment
is the half that touches the durability core**, and it lands on its own so it can be read on its own.
The renderer and the routes are HV-027-05, and they are small, because the deliverables and the plan
already exist and are tested.

`docs/loop/HV-027-04-plan.md` in the project records the touch list this was built against, traced
from how `motion-graphic` is wired.

## What this increment does

- **The stage exists**: `"delivery"` in `JobStage`, in the `hv_jobs` CHECK constraint, and in
  `infra/drizzle/0016_delivery_jobs.sql`.
- **The queue holds it**: `delivery`, `deliveryCheckpoint` and `deliveryOutput` on the job; enqueue
  validation; the four guard sites that keep independent media out of the generation paths;
  `checkpointDelivery` and `completeDelivery`.
- **The contract refuses**: a stage without a plan or a plan on another stage, any reserved or spent
  money, a screenplay or generation history, a frame count other than the film's, a plan naming the
  job's own id or another project's film, and any other stage's fields. Each refusal says what it
  refused and why.
- **Idempotency holds across re-admission**: the same deliverable of the same sealed output is the
  same job; a different one under that key is refused by name.
- **The film is still the film at admission**: `assertDeliverySourceAvailable` re-reads the source
  job's own body — done, sealed under the key its stage seals under, at the revision the plan names,
  with the master in the inventory that revision vouches for. The body rather than the artifact rows,
  because the body is authoritative in both storage modes and says more.
- **Recovery knows what a deliverable is**: `hv-state/14`, with the refusal for older readers in both
  the TypeScript validator and the Python archive packager, against the same schema list.
- **A deliverable is zero-cost by construction**: the ledger refuses a cost attributed to the stage,
  and the snapshot validator refuses a retained charge against one.
- **The permission switch is total again.** `artifactPermission` is a `switch` over `JobStage` with
  no `default:`, so adding a stage is a compile error until the case exists — and
  `artifact-permission.test.ts` reads the union from where it is declared, so the stage list had to
  be updated by hand, deliberately.

### What the type system and the guards caught

Adding one string to a union produced compile errors in exactly the two places a new stage must be
taught about (the log stage set and the permission switch), and test failures in the four
places a new *state tier* must be taught about (the JSON Schema enum, the Python schema tuple, the
Python conformance test's own range, and the migration-head evidence). None of those were found by
reading; all six were found by the guards that exist for it — the fourth by CI, after the local run
missed it, which is exactly what CI is the merge gate for. That is the design working, and it is worth recording because it is the argument
for keeping those guards exhaustive.

## Acceptance criteria

1. **A deliverable is enqueued, checkpointed and completed as its own job**, with a zero cost, and
   its checkpoint is the whole thing: `checkpointFrame` reaches the film's frames in one step.
2. **The checkpoint is immutable**, and completing without it is refused.
3. **A delivery job carries a deliverable and nothing else**, and no other stage's job carries one —
   nine refusals, each asserted on its own message.
4. **The same deliverable of the same sealed output is the same job**: re-admission returns it, and a
   different deliverable under that key is refused.
5. **A retained deliverable is re-derived from its plan**: a file outside its own job, a reframe
   claiming a mezzanine's codecs, the wrong dimensions and the wrong duration are each refused by
   name; the byte ceiling is the plan's own for a mezzanine and a fixed bound for a reframe.
6. **The film a deliverable names is still that film**: a missing, running, wrong-staged or
   re-rendered source is refused, and so is a master absent from the sealed inventory.
7. **A snapshot holding a deliverable needs `hv-state/14`**, an older reader is refused, and a
   provider charge against a deliverable is refused.
8. **Nothing else moves**: the storage, queue, planner, observability and operator suites pass, and
   the artifact-permission totality guard passes with the new stage in its list.

- Tests: `packages/storage/test/delivery-jobs.test.ts` (1–7),
  `packages/api/test/artifact-permission.test.ts` (8, updated stage list).

## Known gaps this leaves, stated rather than implied

- **Nothing can create a delivery job.** There is no route, and the worker has no dispatch for the
  stage — `generationStage` refuses it, as it does every independent media job, so one that somehow
  reached a worker fails rather than being mistaken for a generation job. HV-027-05 adds the renderer
  and the routes.
- **A deliverable is not admissible as an editorial source.** The source stages are an allowlist and
  this one is not on it. That is a decision, not an omission: a delivery is terminal, and re-editing
  a crop of a crop is how a studio loses track of what its master is. It is recorded here because a
  future increment may want to revisit it.
- **Nothing counts several deliverables of one film together.** A mezzanine is capped at half the
  editorial output budget on its own; three deliverables of the same film are not added up against
  any budget. That question is in the plan document for Kevin.
- **The Postgres admission path is tested only by CI.** `PostgresCostLedger.admit` gained a delivery
  branch, and the storage suites that exercise it skip without a database, so the local run does not
  cover it. CI does.
- **No frontend.** A creator cannot see an offer list or ask for a deliverable.
