# HV-019-17 — A referenced live profile, and a per-shot reference budget (Release 3's live run)

epic: HV-019
release: 3 "Features"
gate: G22-202610041528 (Kevin's decision: Release 3's live run uses a referenced fal profile; at most 4 reference images a shot)
spend_usd: 0

## Why

G22-202610041528: no live staging profile could render a locked character. `live-storyboards`,
`live-film` and `live-film-anchored` render the rough cut on FLUX Schnell, which takes no reference
image, and the finals on Kling 2.5 (none) or Kling O3 keyframes, which takes images only with a pinned
first frame that a feature's finals don't have. Every locked character's shot was refused with "No
configured provider supports these render requirements: references" (HV-019-16's known gaps).

The fal adapters that take references already exist: FLUX.2 edit (`image:fal:flux-2-edit`) and Kling O3
reference (`fal:kling-o3-standard-reference`), each one to four images. But each locked character
carries its four turnaround views, so a shot of two locked characters carries eight and would be
refused by both. Kevin decided: a new all-fal profile, with no new vendor or key, and at most four
reference images a shot, two each when two locked characters share one.

## What

**1. The `live-film-referenced` profile** (`scripts/staging-providers.py`). A fixed table entry:

| Setting | Value |
|---|---|
| `HV_ANIMATIC_PROVIDER_POOL` | `["image:fal:flux-2-edit","image:fal:flux-schnell"]` |
| `HV_ANIMATIC_PROVIDER` | `image:fal:flux-2-edit` (the pool decides; this names its lead) |
| `HV_PROVIDER_PRIMARY` | `fal:kling-o3-standard-reference` |
| `HV_PROVIDER_SECONDARY` | `fal:kling-v2.5-turbo-pro` |

The router takes the first eligible provider in configured order. FLUX.2 edit and Kling O3 reference
need one to four images (`minimumReferenceFrames: 1`), so a shot with images goes to them, and a shot
with none is ineligible there and goes to FLUX Schnell and Kling 2.5, which take none. Like every live
profile it is refused without `FAL_KEY` (only its presence is read), prints nothing secret, and changes
only provider lines: every cap is left. A profile may now name a pool line, written as the JSON list the
catalogue parses; any pool line a profile doesn't name is still removed, and `current_profile` reads a
pool back as a list, so a hand-edited pool is `custom`. A deploy writes `mock` again, pool line included.
`docs/STAGING-LOCAL.md`'s table gains the row and the routing rule.

**2. A shot's reference budget** (`packages/planner/src/reference-budget.ts`, `casting.ts`).
- The budget is the largest reference count any provider in the render's pool takes
  (`poolReferenceBudget`): four on this profile. A pool where no provider takes a reference has no
  budget, so images are never cut to fit a text-only provider: such a shot is refused, as before.
- Past it, `allocateReferences` splits the budget evenly across the shot's characters that hold images,
  in prominence order: two each for two characters at four; three at four get 2, 1, 1. A character with
  fewer images than its share passes the rest on.
- Prominence (`castProminence`): characters who speak in the shot, in the order they speak; then those
  its action names; then the scene's others; ties in cast order.
- Each character sends the front of its own order: a locked look's order (the creator's; the desk locks
  the turnaround's front view first), else its images' order.
- More characters than the budget (five at four): the four most prominent send one each, the fifth none.
  It stays in the shot's written cast direction, and the record names it with all four images dropped.
  No character leaves the record.
- The prompt's numbered reference map names only what is sent. The shot's images stay in cast order.
- A shot within budget is unchanged byte for byte and records nothing.

`directCast` takes the budget as an optional last argument (absent or null: every image, as before).
Admission (`server.ts`, from `configuredPool(stage)`), the worker (`worker.ts`, from the admitted
`providerPlan.pool`) and shot reuse (`shot-reuse.ts`, the same) read it from the same pool, so they cut
the same way. No capability, price or revision moves, so plans admitted before this deploy still run.

**3. The record** (`identity-locks.ts`, `assembler`, `provenance.ts`). A cut shot carries
`referenceBudget` (`hv-reference-budget/1`: `max`, `carried`, and per character `locked`, `sent`,
`dropped`, by id and SHA-256), and its `provenance.json` entry gains it beside HV-017-17's
`identityLocks`. Each cut lock in `identityLocks` keeps the whole lock in `assets`, so the lock is still
the lock, and adds `sent` and `dropped`. `shotIdentityLocks` now checks a cut shot against the images it
was sent: the record must split the lock exactly (sent, then dropped, in the lock's order), and the sent
images must be in the shot's references in that order with those bytes. Otherwise it refuses, before the
encode, as before.

**3a. The budget and HV-019-16's `referenceRecord` agree.** The mock (HV-019-16, merged first) records
the images it was sent as `referenceRecord`. That is the adapter's account; `referenceBudget` is the
planner's choice of what to send. They aren't two copies: where a shot has both (a mock-only pool
cutting past 32 images), the assembler checks that the record's images are exactly the budget's sent
images, in the shot's order, and refuses before the encode otherwise (`assertBudgetMatchesRecord`).
The mock's 32 is the pool budget wherever the mock is in the pool, so the rehearsal's eight-image shots
are not cut and record exactly what HV-019-16 recorded.

**4. The quote** (`packages/planner/src/crew/read-through.ts`, HV-030-28). The read-through and the plan
step's facts now price each shot on the lane the router would give its images (`quotedLaneFor`: the
first billed, unretired lane taking that count), from the current cast's images cut to the pool's
budget. On this profile that's Kling O3 reference, $0.42 a 5 s shot, for a shot with a locked (or
imaged) character, and Kling 2.5, $0.35, for the others. `estimate.lanes` lists each lane's shots and
price when more than one is used. A priced stills pool adds `estimate.roughCutStillsUsd`: one rough cut's
stills, each on the stills provider its images route to (FLUX.2 edit at $0.012 × (images + 1) at the
rough cut's size; FLUX Schnell $0.003). A 240-shot feature with two thirds of its shots locked quotes
$95.20 in finals. Every other profile's quote is unchanged: anchored stays all O3 keyframes, live-film
all Kling 2.5, and mock's free stills add no field.

**5. Docs.** STAGING-LOCAL.md (profile row and routing), REFERENCE-PROVIDERS.md ("A shot's reference
budget"), CASTING.md (the lock record's `sent`/`dropped`). The staging-profile parser the tests share
moves to `test/fixtures/staging-profiles.ts` and reads a pool.

Nothing paid runs. No vendor, key, cap or default changes.

## Acceptance criteria

1. **The profile.** `--profile live-film-referenced` writes the stills pool (FLUX.2 edit, then FLUX
   Schnell) and the finals (O3 reference, then Kling 2.5); is refused without `FAL_KEY` and changes
   nothing then; keeps every other line and cap; prints no key; is read back as itself; and another
   profile removes its pool line. The shell reads the pool as the catalogue's JSON list.
2. **Routing, both kinds of shot.** With the profile's settings read from the script and fake fal
   transports for all four models, a rough cut and its final render through the real API and worker: a
   shot with locked characters goes to FLUX.2 edit and O3 reference, a shot with no character to FLUX
   Schnell and Kling 2.5, one request a shot, and each shot's routing names that model. Eligibility per
   pool: 0 images → the plain model only; 1 and 4 → the reference model only; 8 → neither.
3. **The budget.** 1 character → its four views; 2 characters → 2 each, the front of each lock; 3 → 2, 1,
   1; uneven holdings pass shares on; 5 characters at 4 → the four most prominent one each, the fifth
   recorded with every image dropped. Never more than the budget, never a character missing from the
   record (exhaustive over budgets 1-8, 1-5 characters, 1-4 images each). Prominence is speakers, then
   named, then the rest. Unlocked characters' images are cut the same way and recorded as unlocked.
4. **The record.** The shot's provenance carries `referenceBudget` with sent and dropped; HV-017-17's
   lock record keeps `assets` and adds `sent`/`dropped`; a record that doesn't split the lock, or a shot
   not sent what it says, is refused; an uncut shot's records are exactly as before.
5. **Provider-max driven.** Text-only pools have no budget; the mock (HV-019-16, 32) sets 32 alone or
   mixed with a reference vendor, which leaves an eight-image shot exactly as with no budget, and the
   mock-profile rehearsal test passes unchanged. A recording adapter's `referenceRecord` must name
   exactly the budget's sent images in order, or the export is refused.
6. **The quote.** On this profile locked-character shots are quoted at $0.42, the others at $0.35, with
   each lane's share, plus FLUX.2 edit and FLUX Schnell stills, from the read-through route as well as
   `readThroughFacts`. Anchored, live-film and mock quote as before.

## Known gaps

- **No live render has verified this.** Every test runs on closed fal fixtures at $0. The profile is
  exercised for real in Release 3's rehearsal on it and the live run, which may find what fixtures can't
  (vendor acceptance of four images, O3 reference's identity hold, FLUX.2 edit's output size).
- **Stills cost more than G22's "about $0.011".** The FLUX.2 edit adapter prices each reference image as
  a megapixel: at the rough cut's size a still is $0.012 × (images + 1), $0.036 with two images and $0.06
  with four. For a 240-shot feature that's at most $14.40 a rough-cut pass (all shots locked) on top of
  finals of at most $100.80 (all at $0.42): $115.20 in the worst case, inside the $120 declared and the
  $150 film limit, but with little room for remade rough cuts. The quote now says so per feature.
- **"Locked" is "has images".** Routing and the quote follow reference images, so a shot of an unlocked
  character with its own images also goes to O3 reference at $0.42. G22 names locked characters; on this
  rehearsal's cast they are the same.
- **The quote reads the cast at the time.** A read-through before the desk adds images quotes every shot
  on the plain lanes; the plan step's facts and a read-through after the locks give the referenced quote.
  The studio's pitch line still shows only the final video figure; the stills figure is in the facts.
- **Paths that don't budget.** Take groups, motion studies, living-script and current-film renders call
  `directCast` without a budget, so a shot there with more than four images is refused as before. A
  character sheet carries one character's images (at most four), so it never needs one.
- **Prominence is read from the script**, not from the picture's framing. A creator chooses which views
  survive by the lock's order.
- **A pinned first frame** on this profile has no native provider (neither O3 reference nor Kling 2.5
  takes frame anchors); such a shot uses the storyboard fallback if it asks for one. A feature's finals
  don't pin frames today.
