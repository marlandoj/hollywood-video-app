# HV-030-01 — The crew's conversation core

epic: HV-030
release: 1 "Studio" (build order step 1)
gate: G13-202609192200 (the operator's pivot to an AI studio crew; Claude as its model; its own budget line)
spend_usd: 0 (no live model is called; every test injects its model or uses the stand-in)

## Goal

The first thing the crew does is answer a script. The Producer's read-through says back what the film is, flags what the studio can't make, and asks the creator only what matters, with a proposed answer to every question.

## What this increment does

- **The crew** (`packages/planner/src/crew/personas.ts`): six personas, each with a department, at most three questions each.
- **The model** (`packages/generator/src/crew-model.ts`):
  - Claude through the Anthropic Messages API, over plain `fetch` (no new dependency).
  - Usage is priced from a table of current models, and an unpriced model is refused.
  - The key goes only in its header. Errors carry the status, never the key or the provider's body.
  - A request times out.
  - With no `ANTHROPIC_API_KEY`, there is no live model.
- **The crew's budget line** (`packages/operator/src/crew-ledger.ts`):
  - Kept apart from the generation ledger.
  - Alerts at $25, $100, $200 and $1,000, each once.
  - Stops at the approved ceiling ($1,000) before any call. The ceiling can only be raised.
  - Holds tokens and dollars, never text.
  - Survives trimming of old events.
- **The read-through** (`packages/planner/src/crew/read-through.ts`):
  - Studio-computed facts, which the model never states.
  - The model's voice, parsed strictly and gated string by string.
  - A deterministic stand-in crew for when there is no key, the model is down, or its answer is unusable.
  - A script the gate refuses is never sent to the model.
- **The route:** `POST /api/projects/:projectId/crew/read-through`, owner only. The API logs `crew.budget_alert` and `crew.budget_stopped`, both newly allow-listed events.
- **Docs:** `docs/CREW.md`.

## What this increment does not do

- **It does not change a project.** The read-through proposes; applying answers is HV-030-02.
- **It adds no interface.** The front door is HV-030-03.
- **It calls no live model.** The key is entered by the operator when the front door is ready to try.
- **It keeps the crew ledger out of PostgreSQL.** The ledger is a JSON file on the staging host, and moving it into PostgreSQL is Release 2.

## Acceptance criteria

1. **The model client.**
   - It sends the key only in `x-api-key`, with the pinned version, to the fixed URL, with redirects refused.
   - It reports usage and cost.
   - It refuses an unpriced model before any call.
   - It never puts the key or the provider's body in an error.
   - It times out.
   - It exists only with a key.
   - Tests: `packages/generator/test/crew-model.test.ts`.
2. **The ledger.**
   - The thresholds and stop point are the operator's.
   - Each alert fires once.
   - The crew stops at $1,000 until the ceiling is raised, and it can only be raised.
   - The total survives trimming.
   - A damaged file keeps the crew stopped.
   - Invalid spend is refused.
   - Tests: `packages/operator/test/crew-ledger.test.ts`.
3. **The read-through.**
   - Six personas.
   - Strict input.
   - Studio-computed facts.
   - All four concerns.
   - The model's voice is used when valid, and four kinds of unusable answer fall back with their cost still recorded.
   - A refused script never reaches the model.
   - The stand-in is deterministic and gate-clean.
   - The crew stops before calling at the ceiling.
   - A crossed threshold is reported.
   - An unreachable model records no spend.
   - Tests: `packages/planner/test/crew-read-through.test.ts`.
4. **The route, over HTTP.**
   - The live and stand-in answers.
   - Owner only.
   - A 400 on a bad format.
   - A public figure is flagged and not sent.
   - A 429 at the ceiling.
   - Tests: `packages/api/test/crew-route.test.ts`.
