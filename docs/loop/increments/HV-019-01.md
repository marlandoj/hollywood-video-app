# HV-019-01 — One enumerable provider registry and an adapter conformance suite, with the P5 gap register
epic: HV-019
spend_usd: 0

## Goal

Make the provider registry enumerable and provably total, and add the adapter conformance suite that FULL-SCOPE §7 and §8 require before any provider is promoted.

HV-019's routing core is real and well tested for the paths it happens to exercise — `packages/generator/src/capabilities.ts` (hashed, deep-frozen `hv-capability/1` snapshots and `matchCapability`), `catalog.ts` (`hv-provider-plan/1` admission and drift refusal at claim time), `router.ts` (`RoutedGenerator`, decision-before-dispatch, budget recheck, per-process circuit) — but nothing enumerated what a provider *is*. The same spec grammar was re-implemented in four independent string switches: `describeProvider` (`catalog.ts`), `resolveProvider` and `providerUsesPaidInference` (`index.ts`), and `resolveAnimaticProvider` / `resolveImageProvider` (`index.ts`, `fal-image.ts`). Nothing could prove the four agreed, and they did not.

The defect that proves it: `catalog.ts` resolved a final-stage `image:` spec through the animatic branch and then restored **the caller's spelling** rather than the normalized one. So `describeProvider("image:fal", "final").spec === "image:fal"` while `describeProvider("image:fal:flux-schnell", "final").spec === "image:fal:flux-schnell"`, and the two snapshots were byte-identical. Reproduced before the fix on `origin/main` at `4eb5cb2`:

```
specA image:fal              revA 23e079efb756
specB image:fal:flux-schnell revB 23e079efb756
same revision: true
pool size: 2 [ "image:fal", "image:fal:flux-schnell" ]
distinct revisions in pool: 1
```

`configuredPool` de-duplicates by spec, so both survived as two pool entries; `RoutedGenerator` and `packages/queue/src/worker.ts` both key the circuit breaker on `snapshot.revision`. Two nominal providers therefore shared one circuit and one half-open probe: a single failure counted twice toward the three-failure threshold, and opening the circuit removed both candidates from the pool at once. After the fix the same probe returns `pool size: 1`.

This increment adds `packages/generator/src/registry.ts` — `PROVIDER_REGISTRY`, `registeredSpecs`, `registeredSpellings`, `registryEntry`, `normalizeSpec`, `specIsPaid`, `PAID_SPEC_FAMILIES` and `specNamesPaidFamily` — as the single enumerable source; makes `describeProvider` fail closed on any disagreement with it; re-implements `providerUsesPaidInference` over the derived paid families rather than a fourth hand-written switch; fixes the `image:`-on-final normalization; and adds `packages/generator/test/conformance.test.ts`, the adapter conformance suite, which runs every registered `(stage, spec)` pair through sixteen check families using local adapters and a throwing `fetch` stub. It records `docs/evidence/hv019-router/adapter-conformance.json` from a real local run and adds a "P5 gap register" to `docs/PROVIDER-ROUTING.md`.

No new adapter, modality, provider, key, vendor, account, route, migration, dependency, budget default or frozen path. Every paid adapter is constructed with a literal fixture key and never asked to generate; `spend_usd` is 0 and providers stay `mock`.

## Acceptance criteria

1. **One enumerable registry exists, and the fal families are derived rather than transcribed.** `packages/generator/src/registry.ts` exports `PROVIDER_REGISTRY`, a frozen array of `{stage, spec, adapter, modality, paid, aliases, doc}` enumerating every admissible `(stage, spec)` pair, plus `STAGES`, `registeredSpecs(stage)`, `registeredSpellings(stage)`, `registryEntry(spec, stage)`, `normalizeSpec(spec, stage)`, `specIsPaid(spec, stage)`, `PAID_SPEC_FAMILIES` and `specNamesPaidFamily(spec)`. The fal video and fal image entries are built from `FAL_MODELS` and `FAL_IMAGE_MODELS`, so a new model key appears in the registry automatically. A test asserts the derivation in both directions and that no spec or alias is registered twice on a stage. The registry carries routing identity only — it never builds or copies a capability snapshot. Satisfies FULL-SCOPE §3 P5 "Capability registry: every adapter publishes a capability snapshot … no hard-coded model names in product code." and §10 "Provider independence and versioned adapters."

2. **The four spec switches are proved total and mutually consistent, and the registry is load-bearing.** `describeProvider` now computes its entry and then asserts the result equals `normalizeSpec(spec, stage)`, throwing "The provider registry disagrees with the resolved provider configuration." otherwise — so the registry cannot silently drift from the grammar. For every registered pair the suite asserts `describeProvider` returns the canonical spec; `snapshot.adapter` and `snapshot.modality` equal the registry's; `specIsPaid` equals `snapshot.price.unit !== "free"`; the stage resolver returns an adapter whose `name`, `model` and live `capabilities.revision` equal the snapshot's — the exact invariant `instantiateProviderPlan` enforces at claim time. For every unregistered pair `describeProvider` throws. `providerUsesPaidInference` is re-implemented over `specNamesPaidFamily`, keeping its existing two test lines byte-identical and green, including `"fal:model"` — an unregistered model key inside a paid family still answers true, because "this build does not know that model" is not a reason to call it free. (It is worth being exact about what this function is: no production code calls it. Every budget reservation keys off the admitted snapshot's price unit instead, in `packages/api/src/server.ts` and `packages/queue/src/worker.ts`, and those paths never see an unregistered model because `describeProvider` has already refused it. The function is exported and test-covered, and deriving it from the registry removes the fourth switch; that is the whole of its value, and both docstrings now say so.) Satisfies §3 P5 "The router matches shot requirements to capabilities; no hard-coded model names in product code." and CLAUDE.md "Every criterion gets a real test."

3. **Spec normalization is a fixed point, and the `image:`-on-final passthrough is corrected.** For every spelling on every stage, `normalizeSpec(normalizeSpec(s, stage), stage) === normalizeSpec(s, stage)` and `describeProvider(describeProvider(s, stage).spec, stage).spec === describeProvider(s, stage).spec`. A final-stage `image:` spec normalizes what follows the prefix and restores the prefix, never the caller's spelling: `image:fal` → `image:fal:flux-schnell`, `image:fal:flux-2-edit` unchanged, `image:mock` → `image:mock` — **not** `mock`, whose final-stage adapter is the plain deterministic video renderer rather than the rich animatic over the image renderer, which the suite asserts by comparing their revisions. `configuredPool("final", {HV_PROVIDER_POOL: '["image:fal","image:fal:flux-schnell"]'})` returns exactly one entry, and the pool's entry count equals its distinct-revision count, so one circuit is never shared by two nominal providers. A plan admitted under the old spelling and re-instantiated under this build throws "Provider configuration changed after this job was queued. Start a new render to use the current configuration." rather than executing. Satisfies §3 P5 "Capability registry … The router matches shot requirements to capabilities" and ADR-0020 fail-closed.

4. **Every registered snapshot is valid, stable, frozen and built without an inference key.** For every pair: `validateCapability` round-trips; two constructions produce identical `revision` and `priceVersion`; the snapshot and every object reachable from it, at any depth, are `Object.isFrozen` (asserted by a recursive walk that reports the path of any unfrozen node); `policy.adapterPolicyVersion` is `studio-generation-safety/1` and `price.invoiceReconciled` is `false`. The whole metadata path runs with an **empty** environment, proving `docs/PROVIDER-ROUTING.md`'s "Metadata construction requires no inference key" for every registered pair rather than the two cases `router.test.ts` covers. Execution, unlike metadata, does need the key and says so: `resolveImageProvider("image:fal", {})` throws "FAL_KEY is required for image inference" rather than dispatching without one. Satisfies §3 P5 "every adapter publishes a capability snapshot (…)" and §10 "Evidence before promotion: tests, benchmarks, post-flight evals, gap audits."

5. **Declared behaviour is verified against actual behaviour for every claim that is locally checkable.** `determinism: "local-bitexact"` is verified by rendering twice with the same `(prompt, seed, params)` and comparing bytes — five pairs pass (the plain video mock on `final`, `legacy-mock` on `animatic`, and the rich animatic over the mock image renderer on all three stages), and `anchor-storyboard` is verified in its own family with real anchor PNGs. `cancellation: "local"` is verified with an already-aborted `AbortSignal`: the call rejects and leaves no file at `outPath`. `price.unit === "free"` ⟺ `estimateUsd === 0`, and the generated clip's `total_cost_usd` is 0. `region: "local"` ⟺ the adapter is a free local one. `synthetic` ⟺ `allowSynthetic: false` yields the `synthetic` rejection. A `cancellation: "none"` claim is asserted to be the claim, not asserted to cancel — the plain video mock renders through `Bun.spawnSync` and there is nothing to interrupt. Satisfies §7 "each must pass the adapter conformance suite and the studio benchmark before promotion." and §10 "Evidence before promotion".

6. **Eligibility implies dispatchability, and every ineligible dimension is an explicit named rejection.** A requirements vector derived from each adapter's own snapshot (minimum dimensions rounded to the dimension multiple, minimum fps and duration, the minimum reference count, and a first-frame anchor where the snapshot demands one) is eligible with an empty reason list at exactly the estimated budget, for all sixteen configured pairs; the retired `fal:veo3-fast` is ineligible with reasons exactly `["provider-retired"]` on that vector (`matchCapability` accumulates rather than short-circuiting, so on a vector that also violates another dimension the retired reason is joined by that one, not replaced by it). 201 boundary cases then assert the named `RejectionReason` for each dimension: over- and under-sized width, an off-multiple width, fps above range, duration above range, references above the maximum and below `minimumReferenceFrames`, identity locks above the maximum, an unsupported camera move, `native-dialogue` audio, `deterministic` against a non-bit-exact adapter, `nativeResolution` against an `unknown` native resolution, `region: "local"` against a remote adapter, `allowSynthetic: false` against a synthetic one, a budget one cent below the estimate, and a modality flip. Fourteen of the seventeen reasons are reachable from a requirements vector alone and all fourteen are asserted to have been reached; the other three are not requirements — `circuit-open` and `capability-changed` are router state (`router.test.ts`) and `frame-anchors` is anchor state (`frame-anchor-provider.test.ts`). Satisfies §3 P5 "The router matches shot requirements to capabilities" and `docs/PROVIDER-ROUTING.md` "Unknown or unsupported features are explicit rejections."

7. **No paid inference, no real HTTP, no key, no spend.** `globalThis.fetch` is replaced for the whole suite by a stub that counts calls and throws, and the count is asserted to be 0. Paid adapters are constructed only with the literal fixture key `hv019-conformance-fixture-only`; they are described, matched and rejected, and `generate` is never invoked on `FalVideoProvider` or `FalImageProvider`. The evidence record carries `newProviderSpendUsd: 0` and `liveProviderDispatches: 0`. Satisfies CLAUDE.md "Paid providers stay `mock` unless the current increment doc declares `spend_usd` and names the provider." and "Never add keys, accounts, or vendors."

8. **The telemetry label set is a tripwire, not a silent collapse.** `providerKind` is asserted to return a member of the exported `PROVIDER_KINDS` tuple for every registered adapter, and the set of registered adapters collapsing to `other` is pinned to exactly `["anchor-storyboard"]`. The suite additionally pins the label gap that matters for cost: the registry's `rich-animatic` entries include both paid and free providers, yet all of them report the same `providerKind`, so the operator reliability panel cannot distinguish a rich animatic over the paid fal image model from the free local one. This increment does **not** widen `PROVIDER_KINDS`; the gap register names `packages/observability/src/index.ts`, `diagnostics.ts` and `explorer.ts` as the lockstep set, because widening the label without the explorer's `limit` headroom makes `PROVIDER_ATTEMPTS_QUERY` fail closed permanently. Satisfies §10 "Evidence before promotion: … gap audits." and `docs/OBSERVABILITY.md`'s bounded-label discipline under ADR-0018.

9. **The evidence record is a real run and the committed file is re-validated on every test run.** `docs/evidence/hv019-router/adapter-conformance.json`, schema `hv-adapter-conformance/1`, is written atomically when `HV_ADAPTER_CONFORMANCE_EVIDENCE` names a path and records `recordedAt`, `ffmpegPresent`, `registry` (17 entries carrying stage, spec, adapter, model, modality, paid, lifecycle, `capabilityRevision` and `priceVersion` — revisions only, no endpoint URL, no key, no prompt), the sixteen `checks` with their pair, pass and skip counts and any skip reason, `telemetryLabels`, and the honesty fields `newProviderSpendUsd: 0`, `liveProviderDispatches: 0`, `provesVendorAvailability: false`, `provesVisualQuality: false`, `provesLivePricing: false`, `provesRegionalExecution: false`. Every test run — including CI, which sets no such variable — parses the committed file, re-validates the schema, asserts the entry set equals the registry's, asserts **each recorded capability revision equals the revision this build produces**, asserts the check-family set, and asserts the file matches none of `://`, `FAL_KEY`, the fixture key, `/home/`, `/Users/`, `/tmp/`, `fal.run`, `queue.fal` or `cartesia`, and that every 32+ hex run in it is a known revision or price version. The revision check is the tripwire: a capability edit that would invalidate already-admitted plans breaks here before it reaches staging. Satisfies §10 "Evidence before promotion" and CLAUDE.md "Never fabricate launch, legal, or provider evidence."

10. **The deferred register exists, is specific, and names an owner or gate with a current truthful state for every item.** `docs/PROVIDER-ROUTING.md` gains "P5 gap register" covering: audio/voice/lip-sync outside the router; `health`, `extension` and `vendorPolicyVersion` absent or pinned in the snapshot; the eight missing modalities; quality presets and the hero-render chain; routing on policy and evaluation scores, and canaries; the self-hosted lane; end-to-end deterministic mode and the Reproducible Film Manifest; the telemetry label collapse; and invoice reconciliation. Each row states what is not delivered, who owns it, and the current truthful state — no row claims partial delivery. The doc also gains the full `(stage, spec)` table (adding `fal:kling-o3-standard-keyframes`, `anchor-storyboard` and the whole `character-sheet` stage, all previously undocumented), the missing `HV_CHARACTER_SHEET_PROVIDER_POOL` configuration row, and the "Spec normalization" and "Adapter conformance" sections. Satisfies §10 "Evidence before promotion: … gap audits." and EXECUTION-LOOP G6.

11. **No frozen path, dependency, budget default, account, vendor, migration, route, staging mutation or user-facing surface change.** The diff touches nothing under `docs/legal/**`, `docs/adr/**`, `.github/workflows/**`, `packages/safety/**` or `infra/drizzle/**`; it adds no `package.json` or lockfile entry, no HTTP route or request field, no cookie, tracking, account, tier or payment path, and changes no default of `HV_MONTHLY_BUDGET_USD` or `HV_COST_CAP_PER_SHOT_USD`. The new test file is discovered by the existing `unit + integration` step, which runs `bun test packages test`, so no CI step is added and **G4 is not raised**. `docs/loop/STATUS.md` and `docs/PROGRAM-EXECUTION.md` are not in the diff; RECORD owns both. Satisfies FULL-SCOPE §10 "Free and anonymous for every end user; no billing code reachable.", "Safety refusals expand only." and the EXECUTION-LOOP frozen list.
