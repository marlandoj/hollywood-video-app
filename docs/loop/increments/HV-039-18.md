# HV-039-18 — A late take status check drew one shot's groups under another

epic: HV-039
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

While a take group renders, the take desk checks its status every 2.5 seconds with `load(false)`.
That asks for `?shotId=<the shot open now>` and writes the answer into the panel when it arrives.
The answer was written whatever shot was open by then. Suppose a creator pressed "Compare takes for
s2" while a check for s1 was in flight. They saw s2's heading and prompt above s1's saved take
groups, with s1's takes in the player. "Adopt selected take direction" then adopted s1's direction
while the panel said s2.

## What this increment does

- **`load` remembers which shot it asked about.** If that shot is no longer open when the answer
  arrives, the answer is dropped.

## Acceptance criteria

1. **A late answer for another shot.** A status check for s1 that is answered after s2 was opened
   leaves s2's prompt and s2's take groups on the panel.
2. **An answer for the open shot** is written as before: the group's label changes from running to
   done.
3. Reverting `takes.js` fails criterion 1.

- Tests: `packages/frontend/test/take-switch.test.js`.

## Known gaps this leaves

- **The dropped request still reaches the server.** Nothing is aborted. It is a read, so the only
  cost is the request itself.
