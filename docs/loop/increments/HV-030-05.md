# HV-030-05 — The crew never asks for a shot its own dialogue cannot fit

epic: HV-030
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

On 2026-09-21 the operator's rough cut stopped with:

> Temporary dialogue exceeds the selected shot duration. Increase the duration, shorten the dialogue
> or use automatic duration; no image was requested.

The operator had set no duration. The crew had.

`pacedFrames` (HV-017-05) holds each shot to a length the video provider bills, so a 2 s shot does
not waste three of Kling's five. It picks the shortest billed clip that fits the shot's dialogue —
and when none fits, it took the longest one on the ladder anyway:

```ts
const step = timing.stepsSec.find(value => value >= needed) ?? timing.stepsSec.at(-1)!;
```

That fallback is the defect. Any duration set on a shot — by anyone — makes the render exact
(`shot-render-recipe.ts`: `durationFrames != null` ⇒ `exactDuration: true`), and an exact duration
the temporary speech overruns is refused before a single image is requested. So a shot whose
dialogue ran past the longest clip the provider bills was pinned to a length guaranteed to refuse
it, and the creator was told to lengthen a shot the studio had chosen for them — in the studio front
door, which by design offers no per-shot duration to change (G13: a persona decides the setting).

The second half of the defect is that the estimate behind `needed` could itself run short. It was a
flat "about 120 words a minute" against an engine whose own default is 175; the gap was the whole
safety margin, and two ordinary things spent it:

- **a line directed slower.** The editor allows 80 wpm. At 80 the estimate is 1.5× under.
- **punctuation.** A pause is close to a fixed cost, so it dominates a short line. Measured against
  eSpeak NG: *"Stop, wait, listen: did you hear that?…"* takes **19% longer** than its nominal pace,
  while a long plain sentence runs **25% faster** than nominal. One flat rate cannot cover both.

## What this increment does

- **`dialogueSeconds` is measured, not assumed.** Two terms calibrated against the engine — a word
  cost at the line's own directed pace, and a per-mark pause cost that scales with that pace — plus
  the silences the creator authored around each line, which the engine renders and a word count
  never sees. The slowest directed line sets the pace for the shot, so no line is estimated fast.
- **`pacedFrames` returns null when no billed clip holds the shot**, and `crewChanges` then leaves
  that shot on automatic duration, where the clip grows to fit the speech and nothing is refused.
- **The Editor says so**, naming the shots left automatic and asking for them to be split into
  coverage — the one action that both fits the dialogue and uses every billed second. The studio
  front door already reads the crew's notes at the first approval, so this reaches the creator
  before anything renders, without a new control on that screen.
- **The refusal states the measurement.** The renderer has measured the speech by the time it
  refuses, so it reports what the dialogue needs and what the shot is set to, in seconds rounded up
  to the tenth the shot editor accepts. The worker prefixes the shot's own id, so a creator with
  sixty shots is told which one.

A creator who wants to set a duration by hand still does it where per-shot settings live: the
Director's desk, behind Advanced. Nothing new is added to the studio front door.

## Acceptance criteria

1. **The crew's estimate covers what the engine actually produces**, for one-word lines,
   punctuation-dense lines, long plain sentences and lines directed from 80 to 300 wpm, with the
   authored silence counted — and it does not run so long that it refuses a clip that would have
   held the shot (within 1.5× for speech long enough to reach the shortest billed clip).
   - Test: `packages/generator/test/speech-pacing.test.ts`, which synthesizes every case with the
     same function the worker runs.
2. **A shot no billed clip can hold is left on automatic duration**, the other shots keep their
   billed pin, and the Editor's note names it and asks for coverage.
   - Test: `packages/planner/test/crew-introductions.test.ts`.
3. **A longer ladder holds the same shot**, at the shortest billed clip that fits rather than the
   longest on the ladder; and a duration the creator set in their own coverage cut is still never
   touched.
   - Same test.
4. **The refusal reports the measurement** — what the dialogue needs and what the shot is set to —
   and the cancelled job names the shot.
   - Tests: `packages/planner/test/living-script-current-direction.test.ts`,
     `packages/queue/test/shot-duration-refusal.test.ts`.
5. **Nothing else changes.** The crew plan, introductions, performance, animatic and storyboard
   suites pass unchanged.
