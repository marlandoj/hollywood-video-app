# HV-025-12 — The half of an editorial job that nobody could see

epic: HV-025
release: 2 "Voice and crew depth" (a defect found while recording Release 2 evidence, not new scope)
gate: none new
spend_usd: 0

## Why

The Release 2 live proof recorded a known gap: "The titled picture edit took 238 s for a 14 s film,
on the known editorial render path." That sentence is a guess dressed as a finding, and following it
would have led to the wrong fix. What the job's own trace actually holds:

| Span | |
|---|---|
| `job.process` | 241.0 s |
| `media.assemble` (`render`) | 105.2 s |
| `media.assemble` (`seal`) | 1.5 s |
| *nothing* | **132 s** |

More than half the job had no span at all. Two measurements on the staging host settled what was in
it. The pure-JS compositor everyone would suspect costs **0.8 s** per 60-frame span, and the object
store takes **5 ms** per file — so writing all 405 retained files sequentially is about **2 s**, not
two minutes. Neither is the cost.

The cost is `verifyEditMedia`, and it is the design: the checkpoint **reproduces the entire conform**
from the retained plan and sources into a scratch directory and refuses to publish unless the
reproduction's content hashes match frame for frame and sample for sample. An editorial job renders
the film twice on purpose, and what that buys is that nothing is published which cannot be rebuilt
from its own record.

HV-025-09 gave the local path `render`, `seal` and `verify` spans for exactly this reason — "the
flat deadline hid which one was growing". The object-store path verifies **inside**
`checkpointEdit`, which had no span, so on staging the larger half was invisible and the render
looked slow.

## What this increment does

- **`checkpointMedia`** in `packages/storage/src/artifacts.ts`: the shape both media checkpoints
  already had — verify, then store every file behind the lease gate — named once, with a
  `CheckpointPhase` hook the caller supplies. Storage stays telemetry-agnostic; it only names the
  two halves and how many files each covers.
- **`checkpointEdit` and `checkpointAssembly` use it**, with their existing messages, order and
  gating unchanged.
- **The editorial worker passes its own recorder**, so the object-store path now emits
  `media.assemble` spans tagged `verify` and `store` beside `render` and `seal`, each carrying
  `hv.media.files`.
- **`"store"` joins the `hv.edit.phase` allow-list** in `packages/observability`, beside the three
  HV-025-09 added. `hv.media.files` was already allowed.
- **`docs/PICTURE-EDITORIAL.md` says what an editorial job spends its time on**, with the measured
  numbers, so the next person reads the design instead of rediscovering it.

**No optimisation is attempted, deliberately.** Verification by reproduction is an integrity
property, and halving a film's finishing time by weakening it is the operator's decision, not a
build decision. The measurement is now on the job's own trace, so that decision can be made on
evidence from any run rather than on one hand-timed film.

## Acceptance criteria

1. **A checkpoint verifies first and stores second**, and each half is reported once with the number
   of files it covers.
2. **Verification is the gate**: a checkpoint whose reproduction fails stores nothing and reports
   only the verify half.
3. **A file that changed under the checkpoint stops it** with the caller's own message, before the
   next file is uploaded, for both the editorial and assembly wordings.
4. **A caller that records nothing behaves exactly as before** — same order, same lease gate before
   every file, same records.
5. **`store` is an allowed phase** and an unknown phase name is still dropped by the attribute
   filter.
6. **Nothing else changes.** The queue, storage and observability suites pass unchanged; no
   checkpoint message, order or gate moves.

- Tests: `packages/storage/test/checkpoint-media.test.ts` (1–4), `packages/observability` (5).

## Known gaps this leaves

- **The assembly worker records no phases at all.** It takes the hook and defaults to recording
  nothing, because only the editorial job has been measured. Giving it the same spans is a small
  follow-up worth doing when something needs it.
- **The trace still cannot say how much of a verification is picture and how much is sound**, only
  that the verification is the larger half. That needs spans inside the conform itself.
- **Nothing here makes an editorial job faster.** It makes the choice visible.
