# HV-023-04 — The saved cut, exported as OTIO and as a CMX 3600 EDL

epic: HV-023
release: 3 "Features"
gate: none new (Release 3 build order step 8, agreed at G20-202610031349)
spend_usd: 0

## Why

Release 3's build order, step 8: "OTIO and CMX 3600 EDL of the feature's cut, read back in a
test". Its part, `HV-023.interchange` (surface `desk-api`), is exercised when "the feature's cut is
exported as OTIO and as a CMX 3600 EDL, and each reads back to the same shots and frames".
HV-030-27 recorded the starting point: "No OTIO, EDL, FCPXML or AAF code exists". FULL-SCOPE P8 asks
for interchange "so a filmmaker can finish in professional tools".

The cut a creator finishes is the saved editorial sequence: an `EditTimeline` at 30 fps, replayed
from its history, whose sources are retained originals named by their job ids.

## What this increment does

- **`packages/planner/src/edit-interchange.ts`** reads a validated timeline into an interchange cut
  and writes it two ways, by hand, with no new dependency:
  - **OTIO JSON**: `Timeline.1` / `Stack.1` / `Track.1` (one video track per picture layer) /
    `Clip.1` / `Gap.1` / `Transition.1` / `ExternalReference.1` / `RationalTime.1` /
    `TimeRange.1` / `Marker.2`, at rate 30, starting at 01:00:00:00.
  - **CMX 3600 EDL** of picture layer 1: `TITLE`, `FCM: NON-DROP FRAME`, one event per clip with
    source and record timecodes, dissolves as a zero-length outgoing cut and a `D nnn` event, and
    `* FROM CLIP NAME:` / `* TO CLIP NAME:` / `* SOURCE FILE:` comments.
  - Media is `urn:hv:job:<jobId>`. No URL, signed link, storage path, token or expiry is written.
  - A speed change, two clips overlapping on one picture layer, or a source that no longer matches
    the saved branch is **refused by name**. Sound and caption lanes, fades, opacity, crops, masks,
    the EDL's upper layers and its markers are **listed** in `notCarried` (in the OTIO's metadata).
- **`packages/api/src/edit-interchange-api.ts`**:
  `GET /api/projects/:projectId/editorial/sequences/:id/interchange/{otio,edl}?historyRevision=…`
  on the desk API, behind the owner token. It mirrors the closest existing read of a saved cut,
  script navigation (`EditScriptApi`), check for check: the saved history revision, every picture
  original's retained carrier, its binding to this branch, and current character permission —
  before writing and again after, with a fresh carrier selection. It decodes no media, admits no
  job and spends nothing. The response is an `attachment` (`<sequenceId>.otio` / `.edl`),
  `private, no-store`, `nosniff`, `no-referrer`, with the file's SHA-256 in
  `x-hv-interchange-sha256`; at most two run at once, each within 30 s.
- **`docs/PICTURE-EDITORIAL.md`** has an "Interchange export" section, and the route is listed with
  the other owner routes.

## Acceptance criteria

1. **A cut reads back from OTIO to the same shots and frames.** A three-shot cut, made with the
   model's own operations (ripple trims at both ends, a slip, a centred 10-frame dissolve, a
   trailing gap), is exported and parsed back by an independent reader: the same job ids in the
   same order with the same source in/out and record in/out frames as worked by hand, and the
   dissolve's 5 + 5 frames.
2. **And from the EDL.** The same cut's EDL, parsed back, gives the same shots with CMX's own
   record and source frames (the incoming event starting where its dissolve starts, with the
   borrowed handle), and its exact column layout and timecodes are asserted line by line.
3. **The two files agree with each other**: the OTIO's hard cuts, moved into CMX terms, equal the
   EDL's events.
4. **Every picture layer is its own OTIO track**, gaps included, and the EDL says it carries layer 1.
5. **What cannot be written exactly is refused by name, or listed** — never approximated.
6. **The owner downloads both through the desk API**, from a real retained film with three shots, a
   trim at each end and an 8-frame dissolve, and both read back to the hand-worked frames.
7. **Nobody else can**: no token, another project's token, and this project's cut asked for through
   another project's route are refused; a stale history, an unknown format and an extra query field
   are refused; a withdrawn character permission refuses the export. No refusal carries the file.
8. **No token or URL is in either file**: not the owner's token, not the artifact root, no `://`,
   no media file name, no expiry. The download changes no job, no artifact and no spend.
9. Two exports at once is the bound; cancellation and close release stalled reads.

## Checked once, by hand

The planner test's cut (with a second-layer clip) was written to disk and opened with
OpenTimelineIO 0.18.1 and its `otio-cmx3600-adapter`, installed in a scratch virtualenv, not in the
repository. OTIO read the `.otio` as V1 and V2 video tracks of 325 frames with the same clips,
dissolve offsets (5, 5), gaps and marker. OTIO's own CMX writer, given that timeline, wrote the same
four event lines and timecodes as this exporter (it formats `D 010` where this writes `D    010`;
both are read). Its CMX reader read this EDL back as clips at record 0–95, 95–175 and 175–285 with a
10-frame dissolve. This is a one-off cross-check, not a CI test.

## Known gaps

- **The feature's cut is not yet a thing to export.** Release 3's step 7 (feature assembly) has
  not landed; this exports a saved sequence. An accepted assembly (`hv-edit-assembly/1`, ranges
  over a parent's output clock) is not exported either. When step 7 decides what a joined feature
  is, it either is a saved sequence (and this works as is) or needs its own flattening into clips.
- **Picture only, at normal speed.** Sound lanes, captions, fades, opacity, crops, masks and mattes
  are listed, not written. A speed change is refused rather than written as a `LinearTimeWarp` / M2,
  because ramps and holds cannot be written exactly in either format.
- **The EDL carries picture layer 1.** Upper layers are in the OTIO only; one EDL per layer would be
  the CMX way and is not done.
- **No editor button.** The route is the Director's desk API's, as the part's surface says; the
  browser editor does not yet offer the download.
- **No media travels with the files.** The finishing editor relinks by job id; FCPXML, AAF and
  packaged media ("exports with media", FULL-SCOPE P8) remain open.
- **The security checks are a copy of script navigation's**, not shared code. Two routes must agree
  about what may be read from a saved cut; a shared guard would be better and is a refactor of
  `EditScriptApi`.
