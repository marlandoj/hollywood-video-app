# HV-039-12 — The assembly render panel's messages arrived in a new live region every time, and went unheard

epic: HV-039
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

The panel that renders an independent assembly (a trailer or 60-second cut) redraws on every
change, and `draw` rebuilt the whole panel, status line included:

```js
panel.replaceChildren();…const status=node('p',s.message);…status.setAttribute('role','status');…panel.append(status);
```

So every message was written into a newly made `role=status` element that already contained its
words when it was inserted. That covers "Loading render capacity…", "Review the range joins…",
"Submitting the reviewed assembly render…", "Assembly render admitted…", and every refusal. Screen
readers announce a live region when its content changes, not reliably when it appears with its
content already inside (WCAG 2.2 SC 4.1.3, Status Messages). A screen-reader user who pressed
**Render reviewed assembly** heard nothing, whether the render was admitted or refused.

`busy.js` already keeps `aria-busy` off live regions for the same reason (see its header). This
panel defeated that by replacing the region itself.

## What this increment does

- **The heading, status line and warning line are created once**, with the panel. `draw` updates
  the status line's words and state only when they change, and rebuilds everything below them.
- The existing `safe` fallback, which writes an error into the element whose class is
  `edit-assembly-render-status`, finds the same element, so its errors are announced too.

## Acceptance criteria

1. **Every render message is written into the one status line that was there from the start.**
   Across loading the review, and approving and submitting the render, there is exactly one
   `role=status` element, it is the same element each time, and its words change.
2. **A refusal is written there too**, marked as an error.
3. Reverting `edit-assemblies-render.js` fails both.

- Tests: two new tests in `packages/frontend/test/edit-assemblies-render.test.js`, using its
  fixture. The file's other ten tests pass unchanged.

## Known gaps this leaves

- **The rest of the panel is still rebuilt on every change.** Focus on "Render reviewed assembly"
  or "Refresh render review" still falls to the page body after they run. HV-039's survey lists the
  same pattern in `edit-assemblies.js`, and it needs a focus-return rule of its own.
- **Other panels that rebuild their status line in `draw`** have not been audited in this increment.
