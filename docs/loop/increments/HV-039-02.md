# HV-039-02 — Stop suppressing every status announcement in the creator UI

epic: HV-039
spend_usd: 0

## Goal

Move `aria-busy` off the element that carries each panel's live region, so that the messages these panels already write are actually announced; collapse the eleven hand-written copies of that wrapper into one helper, so the fix cannot land in one panel and miss ten; and make the shared module the helper introduces provably reachable by the browser, because the route table that decides what is served was six hand-written path arrays with nothing holding them equal to what the modules import.

## The defect, as a user meets it

Every workbench panel in the creator UI holds its own status element — `role="status"`, in five cases with `aria-live="polite"` as well — **inside** the panel, and each one set `aria-busy="true"` on that panel around its own async work. `aria-busy="true"` tells assistive technology that the element is mid-change and that it may wait before exposing what changed, so:

- the success message, written inside the awaited action, is written under `aria-busy`;
- the error message, written in the `catch`, is also written under `aria-busy`, because `catch` runs before the `finally` that clears it;
- and in the four synchronous `sync()`-shaped panels, `status.textContent = …` and `setAttribute('aria-busy', …)` are adjacent statements in the same pass.

So a screen-reader user presses **Generate audition**, the request fails, the visible red text says the draft was retained — and nothing is announced. The control appears to hang. This is the silent-wrong-answer shape rather than a refusal: the failure is shown and never surfaced.

**Where it was.** Eleven `aria-busy` call sites across ten modules. The audit named six of them (`audio-studio.js:56`, `editorial.js:78`, `graphic-studio.js:13`, `dialogue-replacement.js:19`, `edit-assemblies.js:16`, `edit-assemblies-render.js:52`). Four more have the same defect and were not named: `sound-studio.js:24`, `lipsync.js:8`, `living-script.js:20`, `edit-script.js:29`.

**One that is not a defect, stated because a blanket fix would have broken it.** `performances.js:56` sets `aria-busy` on a play *button*, and the status element beside it is a sibling, not a descendant — so nothing is suppressed there. It is routed through the same helper for uniformity, and the helper is written so that a subtree containing no live region still marks the element itself. Without that branch the conversion would have silently removed a working affordance; perturbation P6 measures it.

**Nothing caught any of it.** There is no `aria-busy` assertion in any test in any of the twelve packages on `main`, and the only `aria` references in the frontend tests are three `aria-label` values used as element selectors. `HV-039-01` left the program its first accessibility assertion, about colour; this is the second, and the first about ARIA semantics.

## The shape of the repair

**One helper, eleven callers.** `packages/frontend/src/busy.js` owns the rule: mark the busy subtrees, never a subtree that carries a live region. `busyRegions(root)` returns `root` itself when nothing under it is live — which is exactly what the eleven copies did, so the button case and the controls-only panels are unchanged — and otherwise the shallowest descendants that carry no live region, so the whole of the panel except its live regions is marked. `markBusy(root)` returns the call that clears it, for the seven `try/finally` panels; `applyBusy(root, busy)` is the form the four `sync()` panels need.

**The marks are reference-counted, which the first draft of this helper got wrong.** `editorial.js` marks its own panel, and the `edit-assemblies` panel mounted inside it marks its own subtree, so one element can be claimed by two roots. With a plain `removeAttribute` the inner panel finishing first stripped a mark the container still held, leaving a busy container with an unmarked child. The test in this increment caught that before the code was committed; perturbation P3 measures the version without the count.

**It is the same code in the browser and in the tests.** `busyRegions` walks `children` and reads attributes through `getAttribute`, both of which the browser DOM and this repository's hand-rolled test element expose, so nothing is stubbed and no DOM library is added.

**The helper has to be served, and that is a second rule written in six places.** The API returns the creator UI's modules two ways: most as the raw file with their `import` statements intact, ten bundled by `previewBrowserModule` with imports inlined. Which module goes which way was decided by six hand-written path arrays in `server.ts` — one of them a thousand lines below the other five — and nothing held them equal to what the modules import. A shared module added to a raw-served panel makes the browser request a path no array names; it 404s, and the whole panel fails to load. Every existing check named one such path by hand, so none of them would have noticed.

`packages/api/test/frontend-modules.test.ts` now walks the graph the way the browser walks it: the entries come out of the two served HTML pages, and every further edge comes out of **the bytes the server returned**, not the source on disk. That distinction is the whole point — a bundled module's response has no imports left to follow while its source has three, so a walk over sources would demand routes the browser never asks for. Perturbation P12 measures exactly that mistake.

The three route lines for modules shared across prefixes are replaced by one derived from two exported constants, `BROWSER_MODULE_PREFIXES` and `SHARED_BROWSER_MODULES`, and `busy.js` joins that list. The other three arrays are left alone; see the deferral below.

## Declared changes beyond the defect

- **`/api/speech-player.js` now answers.** It was served at `/api/cast/` and `/api/direction/` only; folding it into the shared-module list serves it at all three prefixes. It is the same already-public client module at a third path, with the same headers; no new file becomes reachable.
- **A duplicated import walk was deleted, not added to.** `packages/api/test/editorial.test.ts` already walked `/api/editorial.js`'s imports, capped at `expect(visited.size).toBeLessThanOrEqual(9)`. That cap was an assertion about the module count wearing a recursion guard's clothes: adding one shared import to a panel made it 10 and failed the test. The walk is removed with a pointer to the new test, which starts from all thirteen entries rather than one, handles the bundled modules correctly, and needs no hand-updated bound.
- **Five test element stubs gained `getAttribute` and `removeAttribute`.** They had `setAttribute` and an `attributes` bag only. **Six separate `class Element` stubs exist** across `packages/frontend/test` (`edit-assemblies-fixture.js`, `edit-assembly-preview.test.js`, `edit-script.test.js`, `editorial-assembly-guards.test.js`, `living-script-comparison.test.js`, and an inline one in `mask-viewport.test.js`) — the same duplication family this increment is about, one level down. Consolidating them is not attempted here: it would touch every frontend test in the same change as a behaviour fix, and it is recorded so the next reader does not have to rediscover it. `busy.test.js` imports the existing fixture rather than adding a seventh.
- **Collapsing the remaining three route arrays into one directory-backed route is deliberately deferred.** Serving any `*.js` that exists in `packages/frontend/src` would remove the arrays entirely, but it changes what is *reachable* — `operator.js`, today served only as `/api/operator/app.js` with the console's own `content-security-policy`, would answer at `/api/operator.js` without it. That is a change to the API's static surface and deserves its own increment and its own reasoning, not a paragraph inside an accessibility fix. The new test makes the remaining arrays unable to drift silently, which is the failure mode; the arrays themselves are cosmetic by comparison.

## What this increment does not do

- **It does not audit the rest of WCAG 2.2 AA.** It fixes 4.1.3 Status Messages for these eleven sites and nothing else. `mask-viewport.js:6` still declares `role="img"` on a focusable, arrow-key-operated canvas — a live 4.1.2 failure the audit named, untouched here.
- **It does not cover content created during the busy window.** `applyBusy` marks the tree as it stands when it is called, so an element appended while the panel is busy is unmarked. The four `sync()` panels re-apply on every pass and self-correct; the seven `try/finally` panels mark once and may redraw inside the action. Marking the panel instead would cover that case and silence the announcement, which is the defect. The controls in every one of these panels are disabled for the duration, which is the affordance a sighted user actually reads, so the residual is a missing "wait" hint on newly-created content, not a missing state.
- **It does not verify announcement with a screen reader.** These are DOM-structure assertions: they prove the message is not written inside an `aria-busy` subtree. Whether a given screen reader then speaks it is a manual check, and V-020 — which still names WCAG 2.1 AA while this epic is defined as 2.2 AA — remains the open gate.

## Acceptance criteria

1. No live region in the creator UI has an ancestor marked `aria-busy` while its panel is busy. — `packages/frontend/test/busy.test.js`, cases 1, 2 and 8; case 8 drives a real `edit-assemblies` panel into a held request and walks the status element's ancestor chain.
2. Everything in a busy panel other than its live regions is marked. — case 1 (`['h2','div']`) and case 2 (`['header','button','a']`).
3. A subtree with no live region marks the element itself, preserving the button and controls-only behaviour. — case 3; P6 measures the version that marks nothing.
4. A nested panel and its container cannot clear each other's marks, in either completion order. — case 4; P3 measures the version without the reference count.
5. Only real live regions are excluded: `role="status" | "alert" | "log"` and `aria-live` other than `off`; `role="region"` and `aria-live="off"` are not. — case 5; P4 and P5.
6. `aria-busy` is written in exactly one file, and every module that used to write it imports and calls the helper. — case 7; P7 and P8.
7. Every module path the browser will request, following the served responses from the entries in both pages, is served with a JavaScript content type. — `packages/api/test/frontend-modules.test.ts`, case 1; P9 and P10.
8. A name that is not a module is refused at every prefix, so a 200 means something. — case 3 of that file.
9. The walk follows a raw response's imports and does not invent requirements from a bundled module's source. — case 2 of that file; P11 measures the pattern matching nothing, P12 the walk reading from disk.

## Perturbations

Each edit was applied to the shipped files, both suites measured, and the file restored from an explicit copy. `busy` is `packages/frontend/test/busy.test.js` (8 tests); `modules` is `packages/api/test/frontend-modules.test.ts` (3 tests).

| perturbation | busy | modules |
|---|---|---|
| baseline | `8 pass / 0 fail` | `3 pass / 0 fail` |
| P1 — `applyBusy` marks the root unconditionally, exactly as the eleven copies did | `2 pass / 6 fail` | `3 pass / 0 fail` |
| P2 — the walk marks the ancestor that holds the live region instead of descending | `2 pass / 6 fail` | `3 pass / 0 fail` |
| P3 — no reference count: a nested clear strips a mark its container holds | `7 pass / 1 fail` | `3 pass / 0 fail` |
| P4 — `isLiveRegion` looks only at `role`, ignoring a bare `aria-live` | `7 pass / 1 fail` | `3 pass / 0 fail` |
| P5 — `aria-live="off"` counted as a live region | `7 pass / 1 fail` | `3 pass / 0 fail` |
| P6 — a subtree with no live region marks nothing instead of itself | `7 pass / 1 fail` | `3 pass / 0 fail` |
| P7 — `audio-studio` reverted to setting the attribute on its own panel | `7 pass / 1 fail` | `3 pass / 0 fail` |
| P8 — the import stays but the module writes the attribute itself | `7 pass / 1 fail` | `3 pass / 0 fail` |
| P9 — `busy.js` dropped from the shared-module list | `8 pass / 0 fail` | `2 pass / 1 fail` |
| P10 — the `cast` prefix dropped, so the shared modules 404 for one panel | `8 pass / 0 fail` | `2 pass / 1 fail` |
| P11 — the static-import pattern made to match nothing | `8 pass / 0 fail` | `1 pass / 2 fail` |
| P12 — the walk reads each module from disk instead of from the response | `8 pass / 0 fail` | `2 pass / 1 fail` |

P1 and P2 are the defect itself, put back two different ways, and both take six of the eight cases down. P11 failing two cases rather than one is the anti-vacuity floor doing its job: the walk shrinks below its stated minimum *and* the raw-response case stops finding `editorial.js`'s nine imports, so a pattern that silently stops matching cannot leave an empty failure list looking like a pass.
