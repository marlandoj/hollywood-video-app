# HV-029-04 — the owner's display paths chose their permission check by job shape

epic: HV-029
spend_usd: 0

## Goal

Make every owner-facing view of a job ask the same question `/artifacts/` asks — *what guards this job's media?*, answered by the job's stage — so the path that **hands out** the links and the path that **redeems** them cannot disagree.

## The defect

HV-029-03 removed the six-optional-fields shape from the media path. The display side kept it:

```ts
if((job.dialogueReplacement||job.lipSync||job.soundMix||job.pictureEdit||job.assemblyEdit)&&job.output){
  try{assertSelectedOutput(job,project,{jobId:job.id,outputRevision:outputRevision(job)});}
  catch(error){view.mediaUnavailable=(error as Error).message;delete view.output;…}
}
```

The same five fields, on the display side, in `audioJobView`. And `audioJobView` is **one of five** callers of `publicJob`, which is what actually mints the artifact token. The other four had no check of any kind, for any stage:

| call site | what it lists |
|---|---|
| `GET /api/projects/:id` | every job in the project |
| `GET /api/projects/:id/takes` | take groups, with each clip's `mp4Url`, `hlsUrl`, `posterUrl`, `captionsUrl`, `manifestUrl` |
| `GET /api/projects/:id/cast/:id/sheets` | character sheets, with `sheetUrl` and every storyboard frame |
| `PUT /api/projects/:id/dialogue-selection` | the job just selected (this one asserts separately, and still does) |

So a plain `animatic` or `final` cut — which carries none of the five fields — was handed a **freshly minted** `mp4Url`, `hlsUrl`, `captionsUrl`, `manifestUrl`, the per-shot `audioUrl`s with the lines' `speech` text beside them, the take clips' URLs and the storyboard frame URLs, after the cast permission for the character in it had been revoked. A character sheet, which is a character's likeness and nothing else, was listed the same way.

**What this did and did not expose.** Since HV-029-03 the artifact route refuses all of it, so the bytes did not flow. What flowed was the cut's contents — the shot list, the spoken lines, the take labels — and a live token for material the owner was no longer permitted. That is the likeness the revocation was about, and the view asserting `mediaUnavailable` for a lip-sync pass while offering a plain cut's URLs in the next response is the inconsistency the whole HV-029 thread exists to remove.

**Two smaller holes inside the same block.** `delete view.output` removed the output map only. `shotRenders[].audioUrl`, `takeClips[].*Url` and `storyboard[].url` are built from `artifactPrefix`, sliced off the minted `mp4Url` rather than read from `signedArtifactUrls`, so they survived the deletion — on the one path that *did* refuse, a view saying "this media is unavailable" still carried live links to the audio of every speaking shot in it.

## The shape of the repair

**A graphic answers through its own view, everywhere.** `graphicJobView` sets `unavailable` and drops the output for a graphic whose permission has been withdrawn, and it used to be reached only from `audioJobView` — so `GET /api/projects/:id`, which does not use that view, serialized a graphic through `publicJob`. `publicJob` mints from `job.output`/`job.audioOutput` and knows nothing of `graphicOutput`, so it minted nothing and therefore *never asked*, while still emitting the whole `graphicRender` spec and the retained `graphicOutput` through its rest spread. `jobView` now delegates, so there is one view per job for every display path.

**`publicJob` takes a required `permission` parameter.** Not optional. An optional parameter is this increment's own defect one level down — a check hung off something that can be absent, absent exactly where nobody looked — and it is the family that produced both of HV-029's authorization bypasses. TypeScript now refuses a display path that does not name a rule.

**The rule is `mediaPermission`.** `artifactPermission(job.stage)` — HV-029-03's total function over `JobStage` — plus the audio take's voice rule, which is now `audioTakePermission`: one definition, reached by the studio view, by every display path, and by `/artifacts/`. That rule was previously written out twice, once in each place, and the two copies were already drifting — the route's threw `"Unavailable voice permission"`, the view's threw the sentence an owner reads. (A *retained* audition on the narration path has its own rule, `assertRetainedAuditionPermission`, about a different object: the audition as carried into another job's output. That one is not collapsed here.)

**"Is there something to withhold?" is read off the mint, not restated.** `publicJob` calls `signedOutput` first and gates on `minted.output`. The alternative — a second condition naming `job.output || job.audioOutput` — is a second copy of the rule `signedArtifactUrls` already states, and a second copy is how one of the two ends up covering a case the other does not. A token is minted and then dropped when permission refuses; it is an HMAC over three fields and never leaves the function.

**Withheld means withheld.** Every link derived from the token goes with it: the output map, `artifactUrlsExpireAt`, `artifactUrlsExpireInSeconds`, the per-shot `audioUrl` *and the `speech` text beside it*, the take clips' five URLs, the storyboard frames' `url`. The rows themselves stay, so the owner still sees that the cut has shots and takes and what they are; what they do not get is a way to fetch them. **This is not a redaction pass**: `dialogue.report` and `audio.report` still carry their lines, and `audioTake.source` still carries the line's text. The claim is about links and about the per-shot `speech` field that travels with one, not about every string in the document.

**`audioUnavailable` stays where it is.** The audio studio shows it for a **queued** audition, before anything is retained, and `publicJob` decides only about retained media. It now reads from `audioTakePermission` rather than from its own copy of the same two checks.

## What this increment does not do

- **It does not change `/artifacts/`'s behaviour.** The route now reaches the audio rule by name instead of spelling it out; the rule is the same two checks in the same order. Every other line of that route is untouched.
- **It does not narrow the window between a revocation and a client's next request.** A client holding a previously minted token still holds it; the artifact route is what refuses to redeem it, as of HV-029-03. This increment stops *new* links being handed out, which is a different thing from recalling old ones. Nothing revokes tokens themselves.
- **It does not audit the editorial preview-media and original-frame routes.** HV-029-03 recorded those as serving frames "with no cast check at all". **That claim is refuted**: `EditPreviewApi` and `EditOriginalFrameApi` both pass a permission callback into `EditPreviewSessions`, which re-runs it for every binding on every read — `#withSources` calls `session.access(entry.binding)` for every entry before the handler runs and again after it, the page cache awaits the same callback even on a cache hit, and the streaming lease holds it too. The callback is `assertEditOriginalPermission`, which dispatches to `assertCurrentFilmSourcePermission`, the graphic rule, the sound rule or the lip-sync rule, and otherwise to `assertDialoguePermissions` — the cast rule — plus `assertRetainedAuditionPermission` for every audition in the cut. Those routes were checked before this increment and are checked after it. The claim is corrected here rather than left standing in HV-029-03's text.
- **It does not measure the cost of minting a token that is then discarded.** One HMAC per refused job per view. The listing routes cap at 20 (takes) and 10 (sheets) rows; the project read route does not cap, and neither did it before.
- **It does not gate the operator panel's audio listing** (`server.ts`'s `audioBilling` route), which lists jobs through `audioJobView` and therefore does gate, or the editorial and sound APIs, which are handed `audioJobView` as their `view` and therefore gate too. Every remaining `publicJob` caller is `jobView`; the test asserts there are exactly two occurrences of `publicJob(` in the file.
- **It does not unit-test the two frontend guards it adds.** `character-sheets.js` read `job.output.sheetUrl` immediately after `status==="done"`, and a withheld sheet now has no `output`, so this increment would have replaced an over-disclosure with a `TypeError` that aborts the whole sheet history. `takes.js` had the same shape through `takePlayer`'s unconditional `assetUrl(clip.mp4Url)`. Both are guarded and both now render `mediaUnavailable`. Neither module has a unit harness, and the five divergent `class Element` DOM stubs already in `packages/frontend/test` are a backlog item of their own; adding a sixth to cover a two-line guard is the wrong trade. `frontend-modules.test.ts` still serves both modules. This is a rendering guard, not an authorization one.
- **It does not collapse every mint in `server.ts` into one helper.** Four `signedOutput` call sites and two `mintArtifactToken` call sites remain, each gated by something: `publicJob` by `mediaPermission`, the review view by `assertSelectedOutput`, the direction route's storyboard sources by `mediaPermission` (new — see below), the narration takes by `assertRetainedAuditionPermission`. The test pins those counts, so a new mint has to be argued for rather than added quietly. The review view's gate is `assertSelectedOutput` rather than the stage rule, which is HV-029-02's decision and is left standing.

## Acceptance criteria

1. A plain silent cut's owner view stops handing out **any** `/artifacts/` link — not one link that 404s, no link anywhere in the document at any depth — the moment its character's permission is revoked, and hands out the same files again, under a freshly minted token, when the permission is restored, serving the same bytes. — `job-view-permission.test.ts` case 1; AA1, AA2, AA5, AA9, AA12, AA13.
2. The per-shot links a cut carries **outside** its output map — the speaking shots' `audioUrl`, and the `speech` text beside them — go with it. — case 2; AA3.
3. A character sheet's own listing route answers the same way. This is the rule HV-029-03 could give no behavioural case (its Y9 row was green because no request reached the character-sheet branch); that row now bites. — case 3; AA7.
4. An audition's voice permission is the same rule on the listing as on the media path: withdrawing the configured voice policy withholds the audition's `audioUrl` from `GET /api/projects/:id`, which never went through `audioJobView` and so never asked. — case 4; AA6, AA10.
5. The project read route answers the same way, for its own entry and for the whole listing; and a job with nothing retained is **not** reported as a permission problem, because a queued job is not a refused one. — case 5; AA11.
6. A take group's listing withholds its clips' five links, and the rows stay. This is the one listing the defect table names that the first draft covered with a scan alone; its rule derives shots from the take plan rather than from `renderShots`, so a case on a cut does not stand for it. — case 6; AA8, AA14.
7. A graphic is serialized by `graphicJobView` on the project listing, not by `publicJob`. — case 7; AA15.
8. Every display path asks by stage through a parameter it cannot forget: the parameter is required, the mint is what decides there is something to withhold and there is exactly one of it, the gate's condition names no job-shaped field and no `process.env`, `jobView` is the only caller, and `mediaPermission` is `artifactPermission(job.stage)` plus the audio rule. — case 8; AA5, AA9, AA11, AA13, AA14, AA16, AA17.

## The critic's findings

An adversarial read of the first draft found two live defects the draft introduced or missed, one regression it would have shipped to the browser, four ways its scans could be walked past, one piece of coverage its repair quietly dropped, and four claims the code contradicted.

1. **A graphic was left ungated on the project listing — by this increment's own rule.** `graphicJobView` was reached only from `audioJobView`, and `GET /api/projects/:id` does not use that view. `publicJob` mints from `job.output`/`job.audioOutput`, so for a `graphicOutput` it minted nothing and the gate never ran, while the rest spread still emitted the whole `graphicRender` spec and the retained output. And the composed rule would not have helped: `artifactPermission("motion-graphic")` is a *presence* check, because the media path answers the graphic question in its own earlier block. The draft remembered to compose `if(job.audioTake)audioTakePermission(…)` and forgot the graphic — **defect family 2, reproduced inside the increment that exists to remove it**. `jobView` now delegates, and AA15 measures it.
2. **The repair would have crashed the sheet panel.** `character-sheets.js` reads `job.output.sheetUrl` immediately after `status==="done"`, and this increment creates exactly that shape: done, no output. The `if(path)` guard is one level too late, so the `TypeError` aborts the whole sheet history rather than one row. `takes.js` had the same shape through `takePlayer`'s unconditional `assetUrl(clip.mp4Url)`. Both guarded, both now render `mediaUnavailable`.
3. **The direction route mints storyboard links behind a revision comparison, not a permission.** `GET /api/projects/:id/direction` reuses a finished animatic's storyboard frames as source images, gated on `castingMatches(job.casting,cast)` — projectId, version and revision equality. A `revoked` edit bumps the version and is masked by accident; **a grant that lapses by its own `expiresAt` does not**, and that route then mints a fresh token for every frame. Same defect, on a route the draft did not mention. Now behind `mediaPermission`; AA17.
4. **`not.toMatch(/process.env/)` is a spelling, not a rule.** A module-scope `const SKIP_DISPLAY_GATE = process.env.HV_SKIP_DISPLAY_GATE === "1"` read inside the gate walks straight past it. The gate block is now pinned whole — any added condition changes those bytes — and AA16 measures the hoisted form.
5. **The rule's *contents* were tested, not the rule.** `expect(ruleBody).toContain(…)` twice welcomed `if(job.stage==="take-preview")return;` as a first line. `mediaPermission` is now pinned whole, and a second wider shape regex runs over its body. AA14.
6. **The take-group listing — one of the four call sites the defect table names — had no case at all.** Its rule derives shots from the take plan rather than from `renderShots`, so no case on a cut stands for it, and the existing take coverage in `artifact-permission.test.ts` re-fetches a URL it captured *before* the revocation rather than re-reading the listing. Case 6 now renders a group through the real route and re-reads the listing. This also corrected the draft's AA4 row, which claimed to cover the take clips: only the storyboard half bit, because the `SILENT` fixture has no take clips and a reverted `takeClips` guard emits `"undefined…"` strings that the link scan does not see.
7. **"The one place that mints its artifact links" was false.** Four `signedOutput` sites and two `mintArtifactToken` sites exist in `server.ts`, and the assertion meant to pin this was scoped to `publicJob`'s own body, so adding a mint anywhere else was invisible. The counts are now file-wide with each site named, and the claim is gone from the doc.
8. **The redaction test's repair dropped the property it was carrying.** The old line fetched *the link the view had minted* and asserted 401; replacing it with a token the test mints itself moves the expectation into the same function it is meant to pin — a mint/verify drift would pass. The view's own mint is now checked against the cut's `linkExpiresAt` as the test itself wrote it into the queue file. (The `Math.max(0,…)` clamp in `signedOutput` is genuinely unreachable through `publicJob` now: a cut past its expiry fails the gate, so the field is `null`, never `0`. That is a consequence of the change, not a loss.)
9. **Three assertions could not fail** and are gone: a regex run against a string literal, `expect(token.length).toBeGreaterThan(40)` on an HMAC token, and a `toBeGreaterThanOrEqual(6)` floor on `jobView(` occurrences that a route leaving the rule would still satisfy. The token check now verifies the token and matches its claims.
10. **Two scans in `artifact-permission.test.ts` were weaker than they read.** `toContain("audioTakePermission(mediaJob,project)")` is satisfied by the substring inside `assertAudioTakePermission(mediaJob,project)`; the slice bounding the audio rule's body ended at a literal `"}; "`, which a reformat moves and which fails open if it runs long. Both fixed, and the rule is now asserted to `throw`.

The critic also confirmed, against the code, that `artifactPrefix` cannot produce an `"undefined…"` string for an audio take (the optional chain short-circuits before `job.output!.mp4Path` is evaluated), that there is no job for which links are minted and the gate is skipped, and — independently, by reading `edit-preview-sessions.ts` and `edit-preview-cache.ts` — that the refutation of HV-029-03's claim about the editorial preview routes is correct, including on a cache hit.

One claim of the critic's is **not** accepted: that `mediaUnavailable` should mean the response carries no transcript. `dialogue.report` and `audio.report` are the cut's editorial record, which the owner is entitled to whatever the cast permission says about showing the likeness; only `shotRenders[].speech` goes, because it travels with the link it sits beside. The doc now says that rather than implying otherwise.
