## Why

Kevin agreed Release 2's exit criteria in G16, as HV-030-22 proposed them in `docs/ROADMAP.md`. That
increment built the tooling and the test that holds a run to them, and ran nothing.

This increment is the run. Two films by one creator go through the studio, the second pitched with
the first's style card. Everything Release 2 added behind the Director's desk is then driven through
the desk's own routes, and Kevin reviews both films on his phone. The run is recorded in
`docs/evidence/release-2/release-run.json`, and `test/release-2-run.test.ts` holds that record to
the criteria. Kevin acknowledges the release against the record (G6).

Writing the runbook turned up seven things the drivers could not yet do. They are fixed here, with
tests, before anything runs (below).

  - **Film A, "The Lock-Keeper's Lantern"** (`film-a.fountain`): a reel of four scenes and three

    them through the read-through's own facts, which is where the safety gate stops a pitch. Neither
    raises a concern. Both fit their format, and the continuity finding is there to be found.
- **The fixes the run needs**, each tested in `test/release-2-run-fixes.test.ts` or
  `test/release-2-driver.test.ts`:

  4. **Nothing filled the lines' before and after.** `scripts/release-2-lines.ts` reads the four

  5. **The signature was a manual host step.** `--verify-c2pa` runs `scripts/verify-c2pa.ts`'s

  7. **A lapsed operator credential threw the record away.** The diagnostics credential lives 15
     minutes, and a run with deliveries takes longer. An operator view that can't be read is now

## Spend

`spend_usd: 2` is the sum of the caps below. Picture is on `mock`, so the generation line should
not move. If it moves, the run stops (Runbook, step 4).

| Provider | Cap in this run | Its line | What it pays for |
|---|---|---|---|
| ElevenLabs voice | $0.50 | voice, $25 (G14) | 13 lines of dialogue, 347 characters, about $0.02 at the last proof's rate |
| ElevenLabs Music | $1.00 | music, $10 (G15) | at $0.15 a minute: the Composer's own cue for each film at the front door, as long as the film (10 to 120 s, so at most $0.30 each), and the desk step's 60-second cue ($0.15). At most $0.75 |
| Crew model, OpenRouter | $0.50 | crew, $25 alert (G13, G16) | two read-throughs, two plans and one line-notes call |
| Crew model, Synthetic | $0 | the same crew line | the same calls, recorded at $0 with their tokens |
| Picture, `mock` | $0 | generation, $450 | storyboards, finals, the character sheet |

Deliverables, ambience, titles and the C2PA check run on the host and cost nothing.

**Music is asked for three times, and each ask is paid once.** With the vendor on, the front door's
Composer asks for a generated cue for each film's final, keyed by the cut (`crew-music-<cut id>`),
and credits it as generated (HV-024-11). The desk step then asks for one more cue for film A, keyed
by the project (`release-2-music-<project id prefix>`). A retry of any of the three is answered from
its key, never paid again. Only the desk step's cue goes in the record's `HV-024.music` part, because
that part's surface is the desk's. All three show on the music line, and so in the run's spend.

**Holds are not spend.** The voice line counts each ElevenLabs take as a hold until the operator
allocates the vendor's invoice. In the last proof that was about $0.56 a take. These 13 takes will
add about $7 of holds to the voice line, which held $4.44 already. That crosses its $5 alert, as
expected, and stays under its $15 alert. The holds count toward each film's $40 limit and toward
the line, never toward the run's spend.

## Music is not optional

`HV-024.music` is exercised only when "a generated music cue lands in a film's sound library". The
contract accepts no other proof. G16's deferred list covers voice meetings, sound effects, moderation
and line notes. It doesn't cover music. Without `HV_MUSIC_PROVIDER=elevenlabs`, the music step
records "this studio has no music provider configured", the part is neither exercised nor deferred,
and `test/release-2-run.test.ts` fails the record. **The operator must enable music for the run.**
Deferring it would need a new gate entry from Kevin.

## Runbook

Everything runs on the host, from the active release. Every output goes under `R`, which only its
owner can read. No command prints a key, a token or a link. Long steps run detached and are polled.

```sh
. /etc/rough-cut/host.env
REL=$(cat "$RC_RUNTIME/active-release.txt"); BUN="$RC_RUNTIME/bin/bun"; R="$RC_RUNTIME/runs/release-2"
install -d -m 700 "$R"; umask 077; cd "$REL"
S=docs/evidence/release-2/scripts; BASE=http://127.0.0.1:8081
# Each line's figure, read-only, from the studio's own ledgers.
lines() { ( set -a; . "$RC_RUNTIME/storage-api.env"; set +a; "$BUN" scripts/release-2-lines.ts --out "$R/lines-$1.json" ); }
# A few fields of a finished report. Reports hold no secret; this only keeps the terminal short.
show() { python3 -c 'import json,sys; r=json.load(open(sys.argv[1])); print({k: r.get(k) for k in sys.argv[2:]})' "$@"; }
```

1. **Read the lines before:** `lines before`.
2. **Film A, at the front door.** Keep its style card, and share it with five views.

   ```sh
   nohup "$BUN" scripts/studio-run.ts --base $BASE --script $S/film-a.fountain --format reel \
     --keep-style-card "$R/a.card.json" --share 5 --out "$R/a.json" > "$R/a.log" 2>&1 &
   echo $! > "$R/a.pid"
   ```

   Poll every few minutes with `tail -n 2 "$R/a.log"; kill -0 $(cat "$R/a.pid") 2>/dev/null && echo running`.
   When it is done, run `show "$R/a.json" outcome projectId error readThrough plan styleCard finishNotes`.
   - `outcome` is `completed`.
   - `readThrough.source` and `plan.source` name the crew's vendor, not `stand-in`.
   - `styleCard.kept.sha256` is set.
   - `finishNotes` has no "generated music was not used" and no "ambience was not added". Either
     means the Composer fell back. Read why before going on.

   `a.token` and `a.review` are written beside it, mode 600.
3. **Read the lines again:** `lines after-a`. Compare `lines-after-a.json` with `lines-before.json`:
   - generation's spent and held must not have moved (picture is `mock`);
   - crew's spent must have risen by less than $0.25, half its cap for one of two films.

   Otherwise stop.
4. **Film B, pitched with film A's card,** from the Final Draft file.

   ```sh
   nohup "$BUN" scripts/studio-run.ts --base $BASE --script $S/film-b.fdx --format short \
     --style-card "$R/a.card.json" --share 5 --out "$R/b.json" > "$R/b.log" 2>&1 &
   echo $! > "$R/b.pid"
   ```

   Poll the same way. When it is done, run `show "$R/b.json" outcome projectId error readThrough script`.
   - `readThrough.readStyleCard` is `true`.
   - `script.format` is `final-draft`.
5. **A diagnostics credential** (15 minutes, read-only), minted only for the next step:

   ```sh
   ( set -a; . "$RC_RUNTIME/secrets.env"; set +a; "$BUN" scripts/operator-diagnostics.ts "$R/operator-1.json" $BASE )
   ```

6. **Behind the front door,** through the desk's own routes:

   ```sh
   nohup "$BUN" scripts/release-2-run.ts --base $BASE --out "$R/run-1.json" \
     --film-a "$R/a.token" --studio-a "$R/a.json" --script-a $S/film-a.fountain \
     --film-b "$R/b.token" --studio-b "$R/b.json" --script-b $S/film-b.fdx \
     --spend-declared 2 --lines-before "$R/lines-before.json" \
     --lock-look --lock-character NELL --sheet --share-actor --import-as "NELL FROM THE LOCK" \
     --continuity --continuity-apply \
     --deliveries grade,open-captions,sdh,reframe-9:16,reframe-1:1,mezzanine \
     --ambience --music "a slow accordion waltz over lapping canal water, hopeful" --music-seconds 60 \
     --import-fdx $S/film-b.fdx \
     --line-notes "Tighten the dialogue in the last scene" --accept-notes \
     --provenance --verify-c2pa \
     --defer HV-030.voice-meetings=G15-202609301223 \
     --defer HV-024.sfx=G16-202610011400 --defer HV-031.moderation=G16-202610011400 \
     --operator-token "$R/operator-1.json" > "$R/run-1.log" 2>&1 &
   echo $! > "$R/run.pid"
   ```

   Poll the same way. A step that stops is printed as `stopped: <step> <film> <why>`, and the driver
   exits 1. The record is written either way. To list each step's outcome, run
   `python3 -c 'import json; [print(s["step"], s["film"], s["outcome"], s.get("note","")) for s in json.load(open("'"$R"'/run-1.json"))["steps"]]'`.
   - **`music-cue` "no music provider configured":** precondition 2 was missed. Set it and restart.
     Then rerun this command with `--merge "$R/run-1.json" --out "$R/run-1b.json"` added, keeping
     the film options, `--music` and `--music-seconds`, and dropping every other desk option. From
     then on, `run-1b.json` is the record that step 9 merges.
   - **`share-and-import-actor` stopped on a name:** choose another `--import-as`.
   - Any other stop is a defect. Fix it in its own increment before going on, as Release 1 did.

   **Ambience is asked for twice, and recorded once.** Since HV-024-14, the front door's Composer
   lays the studio's ambience under each film's final mix. `--ambience` asks the same route for film
   A's first retained cut through the desk, because `HV-024.ambience`'s surface is the desk's. The
   route takes no key, and costs $0:
   - asked again for the same cut, it answers the same cues;
   - for any cut of the film, it reuses the beds the project's library already holds, recognised by
     their label, rights record and length (docs/SOUND-AMBIENCE.md).

   So the second ask adds no bed and no spend. Only the desk step's answer goes in the
   record (`sound.ambience` and the part's bed asset ids, each once). The front door's shows only in
   the film's credits.
7. **Read the lines after:** `lines after`.
8. **Kevin reviews both films on his phone** (below).
9. **Read back what he did,** with a fresh credential. This also adds the operator's evidence and the
   lines after.

   ```sh
   ( set -a; . "$RC_RUNTIME/storage-worker.env"; set +a; "$BUN" scripts/report-expiry-takedowns.ts ) > "$R/expiry-takedowns.json"
   ( set -a; . "$RC_RUNTIME/secrets.env"; set +a; "$BUN" scripts/operator-diagnostics.ts "$R/operator-2.json" $BASE )
   "$BUN" scripts/release-2-run.ts --base $BASE --merge "$R/run-1.json" --out "$R/run-2.json" \
     --film-a "$R/a.token" --studio-a "$R/a.json" --script-a $S/film-a.fountain \
     --film-b "$R/b.token" --studio-b "$R/b.json" --script-b $S/film-b.fdx \
     --reviews --lines-after "$R/lines-after.json" --operator-token "$R/operator-2.json" \
     --evidence HV-031.expiry-takedown=docs/evidence/release-2/expiry-takedowns.json \
     --evidence HV-039.wcag=docs/ACCESSIBILITY-AUDIT.md
   ```

   Two parts are deferred here only if the run shows they could not be exercised:
   - **`HV-016.line-notes`:** add `--defer HV-016.line-notes=G16-202610011400` only if
     `writersRoom.lineNotes.source` is `stand-in`, meaning no crew model was live. G16 defers line
     notes on exactly that condition. A live crew that wrote no usable note is a finding, not a
     deferral.
   - **`HV-031.signed-c2pa`:** add `--defer HV-031.signed-c2pa=G16-202610011400` only if
     `provenance.hostHoldsKey` is `false`. Criterion 5, agreed in G16, defers it on exactly that
     condition.

The `.token`, `.review`, `.card.json` and `operator-*.json` files stay in `R`. They never enter the
repository or the chat.

## Recording

The record is `$R/run-2.json`, made by the drivers. The build session reads it from the host and
writes it to `docs/evidence/release-2/release-run.json`.

- **From `studio-run.ts`:** the two films, their style card digests and their review link digests.
- **From `release-2-run.ts`:** every step, with its surface, outcome and ids. The slices, the
  deliveries, the sound, the writers' room, provenance with each export's verification, the reviews,
  and the per-film and operator snapshots.
- **From `scripts/release-2-lines.ts`:** each line's before and after, read from the database, with
  the basis named. Every dollar is on exactly one line, so the four lines' differences added up are
  the run's spend:
  - **voice:** ElevenLabs takes, by the query the voice line's own check runs;
  - **music:** the music line's own summary;
  - **crew:** the crew line's own summary, every vendor on one line;
  - **generation:** the rest of the cost ledger. It is read over the database's life, which is never
    less than the month the $450 alert counts.
- **Added by hand,** and only these:
  - `increment`, `host`, `releaseSha` and `profile`, as Release 1's record has;
  - `knownGaps`, as sentences;
  - `stoppedAttempts`, each with what stopped it and what it spent.
- **`docs/evidence/release-2/expiry-takedowns.json`** is `$R/expiry-takedowns.json`, committed
  beside the record. It holds project ids and dates, no tokens.

Evidence is pushed only after `bun test test/release-2-run.test.ts` passes locally against it. That
file's last test reads the real record, against the real gate entries only, and is no longer
skipped once the record exists. If it fails, the record is not edited to pass. The failure is fixed
at its cause, or the run is redone.

- **Film B's own NELL isn't the imported actor.** Film B is shared before the desk steps run, and the

- **Import is proved by Final Draft alone.** No PDF copy is committed. `HV-016.import` accepts

    package. This is also why `bun run typecheck` reports two errors, in
    `packages/assembler/src/c2pa.ts` only.

  Step 1 of the runbook is the first real run of the query. If it fails, or a figure is negative or
  far from the operator console's, the run stops there, before anything is spent.
- **"The same creator" is shown by the style card,** as HV-030-22 said. The studio is anonymous
  (ADR-0018).
