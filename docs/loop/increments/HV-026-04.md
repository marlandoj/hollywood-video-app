# HV-026-04 — The quality check's own honesty, where a missing reading was a finding

epic: HV-026
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0 — no provider is touched; the tests encode their own films with ffmpeg.

## Why

A quality check is believed. Everything else this studio builds is read by someone who can see the
film; a delivery report is read by someone deciding whether to look at all. That makes a wrong
number in it worse than a wrong number anywhere else, and it makes the three findings below defects
rather than polish.

A critic pass over HV-026-01 and HV-026-03 found them:

- **A reading nobody took was reported as a reading of silence.** `decibels` mapped a missing
  `mean_volume:` line to the same `null` a real `-inf` produced, so a log the meter never wrote
  became `silent-programme: The soundtrack measures as silence from end to end.` — a failure
  asserting a measurement that does not exist. The same line disabled the clipping check without
  saying so: a missing `max_volume:` reads as "not at or above full scale".
- **Two detector lists were zipped by index.** A `black_end` with no `black_start` shifted every
  later pair, and the mismatched tail fell off the end of the shorter list. A quality check that
  reports *fewer* defects than it found is the worst failure available to it.
- **The whole ffmpeg log was searched for detector text.** The log also carries the file's name and
  its metadata tags. A title reading `black_start:0.0` put a black span into a delivery report.
- **The scratch was removed on the way past**, so any refusal left `qc-probe.json`, `qc-ymin.txt` and
  `qc-ymax.txt` in the caller's directory — which for the operator script is the directory the film
  is in — and the next run read them.
- **`Math.min(...values)`** spread a per-frame statistic through a call stack: a million-frame film
  is a `RangeError`, not a report.
- **`JSON.parse`** threw a `SyntaxError` out of the check rather than a `PictureQcError`.
- **`"Luma reaches "+lumaMin+"–"+lumaMax`** printed `null–253` when only one of the two per-frame
  statistics carried a value, which is reachable: they are separate files with separate line counts.

## What this increment does

- **`PictureQcMeasurement["sound"]` is nullable**, and the difference is the point: `sound === null`
  means no level reading was taken; a `null` decibel figure *inside* a reading is a measured `-inf`.
  A new **`sound-unmeasured` note** says the first out loud, so the gap appears in the report instead
  of being hidden by an empty findings list — the same shape as `levels-unmeasured`.
- **`soundLevels` refuses half a reading.** `volumedetect` prints both lines or neither; one line of
  the pair means the log is not the log this check thinks it is reading.
- **`spans` refuses a list it cannot pair**, rather than zipping and dropping the remainder.
- **`readDetectors` scopes the log** to each detector's own `[name @ ` lines, and is exported as one
  pure function so every refusal above can be shown in a test. A log that has lost a line is not
  something a test can ask ffmpeg for.
- **The scratch is removed in a `finally`**, on every path out including a refusal.
- `extreme` reduces instead of spreading; `readJson` fails as a `PictureQcError`; the levels finding
  names only the statistics that exist (`a maximum of 255`, not `null–255`).

Nothing here changes a pixel, a recipe or a frame hash: `PICTURE_QC_RECIPE` is untouched, so the
report HV-026-02 recorded against the delivered master still validates against this code.

## Acceptance criteria

1. **A soundtrack nobody metered is a note, not a failure.** `sound: null` produces exactly
   `sound-unmeasured` at severity `note` and a `pass` verdict; a measured `-inf` still produces
   `silent-programme` at severity `fail`.
2. **The clipping check is not disabled by a missing mean.** A measurement carrying both a quiet mean
   and a peak at full scale produces both `clipping` and `quiet-programme`.
3. **A film with no audio stream says so once**, by the stream, not twice.
4. **A retained report cannot swap a reading for none**: `validatePictureQcReport` refuses a report
   whose `sound` was replaced with `null`, and accepts one that was genuinely unmeasured.
5. **The log is read only where the detectors wrote it**: a log with metadata tags containing
   `black_start:`, `freeze_start:` and `mean_volume:` text measures identically to the same log
   without them.
6. **A pairing the log cannot make is refused by name**: an end with no start, a span that does not
   run forwards, and one volumedetect line without the other each throw a `PictureQcError`; a log
   with neither volumedetect line measures as unmeasured.
7. **A refused check leaves nothing beside the film**: after `measurePictureQc` rejects on a file
   that is not a film, the directory contains only that file.
8. **A finding names only the readings that were taken**: with one luma statistic missing, the
   message reads `a maximum of 255` and contains no `null`.

- Tests: `packages/generator/test/picture-qc.test.ts` (four new cases, 1–8 above), with
  `packages/generator/test/picture-qc-script.test.ts` and `test/picture-qc-check.test.ts` unchanged
  and still passing — the second of those re-derives the evidence report HV-026-02 recorded from the
  real master, which is what shows the contract did not move.

## Known gaps this leaves

- **`sound-unmeasured` is a note, and a note passes.** A film whose soundtrack could not be metered
  ships with a `pass` verdict and a line saying why. That is the same bargain `levels-unmeasured`
  makes, and it is a bargain: the alternative is a check that fails a deliverable because of its own
  log parsing. It is stated here so the choice is visible rather than discovered.
- **The half-reading refusal is a guess about `volumedetect`'s output** — both lines or neither —
  taken from its source and from every run seen here. If a build of ffmpeg prints only one, this
  check refuses a film it could have measured. Refusing loudly was chosen over reporting quietly.
- **Nothing here fixes the illegal luma range** HV-026-02 found in the delivered master. That is
  still a render-path change that has to meet the conform's bit-exact standard, and it still waits
  on a decision about where the conversion belongs.
- **The creator still cannot run the check**; it remains an operator script.
