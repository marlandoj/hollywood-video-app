# HV-030-22 — Release 2's exit criteria, and the run that will prove them

epic: HV-030
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

Release 1 closed with a run. Two films went through the front door, the run was recorded in
`docs/evidence/release-1/release-run.json`, and `test/release-1-run.test.ts` held that record to the
roadmap's exit criteria. Kevin acknowledged it against that record (G14-202609210000).

Release 2 has a table of slices and no exit criteria, so nothing says when it is done. Its run can't
copy Release 1's either:

- **Most of Release 2 lives behind the Director's desk.** That covers locks, the cast library,
  continuity repair, deliveries, sound, import and line notes. Release 1's record says
  `directorsDesk: false`, and a Release 2 record that said the same would be untrue.
- **`scripts/studio-run.ts` only pitches.** It can't keep a style card, attach one, or share the film.
- **Nothing drives the desk's routes**, and nothing reads back what a reviewer did.

This increment writes the criteria, builds the tooling, and builds the test that will hold the run to
the criteria. It runs nothing on staging and spends nothing. The run itself is HV-030-23.

## What this increment does

- **The criteria** are in `docs/ROADMAP.md` under "Release 2 exit criteria (proposed; agreed at G6)":
  1. Two films by the same creator, the second pitched with the first's style card.
  2. Each film reviewed on a second device, with a timecoded comment and a decision naming its stage.
  3. Every Release 2 slice exercised with real ids, or deferred to a gate entry that exists in
     `docs/loop/HUMAN-GATES.md`.
  4. Within the declared spend, and within each line's own limit.
  5. Signed C2PA sidecars that verify when the host holds the key.
  6. Every step tagged with the surface it used.
  7. The operator's acknowledgement.

  Two tables make criteria 3 and 4 checkable. One splits each slice into 21 parts, each with its
  surface. The other lists the four spend lines: generation $450, voice $25, music $10, crew $25.
- **`scripts/studio-run.ts`** gains three flags, each a step a creator takes at the front door:
  - `--keep-style-card <file>` keeps the card the studio offers for download, as soon as the crew has
    planned. The file is mode 600, and the report names the card by its SHA-256.
  - `--style-card <file>` attaches a kept card to the pitch, and the report says whether the crew read
    it. A file that isn't a card stops the run before a project exists.
  - `--share N` makes a review link for N viewers through the studio's own share step. The link goes
    only to a mode-600 file (`--review-out`, or `.review` beside `--out`). The report holds the link's
    digest, read back from the owner's review list.
- **`scripts/release-2-run.ts`** drives everything after the front door through the desk's routes.
  Every step is optional:
  - **Script import:** FDX and PDF import, read back but never saved.
  - **Line notes:** asks the crew for notes, and accepts the first one.
  - **A locked look:** locks a character's look, then shares that actor and imports it into film B.
  - **Continuity:** reviews the Supervisor's repair, and applies exactly the edits it showed.
  - **Deliveries:** grade, open captions, SDH, both reframes and the mezzanine, waited for.
  - **Ambience and a music cue:** if either route answers 404 (before #340 and #335 deploy), the
    step is recorded as `unavailable`, not as a failure.
  - **Provenance:** each shared export's record, and its sidecar's bytes compared with the digest the
    record names.
  - **Reviews:** the reviewer's comments and decisions, read back.
  - **Ledgers:** before and after, per film (`/spend`) and from the operator's view
    (`/api/operator/status`, given a diagnostics credential).

  Each step records its surface, outcome and ids, and fills the parts it proves with its own ids.
  `--defer part=GATE-ID` defers a part nothing exercised. `--evidence part=path` names the file that
  proves an operator or audit part. `--merge` re-reads an earlier record, so the review read-back can
  run again after Kevin has reviewed. The record is schema `hv-release-run/2`.
- **Secrets stay out of the record.** The driver reads the project tokens, the actor share token and
  the operator's credential, because they are the only keys to what it drives. None of them, and no
  signed media link, is ever written or printed. An error about an artifact names the kind of link,
  never the link itself.
- **`test/release-2-run.test.ts`** reads the criteria and both tables from the roadmap, and the gate
  entries from HUMAN-GATES.md, and holds a record to them (`test/release-2-contract.ts`). No real run
  exists yet, so the contract is proved on a synthetic fixture in `test/fixtures/release-2-run/`. The
  fixture says it is synthetic, its year is 2099, and its one deferral gate exists only in
  `gates.fixture.md` beside it. Each criterion is shown to bite by breaking the fixture in exactly
  that way. Once `docs/evidence/release-2/release-run.json` exists, the same check runs on it against
  the real gates alone. Until then that test is skipped, and says why.

## Acceptance criteria

1. **The criteria cover the release.** The roadmap's parts table names a part for each of the
   eleven epics in the Release 2 table. The driver's parts and spend lines are the roadmap's, exactly.
2. **The contract holds a record to every criterion.** The synthetic fixture meets them all, lives
   outside `docs/evidence/`, and can't stand as evidence. Each of the following fails, in its own
   words:
   - film B without film A's card;
   - a film with no comment, or a decision with no stage;
   - a part left unsaid, or deferred to an entry that doesn't exist;
   - a part with ids no step reported;
   - a line over its limit, or a run over its declared spend;
   - a host with a key whose sidecar doesn't match or wasn't verified;
   - a record that uses the desk and says it was never opened;
   - a record carrying a token or a signed link.
3. **The real record is held to the same check once it exists**, and is skipped with a reason until
   then.
4. **`studio-run.ts` at the front door:**
   - Film A's style card is kept to a mode-600 file once the crew has planned, named in the report
     by its SHA-256.
   - Film B is pitched with that card, and its report says the crew read it.
   - A file that isn't a card stops the run before a project is made.
   - `--share N` makes the link for N viewers on the final. The link is written only to a mode-600
     file, and never to the report or the terminal; the report holds its digest.
   - `--share` is refused without the final or without a number.
5. **`release-2-run.ts` behind the front door**, against a fake studio:
   - Each step names its surface, and each exercised part carries only its own ids.
   - The continuity repair is applied with exactly the edits and versions it was shown. A refusal
     stops only that step.
   - Deliverables are made from the first retained cut, waited for, and sorted into the grade,
     reframe, caption and mezzanine parts.
   - Ambience and music record `unavailable` when their routes are missing, and are exercised when
     they answer. A deferral never overwrites a part the run exercised.
   - Line notes from the stand-in crew are `unavailable`, not exercised.
   - The ledgers are snapshotted before and after.
   - No project token, share token, operator credential or signed link reaches the record.
6. Reverting `scripts/studio-run.ts` fails the five studio-run tests in
   `test/release-2-driver.test.ts`, and reverting `docs/ROADMAP.md` fails
   `test/release-2-run.test.ts`.

- Tests: `test/release-2-run.test.ts`, `test/release-2-driver.test.ts` (30 tests with
  `test/release-1-run.test.ts`: 29 pass, 1 skipped until the run exists).

## The plan for HV-030-23: the run

`spend_usd: 2`. The providers are ElevenLabs voice and ElevenLabs Music, both on the operator's
existing account (G14, G15). Picture stays on the staging host's `mock` profile, as it has been since
Release 1. A live picture profile would add $5 to $15 and must be declared before the run.

- **Voice costs a few cents and can't be avoided.** Staging casts and voices with ElevenLabs, inside
  its $25 line.
- **Music is at most $1.50.** That is one or two cues of up to five minutes at $0.15 a minute, after
  #335. Without #335 deployed, the music step records `unavailable`.

**Before the run**

1. #339, #332, #335, #336 and #340 are merged and deployed.
2. The host's C2PA certificate is wired (below), and `HV_MUSIC_PROVIDER=elevenlabs` is set.
3. Two new original scripts are committed in `docs/evidence/release-2/scripts/`: film A, a reel, and
   film B, a short. A Final Draft and a PDF copy of one of them are committed for the import step.
4. Each line's "before" is read from the staging database, read-only:
   - generation: the cost ledger;
   - voice: ElevenLabs' line;
   - music: the music line;
   - crew: the crew ledger.

   Release 1 did the same. The owner and operator routes can't tell voice from music, because both
   are booked to `elevenlabs`.

**The run**

5. Film A:

       bun scripts/studio-run.ts --script <a> --format reel --keep-style-card a.card.json --share 3 --out a.json

6. Film B:

       bun scripts/studio-run.ts --script <b> --format short --style-card a.card.json --share 3 --out b.json

7. The desk steps, with `--deliveries grade,open-captions,sdh,reframe-9:16,reframe-1:1,mezzanine`:

       bun scripts/release-2-run.ts --film-a a.token --studio-a a.json --film-b b.token --studio-b b.json
         --lock-look --share-actor --continuity --continuity-apply --deliveries ... --ambience
         --music "<prompt>" --import-fdx ... --import-pdf ... --line-notes "<request>" --accept-notes
         --provenance --operator-token <file> --out run.json

**After the run**

8. Kevin reviews both films on his phone (G6, below).
9. Read back his comments and decisions:

       bun scripts/release-2-run.ts ... --merge run.json --reviews --provenance

10. On the host, the operator:
    - runs `scripts/verify-c2pa.ts` on each shared export, and its one-line report goes in that
      export's `verification`;
    - runs `scripts/report-expiry-takedowns.ts`, committing its output under `docs/evidence/release-2/`
      and naming it with `--evidence HV-031.expiry-takedown=...`. `HV-039.wcag` names
      `docs/ACCESSIBILITY-AUDIT.md`.
11. Each line's "after" is read the same way as "before". The record is written to
    `docs/evidence/release-2/release-run.json`. `test/release-2-run.test.ts` passes on it locally
    before anything is pushed.

Project tokens live 72 hours, so steps 5 to 11 happen inside that window. The `.token` and
`.review` files never enter the repository or the chat.

## Known gaps this leaves

- **The driver doesn't fill the lines' before and after.** It snapshots each film's `/spend` and
  the operator's whole-studio view. It also adds up the crew's and music's spend from their own
  replies. The per-line totals come from the database at record time (step 4 of the plan), and the
  contract refuses a record without them.
- **The operator's view is a rolling 30-day window**, not a calendar month. A run that spans a
  window's edge reads the edge.
- **The signature is verified on the host, not by the driver.** The driver checks that the sidecar's
  bytes are the ones the record names. `verify-c2pa.ts` needs the export's files, which only the
  host holds.
- **Moderation and SFX have no route yet**, so their parts can only be deferred until they are built.
- **Two parts are proved by files.** `HV-031.expiry-takedown` is proved by the operator's report and
  `HV-039.wcag` by the audit. No run can make a project expire, or prove WCAG.
- **"The same creator" is shown by the style card alone.** The studio is anonymous (ADR-0018), so
  the only evidence is the card's digest carried from film A to film B, and the crew saying it read
  it.
- **`--merge` reads the front door back again**, and replaces those steps rather than repeating them.
