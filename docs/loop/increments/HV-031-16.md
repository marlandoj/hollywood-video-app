# HV-031-16 — Main's sound safety test asserted the gate's old blind spot

epic: HV-031
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

HV-031-13 (#326) and HV-031-14 (#329) were each green on their own heads and merged within minutes
of each other. HV-031-13's test `packages/planner/test/sound-assets-safety.test.ts` opened with a
precondition that the shared gate let "Theme from Harry\nPotter" through, to show why the sound gate
collapses whitespace itself. HV-031-14 closed that blind spot in the gate, so on main the
precondition fails and so does the quality job for every head built on main.

## What this increment does

- Changes the precondition to what is now true: `checkPrompt` refuses the split name too.
- Leaves every assertion about the sound gate itself unchanged: the split name is refused in each
  field, and the three two-field pairs are refused only together, with "taken together".

## Acceptance criteria

1. `bun test packages/planner/test/sound-assets-safety.test.ts` passes on main.
2. The sound gate's own refusals are asserted exactly as before.
3. Reverting this change fails "a name split across a line break in one field, or across two
   fields, is refused like the name written whole" on main.

- Tests: `packages/planner/test/sound-assets-safety.test.ts`, `packages/api/test/sound-assets-safety.test.ts`, `packages/safety`.

## Known gaps

- Two increments green on their own heads can still conflict once both are on main. CI runs each
  PR against the base at the time it was pushed; nothing re-runs an open PR when main moves.
