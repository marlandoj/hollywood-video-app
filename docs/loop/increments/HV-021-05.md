# HV-021-05 — A contradiction the repair will not resolve was named only when there was nothing else to say

epic: HV-021
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

HV-021-04 closed this on one branch, in its own words:

> "Nothing in this film's declared look contradicts itself" was said whenever there were no edits —
> including for a film whose only defect is a scene directed against its own heading. The report held
> a warning and the headline said there was none.

It computed the contradictions at the top of `continuityRepairSummary` and then consulted them
**inside the empty-edits branch only**:

```ts
const contradictions=proposal.refused.filter(code=>CONTINUITY_REPAIR_CONTRADICTIONS.includes(code));
if(!proposal.edits.length)
  return contradictions.length ? "Nothing here can be repaired automatically: …" : "Nothing in this film's declared look contradicts itself.";
const shots=…,fields=…;
return "Hold "+[...fields].join(", ")+" across "+shots.size+" shots, matching the first shot that states each.";
```

So a film with a repairable drift in one scene and a scene directed against its own heading in
another got one sentence about the drift and nothing at all about the contradiction. The note was in
the payload; the one line a creator reads before accepting said nothing.

That is the worse half of the same defect. A creator who accepts an empty proposal has applied
nothing and may go looking. A creator who accepts **this** one has applied the repair and has every
reason to believe the continuity pass is done.

Nothing caught it because the three cases in `continuity-repair.test.ts` are
empty-edits-with-contradiction, empty-edits-without, and edits-without. The case with both was the
one nobody wrote.

## What this increment does

- **The contradiction is said whether or not there is a repair beside it.** The repair sentence keeps
  its wording exactly; a second sentence follows it when something is left that this pass will not
  resolve.
- **The list and the instruction are written once** and used by both branches, so the two sentences
  cannot come to name the contradictions differently — which is how this one came apart.
- **An unknown is still not a contradiction.** A wardrobe nobody stated or a character with no
  reference image is a note, not a declared look fighting itself, and the headline stays one sentence
  for a film whose drift is the whole of its trouble. A headline ending "Read the notes." every time
  would be one to stop reading.

## Acceptance criteria

1. **A film with something to repair and something that cannot be says both**: the repair sentence
   unchanged, then the contradiction named, then "Read the notes."
2. **Every contradiction the pass will not resolve is named wherever it is said** — whatever the
   empty proposal says about them, the proposal with edits says too, and both end the same way.
3. **A repair with nothing standing against it is still one sentence**, with notes beside it.
4. Reverting `continuity-repair.ts` fails criteria 1 and 2.

- Tests: `packages/planner/test/continuity-repair-contradiction.test.ts`. Verified: two of its three
  fail on the unchanged source, and the existing `continuity-repair.test.ts` is untouched and passes,
  because none of its cases has both.

## Known gaps this leaves

- **The codes are still the words.** `time-contradicts-heading` is a machine name shown to a creator;
  the note beside it is written in English and the headline is not. That was true of HV-021-04's
  sentence too, and naming them properly is a table this file does not have.
- **`CONTINUITY_REPAIR_CONTRADICTIONS` has one member.** Every other refusal is treated as an unknown
  rather than a contradiction, and nothing checks that a new refusal code is deliberately put in one
  camp or the other — a new one silently becomes an unknown.
- **The headline still does not say how many scenes are involved in the contradiction**, only that
  there is one. The notes do.
- **Nothing tests what the studio does with this sentence**, only what the function returns. The
  front door has no continuity step yet; `claude/HV-021-03-plan.md` is where that is waiting on a
  decision.
