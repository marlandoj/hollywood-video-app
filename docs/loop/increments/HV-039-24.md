# HV-039-24 — The preview pictures and the sound timeline's cues had names no screen reader was given

epic: HV-039
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

Found by the HV-039 accessibility audit (`docs/ACCESSIBILITY-AUDIT.md`, 1.1.1, Sound and Editorial).

Three graphics had their text alternative written as `aria-label` on an element with no role:

    canvas.setAttribute('aria-label','Preview of the '+savedName);                   // preview-controller.js
    canvas.setAttribute('aria-label','Version '+(index?'B':'A')+' picture');          // preview-comparison.js
    const bar=node("span",c.asset.label);...;bar.setAttribute("aria-label",bar.title); // sound-studio.js

A `canvas` or a `span` has no role a name can attach to. ARIA 1.2 prohibits naming `generic`, and
browsers leave the name out of the accessibility tree. Take a creator using a screen reader in
picture editorial. The preview and both sides of a rendered-version comparison are unnamed blank
areas. In the sound session, each cue on the timeline reads as its asset's label, "Rain". Its role,
start, end and level ("Rain · ambience · 1.000–4.500 s · -12 dB") reach only a mouse user who
hovers for the `title`.

## What this increment does

- **The preview canvas and both comparison canvases are `role="img"`**, so "Preview of the saved
  cut", "Preview of the saved assembly", "Version A picture" and "Version B picture" are exposed.
- **Each sound cue bar is `role="img"`**, named by the same description its `title` shows, so
  hovering and listening give the same words.
- **A guard over every module** refuses a variable made only as a `span`, `div`, `canvas` or similar
  that gets `aria-label` and no role. It found a fourth instance, the cast desk's "Project cast"
  `div` (`casting.js`). That `div` is now `role="group"`.
- `mask-viewport-a11y.test.js` reviews every file that sets a static role. The three files that now
  use `role="img"` join its list. None of them is focusable or handles keys.

## Acceptance criteria

1. **The editorial preview.** Mounted as picture editorial mounts it, for a cut and for an assembly,
   the preview canvas is `role="img"` named "Preview of the saved cut" or "Preview of the saved
   assembly". Nothing the panel names sits on an element that cannot take the name.
2. **The comparison.** Mounted for two rendered versions, the canvases are `role="img"`, named
   "Version A picture" and "Version B picture".
3. **The family.** No module gives `aria-label` to a variable made only as a generic element without
   a role. The scan catches a named `span` and a named `canvas`, and passes a canvas with a role and
   a name reused for a `video`.
4. **The sound cue.** The bar takes `role="img"` and the description its `title` shows.
5. **The one left is known.** The only unnamed `aria-label` left in `index.html` is the storyboard
   `div`.
6. Reverting `preview-controller.js`, `preview-comparison.js`, `sound-studio.js` and `casting.js`
   fails criteria 1, 2, 3 and 4.

- Tests: `packages/frontend/test/labelled-graphics.test.js`. It mounts the real preview and
  comparison panels on the `audio-studio-dom.js` DOM, with a 2D-context stub, and scans the modules'
  source for the family. `packages/frontend/test/mask-viewport-a11y.test.js` has its reviewed list
  updated.

## Known gaps this leaves

- **The sound cue is checked from source, not mounted.** The timeline is drawn only once a retained
  session has a quote and cues, and no DOM test builds one yet. Criterion 4 pins the line that makes
  the bar.
- **`<div id="storyboard" aria-label="Storyboard by scene">` in `index.html` is unchanged.** Other
  work is editing that page now. Each scene's `summary` still conveys the grouping. Criterion 5
  fails when it is fixed, so the note goes with it.
- **A name is not a description of the picture.** "Version A picture" says what the canvas is, not
  what is in the frame. The frame's timecode is in the live output beside it. Describing the frame
  itself would need the shot's text, which the preview does not have.
