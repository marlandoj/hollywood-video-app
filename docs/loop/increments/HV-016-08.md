# HV-016-08 — A screenplay read out of a PDF's text layer

epic: HV-016
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

This one is not a defect. Release 2's HV-016 slice is **"FDX and PDF import; the crew suggests
script revisions the writer accepts line by line."** FDX is built — HV-016-01 through 07. PDF is the
other half, and `docs/SCRIPT-IMPORT.md` said of it:

> PDF import is not built. FULL-SCOPE scopes it as "OCR + structure recovery", which is a different
> problem from reading a structured file and needs its own work.

Half of that is still true and stays true: OCR is a different problem and would mean a vendor, which
this program does not add. The other half is not. A screenplay PDF exported by Final Draft,
Highland, Fade In or Writer Duet carries a **text layer**, and a screenplay's element types are
carried by its left margins — action at 1.5in, dialogue at 2.5in, a parenthetical at 3.0in, a
character cue at 3.5in, a transition at 6.0in. That is what screenplay format *is*; it is the only
thing a `.fdx` says that a printed page does not.

So this reads the text layer and recovers the structure from the margins. A file it cannot read that
way is refused, by name — above all a scan, which has no text layer at all and which importing as an
empty screenplay would be exactly the silent drop this package forbids.

## What this increment does

`packages/parser/src/pdf.ts`, written by hand with **no PDF dependency**, the way `final-draft.ts`
was written with no XML one. The rule is the same and is the reason both are readable: every search
is a linear `indexOf` or a single forward pass, so the bound on the input is also a bound on the
work.

- **The objects are found by scanning, not through the cross-reference table.** A PDF that has been
  edited, linearised or appended to has several cross-reference sections, and a reader that trusts
  the wrong one silently reads an older version of the page. Scanning takes the last definition of
  each object number, which is what an incremental update means.
- **Content streams are read raw or through `FlateDecode`** (`node:zlib`), and any other filter is
  refused by the name the file gives it.
- **The text operators are read in one forward pass** — `Td`, `TD`, `Tm`, `TL`, `T*` for position,
  `Tj`, `TJ`, `'` and `"` for the text, with literal and hexadecimal strings, nested parentheses and
  octal escapes.
- **Runs are grouped onto baselines** and ordered down the page and then across it, because two runs
  of one line may be drawn in either order and half a point apart. The gap between them decides
  whether the producer meant a space.
- **The margins are offsets from the page's own leftmost text**, so a different paper size or a
  wider binding margin reads the same screenplay.
- **The route takes `format: "pdf"` with the file base64** in the same JSON body, under the same
  limits, and shows the result back without saving it — exactly as the Final Draft import does.

Refused by name, each because the alternative is silently wrong:

| What | Why not guess |
|---|---|
| Not a PDF, or no readable objects | Nothing to read |
| Encrypted | The text layer is not there to read |
| A filter other than `FlateDecode` | A wrong guess is bytes read as text |
| `/ToUnicode`, `/Differences`, or a `/Type0` font | The stored bytes are not the letters shown — a subset font commonly numbers its glyphs from 1. Reading them anyway produces text shaped like a screenplay that says nothing, which is worse than a refusal |
| No text layer | It is a scan. Said plainly, with what to do about it |
| Lines that do not sit on screenplay margins | It is not a screenplay; the refusal counts how many |

## Acceptance criteria

1. **A screenplay PDF becomes the screenplay the studio reads** — two scenes, their headings,
   action, cues, speeches and transition, nothing unparseable — and compressed and uncompressed give
   the same screenplay.
2. **The margins are read from the page's own leftmost text**: the same screenplay comes back when
   the whole layout is shifted right by 0.4in and 1.1in.
3. **What could not be carried across is reported, never quietly dropped** — parentheticals (for the
   reason the Final Draft importer drops them: one left in a speech is spoken by the voice vendor
   and burned into the caption), styling, and page furniture — and only what the file actually
   contained is reported.
4. **Every page is read, in page order**, and each run comes back with its page.
5. **A cue is written as a cue only when something is said under it**: a cue and its speech with no
   blank line between them, a capitalised line with nothing under it as its own block.
6. **A file this importer cannot read is refused by name** — all ten refusals above, including "no
   text layer" for a scan and a count of the lines that missed the margins.
7. **Runs on one baseline are one line, in reading order**, with the gap deciding the space; and the
   whole document is one pass (eight times the screenplay, at most twenty-four times the work).
8. **The route is the owner's, shows the result back, and saves nothing**: the writer's own save is
   still version 1, and a document that is not base64 is refused before the importer sees it.

  PDF written by hand so a test states the layout it is asserting about rather than proving this
  importer reads one word processor), and `packages/api/test/script-import-route.test.ts`.

## Known gaps this leaves

- **No OCR.** A scanned script is refused with an explanation, not read. That needs a vendor and is
  not this program's to add.
- **The pages are taken in object-number order, not by walking `/Kids`.** Every producer this
  importer has been shown numbers its pages in order; one that does not would import its scenes out
  of order, and the margin check would not catch it because each page is still laid out correctly.
  Walking the page tree is the exact answer and is its own increment.
- **Only `FlateDecode`, and only where the `/Filter` is a single name.** A filter *array*
  (`[/FlateDecode /ASCII85Decode]`) is refused by its printed form rather than read, which is the
  safe direction but is a real file this cannot open.
- **Object streams (`/ObjStm`) are not read.** A PDF 1.5 file that packs its page dictionaries into
  a compressed object stream has no `/Type /Page` for the scan to find and is refused with "no pages
  this importer can read", which is true but is not the whole story.
- **Dual dialogue is not detected.** Two speeches side by side sit on two different margins that are
  neither the cue nor the dialogue margin, so a dual-dialogue page most likely fails the margin
  check and is refused as "not laid out as a screenplay" — which is at least not silent, but it is
  not the note the Final Draft importer gives for the same construct.
- **A line's own wrapping is the writer's.** A speech wrapped over three lines in the PDF becomes
  three lines of Fountain rather than one paragraph, because rejoining them would mean deciding
  where a sentence ends.
- **The Courier advance is a constant.** 7.2 points is twelve-point Courier, which is what a
  screenplay is set in; it is used only to decide whether two runs on one baseline had a space
  between them, and a screenplay set in something else would get that wrong in one direction or the
  other.
