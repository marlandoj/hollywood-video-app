# HV-039-25 — Every Resolve and Reopen button in the review list had the same name

epic: HV-039
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

Found by the HV-039 accessibility audit (`docs/ACCESSIBILITY-AUDIT.md`, 2.4.6, Review). It was the
last F cell in the audit.

The owner's export lists every review comment as a row: a timecode button, the comment, and a
button that resolves or reopens it.

    const label = () => {toggle.textContent = resolved ? "Reopen" : "Resolve"; ...};   // review-notes.js

Take an owner using a screen reader whose cut has twelve comments. The screen reader's list of
buttons gives twelve "Resolve" buttons, and nothing in any of them says which comment it resolves.
The timecode button beside it is named "Play from 00:00:02:09". That one is unique until two
reviewers pin a comment to the same frame, and then it repeats too.

The audit also noted `<div id="storyboard" aria-label="Storyboard by scene">` in `index.html`. A
`div` has no role a name can attach to, so the name was dropped. HV-039-24 left it because other
work was editing that page.

## What this increment does

- **Each row's buttons are named by the comment's number and timecode.** "Resolve comment 3 at
  00:00:02:09", "Reopen comment 3 at 00:00:02:09", "00:00:02:09, play comment 3". A comment on
  another cut: "00:00:01:15, comment 4, on another cut". The words on the buttons do not change.
- **The number is the one on screen.** The comments are an `ol` with no `start` or `reversed`, and
  no style rule sets its `list-style`, so each row shows its number beside it, counting from 1. This is HV-039-23's choice for credit rows ("Remove credit N"): a short number the
  user can see, not an excerpt of the comment. A reviewer's comment is up to 500 characters, and
  any cut of it would be read again on every button. The comment is read with the row anyway.
- **Each name starts with the button's words** (WCAG 2.5.3 Label in Name). "Resolve" or "Reopen"
  starts the toggle's name and the timecode starts the play button's, so a speech user saying
  "Resolve" or the timecode still reaches the button.
- **When a comment is resolved, its button is renamed** with the same number and timecode.
- **The storyboard is `role="group"`**, as HV-039-24 made the cast desk's "Project cast", so
  "Storyboard by scene" is exposed. Not `region`: the animatic section around it is already a named
  region, and a second landmark inside it would only add noise.
- **The page guard reads all of `index.html`.** HV-039-24's check matched only static `span`, `div`,
  `p` and `canvas` tags, so an element made and named in the page's own module script was checked by
  nothing. It now runs the module scan over each inline `<script>`, takes its tag list from the
  same `UNNAMEABLE` list (so `label` and `small` count), and no longer takes `data-role` for a role.
- `docs/ACCESSIBILITY-AUDIT.md`: the matrix now has HV-039-21, -24 and -25 applied, and counts
  **P 202 · F 0 · N 11 · – 12**. The Review 2.4.6 cell is P, the cells -21 and -24 changed are
  marked as merged, and the storyboard note says it is fixed.

## Acceptance criteria

1. **Every button has its own name.** With four comments, two of them on one frame of the shown cut
   and one resolved on another cut, the eight buttons in the owner's list have eight different
   names, each starting with the button's words, numbered as the list shows them. The list is a
   plain `ol`, and no style rule in the page sets a `list-style` on it.
2. **Resolving renames the button.** After Resolve on comment 2, its button is "Reopen comment 2 at
   00:00:03:00", and the list's names are still all different.
3. **A comment on another cut says which.** Its timecode button is named "00:00:00:12, comment 3,
   on another cut".
4. **The storyboard is a named group.** `index.html` has no element from the generic list with
   `aria-label` and no role, in its markup or its inline script, and the storyboard is
   `role="group"` named "Storyboard by scene". The guard catches an element planted in the inline
   script, a named `label` or `small`, and a `data-role` posing as a role.
5. Reverting `review-notes.js` and `index.html` fails criteria 1, 2, 3 and 4.

- Tests: `packages/frontend/test/review-comments.test.js` (three new cases, and the off-cut name
  updated), which runs `index.html`'s own script through `desk-page.js` with the real
  `review-notes.js`, plus a check of the page's list styles. `packages/frontend/test/labelled-graphics.test.js`,
  whose "one remaining unnamed label" case is now a guard over `index.html`'s markup and inline
  script, with a case showing it bites on planted strings.

## Known gaps this leaves

- **What a screen reader announces is not checked.** The names are set; whether NVDA, JAWS and
  VoiceOver read the number and timecode as written needs a person with a screen reader.
- **The number belongs to this rendering.** Refresh reviews renumbers the rows when a comment
  arrives, so "comment 3" can be another comment after a refresh. The timecode in the name stays
  with its comment.
- **The button does not say who wrote the comment.** Two comments on one frame differ only by
  number. The viewer and the words are in the row, read before the button.
- **The 11 N cells stay open.** 1.4.11 for the motion tracks and the mask outline, and 2.4.3 for
  focus after an action in nine panels, need a browser.
