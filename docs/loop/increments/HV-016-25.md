# HV-016-25 — Owned copies of a mixed film's originals, and where provider bytes may land

epic: HV-016
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

PR #83 ("Run mixed films with owned proof and atomic recovery") is being rebuilt on main as small
HV-016 increments. HV-016-23 and HV-016-24 brought over the planner: what a mixed (V3) film
keeps, how it is checked, and what it must carry as proof. None of that touches a byte.

A mixed film keeps takes from earlier films. Before it can use them, the worker has to copy every
original it depends on into the new job's own namespace. The copy must be exact, resumable after a
crash, bounded by the job's disk budget, and stopped as soon as the owner's rights are withdrawn.
The same budget has to hold while fresh provider output is written. This increment ports those
generator helpers. Admission still refuses V3, so nothing on main calls them yet.

## What this increment does

Ported from PR #83 (`packages/generator/src/`):

- **`current-film-access.ts`:** one access check shared between callers while it is running. A result
  is never cached, so the next check always reads fresh authority.
- **`current-film-workspace.ts`:** a whole-job workspace guard. It counts generated attempts,
  delivery files, crash remnants and empty directories, and it refuses linked owner components.
- **`current-film-provider-output.ts`:** each provider invocation writes into its own directory. A late
  aborted writer cannot overwrite a replacement, costs and `LeaseError` pass through unchanged, and
  the job's budget still applies.
- **`current-film-copy-publication.ts`:** idempotent, fixed-byte preparation of copy files. It survives
  process death mid-stream, is safe when attempts overlap, and never replaces or deletes a published
  role.
- **`current-film-origins-media.ts`:** copies and independently verifies a mixed film's whole
  kept-originals inventory from an authenticated carrier.
- **`current-film-proof-copy.ts`:** proof copies through the same publication path.
- **`current-film-adoption-media.ts`** now publishes through `current-film-copy-publication`.
- **`ContinuityClip`** (`index.ts`): the continuity checks need only a clip's fingerprint, so a kept
  take with no inference cost can be scored.
- **`packages/queue/src/current-film-media.ts`:** verification accepts a recorded clip without a cost
  (`CurrentFilmRecordedClip`), and the generic speech and frame checks are exported.

Redone on main:

- **`edit-source-media.ts`:** the PR splits `verifyOriginal` into the checksum pass and
  `verifyOriginalSemantics`, and exports both with `measuredFacts` for proof verification. HV-031-09
  since moved main's provenance checks to `provenanceMatches` and `provenanceShotRecords`. The split
  is applied to main's version and keeps those checks.
- **`current-film-origins-media.ts` uses the same helpers.** The PR hard-coded the spec string and the
  credential claim. It now calls `provenanceMatches` and `provenanceShotRecords`, and main's
  single-source census (`packages/planner/test/provenance.test.ts`) lists it as a reader.

## Acceptance criteria

1. **Shared access.** Checks that overlap share one run, and the next check sees revoked authority. A
   failed or synchronously throwing check rejects every caller and leaves no pending state behind.
2. **Workspace guard.** Whole-job checks count generated attempts, delivery files, stale files, crash
   remnants and empty directories. Linked components fail, and a tighter internal budget cannot
   enlarge the job's limits.
3. **Provider output.** Each invocation owns its roles and keeps its real cost. A delayed aborted
   writer cannot overwrite a replacement. Hostile ownership, unsafe names, foreign or linked roles
   and accessors are refused without deleting bytes.
4. **Copy publication.** Copies keep the original hierarchy and replay immutably. Capacity is
   checked before any carrier is read. Complete and valid partial files are reused. Unknown,
   truncated, corrupt or linked entries are refused. Process death resumes to the exact bytes, and
   stale cleanup cannot delete a published role.
5. **Originals media.** A V2 source restores from the new owned tree alone, unselected inventory
   included. Abort and permission timers cancel a stalled carrier. A missing or corrupt original, or
   resealed manifest bytes, are refused. Linked directories and accessor-bearing plans cannot
   redirect access.
6. **Adoption media.** Selected roles and native PCM restore from target-owned bytes. Carriers that
   fail or lie cannot publish partial copies. A revoked source never leaves a completed target, and
   a directory junction cannot redirect output.
7. **Edit sources still verify.** The existing V2 and ordinary source-inspection tests pass through
   the split verifier. The provenance spec and claim are still written once, and every verifier,
   the originals verifier included, goes through `provenanceMatches`.
8. **V3 is still refused at admission.** The admission test from HV-016-24 still passes.
