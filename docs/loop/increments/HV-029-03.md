# HV-029-03 — the media path checked permission only for jobs shaped a certain way

epic: HV-029
spend_usd: 0

## Goal

Make `/artifacts/` ask one question — *what guards this job's media?* — answered by the job's stage, rather than six questions each answered only when the job happened to carry a particular optional field. Close the hole that left a plain cut's media ungated, and make the stages that are still ungated say so out loud.

## The defect

The artifact route verified the token signature, the project's existence, its `deleteAfter` and its takedown state. Then:

```ts
if(mediaJob?.output?.shotRenders?.some(r=>r.clip.speech)){…assertSelectedOutput…}
if(mediaJob?.lipSync){…}  if(mediaJob?.dialogueReplacement){…}
if(mediaJob?.soundMix){…} if(mediaJob?.pictureEdit){…}  if(mediaJob?.assemblyEdit){…}
```

Six blocks, each reached only when the job carried one particular optional field. **A plain `animatic` or `final` cut carries none of them** — unless one of its shots happens to have dialogue, which is what the first line tests. So the cut of a scene with no dialogue was served with no permission check at all.

**The speech condition is wrong on its own terms, not merely incomplete.** `assertSelectedOutput` reaches `assertDialoguePermissions`, which calls `assertCurrentCastPermission` for every shot's `characterIds`, and `charactersForScene` (`packages/planner/src/casting.ts:139`) matches a character named in a scene's **action** exactly as readily as one with a line:

```ts
const source = [scene.heading, ...scene.action, ...scene.dialogue.flatMap(…)].join("\n");
return snapshot.characters.filter(character => [character.name, ...character.aliases].some(name => mentioned(name, source)));
```

A revoked character standing silently in frame is that character's likeness, and permission is about the likeness. Gating on `clip.speech` asks whether they *said* anything.

**This is where HV-029-02's remaining bypass lived.** That increment closed the review path — an unbound review link skipped the permission gate — and recorded, without fixing, that redeeming the signed artifact URL the answer contained re-checked permission only for certain job shapes. This is that check. An artifact token's `exp` is clamped to `min(job.linkExpiresAt, project.deleteAfter, now + 30 days)`, so expiry and project deletion were enforced transitively even here; cast revocation was not enforced at all for a silent cut, on any path, for owner or reviewer alike.

**The existing coverage hid it.** `packages/api/test/performances.test.ts` asserts that after revoking a character the cut's `mp4Url` answers 404 — but its fixture's shots have dialogue, so it exercised precisely the branch the condition did reach.

## The shape of the repair

**One total function over `JobStage`.** `artifactPermission(stage)` returns the rule that guards that stage's media, and the route calls whatever comes back. Adding a stage without deciding what guards its media is now a type error and a test failure, rather than a silent hole — which is the actual defect, since nothing was ever *decided* about a plain cut; it simply did not match any of the six conditions.

**It is total at compile time and fails closed at run time.** A `never` binding after the switch makes a new `JobStage` member a type error, so a stage cannot be added without deciding what guards its media — the omission that caused this. And `stage` arrives from persisted JSON and is *cast*, not validated (`DurableJobStore.reload` does `JSON.parse(...) as Partial<Job>[]`), so a body carrying a stage this build does not know reaches the route: the fall-through denies rather than returning "no rule", because "no rule matched" read as "no check needed" is the original defect one level up.

**Every stage returns a rule; none returns "nothing to check".** Takes and character sheets are guarded, not deferred — see below. `motion-graphic` and `audio-take` are answered earlier in the route by their own rules (a graphic by `assertGraphicPermission` plus its retained bundle, an audio take by take permission plus the voice policy's revision), and their rule here *confirms the field those blocks key on is present*, so "another check ran" is verified rather than assumed: a `motion-graphic` job with no `graphicRender` used to skip both.

**Takes and character sheets get the same rule, derived differently.** `assertDialoguePermissions` was two things in one function: a project-level precondition plus `assertCurrentCastPermission` over `renderShots(job)`. The permission half is now `assertShotCastPermission(shots, job, project)` in `packages/planner/src/dialogue-jobs.ts`, and the three callers differ only in where the shots come from — `renderShots` for a film, `shotTakeShots` for a take group, and for a character sheet the sheet's own views through `assertSheetDispatch`, the rule the dispatch path already used.

**Two widenings the first draft introduced, and closed.** Gating on `mediaJob?.output` would have *loosened* the five shaped cases: the old blocks keyed on the job field and dereferenced `output!` non-null, so a lip-sync or edit job with clips on disk and no `output` answered 404 through a TypeError; skipping the block entirely would have answered 200. The gate now runs for any job that exists. And an artifact whose job is no longer in the store used to be served on the strength of the token alone; a signed token names a job, so a missing job is now a 404.

**Which file list an artifact must appear in still depends on the job's shape**, and that part stays keyed to the shape — it is a lookup, not a permission decision.

## What this increment does not do

- **The character-sheet rule has no behavioural case, and perturbation Y9 is green because of it.** Emptying that rule's body changes nothing any test can see: the sheet stage is covered by the totality assertion and by its precondition, not by a request. A sheet fixture is a different dispatch path from the film and take ones this suite builds, and rather than assert a weaker thing loudly, the gap is recorded here. The take rule *is* exercised (case 3), which is what makes Y4 bite.
- **It does not change how long an artifact token lives.** A token minted before a revocation is still a valid token; what changed is that redeeming it consults the permission. Nothing revokes tokens themselves, so the window between a revocation and a client's next request is served from whatever the client already holds.
- **It does not measure the cost of checking on every request.** `assertSelectedOutput` on a film stage parses the screenplay and re-derives the shot plan, and HLS playback fetches many segments. That cost was already paid on every lip-sync, sound, picture-edit and assembly-edit segment before this increment; it now extends to plain cuts and takes. No caching is introduced, because a cached permission verdict is how a bypass gets rebuilt — if this shows up in the operator panel's latency rows the answer is one shared derivation per request, not a memo of the answer.
- **It does not audit the routes that serve likeness outside `/artifacts/`.** Three are known and left: the owner's job view (`server.ts`, the `if((job.dialogueReplacement||job.lipSync||job.soundMix||job.pictureEdit||job.assemblyEdit)&&job.output)` block) still chooses by shape and still never checks a plain cut, so a revoked cut is *offered* a freshly minted URL that the artifact route then refuses; and the editorial preview-media and original-frame routes serve frames under owner-token auth with no cast check at all. Those are the same thesis — revocation should stop serving the likeness — on paths this increment did not touch.

## Acceptance criteria

1. A cut whose every shot is silent, and whose character is named only in the scenes' action, stops being served — `mp4` by GET, HEAD and range, the HLS playlist, a named segment, and the captions — the moment that character's permission is revoked; it was served before, and **serves the same bytes again when the permission is restored**, so the refusal is the permission and not anything else that went stale. — `packages/api/test/artifact-permission.test.ts` case 1; Y1, Y2, Y6, Y7.
2. The speaking cut still refuses, so the narrower condition was not the thing carrying it. — case 2; Y1, Y5.
3. A take group's clips are guarded by the take plan's own shots, and restored with the permission. — case 3; Y4.
4. Every stage has a rule, including one this build does not know, which denies; the switch is total by a `never` binding rather than a `default:`; the stage union is read from where it is declared; the route selects by stage, with no job-shaped field anywhere in the statement chain that reaches the call — including the assignment, which the first draft of this scan left outside its window — and no bytes are served before the gate. — case 4; Y3, Y5, Y6, Y7, Y8.

## The critic's findings

An adversarial read of the first draft found four green defects, one regression it had introduced, one widening, and one claim the code contradicted. Y3, Y4, Y6, Y7 and Y8 are the perturbations that came out of it.

1. **Y3 — the total function failed *open*.** The switch had no `default:` and TypeScript accepted it because the cases exhaust `JobStage` — but `stage` comes from persisted JSON and is cast, not validated, so a body carrying an unknown stage fell out of the switch with `undefined`, which the route read as "nothing to check". The first draft's own test asserted `not.toContain("default:")`, so the test that existed to make the switch honest was blocking the construct that made it safe. Now the fall-through denies, and a `never` binding keeps the compile-time force.
2. **Y8 — the shape scan looked at one `if` head.** It sliced back to the previous `;`, which left the `const mediaPermission = …;` assignment outside the window, so putting the shape test in the *assignment* was green. So was un-making the decision inside the rule the test verifies the existence of (`if (job.soundMix) return;`). Both are covered now: a 400-character window before the call, and the same scan over the rule's body.
3. **Y4 — takes were "declared unguarded", and that declaration was wrong twice.** The first draft claimed neither takes nor character sheets *could* be expressed with what exists, evidenced by routing a take through `assertDialoguePermissions` and getting "Reuse requires a film render with an admitted provider plan." That is a fact about `renderShots`, not about the codebase: `shotTakeShots` returns shots carrying `characterIds`, and `assertSheetDispatch` already ends in `assertCurrentCastPermission`. Worse, the draft was a **loosening** for takes: the old speech branch was stage-agnostic, so a take group whose shots had dialogue reached `assertSelectedOutput`, which refuses a non-film stage outright — every artifact of such a job was unserved before, and the draft would have served all of it. Both stages are guarded now, and case 3 exercises the take rule.
4. **Y7 and the `output` widening.** Gating on `mediaJob?.output` would have loosened the five shaped cases, because the old blocks dereferenced `output!` and answered 404 through a TypeError when it was absent. And an artifact whose job had left the store was served on the strength of the token alone — pre-existing, but this route now refuses it.
5. **Y6 — a one-variable kill switch was green.** `process.env` in the gate's statement chain is refused now.
6. **Case 1 proved less than it claimed.** It asserted a 404 after revocation but nothing tied that 404 *to* the revocation; HEAD and HLS segments were untested. It now restores the permission and asserts the same URL serves the same bytes again, and covers GET, HEAD, range, playlist, segment and captions.

The critic also confirmed that the gate sits before both the object-store and filesystem branches, that case 1's fixture is honest (the `characterIds` check uses the same derivation and the same `now` as the gate, ruling out an empty-loop false pass), and that removing the `assertLipSyncPlayback` call is a tightening rather than a loss, since `assertSelectedOutput` reaches it after adding the done/retained/expiry/deletion checks. One of its findings is recorded rather than fixed: the first draft's route slice ran to the end of the file, so `expect(route.match(/assertSelectedOutput/g)).toBeNull()` banned that call from every route below this one and would have taught the next author to alias the import. That assertion is gone; the gate is pinned by its exact text instead.
