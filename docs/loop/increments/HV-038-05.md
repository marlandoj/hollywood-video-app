# HV-038-05 — the committed observability exit evidence stopped matching the host

epic: HV-038
spend_usd: 0

## Goal

Re-record `docs/evidence/hv038-observability/observability-exit.json` from the host as it is, and make `docs/OBSERVABILITY.md` say what that run says. No code changes.

## Why now

Two things happened, and the second is the one that matters.

**The mechanical trigger.** G8-202609181530 re-collected `docs/evidence/hv040-storage/wave-a-exit.json` against the deployed release `39bfb24`. The observability exit document carries a `waveA` reference block derived from that file, and `packages/observability/test/observability-exit.test.ts` holds the two documents equal:

```ts
expect(document.waveA.releaseSha).toBe(waveA.release.status === "recorded" ? waveA.release.sha : null);
```

The wave A file moved to `39bfb24…`; the observability file still said `24d696a7…`. **`main` has been red since that push**, on every branch cut from it, and this increment is what makes it green. That is the ordinary consequence of re-collecting one of two documents that reference each other, and the test is right to fail: the pair is the claim, not either half.

**What the re-collection found.** The staging host restarted at 2026-09-18T18:26:38Z. `rough-cut-observability-metrics` did not come back:

```
level=ERROR source=main.go:1624 msg="Fatal error" err="opening storage failed: reloadBlocks:
  delete 1 blocks: replace of obsolete block for deletion 01M1TGYAFW9110AHDTQJS3QVD3:
  rename …/data/prometheus/01M1TGYAFW9110AHDTQJS3QVD3 …/01M1TGYAFW9110AHDTQJS3QVD3.tmp-for-deletion:
  invalid cross-device link"
```

The block was written on 6 September and is well past Prometheus's own two-day retention, so Prometheus is trying to delete it. The rename fails because the directory now sits in a lower overlay layer, even though `stat` reports the same device number for the block and its parent. It has been restarting on this every few seconds since the boot.

So the honest run records `telemetryRuntime: pending` ("observability service not running") and `metrics: pending` ("metric backend unavailable"), and therefore `metricsQueryable: false` and `instrumented: false`. Seven of nine blocks are `recorded`; the application stack itself is healthy and the release is the deployed one.

## What this increment does

- Commits the run recorded at **2026-09-18T18:54:33.456Z** against release **`39bfb248…`**, exactly as the collector wrote it.
- Rewrites the four places in `docs/OBSERVABILITY.md` that quoted the 2026-09-15 run, so the prose states two `pending` blocks, `instrumented: false`, the reason, and that **HV-038's exit claim is withdrawn** until the metric backend answers. The earlier run is described as what it was — a fact about one moment — rather than deleted from the narrative or held up as the truer reading.
- Raises **G9-202609181900**, because restarting Prometheus means letting it complete a deletion of retained data on staging, and that is an operator decision this loop does not take on its own. The gate also records a second finding from the same diagnosis: the three `rough-cut-observability-*` supervisor programs were rewritten by the host's own maintenance tooling to run through `service_identity.py`, so `scripts/observability-runtime.py`'s `merged_configuration` refuses to adopt them (`observability service belongs to another command`) and **every deploy since that rewrite has silently failed to restore the observability runtime**.

## What this increment does not do

- **It does not touch the staging host.** The collector is read-only by construction — its only child processes are `supervisorctl status|tail`, its only network calls are loopback `GET`s, and its database reads run in a read-only transaction. Nothing here restarts, enables or deletes anything.
- **It does not repair the divergence between the repository's startup path and the host's supervisor.** Which of the two gives is in G9.
- **It does not change the collector, the schema or any test.** The test that caught this is the one that was supposed to, and it needed no help.
- **It does not re-run the collector until the file reads better.** That is the property the evidence system exists for, and this is the first time it has cost something.

## Acceptance criteria

The committed exit document is the collector's own output for the run at 2026-09-18T18:54:33.456Z, validates against `hv-observability-exit/1`, recomputes `observabilityExit` from its sections, claims no percentage and no `99.9`, and its `waveA.releaseSha` equals the wave A document's release sha. — `packages/observability/test/observability-exit.test.ts`, the `(i)` cases, which fail on any of those.
2. Every figure `docs/OBSERVABILITY.md` quotes from the run is that run's own, and the document neither claims a recording it does not have nor describes the file as unrun. — the same suite's document case, which reads both and compares them.
