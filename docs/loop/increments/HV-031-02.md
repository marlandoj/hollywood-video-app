# HV-031-02 — Stop the provenance manifest claiming every export was assembled in 1970

epic: HV-031
spend_usd: 0

## Goal

Make the one field of FR-018's content credential that is a timestamp carry a real timestamp; make forgetting to supply one a type error rather than a placeholder; and collapse the three strings that identify a manifest into one declaration, since they were each written in five places across the producer and its readers.

## The defect

**Every export this program has ever produced ships `"assembledAt": "1970-01-01T00:00:00.000Z"`.** It was a string literal in the manifest constructor at `packages/assembler/src/index.ts:234` — not a parameter, not overwritten anywhere. `grep -n assembledAt` over `packages/` and `docs/` returned exactly two lines: the type declaration and that literal.

`docs/spec/build-spec.json:329` (FR-018) requires the content credential to carry a timestamp, and V-010's threshold is *"Every frame carries model, prompt hash, timestamp, and seed"*. So the single field of that requirement which is a timestamp was a constant, and a rights or legal enquiry asking when a contested export was assembled would be answered `1970` for every project in the system. This is the falsification-of-record shape the P14 rights clause forbids, and it is not a hypothetical: the manifest is the artefact a takedown or authorship dispute would be answered with.

**Nothing looked.** `packages/assembler/test/assembler.test.ts` asserted `credentials.type`, `projectId` and `shots.length`; `test/e2e-12shot.test.ts` asserted `shots.length` and that the claim contains `"AI-generated video"`. Neither read `assembledAt`.

**And the manifest's identity was written five times.** `spec: "hv-provenance/1.0"` and the claim `AI-generated video; content credentials sha256:<hash>` each appear once in the assembler and at four call sites across the three generator modules that verify a manifest before reusing footage — two by string concatenation (`edit-source-media.ts:55,64`), two as template literals (`sound-media.ts:30`, `dialogue-replacement.ts:160`). They agreed; nothing made them agree. A change to the claim in the producer would have made every retained export unreusable one flow at a time, each reporting a different failure.

## The shape of the repair

**One leaf module owns the record's identity.** `packages/planner/src/provenance.ts` holds `ProvenanceManifest` (moved from `planner/src/index.ts`, re-exported from there so existing importers are untouched), `PROVENANCE_SPEC`, `PROVENANCE_ISSUER`, `PROVENANCE_CREDENTIAL_TYPE`, `provenanceClaim(sha256)` and `provenanceCredentials(sha256)`. Everything it imports is type-only and therefore erased, so the assembler and the three generator modules can all reach it with no runtime import cycle between the packages.

**`assembledAt` is a required option with no default.** `AssembleOptions.assembledAt: string`, and `opts: AssembleOptions = {}` loses its default. That is the point: a caller who forgets the clock is a compile error at each of the two production call sites, not a manifest that says 1970. The type check surfaced all seven call sites — two in production, five in tests — and the tests now pass an explicit fixed instant, so where an assembly time *is* frozen it is frozen visibly.

**The assembler has no clock of its own.** It validates what it is given through `provenanceAssembledAt` and writes that. `packages/queue/src/worker.ts` passes `new Date(now()).toISOString()` — the same `now()` that stamps the lease and the completion — and `exportShotTakes` takes the instant as a parameter rather than reading a clock, so neither layer can invent one. A test asserts the assembler contains no `new Date()` or `Date.now()` at all, and no date-shaped literal anywhere in the file.

**The epoch is refused by name, not only by shape.** `provenanceAssembledAt` requires a UTC ISO 8601 instant and then refuses anything at or before the epoch. Refusing by name matters because that exact value is what a frozen placeholder looks like: a validator that accepted it would have passed the entire history of this program. A local-offset spelling (`+01:00`) is refused too, rather than silently reinterpreted, so two readers of a rights record cannot disagree about the hour.

**The identity check is a predicate, and it is the read path's.** `provenanceMatches(manifest, {projectId, sha256})` performs the three comparisons every reader made for itself. It is a predicate rather than a throwing assertion because each of the four read sites reports its own flow-specific refusal — *"The editorial source differs from its original current-film picture provenance."* and three others — and those sentences are what a person sees. What was duplicated was the comparison, not the message, so only the comparison moved; each site keeps its own message and its own extra `contentHash` comparison of the per-shot render records.

**A write-time assertion was written, measured, and deleted.** The first draft also called an `assertProvenanceManifest(manifest, {projectId: manifest.projectId, sha256})` just before writing. Perturbation R8 removed that call and **nothing failed** — correctly, because it was tautological: it compared the manifest's `projectId` to itself and its claim to a value built from the same `sha256` two lines above. It is gone. The validator earns its place at the read boundary, where the manifest comes off disk and is genuinely untrusted.

## Declared changes beyond the defect

- **`assembledAt` is enforced where it is written and tolerated where it is read.** Every export assembled before this increment carries the placeholder epoch, and those are retained media people are still editing. Adding the timestamp check to `provenanceMatches` would have made every one of them unusable for editorial reuse, sound mixing and dialogue replacement — destroying access to existing work over a defect the user did not cause. So `provenanceMatches` does not look at `assembledAt`, and a test pins that decision explicitly rather than leaving it to be rediscovered as a hole.
- **`exportShotTakes` gained a parameter.** `assembledAt: string`, positioned before `signal`. One caller.
- **`ProvenanceManifest` moved file.** `packages/planner/src/index.ts` now re-exports the type from `./provenance`, so the two existing importers are unaffected; the interface's field types are now `typeof` the shared constants rather than restated literals.
- **The assembler test gained three assertions and a type annotation.** It now reads `assembledAt` out of the written file, asserts a second assembly at a different instant records that instant while producing byte-identical media, and asserts the write boundary throws on the placeholder. `const clips = []` became `const clips: VideoClip[] = []` because the added closure moved the inference position.

## What this increment does not do

- **It does not make the manifest a signed credential.** It remains plain JSON beside the MP4 — no CBOR/JUMBF, no embedding, no signature, no key, and `type: "c2pa-style"` continues to say so by name. FR-018's signing half is untouched and still absent.
- **It does not backfill existing exports.** Manifests already written keep their placeholder. There is no migration and no rewrite: a provenance record is a record, and editing one after the fact to say something it did not say is the opposite of what this increment is for. The consequence — that the deployment now holds two generations of manifest, one honest and one not — is real and is the reason the read path tolerates the epoch.
- **It does not validate the rest of the manifest.** `scriptSha256`, the per-shot fields, `casting`, `direction` and `coverage` are unchecked by `provenanceMatches`; the editorial flows' own `contentHash` comparisons over `renderRecord` are the only per-shot verification, unchanged.
- **It does not touch the snapshot-restore defect in the same epic.** `packages/storage/src/snapshots.ts` fabricates a takedown timestamp and reason when a tombstone has no matching log entry, and then re-exports the fabricated values as the record. That is a separate record-falsification defect in a different file with a different failure mode, and it is the next increment rather than a paragraph in this one.

## Acceptance criteria

1. A manifest's assembly time is the instant its caller supplied, and a second assembly at a different instant records that instant while the media stays byte-identical. — `packages/assembler/test/assembler.test.ts`; R1, R3, R9, R10.
2. The placeholder epoch is refused at the write boundary, by name. — `packages/planner/test/provenance.test.ts` case 1 and the assembler test's `toThrow("placeholder epoch")`; R1, R13.
3. Only a UTC ISO 8601 instant is an assembly time: no date-only, no naked local time, no offset spelling, no numeric epoch, nothing before 1970. — case 2 with twelve rejected values; R5.
4. `assembledAt` is a required option with no default, the assembler reads no clock of its own, and no date-shaped literal appears in the assembler. — case 5; R1, R2, R3.
5. Both production call sites pass the worker's own `now()`, and the take path takes the instant as a parameter rather than reading a clock. — case 6; R9, R10.
6. The identity check accepts the right manifest and refuses each wrong one — wrong spec, wrong project, claim bound to other media, absent credentials, absent manifest, a non-object. — case 3; R8, R11, R12.
7. A legacy manifest carrying the epoch is still reusable, while the same value is refused at the write boundary. — case 4.
8. The spec, the issuer, the credential type and the claim are each spelled out in exactly one file across all of `packages/*/src`, and the assembler and all three verifier modules import that file and call the shared predicate. — case 7; R6, R7.
