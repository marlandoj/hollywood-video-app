# HV-031-02 — Stop the provenance manifest claiming every export was assembled in 1970

epic: HV-031
spend_usd: 0

## Goal

Make the one field of FR-018's content credential that is a timestamp carry a real timestamp in the picture-assembly export path; make forgetting to supply one a type error rather than a placeholder; and collapse the four strings that identify a manifest into one declaration — the spec identifier and the claim were each written in five places, the issuer and credential type in two.

## The defect

**Every picture-assembly export this program has produced ships `"assembledAt": "1970-01-01T00:00:00.000Z"`.** It was a string literal in the manifest constructor at `packages/assembler/src/index.ts:234` — not a parameter, not overwritten anywhere. `grep -n assembledAt` over `packages/` and `docs/` returned exactly two lines: the type declaration and that literal.

An earlier draft of this doc said "every export", which is wrong in a way worth naming: six other worker stages write a delivered `provenance.json` of their own, with their own schemas, and **none of them carries a time field at all** — see the disclaimer below. A 1970 timestamp and no timestamp are different defects; this increment fixes the first.

`docs/spec/build-spec.json:329` (FR-018) requires the content credential to carry a timestamp, and V-010's threshold is *"Every frame carries model, prompt hash, timestamp, and seed"*. So the single field of that requirement which is a timestamp was a constant, and anyone reading a contested export's manifest would be told it was assembled in 1970, for every project in the system. This is the falsification-of-record shape the P14 rights clause forbids. What it is *not* — and an earlier draft of this doc asserted otherwise — is a field any code path currently reads for takedown or dispute handling: `packages/api/src/server.ts:355` serves a `manifestUrl` and the takedown machinery never touches the manifest. The record is wrong; the claim that something in the tree depends on it today was unsupported and is withdrawn.

**Nothing looked.** `packages/assembler/test/assembler.test.ts` asserted `credentials.type`, `projectId` and `shots.length`; `test/e2e-12shot.test.ts` asserted `shots.length` and that the claim contains `"AI-generated video"`. Neither read `assembledAt`.

**And the manifest's identity was written five times over.** `spec: "hv-provenance/1.0"` and the claim `AI-generated video; content credentials sha256:<hash>` each appear once in the assembler and at four call sites across the three generator modules that verify a manifest before reusing footage — two by string concatenation (`edit-source-media.ts:55,64`), two as template literals (`sound-media.ts:30`, `dialogue-replacement.ts:160`). The issuer and the credential type appear twice each, in the assembler and in the interface's own type literal. They agreed; nothing made them agree. A change to the claim in the producer would have made every retained export unreusable one flow at a time, each reporting a different failure.

## The shape of the repair

**One leaf module owns the record's identity.** `packages/planner/src/provenance.ts` holds `ProvenanceManifest`, `PROVENANCE_SPEC`, `PROVENANCE_ISSUER`, `PROVENANCE_CREDENTIAL_TYPE`, `PROVENANCE_PLACEHOLDER_AT`, `PROVENANCE_EARLIEST_MS`, `provenanceClaim(sha256)` and `provenanceCredentials(sha256)`. The interface **moved** from `planner/src/index.ts`; a first draft left a re-export behind "so the two existing importers are unaffected", which was wrong twice — there was one importer on `main`, and this increment rewired it, leaving the re-export with no readers at all. It is deleted. Everything it imports is type-only and therefore erased, so the assembler and the three generator modules can all reach it with no runtime import cycle between the packages.

**`assembledAt` is a required option with no default.** `AssembleOptions.assembledAt: string`, and `opts: AssembleOptions = {}` loses its default. That is the point: a caller who forgets the clock is a compile error at each of the two production call sites, not a manifest that says 1970. The type check surfaced all seven call sites — two in production, five in tests — and the tests now pass an explicit fixed instant, so where an assembly time *is* frozen it is frozen visibly.

**The assembler has no clock of its own, and validates at its entry.** It validates what it is given through `provenanceAssembledAt` beside the export-size check and writes that. A first draft validated inside the manifest constructor, which is after every ffmpeg step: a bad instant cost a whole encode and left the output directory holding an mp4, captions and probe output with **no `provenance.json` beside it** — media with no record, which is the state this increment exists to prevent.

`packages/queue/src/worker.ts` passes `new Date(now()).toISOString()` — the same `now()` function that stamps the lease and the completion — and `exportShotTakes` takes the instant as a parameter rather than reading a clock. **Neither claim is left to a source scan.** The critic pass defeated the scans twice: once by adding a comment containing the expected call text, which both regexes matched, and once by assigning a constant over `exportShotTakes`'s parameter inside the function body, which no regex over a call site can see. The scans remain, now over comment-stripped source and with a check that the parameter is never reassigned, but the load-bearing guards are behavioural: `packages/queue/test/worker.test.ts` injects a fixed clock and asserts the written manifest carries it, and `packages/api/test/takes.test.ts` injects a monotonic clock and asserts every take manifest's instant falls inside the injected range. Perturbations R15 and R16 each fail those.

**The refusal is a bound and a round trip, not a single forbidden value.** A first draft refused `Date.parse(value) <= 0`, which is a refusal one millisecond deep: `1970-01-01T00:00:00.001Z` sailed through and is indistinguishable from a placeholder in any reader that truncates to seconds. `PROVENANCE_EARLIEST_MS` is `2020-01-01T00:00:00.000Z` — no export of this program predates it, and every placeholder anyone reaches for is below it.

The same draft matched the shape with a regular expression and then trusted `Date.parse`, which silently rolls `2026-02-30T10:00:00Z` forward two days and `T24:00:00` to the next morning, and stored the impossible string verbatim — so the manifest said one thing and every reader that re-parsed it said another. The value is now required to round-trip through `Date.UTC` and back. A local-offset spelling (`+01:00`) is refused too, rather than silently reinterpreted, so two readers of a rights record cannot disagree about the hour.

**The identity check is a predicate, and it is the read path's.** `provenanceMatches(manifest, {projectId, sha256})` performs the comparisons every reader made for itself — spec, project and claim, plus the declared credential type and issuer, which a first draft single-declared as constants and then left unchecked. It is a predicate rather than a throwing assertion because each of the four read sites reports its own flow-specific refusal — *"The editorial source differs from its original current-film picture provenance."* and three others — and those sentences are what a person sees. What was duplicated was the comparison, not the message, so only the comparison moved; each site keeps its own message and its own extra `contentHash` comparison of the per-shot render records.

**A write-time assertion was written, measured, and deleted.** The first draft also called an `assertProvenanceManifest(manifest, {projectId: manifest.projectId, sha256})` just before writing. Perturbation R8 removed that call and **nothing failed** — correctly, because it was tautological: it compared the manifest's `projectId` to itself and its claim to a value built from the same `sha256` two lines above. It is gone. The validator earns its place at the read boundary, where the manifest comes off disk and is genuinely untrusted.

## Declared changes beyond the defect

- **Exactly one legacy value is tolerated on read.** Every picture-assembly export written before this increment carries `PROVENANCE_PLACEHOLDER_AT`, and those are retained media that the editorial, sound and dialogue flows reuse. Refusing them would make that work unopenable over a defect the user did not cause, so `provenanceMatches` accepts that one literal and validates anything else — a missing, null or arbitrary value is refused on read as well as on write. A first draft did not look at the field on the read path **at all**, which tolerated every one of those while the doc claimed a test pinned the decision; the test now pins eight rejected shapes beside the one accepted value.

  Two honest qualifications the first draft skipped. The tolerated population is self-clearing — anonymous project data auto-deletes after thirty days (FR-057, `docs/spec/build-spec.json:368`) — so a cutoff was available and is not taken, because nothing in the tree records when the last placeholder-bearing export was written and a wrong cutoff refuses live work. And the population is **asserted, not evidenced**: under ADR-0020 there is no public deployment, so the exports in question are whatever private staging holds. The tolerance is the conservative choice, not a measured necessity, and it is one literal wide.
- **`exportShotTakes` gained a parameter.** `assembledAt: string`, positioned before `signal`. One caller.
- **`ProvenanceManifest` moved file, with no re-export.** `packages/planner/src/index.ts` carries a comment where the interface was and nothing else; its one importer now reads the type from `./provenance`. The interface's field types are `typeof` the shared constants rather than restated literals, which is what removed the issuer and credential-type duplication.
- **The four read sites became stricter, which was not the goal.** `provenanceMatches` starts with `Boolean(value) && typeof value === "object"`. On `main` a `null` or non-object manifest was an uncaught `TypeError` at each site; it is now that flow's own refusal message. An improvement, declared because it is a behaviour change nobody asked for.
- **The assembler test gained three assertions and a type annotation.** It now reads `assembledAt` out of the written file, asserts a second assembly at a different instant records that instant while producing byte-identical media, and asserts the write boundary throws on the placeholder. `const clips = []` became `const clips: VideoClip[] = []` because the added closure moved the inference position.

## What this increment does not do

- **It does not make the manifest a signed credential.** It remains plain JSON beside the MP4 — no CBOR/JUMBF, no embedding, no signature, no key, and `type: "c2pa-style"` continues to say so by name. FR-018's signing half is untouched and still absent.
- **It does not backfill existing exports.** Manifests already written keep their placeholder. There is no migration and no rewrite: a provenance record is a record, and editing one after the fact to say something it did not say is the opposite of what this increment is for. The consequence — that the deployment now holds two generations of manifest, one honest and one not — is real and is the reason the read path tolerates the epoch.
- **It does not give the other six manifest writers a timestamp.** `packages/generator/src/edit-media.ts:43` (`hv-edit-output/1`), `edit-assembly-media.ts:41` (`hv-edit-assembly-result/1`), `lipsync-media.ts:97` (`hv-lipsync-result/1`), `sound-media.ts:66` (`hv-sound-result/*`), `dialogue-replacement.ts:238` (`hv-dialogue-replacement-result/*`) and `graphic-media.ts:14` (`hv-graphic-output/1`) each write a delivered `provenance.json` with its own schema, and none of those schemas has a time field at all. Exports from the picture-edit, assembly-edit, lip-sync, sound-mix, dialogue-replacement and motion-graphic stages therefore carry **no** assembly time rather than a false one. That is a larger gap than the one fixed here and it is untouched: adding a field to six schemas is six validators, six fixtures and a compatibility decision per schema, not a paragraph in this increment.
- **It does not meet V-010 as quoted.** V-010's threshold is a timestamp *per frame*; the manifest carries one export-level `assembledAt` and per-shot entries with provider, model, seed and fingerprint and no time. The increment leans on V-010 to establish that the missing field matters and leaves V-010's per-frame half where it was.
- **It does not bound the assembly time from above.** `9999-12-31T23:59:59Z` is accepted. The validator has no trustworthy clock of its own, and the write-time value *is* the caller's clock, so comparing it to another clock would only move the question; a manifest dated in the future is a defect this does not catch.
- **It does not validate the rest of the manifest.** `scriptSha256`, the per-shot fields, `casting`, `direction` and `coverage` are unchecked by `provenanceMatches`; the editorial flows' own `contentHash` comparisons over `renderRecord` are the only per-shot verification, unchanged.
- **It does not touch the snapshot-restore defect in the same epic.** `packages/storage/src/snapshots.ts` fabricates a takedown timestamp and reason when a tombstone has no matching log entry, and then re-exports the fabricated values as the record. That is a separate record-falsification defect in a different file with a different failure mode, and it is the next increment rather than a paragraph in this one.

## Acceptance criteria

1. A manifest's assembly time is the instant its caller supplied, and a second assembly at a different instant records that instant while the media stays byte-identical. — `packages/assembler/test/assembler.test.ts`; R1, R3.
2. The placeholder is refused at the write boundary, and so is a placeholder one millisecond later, or a day later, or in 2019. — `packages/planner/test/provenance.test.ts` case 1 and the assembler test's `toThrow("placeholder epoch")`; R13.
3. Only a UTC ISO 8601 instant that names a date which exists is an assembly time: no date-only, no naked local time, no offset spelling, no numeric epoch, and no February 30th, hour 24, minute 60 or month 0. — case 2, with nineteen rejected values; R5, R19.
4. The content-credential claim carries the **whole** media hash, asserted against a literal written out independently of the function that builds it, and two hashes differing only in their last character are distinguished. — case 3; R14.
5. `assembledAt` is a required option with no default; the assembler reads no clock of any shape, including `new Date(<number>)`; and no date-shaped literal appears in it. — case 6; R1, R2, R3.
6. **Both production paths put the worker's own clock in the written manifest**, checked by reading the file back with an injected clock rather than by scanning the call site. — `packages/queue/test/worker.test.ts` and `packages/api/test/takes.test.ts`; R15, R16.
7. The identity check accepts the right manifest and refuses each wrong one — wrong spec, wrong project, claim bound to other media, claim bound to media differing in one last character, absent credentials, a declared type or issuer that is not ours, an absent manifest, a non-object. — case 4; R8, R11, R12, R20.
8. Exactly one legacy assembly time is tolerated on read, and eight other shapes — missing, null, empty, numeric, arbitrary text, near-placeholder, impossible date, offset spelling — are refused. — case 5; R18.
9. The spec, the issuer, the credential type and the claim are each spelled out in exactly one file across all of `packages/*/src`, **with string concatenation collapsed first**, and the assembler and all three verifier modules import that file and call the shared predicate. — case 7, whose collapsing is itself exercised; R6, R7, R17.

**The seven bold rows are the critic pass's findings, and four of them were green defects** — edits that put a false record into a delivered manifest, or let the identity check pass a manifest it should refuse, with every suite, the type checker and the linter clean:

- **R14** changed `provenanceClaim` to interpolate one hex character of the hash. Every assertion on the claim compared it to the same function that wrote it, and the only fixed text anything pinned was the prefix — so the delivered FR-018 credential stopped identifying its media, and `provenanceMatches` would have accepted roughly one foreign manifest in sixteen.
- **R15** assigned a constant over `exportShotTakes`'s parameter inside the function body. The three guards were regexes over the signature and the call site; none can see an assignment, and `/new Date\(\)|Date\.now\(\)/` requires empty parentheses, so `new Date(1577836800000)` was invisible.
- **R16** froze both worker instants and added one comment quoting the expected call. Both regexes matched the comment. Measured without the comment it is the first draft's R9 figure, which is why R9 only ever caught the un-camouflaged form.
- **R17** re-typed all four identifying strings as `"hv-provenance" + "/1.0"`. `String.includes` is defeated by concatenation, so the drift the leaf module exists to prevent walked straight back in — and the issuer was not scanned for at all, despite being named in the test's own title.

R18, R19 and R20 are the other three findings: the read path ignoring the assembly time entirely, `Date.parse` accepting dates that do not exist, and the declared issuer going unchecked. R4 from the first draft is absorbed into R13, and R10 — the write-time `assertProvenanceManifest` — is described above: applied to that draft it measured `7 pass / 0 fail` across both suites, because the call compared the manifest to values derived from the manifest. The call is deleted and R8 now perturbs the read-path predicate, where it bites.
