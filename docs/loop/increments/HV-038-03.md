# HV-038-03 — Off-host encrypted transport rebased onto main, plus a fixtures-only RPO/DR drill under the existing CI steps
epic: HV-038
spend_usd: 0

## Goal
Land the off-host backup transport from draft PR #19 (`codex/ZOU-1607-offhost-recovery`) on current `main` without its `.github/workflows/ci.yml` commit, and add a synthetic end-to-end drill that packages → encrypts → decrypts → extracts → re-verifies a backup repository, recording the measured snapshot-completion-to-copy-durable lag as an RPO figure.

Today the only recovery path is `packages/storage/src/backups.ts`, whose scheduler (`scripts/storage-backup-service.ts`) writes 120-second snapshots into a repository on the same host as the database and object store, and stamps every status with `localRepositoryOnly: true`. `docs/STORAGE-BACKUPS.md` and `docs/OBSERVABILITY.md` both say plainly that this establishes no off-host RPO. PR #19 built the missing piece — a versioned, bounded, content-addressed `HV-OFFHOST-BUNDLE/1` stream that can be streamed through `age` to an independently held encrypted file and reconstructed into a byte-identical repository — but that branch was cut at `dbc766f` (PR #18) and cannot be merged: it carries a commit that adds a CI step, and because the branch is stale against `main`, replaying its `ci.yml` state would delete the entire `graphics-contract` and `telemetry-contract` jobs. `.github/workflows/ci.yml` is on CLAUDE.md's frozen list, so editing it at all is gate G4.

This increment therefore re-authors the three scripts and the doc onto `main` (adapting to the reference-asset object keys and the `scripts/backup-lock.py` locking scheme that arrived after the branch was cut), registers the Python suite with CI through a Bun test wrapper instead of a new CI step, and adds `scripts/offhost-drill.py` plus `packages/storage/test/offhost-recovery.test.ts` — a drill that builds a synthetic repository from fixtures in a temp directory, runs the full transport round trip, and writes `docs/evidence/hv038-observability/offhost-drill.json` with the measured lag and an explicit statement of what it does not prove. No key, account, vendor or secret is added: the drill generates a throwaway `age` identity inside the test and destroys it with the temp directory. No frozen path is touched, no staging data is read or written, spend is 0, providers stay `mock`.

## Acceptance criteria

1. **The transport lands on current `main` with no `.github/workflows/ci.yml` change.** `scripts/offhost-backup.py`, `scripts/install-backup-encryption.py` and `scripts/test_offhost_backup.py` exist on the increment branch carrying the content of draft commits `b5cd812` and `175db39` with the adaptations of criteria 3 and 4; `git diff --name-only main...HEAD` contains no path under `.github/workflows/`, `docs/legal/`, `docs/adr/` or `packages/safety/`, and `git show HEAD:.github/workflows/ci.yml` is byte-identical to `git show origin/main:.github/workflows/ci.yml`. The `graphics-contract` and `telemetry-contract` jobs are still present and still green on the PR. Satisfies FULL-SCOPE §P15 "Reliability: … disaster-recovery drills." and CLAUDE.md "Frozen without a human gate: … .github/workflows/**".

2. **The Python suite runs in CI through the existing `unit + integration` step, not a new step.** `.github/workflows/ci.yml` names each Python test file literally (`-p "test_archive_package.py"`, `test_storage_bootstrap.py`, `test_storage_runtime.py`, `test_storage_deployment.py`, `test_observability_runtime.py`); `-p` is a filename pattern matched against that literal, so `scripts/test_offhost_backup.py` is never discovered by any existing step. It is registered instead by `packages/storage/test/offhost-recovery.test.ts`, which spawns `python3 -m unittest discover -s scripts -p test_offhost_backup.py` and asserts `OK` and exit code 0, exactly as `packages/storage/test/prepare-object-bucket.test.ts` does for `test_prepare_object_bucket.py`; that file is picked up by `bun test packages test`. Without a `python3` on PATH the check skips rather than passes. Satisfies FULL-SCOPE §10 "Evidence before promotion: tests, benchmarks, post-flight evals, gap audits." and CLAUDE.md "Every criterion gets a real test."

3. **The transport accepts every object key shape `backups.ts` can produce today.** `validate_metadata` accepts, in addition to `v1/<project>/<job>/<sha>/<name>` and `archives/<a>/<b>/<sha>.zip`, the reference-asset key `v1/<projectId>/reference-<uuid>/<sha256>/reference.png` that `createStorageBackupUnlocked` began indexing after the branch was cut (`packages/storage/src/backups.ts`, `packages/planner/src/references.ts`) — the draft's existing five-part `v1/` rule already covers it, and a test pins that with a real `referenceObjectKey` value so a future key change breaks loudly. `MAX_FILES` (draft `scripts/offhost-backup.py`, 100 000) is reconciled against `MAX_OBJECTS` in `packages/storage/src/backups.ts` (1 000 000): the transport keeps a lower, explicitly documented ceiling and refuses an oversized repository with a message that names the limit and the writer's limit, rather than failing obscurely on the 16 MiB header bound. Satisfies FULL-SCOPE §P15 "near-zero loss for approved media" and §P15 "Storage: S3-compatible object storage with multipart upload, lifecycle policies …".

4. **The transport's repository lock is the one `main` actually uses.** The draft takes `fcntl.flock(LOCK_SH)` directly on `<root>/repository.lock` with a fixed 30-second bound. `main` centralised locking in `scripts/backup-lock.py`, which `withRepositoryLock` (`packages/storage/src/backups.ts`) spawns for every create (exclusive), prune (exclusive), verify and restore (shared). The rebased transport takes a **shared** lock on the same `repository.lock` inode with the same `O_NOFOLLOW` discipline, so it can never run concurrently with a create or prune; the wait bound becomes `--lock-timeout` (default 30 s, range 1–3600 s) and its expiry message names the 120-second scheduler cycle as the expected contender. A test proves an exclusive `backup-lock.py` holder makes the transport fail closed within the bound rather than packaging a half-written snapshot. Satisfies FULL-SCOPE §P15 "RPO 5 min for state" and "near-zero loss for approved media".

5. **A fixtures-only drill runs the whole pipeline and measures the lag.** `scripts/offhost-drill.py` builds a synthetic repository in a `mkdtemp` (mode 0700) containing `repository.json`, `latest.json`, `snapshots/<id>/{backup.json,receipt.json,state.dump}`, `repository.lock` and a blob pool that exercises deduplication (two object keys sharing one blob), an `archives/…/<sha>.zip` key and a `reference-<uuid>` key; it then runs, in order, `offhost-backup.py encrypt` → `age --decrypt` with an identity generated in that same temp directory → `offhost-backup.py inspect --extract <new dir>` → a reconstruction check that `snapshot_header(extracted)` equals `snapshot_header(source)` field for field and that every extracted blob re-digests to its content address. It prints one JSON object and never writes outside its temp root and the `--output` evidence path. No live database, bucket, staging repository or operator identity is touched. Satisfies FULL-SCOPE §P15 "disaster-recovery drills" and CLAUDE.md "tests use a per-run database/bucket prefix, never the staging data."

6. **The throwaway identity is generated inside the test; no secret is introduced.** The drill runs `age-keygen -o <tmp>/identity.txt` (mode 0600) inside its temp root, derives the recipient with `age-keygen -y`, uses it for one round trip, and lets `TemporaryDirectory` destroy both. No identity, recipient, ciphertext or receipt is committed; nothing is ever written into the checkout. The drill record states `operatorIdentityUsed: false`. Gate G3 is therefore not required for the drill. Satisfies CLAUDE.md "Never add keys, accounts, or vendors. Secrets come only from the environment (Zo Secrets)." and ADR-0020 fail-closed.

7. **The `age` binary is obtained the way this repo already obtains pinned tools, and its absence skips rather than fails.** `age` is **not** present on GitHub's `ubuntu-24.04` runner image and cannot be installed by `apt` without a new CI step (G4). `packages/storage/test/offhost-recovery.test.ts` therefore invokes `scripts/install-backup-encryption.py --root <cached temp root>` — which fetches the official `age` v1.3.2 release asset over HTTPS and verifies its exact byte length and SHA-256 before extracting exactly two executables — the same checksum-pinned-download pattern as `scripts/install-observability-runtime.py` and `scripts/install-graphics-runtime.ts`. The install is bounded by a timeout and cached for the process; if it fails (no network, GitHub unavailable, non-amd64), or if `HV_ENCRYPTION_RUNTIME` already names an installed runtime it is used instead. The encrypt/decrypt legs then **skip** with a recorded reason and the package → extract → re-verify legs and the lag measurement still run, so an offline developer machine or a GitHub outage never turns the `quality` job red. This adds no vendor, no account and no `package.json` or lockfile entry. Satisfies CLAUDE.md "Never add keys, accounts, or vendors" and FULL-SCOPE §10 "Provider independence and versioned adapters."

8. **The RPO figure is defined exactly, measured, and bounded in what it claims.** `docs/evidence/hv038-observability/offhost-drill.json` (schema `hv-offhost-drill/1`) records `rpo: {definition, snapshotAt, copyDurableAt, snapshotToCopyMs, encrypted, measuredOn}` where `snapshotAt` is the manifest's `snapshotAt` (on a real repository the PostgreSQL `transaction_timestamp()` of the exported repeatable-read snapshot, `packages/storage/src/backups.ts`) and `copyDurableAt` is the wall-clock instant at which the ciphertext **and** its receipt have been `fsync`ed. The file also carries `provesOffHostRpo: false`, `provesHostLossRecovery: false`, `independentDestination: "none (same filesystem, temp directory)"`, `continuousReplication: false`, `restoredIntoLiveDatabase: false` and `newProviderSpendUsd: 0`. A test parses the committed file, re-validates the schema, and asserts `snapshotToCopyMs === Date.parse(copyDurableAt) - Date.parse(snapshotAt)` and that every `proves*` field is `false`. Satisfies FULL-SCOPE §P15 "RPO 5 min for state" (instrumented, not claimed) and CLAUDE.md "Never fabricate launch, legal, or provider evidence."

9. **The documentation states plainly that a CI drill is not host-loss recovery.** `docs/OFFHOST-RECOVERY.md` lands with the draft's operator procedure rewritten for current `main`, plus a section "What the CI drill does and does not establish" saying in the first sentence that the drill runs on one machine, against a synthetic repository, with a key created and destroyed in the same process, and therefore measures format and pipeline correctness plus a packaging lag — not off-host RPO, not durability of an independent copy, not recovery from the loss of the host, and not that any live copy exists anywhere. `docs/STORAGE-BACKUPS.md` and `docs/OBSERVABILITY.md` keep their existing "off-host recovery remains open" language and gain a pointer to the new doc; `docs/STORAGE-DEPLOYMENT.md`'s "Deferred from HV-040" entry has its "(draft PR #19)" reference corrected to name this increment and the closed PR. Satisfies CLAUDE.md "Never fabricate launch, legal, or provider evidence" and FULL-SCOPE §10 "Evidence before promotion".

10. **No frozen path, dependency, budget default, account, vendor, migration, route or staging mutation.** The diff adds no `package.json` or lockfile entry, no `infra/drizzle/` file, no HTTP route, no safety-refusal change, and performs no write against staging PostgreSQL, the staging bucket or the live backup repository. G8 is not triggered. Satisfies FULL-SCOPE §10 "Free and anonymous for every end user; no billing code reachable." and "Safety refusals expand only."
