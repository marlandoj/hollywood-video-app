# HV-031-13 — The words on an uploaded sound never met the safety gate

epic: HV-031
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

A recording in the sound library carries four pieces of the creator's own text: its label, and its
rights record's source, credit and licence notes. The library lists them, the spotting list and cue
sheet credit them, and the SDH track puts the label in front of viewers. Every other creator text in
the studio passes `checkPrompt` — cast records, direction notes, review comments, crew answers,
graphic credits. `sound-assets.ts` never imported `packages/safety`, so none of these four did.
"A portrait of Taylor Swift" was an accepted sound label, and a licence note could say anything up
to 2,000 characters.

The only check was late: HV-027-16 gated the label when an SDH track is made. By then the words had
been stored, shown in the library and written into cue sheets. Source, credit and notes were never
checked at all.

The text controls had a smaller gap of their own. `soundText` refused C0 controls and DEL but not
the C1 block (`\u0080`–`\u009f`).

## What this increment does

- **`gateSoundText`** (`packages/planner/src/sound-assets.ts`) checks the label, source, credit and
  licence notes one at a time, so the refusal can name the field. Then it checks all four together,
  so a refusal can't be split across fields (as HV-030-21 did for the plan step). The fields are
  joined with a space, and each field is also read with its whitespace runs collapsed to one space:
  some rules match only a literal space between words ("harry potter", "the famous actor"), so a
  newline join, or a line break inside one field, carried a name through. It also refuses any
  control character that isn't a newline or tab, C1 included.
- **A refusal is `SoundRefused`**, which carries the verdict. The route answers **422**
  `{reason: "content_policy", category}` with *"We can't keep this sound: its credit names a real
  person or falls outside the content policy. Reword it and import the recording again -- nothing
  was stored."*
- **The gate runs before anything is kept, in three places:**
  - **The import route** runs it on the `x-hv-sound-record` header, before the upload body is read.
  - **`normalizeSoundUpload`** runs it before its scratch directory is made.
  - **`updateSoundLibrary`** runs it on every record it admits. That covers the file store and the
    PostgreSQL store, and any later path that adds a sound through them.
- **No other path makes a sound record from client input.** A sound session's cue names a library
  asset by id and revision, and the server copies the stored record. Snapshot restore and archive
  import are operator paths. They read records back through `validateSoundLibrary`.
- **Stored records aren't re-checked.** The gate sits at admission, not in `validateSoundAsset`, so a
  library that loaded yesterday still loads. Its sounds can still be made available or withdrawn.
- Safety refusals only grow. `packages/safety` is unchanged.

## Acceptance criteria

1. **Each field is checked alone.** Every prompt in `PROHIBITED_PROMPT_BATTERY` is refused in the
   label, source, credit or licence notes. The refusal carries the battery's category, names the
   field, and says nothing was stored.
2. **The fields are checked together.** The safety package's split pair, "An explicit scene." and
   "The character is a minor.", passes in any one field. Put in two fields of the same sound, it is
   refused.
3. **A name split by a line break, or across two fields, is still the name.** "Theme from
   Harry\nPotter" is refused in any field. "Theme from Harry" with "Potter fan recording", and "Voice
   of the famous" with "actor recorded at home", are refused together.
4. **Controls are refused** in every field, C1 included. A newline or tab is kept.
5. **The library won't admit a refused record**, whatever path built it, and is left unchanged.
6. **A sound stored before this increment is not re-checked.** Its library still reads and still
   updates.
7. **The route stores nothing on a refusal.** A refused label, credit, licence note, or split
   label + credit answers 422 `content_policy`. The library stays at version 0, and there is no
   state entry, media file or scratch directory. So does a line break inside the credit's name,
   or the name split across label and source. A clean import still answers 201.
8. Reverting the gate in `sound-assets.ts` fails criteria 1, 2, 3, 4, 5 and 7 (measured: 6 of the 8
   tests fail). Reverting only the space join and the whitespace collapse fails criteria 3 and 7
   (measured: 2 of the 8 tests fail).

- Tests: `packages/planner/test/sound-assets-safety.test.ts`,
  `packages/api/test/sound-assets-safety.test.ts`. `packages/api/test/sound-assets.test.ts` still
  passes.

## Known gaps this leaves

- **Existing stored sounds are not re-validated.** A label or credit saved before this increment
  stays in the library, its spotting lists and cue sheets until the owner withdraws it. SDH still
  refuses such a label when a track is made (HV-027-16). A sweep would rewrite or hide stored records,
  which is a destructive migration and is not made here.
- **The gate is over-inclusive here too.** A credit or licence note that names a brand on the
  gate's list (for example a licence "from Disney") is refused. The creator has to describe the
  licence without the name.
- **The space join lives here, not in the gate.** `checkPrompt` itself still treats a line break
  between two words differently from a space; a separate increment is to make it
  whitespace-insensitive. Until then, other callers that join with `"\n"` keep that gap.
- **The refusal names the first failing field, not all of them,** and the joined refusal doesn't
  say which pair tripped it. The gate's other refusals work the same way.
- **The route checks the header before rights attestation.** A refused label is reported as a
  content-policy refusal even on a project whose rights aren't confirmed yet. Either way, nothing is
  stored.
