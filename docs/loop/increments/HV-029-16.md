# HV-029-16 — The review page told reviewers of an unlimited link that reloads were free, when each one used a view

epic: HV-029
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

HV-029-13 qualified the review page's intro to "In most browsers, reloading this page does not use
another view." The sentence sat in the static HTML, so every review page showed it.

It is true only on a link minted with an owner-chosen limit. Those links count each viewer id once,
and their review view carries `maxViews`. A link minted without one counts every serve in every
browser (HV-029-05). HV-029-13's own comment says so, and its "this browser" note is already held
back on such a link. On that page each reload does use a view, and the intro said it did not.

The studio's share button always sets a limit. So the wrong sentence showed only on links minted
through `POST /api/projects/:id/reviews` without `maxViews`, or on links older than HV-029-05.

## What this increment does

- **The reload sentence arrives with the view.** The intro ends in an empty
  `<span id="review-reload-note">`. Once the review view loads and has `maxViews`, the script fills
  it with " In most browsers, reloading this page does not use another view."
- **An unlimited link says nothing about reloads.** "There is no limit" would be false: such a link
  still stops at FR-047's 3 serves. "Reloads count here" would be a new claim that G15 did not
  decide. So the page makes no claim either way.
- **A page whose cut could not be shown says nothing about reloads.** It cannot know which kind of
  link it was.
- **HV-029-13's "this browser" note is unchanged.** It already appears only on a link with
  `maxViews`, and the tests pin that alongside the intro.
- `docs/REVIEW-LINKS.md` says when the page talks about reloads.

## Acceptance criteria

1. **A limited link in a browser that remembers the reviewer** reads " In most browsers, reloading
   this page does not use another view." in the intro, and the "this browser" note stays empty.
2. **A limited link where `sessionStorage` throws** shows both the intro sentence and HV-029-13's
   note.
3. **A link without `maxViews`** shows neither, whether `sessionStorage` works or throws.
4. **A link that cannot show the cut** (403) shows no reload sentence.
5. **The static intro holds an empty slot**, and no reload claim of its own.
6. Reverting `index.html` fails the tests for criteria 1, 2 and 5. The tests for 3 and 4 pass on the
   old page too: the test harness does not render static HTML, so criterion 5 is what catches the
   old static sentence. They pin what must not change.

- Tests: `packages/frontend/test/review-reload-note.test.js` (5 tests) runs `index.html`'s own module
  script through `desk-page.js`. HV-029-13's `review-viewer-note.test.js` passes unchanged (7 / 0).

## Known gaps this leaves

- **The intro sentence appears only once the cut loads.** Before then the page cannot know which kind
  of link it is. A reviewer who reads the intro first sees it complete itself.
- **On an unlimited link, the status still reads "N more viewer(s) can open this link."** There it is
  N more serves, reloads included. Saying so is a wording decision for G15's owner, not made here.
