# HV-024-01 — Pin the three sound recipe revisions, and tie the two closed stem sets together
epic: HV-024
spend_usd: 0

## Goal

Pin the three recipe revisions that every delivered sound record is validated against, and assert the two closed stem sets that are declared in different files are the same set rather than two sets that happen to agree. No behaviour changes.

**How this increment was found.** A program-wide re-verification of the pre-loop credit ran one auditor per epic across all 22 epics that had never had the pass `docs/loop/STATUS.md` says the first planner is supposed to run. It found this defect family — a content-hashed identity pinned into an already-delivered record with nothing guarding it — for the sixth time in this program. HV-019-01 found one. HV-019-03 found five in the performance lane. HV-025-01 closed the graphics lane. This is sound.

**What is pinned into delivered sound records.** `validateSoundOutput` refuses a record whose `report.recipeRevision` differs from `contentHash(SOUND_MIX_RECIPE)`; the finishing and restoration reports carry and re-derive `contentHash(SOUND_FINISH_RECIPE)` and `contentHash(RESTORATION_RECIPE)` the same way. All three constants live in the repository, are edited like ordinary configuration, and were guarded by nothing.

**Demonstrated, not asserted.** On this branch, adding one field to `SOUND_MIX_RECIPE` — the value every delivered sound version is validated against:

```
nine existing sound suites (24 tests)   22 pass  2 skip  0 fail  447 expect() calls
sound-identity.test.ts (new)            1 fail
```

That is the defect: the expectation is derived from the same live constant as the code, so the suite cannot notice. The consequence is not a failed render — it is that every sound version already delivered becomes permanently unreadable, on content-addressed records that cannot be rewritten without breaking their own seals.

**The second half closes a related defect.** `RESTORATION_TRACKS` and `RESTORATION_STEMS` are declared in `packages/planner/src/sound-restoration.ts`; `SOUND_ROLES` and `SOUND_STEMS` are declared in `packages/planner/src/sound-session.ts`. They agree today by coincidence of maintenance, not by construction, and `generator/src/sound-restoration.ts` indexes the restoration outputs positionally, so the *order* is load-bearing as well as the membership. Every remaining P9 clause — score, foley and SFX, ambience beds, auto-spotting — must widen the cue roles. Today that edit leaves every unit test green, renders a non-restoration mix correctly, and fails a restoration session with a raw `ENOENT`.

## Acceptance criteria

1. **The three recipe revisions are committed and re-derived on every run.** `docs/evidence/hv024-sound/recipe-revision-pins.json` (schema `hv-sound-recipe-pins/1`) records, for each of `SOUND_MIX_RECIPE`, `SOUND_FINISH_RECIPE` and `RESTORATION_RECIPE`, its constant name, its own `schema` string, `contentHash(...)`, and the record field it is pinned into together with the validator that re-derives it. The file is written when `HV_SOUND_PINS_EVIDENCE` names a path and **re-validated on every test run including CI**, which sets no such variable. The env value is resolved against the repo root and asserted to equal the committed path, so regeneration from another working directory cannot silently write a stray file and report success. Satisfies FULL-SCOPE §10 "Evidence before promotion: tests, benchmarks, post-flight evals, gap audits." and CLAUDE.md "Never fabricate launch, legal, or provider evidence."

2. **The two closed stem sets are asserted equal, in order.** A test asserts `RESTORATION_STEMS` equals `SOUND_STEMS`, that `RESTORATION_TRACKS` equals `["dialogue", "narration", ...SOUND_ROLES]`, that `SOUND_STEMS` equals `[...RESTORATION_TRACKS, "me", "mix"]` — order included, because the restoration filter indexes its outputs positionally — and that the stem set has no duplicate. Widening the cue roles in one file now fails here rather than at the first restoration session. Satisfies §10 "Provider independence and versioned adapters." read with ADR-0020 fail-closed.

3. **The failure direction is demonstrated rather than described.** A test asserts that adding one field to each of the three recipes moves its revision, which is the exact condition under which a delivered record stops validating. Satisfies CLAUDE.md "Every criterion gets a real test."

4. **The evidence file carries no credential, destination or host path, and its honesty fields are explicit.** The file matches none of `://`, `API_KEY`, `/home/`, `/Users/`, `/tmp/`, and every 32+ hex run in it is one of the three pinned revisions. It carries `behaviourChanged: false`, `newProviderSpendUsd: 0`, `provesLoudnessQualification: false` and `provesRestorationQuality: false` — the last two because the shipped sound docs are explicit that R128/A-85 qualification has not been passed, and this increment does not change that. Satisfies ADR-0018's identifier discipline and CLAUDE.md "Never fabricate … evidence."

5. **No behaviour, frozen path, dependency, budget default, account, vendor, migration, route or user-facing surface changes.** `packages/planner/src/sound-session.ts`, `sound-finishing.ts`, `sound-restoration.ts`, `sound-jobs.ts` and `packages/generator/src/sound-restoration.ts` are **not in the diff**, and the frozen-path check names them on purpose. The diff touches nothing under `docs/legal/**`, `docs/adr/**`, `.github/workflows/**`, `packages/safety/**` or `infra/drizzle/**`; adds no `package.json` or lockfile entry, no HTTP route or request field, no cookie, tracking, account, tier or payment path; and changes no budget default. No audio is rendered, no FFmpeg is invoked, no provider is constructed and no key is read. `docs/loop/STATUS.md` and `docs/PROGRAM-EXECUTION.md` are not in the diff; RECORD owns both. Satisfies FULL-SCOPE §10 "Free and anonymous for every end user; no billing code reachable." and the EXECUTION-LOOP frozen list.

- **Deriving `RESTORATION_STEMS` and `RESTORATION_TRACKS` from `SOUND_STEMS` and `SOUND_ROLES`** rather than asserting they agree, and replacing the positional `values[2..4]` indexing in `packages/generator/src/sound-restoration.ts` with named lookups. Both are the right repair and both are behavioural changes to code that produces delivered records; this increment's pins are what will prove they moved nothing.
- The two MINOR defects the audit raised in this lane: `RESTORATION_RECIPE`'s hop and tail-padding values duplicated as literals inside `restorationFilter`, so a retained receipt can describe processing that did not run; and the 2048 voice-window bound enforced only at seal time, so a dialogue-dense cut burns a full mix, AAC encode and HLS package before failing with a non-actionable message.
