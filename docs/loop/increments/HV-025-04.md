# HV-025-04 — Graphics render on PostgreSQL workers

epic: HV-025
release: 1 "Studio"
gate: none new
spend_usd: 0

## Why

On staging, the Editor's title failed with "This graphic or its project permission is no longer available." The graphics worker checked permission through `context.projects.peekProject`. Production PostgreSQL workers have no in-process project store (`packages/queue/src/worker.ts`: `projects: database ? undefined : …`), so every graphic render on staging failed.

The PostgreSQL graphics test passed only because it gave its worker a project store the real worker doesn't have. The sound and editorial workers already read permission through the ledger.

## What this increment does

- **`PostgresCostLedger.assertGraphicPermission(job, workerId, now)`** reads the project and the job's fence in one project-scoped transaction, then applies the same `assertGraphicPermission`.
- **`processGraphicJob`** uses it on PostgreSQL, as the sound and editorial workers do.
- **`packages/storage/test/graphics.test.ts`** now runs its worker without a project store, the way production does.

## Acceptance criteria

1. **A PostgreSQL graphic render, checkpoint and resume** succeed with a production-shaped worker context.
   - Test: `packages/storage/test/graphics.test.ts` (CI's PostgreSQL job).
2. **The titled studio film completes on staging** in the release run.

## Also: the graphics CI job fits its budget again

HV-025-03's CI-size test rendered the Editor's full 4 s title and 6 s credits, and then short copies of both for the edit. That took the graphics job to about 9.5 of its 10 minutes, and runs began to be cancelled (#138, #139 and main).

The full-length renders are removed. The short copies keep the same text, type and safe area, so text that doesn't fit still fails. The full-length renders run in the opt-in whole-studio test (`HV_STUDIO_E2E=1`).
