# HV-024-06 — The file a learned noise profile is trained on had its shape described in two places

epic: HV-024
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

A reference-trained restoration does not hand ffmpeg the stem. It hands it the reference, then a gap
of silence, then the stem, and trims the result back to the stem. Two places have to agree about
where the stem starts in that file:

```ts
// packages/planner/src/sound-restoration.ts — reads the gap from the recipe
const prefix=t.reference?t.reference.frames+RESTORATION_RECIPE.trainingGapFrames:0,start=prefix+RESTORATION_RECIPE.delayFrames;

// packages/generator/src/sound-restoration.ts — spells its current value out, twice
writeFileSync(input,Buffer.concat([soundWavHeader(r.frames+2400+frames),bytes,Buffer.alloc(2400*6)]),{flag:"wx"});
```

Change `trainingGapFrames` and the trim lands 2,400 samples — **50 ms** — from where the stem
actually begins, and **every check still passes**:

- `quantize` compares only the output's sample count with the stem's, which `atrim` guarantees
  whatever it trims;
- `validateRestorationReport` compares the recorded filter with `restorationFilter`, which is one
  side of the disagreement comparing itself with itself.

The delivered stem would simply be out of sync with picture and with every untreated stem beside it,
with a clean receipt.

Nor would the tests have shown it. The impulse-alignment test uses `settings()` with **no reference**,
so it never builds a training file at all; the reference test measures tone energy over
`i>100000 && i<190000` inside a tone spanning 96000–192000, which a 2,400-sample shift stays
comfortably inside. And HV-024-01's pinned filter string does not cover it either: `FILTER_PROBE` in
`packages/planner/test/sound-identity.test.ts` sets `reference: null`, so the prefix branch is never
rendered into the pin. The recipe-hash pin would fire on a changed gap, and its documented remedy is
to regenerate the pins — which leaves the generator's literal exactly where it was.

## What this increment does

- **`restorationTraining(referenceFrames, frames)` owns the layout**: the gap, the prefix, the total
  length of the training file and the sample the trim starts at. The generator builds the file from
  it and `restorationFilter` trims from it, so the file and the trim move together or neither moves.
- **The alignment claim is made with a reference for the first time**: impulses go in at three known
  samples and must come out at the same three, searched a whole gap either side so a shift is found
  rather than missed.

## Acceptance criteria

1. **The trim and the file it trims are the same arithmetic**, over a table of reference and stem
   lengths: the layout's parts add up, the filter's `atrim` starts exactly at `startSample` and takes
   exactly the stem, and a track with no reference trims at the processor's own delay.
2. **A track restored from a learned reference comes back in sync, sample for sample.**
3. **Neither side spells the gap out again**: the generator's code names no `2400` and builds from
   `restorationTraining`; `restorationFilter` reads `startSample` rather than re-adding the parts.
4. Reverting either source file fails criterion 3; making the two sides disagree by 600 samples fails
   criterion 2.

- Tests: `packages/generator/test/sound-restoration-training.test.ts`. Verified both ways: on the
  unchanged source the file fails to run at all (`restorationTraining` does not exist), and with the
  fix in place but the generator's gap moved by 600 samples, criterion 2 fails and the other two
  pass — which is the shape of the defect this is about.

## Known gaps this leaves

- **`delayFrames`, `hopFrames` and `tailPaddingFrames` are still read straight from the recipe in
  both files.** They happen to be read rather than spelled out, so there is nothing to fix today, but
  nothing stops the next one being written as a literal either — the guard added here names `2400`
  and this file only.
- **The pinned filter probe still has no reference.** `sound-identity.test.ts`'s `FILTER_PROBE` sets
  `reference: null`, so the prefix branch is not in the pin; adding a second probe would put the
  training layout under HV-024-01's identity pin as well, and that is a change to what that pin
  covers rather than a fix to this.
- **Nothing asserts the gap is long enough for what it is for.** 2,400 samples at 48 kHz is 50 ms of
  silence between the reference and the stem, chosen so the profile has settled; whether it is
  enough is a measurement nobody in this repository has taken.
- **The reference itself is still trusted to be noise.** `assertRestorationReferences` keeps a
  reference out of measured voice windows for dialogue and narration and does nothing for the other
  three tracks, which is what the creator's attestation is for.
