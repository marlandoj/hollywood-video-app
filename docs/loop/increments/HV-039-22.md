# HV-039-22 — The mask viewport told keyboard users to select a handle, and gave them no key to do it

epic: HV-039
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

Found by the HV-039 accessibility audit (`docs/ACCESSIBILITY-AUDIT.md`, 3.3.2, Masks).

The mask viewport is a focusable canvas that the arrow keys operate. Its accessible name told the
creator how:

    MASK_VIEWPORT_LABEL = 'Mask shape editor. Select a handle, then move it with the arrow keys. ' + ...   // mask-viewport.js

Only a pointer could select a handle. `selectedHandle` is assigned in the `pointerdown` handler and
nowhere else, and it starts as `move`, the whole shape:

    ...hit=candidates[0];if(!hit||hit.d>22)return;selectedHandle=hit.id;...   // mask-viewport.js, pointerdown

Take a creator who draws a rectangle mask and resizes it from the keyboard. They focus the viewport,
hear "Select a handle", and press an arrow key. The whole rectangle moves. There is no key that picks
a corner. They can still resize through the coordinate fields beside it, so the function is not
keyboard-inaccessible (2.1.1), but the instruction written for them is wrong (3.3.2). For a polygon,
the editor's "Selected polygon vertex" list worked, but the viewport the arrows act on had no key of
its own for it.

## What this increment does

- **Space selects the next handle, Shift+Space the previous one.** The order is the order the
  viewport already lists handles in: the four corners, then the whole shape, or each vertex round
  the ring. The choice wraps, is announced in the existing live region ("Top-right corner at source
  pixel 240, 45."), and stops Space from scrolling the page.
- **A vertex chosen this way reaches the editor** through `onVertex`, as a pointer's choice does, so
  the vertex list and the X and Y fields follow.
- **Space does nothing while a shape is being drawn**, where Enter and Escape already have meanings,
  **or while mask changes are locked**, as a pointer press does nothing then.
- **The name and the editor's paragraph say so.** `MASK_HANDLE_SENTENCE` is declared once and used
  by both, as HV-039-03 did for the arrow-key steps. The name no longer says "Select a handle, then".

## Acceptance criteria

1. **A corner, from the keyboard.** On a rectangle, Space announces the top-left corner and Space
   again the top-right. ArrowRight then widens the shape by one step: the left edge and the height
   stay, and the announcement gives the corner's new position.
2. **Backwards, and round.** On an ellipse, Shift+Space from the whole shape selects the bottom-right
   corner. Five presses of Space visit the whole shape and all four corners in order. With the whole
   shape selected, an arrow key moves it and keeps its size.
3. **A vertex, from the keyboard.** On a polygon, Space selects vertex 2, tells the editor, and
   announces it. ArrowDown moves only that vertex. Shift+Space twice goes back past vertex 1 to
   vertex 3.
4. **Not while drawing or locked.** While a polygon is being drawn, and while mask changes are
   locked, Space changes nothing and does not suppress the page's own Space.
5. **The instructions match.** The name is "Mask shape editor." plus the handle sentence plus the
   step sentence. The editor's coordinate paragraph builds on the same export.
6. Reverting `mask-viewport.js` and `mask-editor.js` fails criteria 1, 2, 3 and 5.

- Tests: `packages/frontend/test/mask-viewport-handles.test.js`. It mounts the real viewport on the
  same canvas stub as `mask-viewport-a11y.test.js` and dispatches `keydown` events. The HV-039-03
  tests pass unchanged.

## Known gaps this leaves

- **What a screen reader does with Space inside `role="application"` is not verified.** The role
  should pass the key through to the widget. NVDA, JAWS and VoiceOver have not been tried, and the
  audit lists this as open.
- **The handles are still not elements.** A handle is chosen and described through the live region.
  It is not a focusable child with `role="slider"`. HV-039-03 records why `application` rules that
  out for now.
- **A keyboard-drawn shape still starts from a pointer.** "Draw shape in viewport" asks for a drag or
  clicks. A shape can be made from the keyboard only by adding a mask and editing its fields, which
  is the existing alternative.
