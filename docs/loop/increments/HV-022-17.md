# HV-022-17 — The voice vendor's $25 line was each project's own, and forgot a project once purged

epic: HV-022
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

G14 gives ElevenLabs a $25 line for the whole studio, with alerts at $5 and $15. `voiceVendorSpend`
summed that line like this:

```sql
sum(e.total_usd) from hv_cost_events e join hv_jobs j on j.id = e.job_id where <j's vendor>
sum(r.remaining_usd) from hv_reservations r join hv_jobs j on j.id = r.job_id where <j's vendor>
```

Both sums reached the vendor through `hv_jobs`, and that caused two problems:

- **The line was per project.** Admission reads the line as `hv_api` inside `forProject`, and
  `hv_jobs` is row-secured to the admitting project. Every other project's takes were invisible, so
  each project had its own $25. The existing vendor tests read the line as `hv_worker`, which sees
  every row, so they never saw this.
- **A purged project dropped off the line.** `PostgresRetention.purgeProject` deletes a project's
  jobs but keeps its receipts, attempts and unknown-liability holds on purpose. After a purge, a line
  holding $20 spent and $4 held read $0, and a new $20 take was admitted on a $25 line. An invoice
  settled after the purge never counted.

## What this increment does

- **Spend is read from `hv_cost_events` by its provider column.** Every role can read that table
  across projects (`hv_cost_events_api_read`), and retention keeps it.
- **A hold says which vendor it belongs to.** Audio admission writes the vendor into the hold's
  body, in a new optional `provider` field on `BudgetReservation`. `hv_reservations` is also
  readable across projects, and retention keeps it.
- **Holds written before this change carry no provider.** They are still found through their job or
  attempt, which the admitting project can see for its own takes.

## Acceptance criteria

1. **Another project's takes are on the line when a project admits against it.** The line reads
   $20 spent and $4 held both as the worker and as `hv_api` inside a project with no takes of its
   own.
2. **They stay on the line after that project's content is purged**, with its jobs gone. The line
   reads the same from both roles.
3. **A hold written by admission's path records its vendor.** A hold from before, with no vendor,
   is still counted through its own project's job. Another vendor's line is untouched.
4. Reverting `audio-ledger.ts`, `ledger.ts` and the `BudgetReservation` field fails all three.

- Tests: `packages/storage/test/voice-vendor-line.test.ts`. It needs PostgreSQL only (the admin, API
  and worker URLs), and CI provides it. Locally it was run against a throwaway PostgreSQL 16
  migrated with the real schema, and passes 3 / 0.

## Known gaps this leaves

- **Holds opened before this deploy by other projects** carry no vendor, and `hv_api` cannot see
  their jobs. They are not on another project's reading of the line until they settle or are
  released, which happens within a take's lifetime.
- **Other ledgers** were checked for the same join through `hv_jobs`, and `lipsync-ledger.ts` has
  none. The film limit (`filmSpend`) is per project by design, so reading it within the project is
  correct.
