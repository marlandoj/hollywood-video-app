# HV-016-02 — The importer's own reading of a hostile file

epic: HV-016
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

A critic pass over HV-016-01 found four defects in the importer I had just merged. The first is
serious, and the other three are the exact failure the module was written to prevent.

**The reader was quadratic.** Both scans had the shape `<Tag[^>]*>`: at every position where the tag
name matched, `[^>]*` ran to the end of the buffer and backtracked. Measured through the exported
function:

| `<Content` repeated | |
|---|---|
| 50,000 | 3.25 s |
| 100,000 | 10.44 s |
| 200,000 | 46.57 s |

Fourfold per doubling. At the importer's own 4 MiB limit that is **minutes of blocked event loop for
one request**, on a single-threaded server, from an authenticated route with no concurrency guard.
Every guard ahead of it passes: such a document is under the size limit, has no `<!DOCTYPE`, and
carries `DocumentType="Script"`. The increment doc said "bounded at every step"; the bounds capped
the *input*, and nothing capped the *work per byte*.

Then three silent losses, each the thing the module's own header says it exists to prevent:

- **A script note became action.** Final Draft nests `<Paragraph><Text>` inside `<ScriptNote>` inside
  an action paragraph, and the reader harvested every `<Text>` in the span. "TODO: rewrite this beat"
  was concatenated onto the action line — with no space, no note and no refusal — and action becomes
  the shot prompt, and a speech becomes a voice read and a burned-in caption. A writer's private note
  could have ended up in the film.
- **A heading that was already forced lost its scene.** `.THE VOID` became `..THE VOID`, which
  Fountain reads as an escape rather than a forced heading. Three headings in, two scenes out, no
  warning.
- **Control characters 11–31 passed through**, by entity and literally, into text offered to the
  writer to paste straight into the screenplay. Every other ingest point in this codebase refuses
  them.

## What this increment does

- **Every tag is found by scanning, not by matching.** `indexOf` for the open, the `>`, and the
  close, with a boundary check so `<Contents>` is not read as `<Content>`. The two header probes are
  scanned the same way, because a pattern anchored on a tag name is linear *per occurrence* and a
  hostile file can hold three hundred thousand of them. The bound on the input is now also the bound
  on the work.
- **`<ScriptNote>` is removed before anything is read**, and reported: *"1 script note was not
  imported. They are notes to yourself, and importing them would put their words in the film."* A
  paragraph nested any other way is refused by name, and so is an unclosed one.
- **A heading keeps one dot.** Leading dots are stripped before the forced-heading rule runs, and a
  heading of nothing but dots is refused as empty.
- **Every control character is refused**, by entity or literally, in one predicate used by both
  paths — tab, newline and carriage return excepted, because those are text.

## Acceptance criteria

1. **A hostile document is bounded in time as well as in size.** Four pathological shapes — an
   unterminated `<Content`, `<Paragraph`, `<Text` and `<FinalDraft`, each at 300–400 thousand
   occurrences — are each refused in under two seconds, and a real script of nineteen thousand
   paragraphs is read in the same breath.
2. **A script note is not imported and does not become part of the film**: its words are absent from
   the screenplay, the action around it is intact, and the note says how many were left out. A
   paragraph nested any other way, and an unclosed paragraph, are refused by name.
3. **A heading the writer already forced keeps one dot and its scene survives** — three headings in,
   three scenes out — and a heading of only dots is refused.
4. **Every control character is refused**, as `&#11;` through `&#31;`, as `&#x1b;`, as `&#0;`, in the
   `0x7f–0x9f` range, and as a literal byte in a `<Text>` run; tab, newline and carriage return
   survive as themselves.
5. **Nothing else changes.** The HV-016-01 criteria all still hold, with their original tests
   unedited.

- Tests: `packages/parser/test/final-draft.test.ts` (the four new cases, alongside the original four).

## Known gaps this leaves

- **The route still has no concurrency guard.** One import is now fast; a hundred at once are a
  hundred decodes. The reference upload route bounds itself to two at a time and this one should
  borrow that, which is a change to the route rather than to the reader.
- A paragraph with bare text and no `<Text>` run is still skipped silently. Real Final Draft always
  wraps its text, so this has no known trigger, but it is not a refusal and should be.
- PDF import is still not built, and no export exists.
