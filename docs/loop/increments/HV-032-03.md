# HV-032-03 — Name the supervisor once, so staging can leave Zo

epic: HV-032
release: 1 (build order step 1)
spend_usd: 0

## Goal

Make the staging scripts run on any Linux host with its own supervisord, by turning Zo's supervisor path and XML-RPC endpoint into two settings whose defaults are Zo's. Nothing changes on Zo.

## Why now

Release 1 moves private staging to the operator's desktop (`docs/STAGING-LOCAL.md`, G10-202609191100). Seven scripts named `/etc/zo/supervisord-user.conf` directly, and one named Zo's supervisor XML-RPC port `29011`:

| file | form |
|---|---|
| `scripts/bootstrap-storage-platform.py` | module `CONFIG` |
| `scripts/storage-runtime-launch.py` | module `CONFIG` (also used by `deploy-storage-staging.py` and `configure-observability.py`) |
| `scripts/observability-runtime.py` | module `CONFIG` |
| `scripts/prepare-postgres.py` | local `config` |
| `scripts/prepare-object-storage.py` | local `config` |
| `scripts/deploy-private-staging.py` | inline `supervisorctl -c` argument |
| `scripts/storage-wave-a-evidence.ts` | exported `SUPERVISOR_CONFIG` (also read by `observability-exit-evidence.ts`) |
| `scripts/deploy-storage-staging.py` | `ServerProxy("http://127.0.0.1:29011/RPC2")` |

A host without that file cannot bootstrap storage, deploy, or collect evidence.

## What this increment does

- **`scripts/host_config.py`** is the one place that knows the supervisor: `supervisor_config()` reads `HV_SUPERVISOR_CONFIG`, `supervisor_rpc_url()` reads `HV_SUPERVISOR_RPC_URL`. Unset, they return Zo's values.
  - The path must be absolute, with no surrounding whitespace. A relative one would resolve against whatever directory a wrapper started in.
  - The RPC URL must be `http` on loopback with an explicit port. These scripts stop and start the studio's services, and must not be pointed at another machine.
- **`scripts/host-config.ts`** is the TypeScript half, for the evidence collectors, with the same default and the same refusals.
- **Each script loads the module by path** (`Path(__file__).with_name("host_config.py")`), the way the scripts already load one another. So it works however the script was started, from a release directory included.
- **Documentation:**
  - `docs/STORAGE-BOOTSTRAP.md` gains "Which supervisor".
  - `docs/STAGING-LOCAL.md` records what the operator setup actually did. It differs from the first plan in several places: the Debian 12 image source, NAT networking, masked units, the connectors, and the token's scope.

## What this increment does not do

- **It does not install anything on the new host or change Zo.** Provisioning is build order step 4.
- **It leaves test fixtures and historical increment docs that quote `/home/workspace/...` as sample values alone.** They describe Zo runs that happened.
- **It does not change `scripts/loop/loop.env` or `scripts/loop/alert.sh`.**
  - `LOOP_STAGING_ROOT` is already a setting and moves at cutover.
  - The alert script's Zo mail skill is guarded by `[ -x … ]`, so it does nothing elsewhere.
- **The Python and TypeScript halves are held to the same default by reading `host_config.py`'s source text, not by a shared file.** A shared JSON file would be one more thing the release directory had to carry.

## Acceptance criteria

1. **Unset, both settings are Zo's.** The three module-level `CONFIG`s equal `/etc/zo/supervisord-user.conf`. Tests: `scripts/test_storage_bootstrap.py` `HostConfigTests` (unset, every-script) and `packages/storage/test/host-config.test.ts` (unset).
2. **Set, every script that registers programs uses the variable**, including the TypeScript collector freshly imported. Tests: `test_every_script_that_registers_programs_reads_the_setting` and the collector case in `host-config.test.ts`.
3. **The two settings refuse bad values.**
   - A relative, empty or whitespace-padded path is refused, in both languages.
   - An RPC URL off loopback, without a port, over https or unix, or on a lookalike host (`127.0.0.1.evil.example`) is refused.
   - Tests: the refusal cases in both suites.
4. **No script other than the two host-config modules names `/etc/zo` or `29011`.** Every Python script that runs `supervisorctl` takes its file from the setting, directly or through the launcher's `CONFIG`, and assigns no `config = Path(…)` of its own. Tests: `test_no_script_names_the_zo_supervisor_itself`, `test_every_script_that_drives_supervisor_asks_the_setting_for_its_file`, and the scan case in `host-config.test.ts`.
