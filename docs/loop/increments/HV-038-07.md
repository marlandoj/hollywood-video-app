# HV-038-07 — An anonymous request re-read the whole studio before asking whether it was allowed to

epic: HV-038
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

A critic pass over the API's anonymous surface.

`GET /api/reviews/:token` and `POST /api/reviews/:token/decision` are the only routes this studio
serves without a bearer token — a review link is how a creator shows their film to someone who has
no account, because nobody here has an account. Both of them did this:

```ts
openReviewLink(token, viewer, now) {
  this.reload();                                   // re-parse and re-validate every project
  const link = this.reviewLinks.get(token);
  if (!link || link.revoked) return null;
  const payload = verifyToken(token, now);         // ...and only now, is this even a token?
```

`reload()` re-reads the state file and runs `loadState`, which rebuilds **every project in the
studio** and re-validates each one — `validateReference`, `validateDirection`,
`validateMotionStudies`, `structuredClone`. The decision route pays for it twice, once in
`peekReviewLink` and once in `submitReviewDecision`.

Measured through the real server, with a token that is not a token at all — 83 `a`s:

| projects | state bytes | `GET /reviews` | `POST /decision` |
|---|---|---|---|
| 250 | 132,349 | 19.0 ms | 40.0 ms |
| 500 | 264,599 | 48.1 ms | 103.8 ms |

Linear in the studio. The api bucket is **120 requests a minute**, so at 500 projects one address's
*allowed* budget is about **12.5 seconds of blocked event loop per minute** on a single-threaded
server, from requests that are all 403s. A free, account-less studio is designed to accumulate
projects, so it is a number that only goes up; at 2,000 projects the same budget was measured at 49
seconds of wall clock, which is more than the minute it is spread over.

And the same reload sits behind two other anonymous-ish routes: `GET /health`, which also
materialises every job in the shared store, and every signed `/artifacts/` media fetch, which does
both — a project reload and a jobs reload — on URLs handed to review-link viewers, in a bucket of
600 a minute.

The obvious fix is the wrong one, and that is the interesting part. `reload()` looks like it wants a
`stat` guard — `writeJsonFile` publishes by `rename`, so an unchanged inode, mtime and size ought to
mean the same bytes. **It does not.** `packages/api/test/project-historical-cache.test.ts` already
establishes two invariants a guard like that breaks:

- *"external same-size and same-mtime writes … are observed immediately"* — the test writes a
  replacement of exactly the same length and restores the old mtime with `utimesSync`, and requires
  the change to be seen. A stat-based guard serves the old bytes.
- *"unchanged disk rebuilds mutable projects, histories and VersionStore without exposing cache
  references"* — callers mutate what `authorize()` hands them, so the rebuild on every read is
  load-bearing, not waste.

Someone reached this ground before, decided what it costs, and wrote the tests down. So what is left
is the thing that was simply in the wrong order.

## What this increment does

**The signature goes first**, in all four review-link methods — `openReviewLink`, `peekReviewLink`,
`submitReviewDecision`, `bindReviewLink`. Each of them already verified the token; each did it
*after* reading the studio. The now-redundant second `verifyToken` in each was removed rather than
left to drift out of agreement with the first.

That is the whole change: eleven lines in one file.

```
                      before (500 projects)   after
GET  /api/reviews      48.1 ms                 0.1 ms
POST /api/reviews/…    103.8 ms                0.1 ms
```

Nothing about what any route answers changes. A caller who *does* present a valid signature reaches
exactly the state it always did, at exactly the cost it always did — which is the point of the
second test below.

## Acceptance criteria

1. **A request with no valid token costs the same whether the studio holds thirty projects or a
   hundred and twenty**, for both routes, measured on one machine as a growth ratio rather than
   against a number, so the assertion does not depend on the runner. The decision route, which paid
   twice, is asserted separately.
2. **It is refused without the studio's state being read at all**, timing-free: with the state file
   truncated, both anonymous routes answer 403, while an owner route — which must read the state —
   fails by name with `is unreadable` (HV-038-06). That contrast is what says the refusal came from
   the signature and not from a shortcut that would refuse a real link too.
3. **A token that is merely well-formed is still refused**, over four shapes — nothing, an owner
   token, a valid review signature for a link this studio never issued, and an expired one — on
   both routes. Reordering a check is the kind of change that turns a refusal into an acceptance,
   and this is what says it did not.
4. Reverting `index.ts` makes 1 and 2 fail; 3 passes either way, which is its job.

- Tests: `packages/api/test/anonymous-cost.test.ts`.

## Known gaps this leaves

- **The reload is still the reload.** An authenticated request still rebuilds and re-validates every
  project in the studio, and the two invariants above are why this increment does not touch it.
  Making that cheap means separating the parse from the rebuild — keeping the parsed state and
  re-deriving only the mutable half per call — and that is a change to `loadState`'s shape, with
  those two tests as its acceptance criteria.
- **`GET /health` still materialises every job in the shared store**, anonymously, at 120 a minute;
  measured by the same pass at 51 ms per call with 2,000 jobs, and 6.4 s of blocked loop for one
  address's minute. Serving `queueDepth` and `runningJobs` from maintained counters is the fix.
- **Every signed `/artifacts/` fetch does both reloads** — the project state and the jobs store — in
  a bucket of 600 a minute, on URLs handed to review-link viewers and valid for 30 days. Measured at
  28.5 ms each with 1,501 jobs, against 55 ms total for 600 *unsigned* probes, which is where the
  cost is: entirely behind the signature check.
- **The state file is still rewritten whole on every save**, which is why these numbers grow with
  project count at all, and is the JSON deployment's ceiling.
- **This is the JSON deployment.** `PostgresProjectService` does not reload a file and never had
  this cost; staging runs PostgreSQL. What runs the JSON path is `createApiServer()`'s default and
  `docker-compose.yml` — the same pairing that made HV-029-06's leak reachable.
