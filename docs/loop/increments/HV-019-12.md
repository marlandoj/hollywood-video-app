# HV-019-12 — The lease-loss pipeline test failed the merge gate at random

epic: HV-019
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

`packages/storage/test/pipeline.test.ts` › "lease loss aborts the active provider and prevents
secondary inference" failed CI twice on 2026-09-28, on PRs #267 and #271, neither of which touches
the queue:

```
expect((await processing)!.claimedBy).toBe("new-worker");
Expected: "new-worker"
Received: null
```

The test starts a render on an "old" worker with a 150 ms lease. It advances the **old worker's
clock** by 500 ms, then has a replacement worker claim the job. But the old worker renews its lease
on a real 50 ms timer, reading that same clock. When the timer fired between the clock change and
the claim, the old worker saw its own lease expired and gave the job up before anyone had claimed
it, so it returned the job unclaimed. Whether it did depended on how fast the runner reached the
claim.

## What this increment does

- **The replacement claims on its own clock, 500 ms on.** The old worker's clock is left alone, so
  it learns of the loss only from the claim, which is the path the test is about.
- **A 120 ms pause before the claim** stands in for a slow runner.

## Acceptance criteria

1. **The test passes with a slow claim.** With the 120 ms pause, the replacement claims the job, the
   old worker's provider is aborted, the provider was called once, and the old worker returns the
   job as claimed by the new worker. It passed on each of three local runs against PostgreSQL 16.
2. **The old arrangement fails with the same pause.** Advancing the old worker's clock fails the
   test deterministically, on both of two runs.

- Tests: `packages/storage/test/pipeline.test.ts` (PostgreSQL-gated).

## Known gaps this leaves

- **Test-only.** The worker's behaviour is unchanged. A worker that sees its own lease expire before
  a replacement claims the job gives the job up. That is correct, and it is a different path from
  this test's.
