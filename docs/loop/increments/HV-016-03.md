# HV-016-03 — The bound on the input was not a bound on the work

epic: HV-016
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

A critic pass over the Final Draft importer, merged yesterday, found four defects. Two of them are
the kind this file's own header says it exists to prevent, and one of those is reachable from a
route by anyone with a project.

**The 4 MiB bound was not a bound on the work.** `collapse` ran on every paragraph and its second
pass was `value.replace(/\s*\r?\n\s*/g," ")`, which is quadratic on a run of whitespace that is not
a newline: at every position the leading `\s*` eats the whole run, fails on the newline, and
backtracks one character at a time. The first pass collapsed spaces, tabs and non-breaking spaces
and **not carriage returns**. Measured:

| input | before |
|---|---|
| 4,000 CR | 10.1 ms |
| 8,000 CR | 40.2 ms |
| 16,000 CR | 160.9 ms |
| 19,980 CR — inside the 20,000-character paragraph bound | 257.1 ms |

Two hundred of those paragraphs is 3.82 MiB of document, inside the 4 MiB bound, and 8,002,580 bytes
of JSON once the carriage returns are escaped — inside the route's own 8 MiB body limit.
`POST /api/projects/:id/script/import` took **54.4 seconds of blocked CPU** on it. The work is
synchronous and checks no abort signal, so the socket idle timeout disconnects the client while the
server keeps burning; the requests can be fired and forgotten.

HV-016-02's header says: *"Every search here is a linear `indexOf`, and the bound on the input is
therefore also a bound on the work."* The tag scanning was fixed. The whitespace normalizer that runs
on every paragraph was not.

**A script note inside another script note put its words in the film.** `element` takes the first
close tag after the open one, so with a nested note that close belongs to the *inner* note: removal
stopped there, and everything between the inner close and the outer close survived into the
screenplay — reaching the shot prompt, to be spoken and captioned, which is the exact harm the code
comment beside it names. And the creator-facing note reported one note removed. **The words reached
the film and the report said they had not**: both halves of this epic's rule broke at once.

**A `<Text>` run that is never closed silently dropped the rest of the paragraph.** `element` answers
null both for "no more runs" and for "one opens and never closes", and the loop read both as done.
`<Text>the bomb is under the table</Paragraph>` imported as an empty paragraph, with no note.

**An element name longer than two hundred characters stepped around the refusal.** The `{0,200}` cap
is on the *match*, so a longer value made the pattern fail and the `??"General"` fallback imported
the paragraph as action. `Type="Lyrics"` is refused by name; `Type="AAA…"` (201 characters) was not.

## What this increment does

- **`collapseFinalDraftText` is a scan**, not three replacements: two inner loops over the string,
  no regex, the same six characters collapsed as before and no others. The 54-second document reads
  in **49 ms**.
- **A nested script note is refused by name**, rather than guessed at. Flattening the notes or
  exporting as Fountain is what the message says.
- **An unterminated `<Text>` run is refused.** `opens()` tells "no more" from "never closed", which
  every caller of `element` now has to do for itself, and the one that did not is why this is here.
- **A `Type` attribute the pattern cannot read is refused**, whether it is too long or its quote is
  never closed. A paragraph with no `Type` at all is still General, which is what Final Draft means.
- **The route refuses a project past its deletion date**, as every neighbouring project route does
  and this one did not.

## Acceptance criteria

1. **A bound on the input is a bound on the work**: 19,980 carriage returns normalize in under 50 ms,
   and a 4 MiB document made of two hundred such paragraphs imports in under five seconds. Both are
   asserted with the timing, because the defect was a timing and nothing else would have caught it.
2. **The six characters the old pass collapsed are the six it collapses**, and a thin space is still
   a character the writer typed.
3. **A nested script note is refused**, and an ordinary one is still removed and still reported.
4. **An unterminated text run is refused**, in both the whole-paragraph and the half-paragraph shape,
   and a paragraph with no text is not mistaken for a malformed one.
5. **An unreadable `Type` is refused** — too long, and unterminated — while `Lyrics` is still refused
   by its own name and a typeless paragraph is still General.

- Tests: `packages/parser/test/final-draft.test.ts` (1–5).

## Known gaps this leaves

- **The import route has no concurrency guard.** Reference adoption refuses a second simultaneous
  upload; this route does not. With the work now linear in the input that is a much smaller thing
  than it was, but a 4 MiB import is still the largest synchronous read a project can ask for, and
  nothing stops ten of them at once.
- **The timings are this machine's.** The 50 ms and the 5 s in the test are generous bounds chosen so
  they fail on a return of the quadratic and not on a slow CI runner; they are not a performance
  budget and should not be read as one.
- **Nothing was found wrong with the entity decoder, the tag scanner or the paragraph walk**, which
  were HV-016-02's subject. The defects here are all in code that pre-dates or sits beside that
  rewrite.
