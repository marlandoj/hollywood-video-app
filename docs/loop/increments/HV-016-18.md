# HV-016-18 — The Director's desk waited on a stuck render for as long as the tab stayed open

epic: HV-016
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

HV-030-08 gave the studio's `pollJob` a ceiling. The Director's desk has its own `pollJob` in
`index.html`, and it had none:

    async function pollJob(jobId) {
      while (true) {
        const job = await api(`/api/jobs/${jobId}`, { headers: authHeaders() });
        if (job.status === "done") return job;
        if (job.status === "failed" || job.status === "cancelled") throw ...;
        setStatus(...);
        await new Promise((resolve) => setTimeout(resolve, 1500));
      }
    }

Create film, Approve and generate, and a reopened project link all wait on it. A job that never
reaches a terminal status (queued with no worker registered, or a queue that stays saturated) was
polled every 1.5 s, 2,400 requests an hour, for as long as the tab stayed open. Create film stayed
disabled the whole time. The only way out was a reload, and nothing told the creator the render was
still on the server.

## What this increment does

- **The desk keeps the studio's clock.** It counts polls in which neither the status nor the
  checkpointed shot count changed; a change to either resets the count. The count ends at the
  studio's `STALL_LIMIT_MS`, read from the studio module the page already imports. That is thirty
  minutes, the queue's lease clock (`DEFAULT_LEASE_MS` × (`MAX_LEASE_RECOVERIES` + 1)), which
  HV-030-08 derived and `poll-ceiling.test.js` guards. The desk therefore does not keep a second
  copy of the number. The poll count is computed from the desk's own interval, so if the interval
  changes the ceiling is still half an hour.
- **The message says where the render is, not that it died.** It names the status and the job id,
  says the render is retained on the server, and says asking again is free. The error reaches the
  desk's existing catch, which re-enables Create film.

## Acceptance criteria

1. **A render that never moves stops being polled at thirty minutes.** There is one first poll and
   then 1,200 polls that saw no change, each after a 1,500 ms wait (exactly thirty minutes of
   waiting), and then no more polls. The status names `queued` and job `j1`, says the render is
   retained and that asking again is free, and does not call it a failure. Create film is enabled.
2. **A render that keeps moving is waited on as long as it moves.** A shot finishes every 1,000 polls
   for three shots, which is 3.5 windows in all, and the desk keeps polling. The ceiling then counts
   from the last finished shot.
3. **A status change resets the clock.** The job is queued, then running, then queued again, each
   for under a window. The ceiling counts from the last change.
4. Reverting `index.html` fails criteria 1, 2 and 3. Without the fix, polling runs past each
   ceiling.

- Tests: `packages/frontend/test/desk-poll-ceiling.test.js`. It runs `index.html`'s own module script
  through `packages/frontend/test/desk-page.js`, with the page's `setTimeout` recorded, not slept.

## Known gaps this leaves

- **"Asking again is free" depends on HV-030-18.** On `origin/main` the desk still sends a random
  `idempotencyKey`, so a second Create film would be admitted as a new render. HV-030-18 removes that
  key, which makes the message true. Ship the two together, or ship HV-030-18 first.
- **The desk does not resume a wait it gave up on.** After the ceiling, the render may still finish
  on the server. Reopening the project link picks it up (`resumeProject` polls the active job). The
  open page does not, until the creator asks again.
- **The desk's other harness does not supply the ceiling.** `studio-resume-desk.test.js` stubs the
  studio module with only `initStudio`, so in that test the desk has no ceiling. It never waits long
  enough for that to matter. `desk-page.js` passes the real `STALL_LIMIT_MS`.
