# HV-039-14 — Picture editorial dropped keyboard focus to the page body after every edit

epic: HV-039
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

The picture editorial desk is drawn by `drawEditor()`, and the first thing it does is
`editor.replaceChildren()`. The "Selected clip" list, every tool section and every button are thrown
away and built again, and two ordinary actions reached it while the creator's focus was inside it:

```js
choose.onchange=()=>{...selectedClip=choose.value;drawEditor();};
const button=(label,action)=>{...e.onclick=()=>run(action);...};
```

- **Choosing a clip destroyed the list being used.** On Windows the arrow keys on a closed `<select>`
  fire `change` on every press, so a keyboard user moving through "Selected clip" lost the list at
  the first arrow and was sent to the start of the page.
- **Every saved edit ended the same way.** Split at frame, Move to frame, Apply trim, Apply clip
  settings, Save crossfade, Remove marker, Undo saved edit, Open this branch and Discard unsaved
  fields all go through `run()`, which disables the panel's controls while the request is out — so
  the browser has already moved focus off the pressed button — and then through `sendEdit()` to
  `drawEditor()`. When the request finished the button no longer existed, focus was on the page body,
  and every tool section the creator had opened was closed again except the default-open
  "Split, move and trim".

A creator trimming a clip by keyboard had to tab back from the top of the page through the preview,
the screenplay links and the assembly panels, and reopen "Levels, opacity, crop and fades", after
every single saved change. That is WCAG 2.4.3 Focus Order (A). HV-039-04 fixed the same defect on the
front door and listed the Director's desk panels as not looked at; this is the densest of them.

## What this increment does

- **What to come back to is taken before anything is disabled.** `button` hands `run` the pressed
  button's words, and `run` stores them as `returnTo` after its guards and before
  `controlLocks.acquire('busy', …)`. The "Selected clip" list sets `returnTo` to itself before it
  redraws.
- **`drawEditor()` spends it.** It notes which `<details>` in the desk are open (by summary text)
  before replacing them, reopens the matching new sections at the end, and focuses the new
  "Selected clip" list or the first enabled, visible button with the same words, opening any closed
  section it sits in. When that control is gone, disabled or hidden — Undo after undoing to the
  original sequence — focus goes to the sequence heading, an `<h3>` now given `tabIndex = -1`, rather
  than the page body.
- **`run` clears it in `finally`.** An edit that failed, or finished without redrawing, cannot leave
  a target behind for a later redraw that the creator did not cause with a desk button. A redraw
  inside the action still sees it, because `finally` runs after the action.
- Redraws with no `returnTo` — opening picture editorial, choosing a clip from the screenplay links —
  do not move focus or reopen sections, as before.

## Acceptance criteria

1. **Choosing another clip leaves the creator on the list**: after `change` on "Selected clip" the
   old list is out of the page, focus is on the new "Selected clip" list, and it shows the clip that
   was chosen; a second change behaves the same.
2. **A saved edit returns focus to the control that made it**: after "Apply clip settings" saves, focus
   is on the redrawn, enabled "Apply clip settings" button; "Levels, opacity, crop and fades" and
   "Speed ramps and freeze frames", which the creator had opened, are open again; a section that was
   closed stays closed.
3. **A control that cannot take focus after its edit sends the creator to the sequence heading**:
   after undoing back to the original sequence the new "Undo saved edit" is disabled, and focus is on
   the "Parent cut" `<h3>`, which has `tabIndex = -1`; the opened "Redo and branch history" section is
   still open.
4. **A failed edit leaves nothing behind**: after "Apply clip settings" fails without a redraw,
   selecting a clip from the screenplay links redraws the desk without moving focus off the link the
   creator pressed.
5. Reverting `editorial.js` fails criteria 1, 2 and 3. Criterion 4 guards the fix's own hazard and
   passes on the old code, which never moved focus at all; removing only `returnTo=null` from `run`'s
   `finally` fails it. Removing only the section reopening fails 2 and 3.

- Tests: `packages/frontend/test/editorial-focus.test.js`, mounting the real `initEditorial` on the
  editorial tests' DOM stub with a `focus()` that records `document.activeElement`, against a fake API
  that applies each saved edit with the planner's own `appendEdit` and `moveEditCursor`.

## Known gaps this leaves

- **A failed edit still leaves focus where the browser put it.** `run` disables the pressed button
  while the request is out, and a browser moves focus off a control that becomes disabled; when the
  edit fails nothing is redrawn and nothing returns focus to the button, which is still there. The
  error is announced by the status region, but the creator is on the page body.
- **Masks and mattes are not covered.** "Apply masks and mattes" saves through the mask editor's
  `onSave`, which calls `run` without a return target, so it redraws the desk and focus is lost as
  before. The mask editor's own buttons are not built by `button`.
- **Buttons outside the desk land on the heading.** "Open sequence", "Refresh saved state",
  "Create sequence" and "Retry the same saved request" redraw the desk but are not in it, so focus goes
  to the opened sequence's heading. That is where the creator wants to be after opening a sequence,
  but "Refresh saved state" would be better returned to itself.
- **Matching is by the words on the control.** If two desk buttons ever carry the same words, focus
  goes to the first enabled one, not necessarily the one that was used. "Remove marker …" names its
  marker, so after a removal its button is gone and focus goes to the heading. Section matching is by
  summary text too, so a per-layer section whose summary counts ranges will not reopen once its count
  changes.
- **Only the picture editorial desk is covered.** The other Director's desk panels still replace their
  own subtrees without returning focus.
