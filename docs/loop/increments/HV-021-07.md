# HV-021-07 — The continuity report and its one repair reach the Director's desk

epic: HV-021
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

Release 2 promises the Continuity Supervisor's "drift detection and one-click repair". Both halves
existed only in the API:

- `GET /api/projects/:id/direction` has returned a `continuity` report since HV-021-01.
- `POST .../direction/continuity/repair` and `.../repair/accept` have existed since HV-021-02.

No page showed either. `grep continuity packages/frontend/src` found only a coverage disclaimer and
a cast-desk heading. HV-021-02 said so in its own Known gaps: *"No frontend control ships here."*
A creator could not see a drift finding or press the repair. Three later increments (04, 05, 06)
fixed what the repair says and proposes, and no creator could read any of it.

## What this increment does

- **A Continuity panel on the shot-direction desk** (`packages/frontend/src/continuity.js`). It draws
  the report the desk already loads, grouped by scene. Each finding reads as its severity and kind in
  words, then the server's sentence, then the shots it names. A count sits above it. An empty report
  says there is nothing to fix, and if nothing was declared that could be compared, it says that is
  not a pass.
- **Review continuity repair** shows the summary, each edit (shot, field, from what to what) grouped
  by scene, and the notes on what is left to the creator. Reviewing changes nothing. When the server
  says no repair can be made, the panel shows the reason and keeps the report.
- **Apply continuity repair** posts the reviewed edits unchanged, with the direction version, the
  screenplay version and the shot tier they were reviewed under. The server already refuses any edit
  set that differs from its own. A 409 says the direction changed, sets the review aside and reloads
  the report; it is not retried. A successful apply reloads the desk, so the report shown is the new
  one.
- **A review is bound to the direction it was read from.** If the desk is behind the server when the
  review comes back, or the desk later reloads onto another direction, the review is set aside
  rather than applied under a version it doesn't belong to.
- **Accessibility**: a `section` labelled by its `h3`, real `type="button"` buttons, a `role="status"`
  line, and `aria-busy` through `busy.js`, so the status stays outside the busy state. Buttons are
  disabled while a request is out and a second press is ignored.
- The API serves the new module at `/api/direction/continuity.js`. That is one path added to the
  existing allowlist in `server.ts`; nothing else in the backend changes.

## Acceptance criteria

1. **The report is grouped by scene**, each finding in words with its severity, under a count of
   warnings, unknowns and notes. Server text is DOM text, and the panel never writes markup.
2. **An empty report says there is nothing to fix**, and a film with nothing to compare isn't
   called a pass.
3. **Reviewing shows the summary, the notes and every edit from what to what, and applies nothing**:
   one POST to `/continuity/repair` with the shot tier, no accept, and the direction unchanged.
4. **When no repair can be made**, the server's reason is shown, nothing is offered to apply, and the
   report stays.
5. **Applying sends exactly the reviewed edits and versions**, in the same order, then reloads the
   report, which no longer holds the repaired drift.
6. **A 409 on apply says the direction changed, reloads the report, and doesn't retry.** One accept
   request, and the stale review is gone.
7. **A desk behind the server's direction reloads** rather than offering a repair bound to another
   version.
8. **The panel is a headed region with real buttons and a live status outside the busy state**, and
   pressing twice sends one review and one apply. An open shot edit holds the repair back.
9. **The Director's desk draws the panel from its own load** and routes its requests through the
   desk's direction path.
10. Reverting `continuity.js`, `direction.js` and `server.ts` fails `continuity-desk.test.js`,
    `frontend-modules.test.ts` and `busy.test.js`. Reverting only `direction.js` fails criterion 9.

- Tests: `packages/frontend/test/continuity-desk.test.js` (1–9, 12 tests). Updated honestly:
  `packages/frontend/test/busy.test.js` (the importers of `busy.js` now include `continuity.js`) and
  `packages/api/test/frontend-modules.test.ts` (the pinned set of served modules now includes
  `/api/direction/continuity.js`). The frontend package passes (372 / 0), and so do the API
  continuity, repair-route and frontend-module suites (8 / 0).

## Known gaps

- **The repair's headline still names a code.** The panel shows the server's summary as-is, so a
  contradiction reads "time-contradicts-heading" there (HV-021-05's gap). The finding list beside it
  names each kind in words; the headline doesn't.
- **The kind labels live in the frontend.** `CONTINUITY_KINDS` covers the six codes the report emits
  today. A new code shows as its raw name until someone adds a label there.
- **There is still no Continuity Supervisor persona.** The panel sits on the shot-direction desk. The
  crew member who offers the repair in the studio's conversation is still waiting on the decision in
  `claude/HV-021-03-plan.md`.
- **The desk follows the 24-shot plan**, as the rest of it does. The panel sends the desk's own
  `maxShots`, so a 60-shot review is reachable only where the desk itself loads that plan.
- **Checked on the repository's DOM stub, not in a browser or screen reader.** The live-region and
  busy behaviour is asserted structurally, the same way `busy.test.js` does it.
