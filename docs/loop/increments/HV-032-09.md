# HV-032-09 — The staging scripts stop assuming Zo

epic: HV-032
release: after Release 3 (housekeeping; no release criterion)
gate: none new (follows G10-202609191100, which moved staging off Zo)
spend_usd: 0

## Why

Zo no longer exists (2026-11). Staging moved to the operator's desktop on 2026-09-19 (G10,
`docs/STAGING-LOCAL.md`), and the headless conveyor was retired on 2026-09-14
(`docs/loop/HANDOFF-2026-09-14.md`). The scripts still carried Zo as a default:

- `scripts/host_config.py` and `scripts/host-config.ts` answered an unset `HV_SUPERVISOR_CONFIG`
  with `/etc/zo/supervisord-user.conf`, a file no host has now. A staging script run without
  `/etc/rough-cut/host.env` sourced would hand `supervisorctl` that path and fail with a message that
  names neither the setting nor the fix.
- The constant that held the supervisor's RPC URL was called `ZO_SUPERVISOR_RPC_URL`, though the
  desktop's supervisor listens on the same loopback port and the provisioner reads the port from it.
- `scripts/loop/service.sh` sourced `/root/.zo_secrets`; `scripts/loop/alert.sh` tried a Zo
  workspace skill to send email. Both belong to the retired conveyor.
- `docs/loop/EXECUTION-LOOP.md` and `PROGRESS.md` did not say where the build runs now, and
  `PROGRESS.md` still said Release 3 was next.

## What this increment does

- **`HV_SUPERVISOR_CONFIG` is required.** Unset, `supervisor_config()` / `supervisorConfig()` raise
  `HV_SUPERVISOR_CONFIG is not set: source /etc/rough-cut/host.env, or name the host's supervisord.conf`.
  The refusals of a relative or padded path are unchanged.
- **The setting is read when it is used, not when a module loads.** The three Python drivers that
  held `CONFIG = host_config.supervisor_config()` at import (`bootstrap-storage-platform.py`,
  `storage-runtime-launch.py`, `observability-runtime.py`) now call `supervisor_file()` at each use,
  and keep `module.CONFIG` available lazily through a module `__getattr__`, which
  `deploy-storage-staging.py` reads as `runtime.CONFIG`. `storage-wave-a-evidence.ts` exports
  `supervisorFile()` in place of the `SUPERVISOR_CONFIG` constant, and `observability-exit-evidence.ts`
  uses it. Without this, failing closed would have made every test that imports these modules need
  a host.
- **`HV_SUPERVISOR_RPC_URL` keeps its default**, renamed `DEFAULT_SUPERVISOR_RPC_URL`
  (`http://127.0.0.1:29011/RPC2`): it is loopback-only, and it is the port the desktop's supervisor
  listens on, so the default is right on every host the studio has run on.
- **Retired conveyor scripts are labelled, not deleted.** `conveyor.sh`, `service.sh` and `alert.sh`
  open with a RETIRED note; the `/root/.zo_secrets` source and the Zo email call are removed.
- **Docs.** `EXECUTION-LOOP.md` gains a dated note on where builds run now (policy sections
  unchanged). `PROGRESS.md` records Release 3's acknowledgement and the open follow-ups.
  `STORAGE-BOOTSTRAP.md`'s settings table no longer lists Zo's file as the default.

## What it deliberately does not change

- **The worker id prefix `zo-staging-worker-N`.** Desktop workers still register under it, and the
  rows and logs already written carry it. Renaming it would make every running worker read as a new
  one in `hv_workers` and in the wave-A and observability evidence. A comment at both places that set
  it says the prefix is historical.
- **Nothing on the desktop host.** It already sets both settings: `/etc/rough-cut/host.env`, every
  program its supervisor starts (`provision-staging-host.py`'s `supervisor_base`), and
  `scripts/loop/loop.env`. `provision-staging-host.py` already refused to run without one.
- No frozen-list file: nothing in `packages/safety`, `docs/legal`, `docs/adr` or `.github/workflows`.

## Acceptance criteria

1. **Unset is refused by name, in both halves.** `supervisor_config({})` raises `ValueError` and
   `supervisorConfig({})` throws, each naming `HV_SUPERVISOR_CONFIG is not set`.
   - Tests: `scripts/test_storage_bootstrap.py` (`test_unset_supervisor_file_is_refused_by_name`),
     `packages/storage/test/host-config.test.ts`.
2. **Importing a driver or collector needs no host.** Each of the three Python drivers imports with
   the setting unset; asking it for the file then raises by name, and with the setting it answers the
   setting through both `supervisor_file()` and `module.CONFIG`. The TypeScript collector imports with
   the setting unset and answers it once set.
   - Tests: `test_every_script_that_registers_programs_reads_the_setting`, `host-config.test.ts`.
3. **The RPC default is unchanged and no script names Zo's supervisor.**
   - Tests: `test_unset_rpc_url_keeps_the_studio_port`, `test_no_script_names_the_zo_supervisor_itself`,
     `test_the_supervisor_exports_the_settings_every_script_reads` (`test_storage_deployment.py`),
     and the matching case in `host-config.test.ts`.
4. **The collectors' probes are unchanged.** `wave-a-evidence.test.ts` and `observability-exit.test.ts`
   pass with the setting unset in the environment (each names a supervisor file of its own for its
   stand-in runner).

### Independent review

The workshop (gemini) reviewed the patch read-only and approved it: no caller still reads the setting
at import, `module.CONFIG` reaches the module `__getattr__` for the importlib-loaded drivers, and no
desktop script loses a setting. It ran the five Python suites (the five PKI cases in
`test_storage_deployment.py` could not run there, the same on main). Its two nits are fixed here:
`STORAGE-BOOTSTRAP.md` still listed Zo's file as the default, and the unset case now also reads
`module.CONFIG`.
