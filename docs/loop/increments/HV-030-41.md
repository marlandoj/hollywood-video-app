# HV-030-41 — The studio flow tests get the time they take on a loaded runner

epic: HV-030
release: 3 "Features"
gate: none new
spend_usd: 0

## Why

`packages/frontend/test/studio.test.js` drives the studio's flows: it composes the Composer's score,
inspects sources and titles cuts. Each test takes 0.5–2 s alone and the file about 30–50 s. Several
tests have crossed bun's 5 s default on a loaded runner without failing an assertion:

- "the credits name the Continuity Supervisor…": HV-019-21 (#382) gave this one 20 s.
- "a refused ambience request still finishes the film with its score…": failed twice in one CI job on
  #388, after passing on #387 with the same code.
- "a second pass reuses the saved graphics…": failed locally while the host was busy.

Each of these failures costs a CI rerun of about 50 minutes, during Release 3's live run.

## What this increment does

- **`studio.test.js` sets `setDefaultTimeout(20_000)`.** Every test in the file now gets the 20 s
  that one test already had. No assertion changes.

## Acceptance criteria

1. Every test in `studio.test.js` runs under a 20 s timeout, and the file passes.

- Tests: `packages/frontend/test/studio.test.js`.

## Known gaps

- The tests remain slow because they do real work. Making them faster is not part of this increment.
