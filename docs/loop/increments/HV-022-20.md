# HV-022-20 — A lip-sync pass the server refused stayed saved and locked the studio

epic: HV-022
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

**Render reviewed lip-sync** saves the request in localStorage before sending it, so that a lost
reply can be checked later under the same idempotency key. Only a successful reply ever cleared it:

    const admitted=await request("/"+pending.sourceId,{method:"POST",body:pending.body});
    remember(null);dirty=false;…

When the server refused the request outright, for example with a 400 because the provider policy
had moved on, or with a 403, 409 or 422, the call threw before `remember(null)`. The saved request
stayed, and everything around it refused because of it:

| Action | What happened |
|---|---|
| **Check or resume saved request** | sent the same body again and was refused again |
| **Discard speaker draft** | "Resolve the saved request before discarding its draft." |
| **Load applied lines** | stayed disabled |
| **Open result** | "Resolve the saved request before opening another result." |

`unsaved` also stayed true, so the page's `canEdit` kept the sound session, picture editorial and the
graphics desk closed. Because the request lives in localStorage, this survived a reload. The only
way out was to clear site data by hand.

## What this increment does

- **A definite refusal clears the saved request.** That means any 400–499 except 408 and 429, which
  mean "try again". The panel also removes the saved request's confirmation and reads the catalogue
  again. It then says: *"This lip-sync pass was not saved. <the server's reason> Review a new pass
  before rendering."*
- **The speaker draft stays.** If the pass was refused as it was rendered, the marked face is still
  there. **Review lip-sync pass** builds a new request against the policy that was just re-read, with a
  new key.
- **Anything that might still have been admitted keeps the request.** That covers a network error, a
  408, a 429 and a 5xx. Checking it again sends the same key, as before.

## Acceptance criteria

1. **A definite refusal of a saved request clears it.** For 400, 403, 404, 409, 410, 422 and 499,
   the request leaves localStorage, **Check or resume saved request** goes away, `unsaved` becomes
   false and the error status says the pass was not saved.
2. **After a refusal the owner can leave.** The catalogue is read again, **Load applied lines** is
   enabled, and both **Discard speaker draft** and **Load applied lines** work.
3. **A pass refused as it is rendered keeps its speaker draft.** The next review sends the re-read
   policy revision under a new idempotency key.
4. **A 408, a 429, a network error or a 5xx keeps the saved request.** Checking it again resends the
   same key, and success then clears it.
5. Reverting `lipsync.js` fails criteria 1, 2 and 3.

- Tests: `packages/frontend/test/lipsync-refused-request.test.js`.

## Known gaps this leaves

- **The refusal doesn't distinguish its causes.** A stale policy, a spent film budget and a removed
  source all get the same "review a new pass" advice. The server's own reason is shown alongside it.
- **The graphics desk marks a refused request `rejected` and keeps it** (graphic-studio.js `recover`).
  The voice studio drops it, and lip-sync now drops it too. The panels still don't share one rule for
  this.
