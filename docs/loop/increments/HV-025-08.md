# HV-025-08 — Saving a sequence reuses the check the creator was just shown

epic: HV-025
release: 1 "Studio" (closing gap), carried into 2
gate: none new
spend_usd: 0

## Why

HV-025-07 moved the source check beside the request, and the Release 1 short's titles still failed.
Re-running the Editor's title pass on the approved short on staging:

- `GET editorial/sources/:jobId` now answers 202, then the receipt — the read is fixed;
- `POST editorial/sequences` then ran for **257 seconds** and died behind the edge's timeout
  (`/api/projects/:id/editorial/sequences -> 502 upstream unavailable`).

The save re-checks the original: `binding()` looks for the receipt in the project's saved library,
and the receipt is only written to that library *by* this save. So the studio's own sequence — look
at the film, then save it — paid the full check twice, and the second one had no way to answer in
time.

## What this increment does

`EditApi.binding()`, before starting a check, looks at the finished checks it is already holding
(HV-025-07's map) and reuses one when it is for the same project, the same job output and the exact
receipt revision the caller is saving. The reused binding is put through the same gates as any
other: `assertEditBindingAvailable` against the job as it stands now, and
`assertEditOriginalPermission` against the project as the caller's own refresh reads it.

- A revision the check never produced is refused, as before: nothing is served from the cache that
  the creator was not shown.
- A new render of the same job is a different output, so it is a different key and a new check.
- The saved library receipt still wins when it exists; this only fills the gap before the first save.

## Acceptance criteria

1. **The save reuses the check.** After a source check answers with its receipt, the original's
   media is moved out of reach and the sequence is still created (201) with that receipt in the
   project's library — a second check could not have succeeded.
   - Test: `packages/api/test/editorial-inspection-reuse.test.ts`.
2. **Only the receipt that was shown.** With the media still out of reach, saving a sequence that
   names a different source revision is refused with 400.
   - Same test.
3. **Nothing else changes.** The editorial, inspection, preview, assemblies, script, mattes and
   graphics suites pass unchanged.
