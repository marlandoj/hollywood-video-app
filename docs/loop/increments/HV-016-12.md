# HV-016-12 — An imported line containing "/*" deleted the rest of the film, silently

epic: HV-016
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

Final Draft and PDF text is the writer's literal words. Both importers hand it to `parseFountain` as
Fountain — and Fountain reads `[[…]]` as a note and `/*` as the start of a boneyard that runs to the
next closer, or to the end of the document.

So a Final Draft action line reading

```
Mara types rm -rf /* and hits enter.
```

imported with `notes: []`, and the text shown in the editor still held every scene. The film did not:
`parseFountain` found **one scene**, whose action was `"Mara types rm -rf"`, with no dialogue. Everything
after `/*` — the rest of the line, the speech, the whole second scene — was boneyard, with no warning
and nothing in `unparseable`. A speech reading `It says [[classified]] on the cover.` lost its middle
the same way. The PDF importer pushes its lines raw too, and has the same problem.

The importers' own rule, in `final-draft.ts`'s header: an importer "that silently loses a line is worse
than one that will not run". HV-016-05's gaps cover the Fountain reader's notes, not imported text
being read as Fountain markup.

## What this increment does

- **`hiddenImportedLine(text)`**, beside `scanProtectedSpans` in the parser, answers the first line
  of an imported screenplay the Fountain reader would hide part of — defined in terms of the same scan
  the reader uses, so the two cannot disagree.
- **Both importers refuse by line**, with one shared message naming the line and the marker. Fountain
  has no escape for either marker, so an importer cannot carry them; rewording them would be the
  studio changing the writer's words.

## Acceptance criteria

1. **What the defect did, measured**: the reader keeps one scene of two, and `hiddenImportedLine`
   names line 3.
2. **A Final Draft line the reader would hide is refused by line**, for `/*` and for `[[ ]]`.
3. **A PDF line the same.**
4. **Everything the importers already read is read exactly as before**: a lone closer, single
   brackets, a slash and `/usr/local` import as written, and the existing PDF fixture still gives two
   scenes.
5. Reverting the two importers fails criteria 2 and 3.

- Tests: `packages/parser/test/import-hidden-text.test.ts`. `packages/parser` and the script-import
  route: 64 / 0.

## Known gaps this leaves

- **The writer has to reword the line.** A refusal is the honest answer, not a convenient one. A
  studio-side escape for these markers would let the text through intact, but it would change what
  Fountain means in this studio and every consumer of the text would have to learn it.
- **A Fountain script pasted into the pitch box is not checked.** There, `/*` is the writer's own
  Fountain and may well be a deliberate boneyard; nothing can tell the two apart.
- **Only the first offending line is named.** A script with several gets them one import at a time.
