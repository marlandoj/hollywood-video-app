# HV-030-24 — The crew can think through OpenRouter or Synthetic, on the one crew line

epic: HV-030
release: 2 "Voice and crew depth"
gate: G16-202610011400 (G3: OpenRouter and Synthetic.new approved for the crew)
spend_usd: 0

## Why

The crew calls a language model from the server, and the only vendor it could call was Anthropic.
The operator can't supply an Anthropic API key, so every crew run so far has been the deterministic
stand-in, and Release 2's crew line notes were deferred for want of a live model.

In G16 Kevin approved OpenRouter and Synthetic.new as the crew's language-model vendors. He also
said the crew's spending limits are standard across providers: one crew line, whichever vendor
answers, with G13's alerts at $25, $100 and $200 and the stop at $1,000.

## What this increment does

- **Two new vendors, one class.** OpenRouter and Synthetic.new both speak OpenAI's chat-completions
  shape, so `OpenAiCompatibleCrewModel` calls either. Each vendor is its endpoint, the variable its
  key comes from, its default model and how many requests it allows at once. The key goes only in
  the bearer header. OpenRouter is sent `X-Title: Rough Cut` and nothing that names the staging host.
- **Choosing the vendor.** `HV_CREW_PROVIDER` is `anthropic`, `openrouter` or `synthetic`. Unset, the
  crew behaves as before. The keys follow the repository's `HV_` names: `HV_OPENROUTER_API_KEY` and
  `HV_SYNTHETIC_API_KEY`. A vendor named without its key stops the API at startup, and the message
  names the variable, never a value. `HV_CREW_MODEL` picks the vendor's model by the vendor's own id.
  Defaults: `anthropic/claude-sonnet-5.5` on OpenRouter, `hf:moonshotai/Kimi-K3` on Synthetic.
- **Metered the same way.** Every call reports what it cost:
  - OpenRouter at the larger of the price table and its own reported `usage.cost`, so a call is never
    under-metered.
  - Synthetic at $0, with its tokens. It is a flat subscription with no per-token charge, and the
    table says so (`billing: "subscription"`) rather than inventing a rate.
  - A model not in the table is still refused at construction.
- **One crew line.** Every vendor's calls go on the same budget line, with the same alerts and the
  same stop. The line's `model` field names the vendor (`openrouter:…`, `synthetic:…`, or Anthropic's
  ids as before), so the spend shows who answered, with no migration. The answer's `source` names the
  vendor too.
- **Answers that can't be used.** An answer that is empty, declined, cut off at its length limit or
  withheld by the vendor's filter is an error that carries what it cost. The stand-in answers
  (`model_unusable`) and the cost is still recorded. Before this, a billed failure could only be
  counted as $0.
- **Rate limits.** A 429 falls back to the stand-in, as any unavailable model does, and the crew
  doesn't ask that vendor again until its `Retry-After` has passed (30 seconds by default, at most 5
  minutes). Synthetic allows one request at a time per model, so the crew queues up to four more
  rather than drawing a 429.
- **Safety is unchanged.** Every prompt passes the gate before any vendor is called.

## Acceptance criteria

1. **OpenRouter's request.** The chat-completions endpoint, the key only as a bearer token, the
   system prompt as the first message, `max_tokens`, and no URL in any header. The answer's text,
   tokens and cost come back, under the model id `openrouter:anthropic/claude-sonnet-5.5`.
2. **OpenRouter's metering.** A call is charged the larger of the table's price and the reported
   cost. A missing or invalid reported cost is charged the table's price.
3. **Synthetic's request and metering.** Synthetic's endpoint, a bearer key and an `hf:` model. The
   call is recorded at $0 with its tokens. Every Synthetic model in the table is priced at $0 and
   marked as a subscription, and no other vendor's is.
4. **Errors.** A non-200, an unreachable vendor, an unreadable body and a timeout fail with at most
   the HTTP status: never the vendor's body, never the key. An empty, declined, cut-off or filtered
   answer is an error that carries its cost.
5. **Choosing from the environment.** Unset, the crew is Anthropic with its key and the stand-in
   without. Each provider takes its own key and its default or chosen model. A model from another
   vendor's table is refused.
6. **Startup errors.** A provider named without its key fails, naming the variable and no key. So
   does an unknown provider.
7. **The one crew line.** Spend from OpenRouter, Synthetic and Anthropic adds up on one line. It
   alerts once at $25, $100, $200 and $1,000, records which vendor answered each call, and stops every
   vendor at the ceiling before it is called, Synthetic included.
8. **A cut-off answer** falls back to the stand-in on the read-through, the plan and line notes, and
   its spend is recorded.
9. **429s.** A 429 falls back to the stand-in at $0. The vendor isn't called again until its
   `Retry-After` has passed, and a missing or huge one is bounded. Synthetic gets one request at a
   time, and a full queue is told the crew is busy.
10. **The gate.** For each vendor, a read-through, a plan and line notes the gate refuses make no
    request.
11. Reverting `crew-model.ts` fails every test for criteria 1–10, since the vendors it adds are gone.
    Reverting only the three crew paths (`read-through.ts`, `production-plan.ts`, `line-notes.ts`)
    fails criteria 7 and 8.

- Tests: `packages/generator/test/crew-model-vendors.test.ts` (criteria 1–6 and 9),
  `packages/planner/test/crew-vendors.test.ts` (criteria 7–10). The existing crew suites pass:
  `packages/generator/test/crew-model.test.ts`, `packages/planner/test/crew-*.test.ts`,
  `packages/operator/test/crew-ledger.test.ts`, `packages/api/test/crew-*.test.ts`.

## Known gaps this leaves

- **Nothing has called either vendor.** `spend_usd` is 0 and every test answers through a fake
  fetch. The first live call is the operator's, once a key is on the host (docs/CREW.md, "Setting it
  up"). The exit run (HV-030-23) is where that happens.
- **Synthetic's 500 requests per 5 hours aren't counted here.** The crew learns of the limit from the
  vendor's 429, and waits.
- **The queue for Synthetic's one slot is per API process.** Two API processes could each send one
  request at once, and the second would draw a 429.
- **The subscription itself isn't on the crew line.** Synthetic's $30 a month is paid outside the
  studio, and the line records its calls at $0.
- **An answer with no readable `usage` is still counted as $0.** It can't be priced, so it fails as
  unreadable, as Anthropic's did.
- **The Anthropic class doesn't yet report a cut-off answer as unusable-with-cost.** Its behaviour is
  unchanged; a cut-off Anthropic answer fails validation, which records its cost already.
- **Kimi and OpenCode** keys are held by the operator but weren't approved as crew vendors in G16.
