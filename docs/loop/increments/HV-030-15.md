# HV-030-15 — The read-through described a film the studio would not make

epic: HV-030
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

The Producer's read-through computes the "studio facts" that the creator sees first. They are:

- the number of shots;
- the runtime;
- the final-video quote;
- whether the script runs past its format.

The crew is told these facts are computed and must not be restated differently.

The facts came from `planShots(parsed)`, which has no shot limit and ignores accepted scene cuts. The
plan step and a free-tier render use `sourcePlan(parsed, direction, 7000, 24)` instead. So a
four-scene script with forty action paragraphs got two different answers:

| | Shots | Runtime | Quote | Format |
|---|---|---|---|---|
| Read-through facts | 40 | 80 s | $14 | "over_format" for a reel |
| Plan and render | 24 | 48 s | — | — |

The plan prompt then told the model "shots: 40 (computed, do not restate differently)" beside a list
of 24 shot ids.

## What this increment does

- **`readThroughFacts` takes the planned shots.** Both routes pass the plan the studio will make.
  - The read-through route computes it with `sourcePlan(parsed, currentDirection(...), 7000, 24)`,
    the same call the plan step makes.
  - The plan route passes the shots it already computed.
- **If `sourcePlan` refuses**, because a scene cut no longer matches the script, the read-through
  reads the script as before. The plan step reports that refusal itself.

## Acceptance criteria

1. **What the defect did, measured.** Read alone, the script gives 40 shots. The plan gives 24.
2. **The read-through route's facts match the plan:** 24 shots, and the runtime those shots add up to.
3. Reverting `server.ts` and `read-through.ts` fails criterion 2.

- Tests: `packages/api/test/crew-read-through-plan.test.ts`. The crew route, plan and voice suites,
  and the planner's crew suites, all pass (56 / 0).

## Known gaps this leaves

- **The tier is the free tier's 24 shots in both routes.** An operator on the 60-shot plan through the
  API gets facts for 24, which is what the crew plans for today as well.
