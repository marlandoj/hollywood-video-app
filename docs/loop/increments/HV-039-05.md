# HV-039-05 — The cast desk dropped keyboard focus to the page body after every save

epic: HV-039
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

HV-039-04 moved focus to each studio step's heading as the creator arrives at it. The cast desk had
the same hole one level down. Every cast change goes through `mutate`, which on success hides the
editor and calls `renderList`, and `renderList` starts with `list.replaceChildren()`. So:

- **Save character** sits in the editor that was just hidden;
- **Remove Mara**, **Revoke permission for Mara** and **Remove reference 1** sit in the list that was
  just rebuilt, and no longer exist;
- **Cancel edit** hides the editor it is in;
- **Close cast editor** hides the whole desk.

In each case the browser drops focus to the page body. The status line says "Saved cast version 4"
(it is `role=status`), but the next Tab starts at the top of the page, several screens above the
desk, and a screen-reader user has to find their way back to the character they were working on.
No test had ever mounted `casting.js`.

## What this increment does

- **Close** returns focus to the button that opened the desk ("Save screenplay and edit cast").
- **Cancel edit** returns focus to the button that started the edit (**Edit Mara** or **Add
  character**).
- **A successful save** puts focus on the saved character's card heading. If the character is gone
  (a removal, or a restore that dropped it), focus goes to the desk heading. Character sheets and
  costume presets save through the same path, with the same character.
- **A refused save** leaves focus alone. Nothing was rebuilt, so the pressed button is still there.
- The test DOM (`audio-studio-dom.js`) now records `focus()` in `document.activeElement` and knows
  `isConnected`, `contains` and `closest("[hidden]")`. That's enough to ask where focus went, and
  whether a person can still reach that element.

## Acceptance criteria

1. **Close returns focus to the opener.**
2. **Removing a character leaves focus on the desk heading**, not on a removed button.
3. **Saving an edit or revoking permission leaves focus on that character's card.**
4. **Cancelling an edit returns focus to Edit Mara, or to Add character.**
5. **A refused save leaves focus on the button that was pressed**, and that button is still on the
   page.
6. Reverting `casting.js` fails criteria 1–4.

- Tests: `packages/frontend/test/desk-focus.test.js`. The test serves the desk the way the API does,
  with `character-sheets.js` as `sheets.js` and `actor-library.js` as `library.js`, so the real modules
  load.

## Known gaps this leaves

- **Shot direction has the same shape** (`direction.js`: `mutate` hides the form and rebuilds the
  list, and Close does not return focus). That is the next increment. The desk's other panels (takes,
  sound, graphics) close without returning focus too.
- **Focus on the card heading is not focus on the card's controls.** One Tab reaches the character's
  Edit button, which is where most creators go next. It is not a return to the exact control, because
  that control was rebuilt.
- **Disabled controls during a save.** `mutate` disables every desk control while the request is in
  flight. Some browsers move focus off a control when it is disabled. The pressed button is enabled
  again afterwards, but this increment doesn't refocus it on a refused save.
