# HV-025-07 — Checking an original takes as long as it takes

epic: HV-025
release: 1 "Studio"
gate: none new
spend_usd: 0

## Why

In the Release 1 run the short, "Paper Boats" (10 shots, 50 seconds), was shared without its title
and credits. The Editor said so in the film's finishing notes:

> Editor: the title and credits could not be added (/api/projects/:id/editorial/sources/:id -> 502
> upstream unavailable); the film is shared without them.

`GET /api/projects/:id/editorial/sources/:jobId` checks an original the studio has not inspected
before: it copies the job's media out of the object store, verifies every file against its receipt,
and re-probes the picture frame by frame. For the shared short that is 247 MB across 48 files, and
the call took **340 seconds** on the staging host. A socket may be idle for at most 255 seconds
(Bun's ceiling for `idleTimeout`), so the reply could never arrive: the edge gave up at its own
timeout and answered 502, and the studio shared the film untitled. The reel's 15-second film is
small enough to answer inside the ceiling, which is why the reel is titled.

Raising a timeout cannot fix this. The work is minutes long and grows with the film; no socket
setting covers it.

## What this increment does

The check now runs beside the request instead of inside it. `GET editorial/sources/:jobId`, for an
original with no receipt yet:

- starts the check once and answers `202 {inspecting: true, jobId, startedAt}`;
- answers `202` with the same `startedAt` while it runs, for every reader, and never starts a
  second check for the same original;
- answers `200 {sources: [receipt]}` once it is done, after re-checking that the project still
  allows that original and that its job is still available;
- raises the check's own refusal, once, if it failed, and forgets it so the next call checks again.

A receipt is kept only for the job output it was made from: a new render is a new check. At most
eight finished receipts are kept, oldest forgotten first, and a check is abandoned after 15 minutes.
A retained source (a picture edit or an assembly) still answers `200` at once from its own stored
receipts, as before.

The studio and the editor wait: `createStudioFlow`'s title step polls every 5 seconds for up to ten
minutes, saying "The Editor is checking the film for the title and credits"; `editorial.js` does the
same from its two Inspect buttons.

Nothing about the check itself changes: the same files are copied, the same checksums verified, the
same probe run, the same permissions asserted before the receipt is handed out.

## Acceptance criteria

1. **202 while it runs, then the receipt.** The first call answers 202 with a start time, a second
   call while it runs answers 202 with the same start time (one check, not two), and polling ends in
   200 with a 64-character source revision and the film's measured frames. Asking again afterwards
   answers 200 at once with the same receipt. An unauthenticated caller is still refused with 401
   and an unknown original with 400.
   - Test: `packages/api/test/editorial-inspection.test.ts`.
2. **The studio waits.** When the API answers 202 twice before the receipt, the Editor polls three
   times, titles the cut, and leaves no finishing note.
   - Test: `packages/frontend/test/studio.test.js`, "the Editor waits while the film is still being
     checked, then titles it".
3. **Nothing else changes.** The editorial, editorial-preview, editorial-assemblies,
   editorial-script, graphics and living-script suites pass, inspecting through the same wait.
