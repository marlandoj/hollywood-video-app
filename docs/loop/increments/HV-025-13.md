spend_usd: 0

## Why

Release 3's parts table asks for a masked composite rendered into a shot of the feature, from the
Director's desk. Before building anything, what already exists:

| Needed | Already there |
|---|---|
| Layers over a shot | Four picture layers (`edit-timeline.ts`) |
| A mask | Rectangle, ellipse and polygon masks, feathered, inverted, keyed, in source coordinates (`edit-composite*.ts`, `docs/EDITORIAL-MASKS.md`) |
| A matte | Alpha and luma track mattes, matte-only layers |
| Opacity, crop, a simple transform | Clip opacity and crop; placement (translate, scale, rotate) |
| Native alpha | Graphics as `graphic-rgba` sources (`edit-rgba*.ts`) |
| A local render at $0 | The editorial conform with ffmpeg, verified by reproduction before it is published |
| Provenance | The render's `provenance.json` holds the plan: bindings, timeline and history |
| Refusing a stranger | The editorial routes' owner check |

So the compositing engine is done, and was built for creators. What was missing is small and is what
this increment builds: a way for the crew to ask for **one** composite without authoring a timeline by
hand, validated exactly as a creator's save is, and a reading of a rendered picture edit that says
plainly which composite it holds, over what, with which matte, made by which edit. Most of this
increment is that tool, that record and a test that drives it end to end through the desk's own routes.

## What this increment does

- **The Editor's tool, `vfxCompositeOperation`** (`packages/planner/src/crew/vfx-composite.ts`). One
  element already in the sequence (a generated still or graphic, or a second clip) over one shot: one
  rectangle or ellipse mask in the element's source coordinates, held from its first frame, with feather
  and inversion; an opacity; an optional placement. It returns the single `insert` a creator could have
  saved, on the free layer directly above the shot, applied with `applyEditOperation`, the validator the
  desk runs on every `PATCH`. It also refuses a window outside the shot's clip, a plate on the top layer,
  a layer above that is in use over the window, an element the sequence does not hold and zero opacity.
  `vfxCompositeLabel` names the history event.
- **The record, `vfxComposites`** (`hv-vfx-composite/1`). Read from the picture edit's plan (the job's
  `pictureEdit`, or the `plan` in its `provenance.json`): each composited clip's window, its element and
  every visible plate under it by retained job, stage and revisions, the matte (each mask, and a track
  matte's own inputs), the opacity, the placement, and the edit on the selected branch that last set
  it. Null when the edit holds no composite.
- **The job view** (`GET /api/jobs/:id`) carries it as `pictureEdit.vfx`, only for an edit that holds a
  composite. Every other view is unchanged.
- **`docs/EDITORIAL-MASKS.md`** says what the tool does and does not do.

No render path, schema, migration, queue or stage changes. No provider is called.

## Acceptance criteria

1. **The Editor's composite is one edit a creator could save.** One `insert` of one picture clip on the
   layer directly above the shot, its mask keyed to the element's revision and first frame, with the
   requested opacity and placement; the timeline it produces is the one `applyEditOperation` produces
   from the same operation. A second clip works as an element as well as a still.
2. **The crew can propose nothing a creator could not save.** The desk's own limits refuse what the tool
   passes through, in the desk's own words (an over-soft matte, a placement scale out of range), and the
   tool refuses a window outside the shot, a busy layer above it, a top-layer plate, an unknown element,
   a reused clip id and zero opacity.
3. **On the desk, an unauthorised caller is refused and nothing is saved.** No caller: 401. Another
   project's owner: refused. An over-soft matte from the crew: 400, the history unchanged.
4. **Rendered locally at $0, with the expected pixels.** The saved composite renders through the desk's
   review and admission on the studio's machine, $0 on the ledger. Sampled with ffmpeg from the export:
   inside the matte the frame is the plate and the moved element blended at the opacity (mean error
   under 6 of 255), and the element's text pixels follow the element, not the plate; above, right of and
   below the matte, and before and after the window, it is the plate (mean error under 4).
5. **The record names each input, the matte and the operation.** The plate and element by retained job,
   stage, revision, layer and frames; the mask; the opacity and placement; the history event and its
   label. The job view's record equals the one read back from the render's `provenance.json`. A later
   creator edit to the matte is the edit named; a branch without the composite has none; a track
   matte's own inputs are named; a source the edit did not retain is refused. A stranger cannot read the
   job.
6. **Reels, shorts and features are otherwise unaffected.** An edit without a composite, and the
   Editor's title-and-credits insert, read as no composite and the job view has no `vfx`. The studio
   flow, the feature join and the render path are untouched.

## Known gaps this leaves

- **The crew does not decide by itself that a shot needs an effect.** No persona's answer proposes a
  composite, and the studio flow does not call the tool; it is called from the desk's routes, as the
  Release 3 run driver (step 14) will. A model choosing the element, matte and placement is later work.
- **A composited picture edit is not a sequence final, so the feature's join does not take it**
  (HV-030-30 joins finals). Until the join accepts a sequence's picture edit, the release record can
  show the composite rendered into a shot of a sequence's final, not carried into the joined film.
- **The tool's matte is one held rectangle or ellipse.** Polygon, animated and tracked mattes, chroma
  key and despill stay the creator's or remain unbuilt (`docs/EDITORIAL-MASKS.md`).
- **The end-to-end test's element is a second clip of the mock film, not a generated graphic.** Graphic
  rendering needs a browser this host doesn't have; the graphic case is covered at the planner level,
  and native alpha in the conform by the existing RGBA tests.
- **The record is a reading, not a new signed field.** It is derived from the plan already in
  `provenance.json`, and is exactly as trustworthy as that file.
