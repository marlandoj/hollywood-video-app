# HV-024-04 — One keystroke discarded every phrase direction on the line, and said nothing

epic: HV-024
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

A critic pass over `packages/frontend`.

A phrase direction is work a creator does by hand: they choose a phrase's first and last word, then
set a speed, a volume or a native emphasis, and requested pauses before and after it. A line may
carry sixteen. `audio-studio.js` threw all of them away on every keystroke, from three handlers:

```js
narrationText.oninput = () => { …; phraseEditor.set(language.value ? translation.value : narrationText.value, []); editChanged(); };
translation.oninput   = () => { …; phraseEditor.set(translation.value, []); };
language.onchange     = () => { …; phraseEditor.set(language.value ? translation.value : selected?.source.text, []); editChanged(); };
```

The second argument is the line's phrases, and `[]` is all of them. Exhibited:

```
phrase directions on this line: [{"start":4,"end":9,"speed":0.8},{"start":20,"end":26,"volume":1.4}]
phrase directions after typing one more character: []
```

Nothing said so. `editChanged()` says *"Review this line's settings before generating an audition"*,
which is what it says when anything at all changes.

And it did not have to. **A phrase is a character range plus the exact words inside it** — `{start,
end, text, …}`, with `start` and `end` as offsets into the line — so whether an edit invalidated one
is a question with an answer, and it is the same question `describePhrase` and the Edit button
already ask when they look up a word starting at `p.start` and one ending at `p.end`. Typing at the
end of a line leaves every earlier phrase exactly where it was.

The same call also rebuilt the word lists. Two `<select>` elements, one `<option>` per word, on
every keystroke — measured here at **800 option constructions for a 400-word line**, and the
narration box holds 20,000 characters, which is about 3,200 words: **6,400 per keystroke**, into
live elements, where each insertion also invalidates layout. (The count is the measurement rather
than a millisecond figure, because this repo's tests build a plain-object `Element`; a timing there
would understate the real cost and reporting it as the real cost would be wrong.)

## What this increment does

- **`retainedPhrases(text, phrases)`** answers which directions an edit left standing: the new text
  has a word starting at `start`, a word ending at `end`, and the same characters between them. It
  is exported, so it is a rule with a name and a test rather than a line inside a handler.
- **`phraseEditor.retext(text)`** keeps those, drops the rest, and **returns how many it dropped**.
  What cannot be kept is dropped rather than shifted: guessing where a direction moved to is a guess
  about the creator's intent, and this studio's rule one package over is to refuse rather than
  silently drop.
- **The studio says so.** The three handlers call `retext`, and when anything was dropped the line's
  status reads *"2 phrase directions were removed because the words they name changed"* rather than
  the generic review prompt.
- **The word lists are rebuilt only when the words changed.** `set` and `retext` share one `load`,
  which compares the new word list against the last one it built and does nothing when they match.
  That is free for the calls that re-set the same text — `language.onchange` re-setting the original
  line, a reload of an unchanged draft — and does not help a keystroke inside a word, which is the
  case the gap list below is about.

## Acceptance criteria

1. **A phrase the edit left exactly where it was is kept, and one it moved is not**, over eight
   named edits — nothing changed, a word appended, the last word edited, a later phrase edited, an
   earlier word edited, a word inserted before both, the text replaced, the text emptied — plus a
   space inserted inside the first phrase (which moves the second one too, and neither survives) and
   one inserted after both (which moves neither), and a range that no longer starts and ends on
   words even though the characters match.
2. **The editor keeps them across an edit and says how many it could not**: typing at the end costs
   nothing and reports nothing; editing a word inside one phrase costs that one and reports one;
   replacing the line costs the rest. Before this increment every one of those left the list empty.
3. **It does not rebuild the word lists when the words did not change** — 800 options for a
   400-word line, none for the same line again, and 800 again when a word actually changes.
4. Reverting `audio-phrases.js` makes the test file fail to load, because the rule it names does not
   exist.

- Tests: `packages/frontend/test/audio-phrases.test.js`.

## Known gaps this leaves

- **A keystroke inside a word still rebuilds both lists.** The signature guard only helps when the
  words are unchanged, and typing changes a word. The real fix is the 150 ms debounce
  `edit-script.js` already uses for the same shape of work, and it needs the editor to hold a draft
  across the debounce window so a phrase applied mid-type is not lost — which is a change to when
  the editor reads the box, not to what it keeps.
- **A phrase that moved is still lost.** An insertion early in the line invalidates every phrase
  after it, and this increment does not try to re-anchor them. A diff that shifted the offsets would
  keep more, and it would also be a guess: the words may have moved, or they may have been rewritten
  into something the direction no longer suits. What is fixed here is that the loss is now the
  exception rather than every keystroke, and that it is stated.
- **This is the audio studio only.** Nothing checked whether other editors in this frontend pass
  `[]` where they hold something; the pattern `editor.set(value, [])` is the shape to look for.
- **The message is a status line.** It says how many and why; it does not say *which*, and the list
  it was in has already been redrawn without them. Naming them would mean keeping the dropped ones
  long enough to describe, which is a small change and a different one.
