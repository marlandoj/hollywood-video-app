# HV-022-06 — The ElevenLabs adapter

epic: HV-022 (performance: voice, dialogue, lip-sync, ADR)
release: 2 "Voice and crew depth"
gate: G14-202609210000 (the operator approved ElevenLabs and provisioned its key on the staging host)
spend_usd: 0

## Why

HV-022-05 wrote the contract. This is the adapter that speaks it: one request, on the same
protocol every paid voice in this application uses — authorize and hold, check the permission
again, dispatch exactly once, and record the attempt whatever happens to it.

No qualification of voice quality is claimed here, and nothing is dispatched by the tests: the
transport is a stub, as the Cartesia and Azure adapters' fixtures are. A read against the real
service happens in the increment that authorizes voices, with the operator's evidence and its own
declared spend.

## What this increment does

- **`ElevenLabsAudioProvider.synthesize`** (`packages/generator/src/elevenlabs-audio.ts`):
  - the reservation exists before the network call, so an ambiguous failure leaves a held attempt to
    reconcile rather than a second dispatch; there is no retry, no alternate voice, no fallback;
  - the remote body is never echoed into an error, because it can carry the credential or the
    screenplay line back;
  - a `request-id` header is kept as the provider's own attempt identity when it is well formed;
  - the delivery is withheld unless the project's permission still holds after the read.
- **The conversion**: the service returns 44.1 kHz and every delivery here is 48 kHz, so the read is
  resampled once with the fixed recipe the capability declares
  (`aresample=48000:resampler=swr:filter_size=64:phase_shift=10:exact_rational=1:dither_method=none`).
  The command is not owner-supplied and the result is byte-identical run to run.
- **The words**: from `normalized_alignment` when the service sends one — that is the text it
  actually spoke — and from `alignment` otherwise.
- **The shared validators** (`validateAudioIntent`, `validateAudioOutcome`) learn the vendor: its
  dispatch schema, its request hash and the HTTP rules that apply to an HTTP vendor.
- **The worker** builds it when a line names the vendor and `HV_ELEVENLABS_API_KEY` is present. A
  line names its own adapter; nothing falls back from one vendor to another mid-take, because a
  second dispatch would be a second reservation.

## Acceptance criteria

1. **One read.** Authorize, check, dispatch once, check again, record — in that order; the request
   carries the key in its own header, the timestamped endpoint, and exactly the four voice settings;
   the delivery is 48 kHz with the leading pause and the two aligned words; the outcome is completed,
   with the provider's request id and an unreconciled cost.
   - Test: `packages/generator/test/elevenlabs-audio.test.ts`.
2. **Every failure leaves one attempt.** A refusal, four unusable payloads, permission withdrawn
   before the request and during it, the deadline, and a failed outcome recording: each records
   exactly one attempt, withholds the delivery, keeps the hold, and leaks no provider text.
   - Same test.
3. **The conversion is the declared one.** Half a second at 44.1 kHz becomes half a second at
   48 kHz, byte-identical on a second run, by the recipe the capability names.
   - Same test.
4. **Nothing else changes.** The Cartesia and Azure adapters and the performance conformance suite
   pass unchanged.
