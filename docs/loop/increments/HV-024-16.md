# HV-024-16 — The Composer asks again for a cue that was charged but not kept

epic: HV-024
release: 3 "Features"
gate: none new
spend_usd: 0

## Why

In Release 3's live run, sequence 10's music cue was made and charged ($0.12) but could not be kept,
because the project's sound library was full (HV-024-15). The music-cue route settles such a cue with
no asset. From then on, its key (`crew-music-<final>`) answers only:

> This cue was charged but could not be kept in the sound library. Ask again with a new request key.

A resumed feature asks with the same key. So even once the library has room, sequence 10 would be scored
with the Composer's own music instead of a generated cue like the other nine sequences.

## What this increment does

- **`generatedCue` steps past a lost cue.** When that replayed answer comes back, the Composer asks
  again under `crew-music-<final>-retry-<n>`.
  - The step is bounded: `MUSIC_CUE_LOST_RETRIES` is 3.
  - Only that replayed answer moves the key, and a replay costs nothing.
  - A cue that fails to be kept *now* is not asked for again. Its error is "The cue was made and
    charged …, but could not be kept …", and it keeps the Composer's own score, as before. So one
    finishing pass pays for at most one new cue.
- **`packages/frontend/test/studio-resume-finishing.test.js`:**
  - a resumed feature whose cue key answers "charged but not kept" asks under `-retry-1` and is scored
    with generated music;
  - a lost retry steps to the next key, and the steps stop after three;
  - a cue that fails to be kept now is asked for once.
- **`studio-retry.test.js`:** the source's request-key list names the retry key.

## Acceptance criteria

1. On the "charged but could not be kept" replay, the cue is asked for again under
   `crew-music-<final>-retry-1`, and the sequence is scored with the generated cue.
2. At most three such steps are taken. After them, the Composer's own score is used and noted.
3. A fresh failure to keep a cue is never asked for again in the same pass.

- Tests: `packages/frontend/test/studio-resume-finishing.test.js`, `packages/frontend/test/studio-retry.test.js`.
