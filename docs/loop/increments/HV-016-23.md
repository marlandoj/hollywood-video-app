# HV-016-23 — The contracts a mixed film is checked against, without a worker to run one

epic: HV-016
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

A mixed film keeps some takes from an earlier current film and generates the rest. Main can already
plan one (`hv-current-film-job/3`) and seal a mixed checkpoint, but nothing can run it: the queue
refuses V3 at admission and no worker, storage or archive path knows the shape. PR #83 ("Run mixed
films with owned proof and atomic recovery") built all of that in one change of about 9,300 lines. It
is now 648 commits behind main and cannot be merged as it stands, so it is being rebuilt as a run of
small HV-016 increments. This is the first. It brings over only the planner's pure contracts, the
ones everything later is checked against. None of them is reachable from a request yet.

## What this increment does

Ported from PR #83, with main's changes since kept:

- **The inventory of kept originals** (`packages/planner/src/current-film-origins.ts`). A mixed film
  gets one full owned copy of every original it keeps from, in a fixed order, under its own namespace.
  The inventory is bounded, and the new paths are checked so they cannot overflow.
- **Shared limits** (`current-film-proof-limits.ts`). The origin limit moves here so the validators
  can import it in any order. `current-film-mixed-jobs.ts` re-exports it.
- **The mixed assembly clock** (`current-film-mixed-clock.ts`). This is the measured frame and
  caption clock of a film whose rows are partly kept and partly fresh. The measured-media check it
  shares with V2 is split out of `current-film-clock.ts` as `validateCurrentFilmAssemblyMedia`.
- **Camera and frame-anchor reports on mixed rows** (`current-film-mixed-controls.ts`). The mixed
  checkpoint checks them against the shot as admitted, both for fresh rows and for kept rows.
- **Only a selected fresh slot may add routes to a mixed checkpoint's journal**
  (`current-film-mixed-context.ts`).
- **The mixed-plan cache keys on the complete own-field digest** and returns a detached copy
  (`current-film-mixed-jobs.ts`).
- **An explicit V2 view.** `currentFilmV2Job` and `CurrentFilmV2Job` are added, and
  `assertCurrentFilmMode` now narrows its argument (`current-film-job-context.ts`). Reuse
  (`current-film-reuse.ts`) reads its original through that view.
- **A bounded normaliser for Bun SQL result arrays** (`packages/storage/src/sql-result-rows.ts`),
  with a fixture that models that container. No caller uses it yet.

The only adaptation to main is in the mixed-clock test, which passes the `assembledAt` that
`assembleAsync` now requires (HV-031-02). The PR's PostgreSQL case for `sqlResultRows` is left for
the storage increment.

## Acceptance criteria

1. **Originals inventory.** Keeping one take retains that original's whole V2 inventory exactly once,
   and the source evidence is unchanged. Direct-origin order and carrier maps survive a reordered
   source. An all-fresh V3 plan has an empty inventory. Resealed omissions, aliases, reordering, and
   owner or binding changes are refused. A long original address cannot overflow the owned
   namespace. Capacity, duplicate paths and descriptors are checked before any accessor runs.
2. **Mixed clock.** The assembly takes detached original records and the target's intent. Measured
   mixed media binds new frame positions, the originals' native samples and exact captions. A silent
   final keeps the odd 15-frame dissolve. An incomplete selection, a substituted record or resealed
   clock facts are refused, and hidden, sparse or non-finite evidence fails before any getter runs.
3. **Controls.** Camera evidence needs exact keyframes, the row's real frame count and an admitted
   path. Anchor evidence binds the preview and final fallback modes and the exact positions. Plain
   rows still pass. A null control cannot hide malformed metadata.
4. **Mixed checkpoint.** A resealed fresh row that reports a camera path or frame anchors the shot
   never admitted is refused. A route from a slot that was not selected as fresh cannot enter the
   held journal.
5. **Mixed-plan cache.** Repeated validation returns equal but detached plans. An own field that is
   explicitly `undefined`, a hidden field or an accessor is refused even when the cache is warm. A
   changed selection or source is refused under an unchanged revision.
6. **SQL result rows.** Only dense own data rows are copied into a plain array. No iterator, `map`,
   `toJSON` or transport getter runs. Holes, accessors, hidden rows, proxies and over-capacity
   results are refused before any row is read. Normalising does not approve a hostile row body.
7. **V3 is still refused at admission.** Enqueueing a complete V3 mixed plan throws, and the store
   gains no job.
