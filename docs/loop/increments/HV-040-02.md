# HV-040-02 — Signed short-lived media access: contract, scope and expiry conformance
epic: HV-040
spend_usd: 0

## Goal
Make the existing artifact capability proxy the audited, tested answer to the "signed short-lived URLs" bullet of the storage pillar. Every media URL the API emits is `/artifacts/<token>/<projectId>/<jobId>/<path>`, where the token is an HMAC-SHA256 capability (`packages/api/src/tokens.ts`) bound to one project and one job, with `exp = min(linkExpiresAt, project.deleteAfter)` (`artifactLinkExpiry` in `packages/api/src/server.ts`), served by the artifact route from either the local artifact root or `PostgresArtifactStore.response` (range, HEAD, `private, no-store`). No presigned object URL is issued anywhere (repo-wide grep for `presign` is empty), by design: ADR-0018 requires revocable capability tokens rather than account-bound access, and a presigned S3 URL can be neither scoped by project state (takedown, retention) nor revoked short of key rotation. What is missing is not the mechanism but its contract: there is no single table-driven test of what a token binds and refuses, `verifyToken` accepts a MAC-valid payload whose `exp` is missing or non-numeric, `mintArtifactToken` takes an unbounded caller-supplied expiry, the expiry boundary differs from the other two verifiers in the package (`exp < now` versus `exp <= now`), path traversal answers 404 on the local backend but 400 with an internal message on the S3 backend, and no docs/*.md states the lifetimes, clock rule or revocation levers. This increment adds the contract tests, three small hardenings that leave the token wire format and every live staging token valid, and the runtime/contract doc. CDN delivery and regional placement stay out (vendor, gate G3).

## Acceptance criteria
1. **Table-driven HTTP contract for signed media URLs.** A new offline test `packages/api/test/signed-media-access.test.ts` drives a local-artifact `createApiServer` through a case table and pins each status: a valid token serves `export.mp4`, `hls/index.m3u8`, a playlist-relative segment, `captions.vtt` and `provenance.json` with 200, the expected `content-type`, `cache-control: private, no-store` and `referrer-policy: no-referrer`; `HEAD` answers 200; `POST`, `PUT` and `DELETE` on a signed URL are never served (404, no mutation); the token presented as `?token=` or as `Authorization: Bearer` on an unsigned `/artifacts/<p>/<j>/…` path is 401; an artifact token used as Bearer on `/api/projects/<id>` or `/api/jobs/<id>` is 401 and as `/api/reviews/<token>` is 403; a project token or review token placed in the artifact path is 401; every `*Url` field in a job view, a project listing and a review view matches `^/artifacts/[A-Za-z0-9_-]+\.[A-Za-z0-9_-]{43}/<projectId>/<jobId>/` and none contains `X-Amz-`. Existing cross-job, cross-project and tampered-signature cases in `packages/api/test/server.test.ts` stay unchanged and are cited, not duplicated. Satisfies FULL-SCOPE §3 P15 "Storage: S3-compatible object storage with multipart upload, lifecycle policies, signed short-lived URLs, CDN delivery, regional placement.", §8 "Security: capability isolation, signed URL scope, IDOR" and §10 "Evidence before promotion: tests, benchmarks, post-flight evals, gap audits."
2. **Expiry is enforced twice and at the exact instant.** Using `setSystemTime` from `bun:test`: a token minted with `exp = T` is served at `T − 1 ms` and refused with 401 at `T`; a token still inside its own `exp` is refused with 404 once `project.deleteAfter` has passed. To make the first half true, `verify` in `tokens.ts` treats `exp <= now` as expired (today `exp < now`), matching `verifyActorToken` and `verifyDiagnosticsToken` in the same package and the route's own `deleteAfter <= Date.now()` rule. `artifactUrlsExpireAt = min(linkExpiresAt, deleteAfter)` remains as tested in `server.test.ts`. Satisfies §3 P15 "signed short-lived URLs" and ADR-0018 "Revocable capability tokens … replace accounts and billing."
3. **Strict verification, unchanged wire format.** `verifyToken` rejects, before any HMAC is computed, a token longer than 1024 characters or not matching `^[A-Za-z0-9_-]+\.[A-Za-z0-9_-]{43}$`; after the MAC check it rejects a payload that is not a JSON object, an `exp` that is not a safe integer (today a MAC-valid `{"exp":"tomorrow"}` or a payload with no `exp` verifies forever because `NaN < now` is false), a kind-specific key set other than exactly `exp,kind,nonce,projectId` (project), `exp,kind,nonce,permission,projectId` with `permission ∈ {read, approve}` (review) or `exp,jobId,kind,nonce,projectId` (artifact), a `projectId`/`jobId` that is not a non-empty string of at most 128 characters, or a `nonce` that is not a non-empty string of at most 64 characters. Operator grants keep their own key set and gain only the generic length, format, object and integer checks. Tokens minted by `mintProjectToken`, `mintReviewToken`, `mintArtifactToken` and `mintOperatorGrant` already satisfy every rule, so tokens live in private staging keep verifying; the test signs each malformed payload with the test secret and asserts `null`. Satisfies ADR-0018 (capability tokens are the only access control, so their verifier must be strict), §8 "capability isolation" and §10 "Evidence before promotion".
4. **Artifact token lifetime is bounded at mint; clock rule stated.** `mintArtifactToken(projectId, jobId, expiresAt, now = Date.now())` throws when `expiresAt` is not a safe integer and otherwise signs `exp = min(expiresAt, now + ARTIFACT_TOKEN_TTL_MS)`, with `ARTIFACT_TOKEN_TTL_MS = 30 * 24 * 3600 * 1000` exported from `tokens.ts` and asserted equal to `DOWNLOAD_LINK_TTL_MS` (`packages/queue/src/index.ts`) by the test. All call sites already pass `min(linkExpiresAt, deleteAfter)`, so no user-visible expiry changes; the clamp guards future callers and bounds worker/API clock drift. The contract doc states the clock rule: the verifying host's clock is authoritative, there is no skew allowance (a verifier running ahead shortens links, never lengthens them), and `linkExpiresAt` originates from the worker's clock at completion, so cross-host drift moves a link's end by the drift but never past 30 days from the API host's own clock. Satisfies §3 P15 "signed short-lived URLs" and the baseline commitment in §1 "72 h capability links, 30 d retention sweeper".
5. **Path scope is validated the same way on both backends and never leaks an internal message.** The artifact route validates `[projectId, jobId, ...rest].join("/")` with `artifactKey` (`packages/storage/src/artifacts.ts`) immediately after the token check and answers 404 `{error:"not found"}` on failure, in local and S3 mode alike; today the S3 branch surfaces the `artifactKey` throw through the generic catch as 400 `{error:"invalid artifact path"}` while the local branch answers 404. Offline rows: `..%2F..%2Fjobs.json`, `%2e%2e/x`, a literal `.` segment, an empty segment, a path over 1024 characters — all 404 with the generic body and no file served. One S3-lane row in `packages/storage/test/artifacts.test.ts` asserts the traversal URL answers 404 through `PostgresArtifactStore`. Satisfies §8 "signed URL scope, IDOR" and §10 "Evidence before promotion".
6. **Revocation levers are proven and the limit is stated.** Offline: after `ProjectService.takedown` is issued through a second `ProjectService` on the same state path, a signed URL that served 200 a moment earlier answers 404 on the next request (the service reloads state per request); this is the local counterpart of the S3-lane takedown check in `artifacts.test.ts`, which stays. The doc records honestly that revoking a review link or exhausting its three views does not invalidate artifact URLs already fetched through it (the artifact token does not carry the link identity); such URLs live until `exp`, and project takedown, project retention and `HV_TOKEN_SECRET` rotation are the revocation levers. Satisfies ADR-0018 "Revocable capability tokens" and §3 P14 "rapid revocation" as far as the current token format allows; the per-link variant is listed under out of scope.
7. **Evidence is a real run.** `packages/api/test/signed-media-access.test.ts` writes `docs/evidence/hv040-storage/signed-media-access.json` when `HV_SIGNED_MEDIA_EVIDENCE` names that path, recording every observed row; because the matrix is offline, the committed file must come from an actual run on the build host, never a `pending` stub. The S3-lane section of the file is `pending` unless the storage lane ran. Satisfies §10 "Evidence before promotion".
8. **No frozen path, dependency, budget default, account, vendor or user-facing surface change.** The diff touches nothing under `docs/legal/**`, `docs/adr/**`, `.github/workflows/**` or `packages/safety/**`, adds no package.json or lockfile entry, no key, account, tier, cookie or tracking, and keeps the token wire format (`base64url(JSON).base64url(HMAC-SHA256)`) and `HV_TOKEN_SECRET` unchanged. Satisfies §10 "Free and anonymous for every end user; no billing code reachable." and "Safety refusals expand only."

## Out of scope
- CDN delivery and regional placement (edge vendor, gate G3/G7); anything that would cache a signed URL in a shared cache.
- Presigned S3 URLs in any form (rejected: not revocable, not scoped by project state; ADR-0018).
- Shortening the 30-day artifact link (FR-040 product requirement) or issuing per-fetch minutes-scale URLs; the token is re-minted with a fresh nonce on every job/review read but keeps the same `exp`.
- Binding artifact tokens to the review link they were fetched through (per-link revocation needs a versioned token payload and a lookup per media request; propose as HV-040-0N or HV-029).
- `HV_TOKEN_SECRET` rotation with overlap (dual-secret verification), key management, or any secret change on staging (gate G8).
- Range support on the local artifact backend; changes to `artifacts` rate limits; frontend player changes; operator console fields.
- Any change to `packages/storage/src/artifacts.ts`, retention, lifecycle rules, or the S3 request signer from HV-040-01.
- Any new npm or pip dependency, vendor, account or key.
