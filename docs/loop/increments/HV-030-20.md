# HV-030-20 — The studio lets the creator keep their style card and attach it to a pitch

epic: HV-030
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

HV-030-19 made the crew's memory of a creator a style card. The plan step hands it back, and the
server keeps no copy (ADR-0018: no accounts, no cookies, no tracking). The studio did nothing with
it, so the card was dropped with the answer, and the crew still remembered no one from one film to
the next.

## What this increment does

- **At the finished film** (`packages/frontend/src/studio.js`), a "Your style card" section offers:
  - **"Keep my style card in this browser".** This writes the crew's card to `localStorage` under
    `hv-studio-style-card`, only when pressed.
  - **"Download my style card".** This gives the same card as `rough-cut-style-card.json`, from a
    `data:` link. Nothing is sent.

  The section says the studio keeps no copy.
- **At the pitch,** "Your style card (optional)" offers:
  - **the kept card**, behind a box that starts **unticked**. Ticking it fills an empty tone from
    the card.
  - **a style card file** to load, which ticks the box for that pitch.
  - **"Forget the style card kept in this browser".**
- **Sending the card.** It is sent with the read-through only when the box is ticked. It is sent
  again when the creator sends the crew back from the rough cut, and never with any other request.
- **A browser that won't store anything** (a private window, blocked site data, or an accessor that
  throws) still makes the film. "Keep" says to download the card instead, and every read and write
  is inside `try`/`catch`.
- **A file the studio did not make** is refused at the pitch. It needs the card's schema, a reel or
  short format and a list of choices. The crew's own gate (HV-030-19) reads the words.

## Acceptance criteria

1. **Kept only when asked.** Nothing is written to the device before "Keep" is pressed. Pressing
   it writes exactly the card the plan answered with, under `hv-studio-style-card`, and makes no
   request. The download is the same card. "Forget" removes it.
2. **Sent only when attached.** A pitch whose card is not attached sends `{format, tone}` only,
   even with a card kept on the device. An attached card goes with that read-through and with the
   one the creator asks for from the rough cut. No other request carries it.
3. **Unticked by default.** With a kept card, the pitch shows the box unticked. Submitting it
   unticked sends no card. Ticked, it sends the card and fills an empty tone from it. With no kept
   card there is no box, only the file to load.
4. **Still works without storage.** With storage that refuses every call, or whose accessor throws,
   the film is still made. There is no kept card, "Keep" says to download it instead, and the
   download still works. A film whose plan was not retained has no card to keep, and says why.
5. **Only the studio's own cards.** A file that is not JSON, not an object, or has another schema,
   format or choices shape is refused.
6. Reverting `studio.js` fails every criterion. Reverting only the read-through body fails
   criteria 2 and 3. Reverting only the unticked default fails criterion 3.

- Tests: `packages/frontend/test/studio-style-card.test.js`.

## Known gaps this leaves

- **A resumed film has no card to keep.** The crew's plan answer isn't retained (HV-016-09), so a
  reopened link can't offer "Keep". The creator keeps it at the end of the pass they made it in.
- **One kept card per browser.** Keeping a new one replaces the old. Several styles live as
  downloaded files.
- **The card isn't shown before it is sent.** The creator sees its effect as the crew's proposals,
  each of which they accept or change. There is no view of the card's own contents yet.
