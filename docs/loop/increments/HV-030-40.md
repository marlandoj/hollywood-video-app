# HV-030-40 — Release 3's criteria read the $135 that G23 declared

epic: HV-030
release: 3 "Features"
gate: G23-202610050215 (Kevin started the live run with $135 declared)
spend_usd: 0

## Why

G20 agreed Release 3's criteria when the plan was for the exit run to declare about $120. HV-030-31's
contract reads that figure from the roadmap ("The exit run declares about $120") and fails any record
that declares more: "the record declares more than the roadmap's $120 for the feature".

Then G23 started the live run with **$135 declared**. HV-030-36 declares `spend_usd: 135`, and the
runbook passes `--spend-declared 135`. The record must carry what was actually declared. Under the
contract as written, the real record would fail criterion 5 on the declaration alone, however little
the run spends.

The roadmap was never updated to match G23. This increment does that, and nothing else.

## What this increment does

- **`docs/ROADMAP.md`, Release 3:**
  - The proof paragraph now says the exit run declares about $135, and that G20 planned about $120
    before G23 raised it.
  - The generation line's basis reads "The feature run declares about $135 (G23)".
- **`test/release-3-run.test.ts`:**
  - The criteria parse is now expected to give $135.
  - Criterion 5's "declaration past" case now expects the $135 wording.
  - The fixture still declares $120. That is within $135, so it still meets the contract.
- **`test/release-3-contract.ts` and `scripts/release-3-run.ts`:** the comments and usage example
  name $135.

Nothing else moves:
- the four spend lines and their limits;
- the feature's $150 film limit;
- the $500 program cap;
- the run-within-its-declaration check.

## Acceptance criteria

1. `readCriteria` reads $135 from the Release 3 section, and the parse is unchanged otherwise.
2. A record that declares more than $135 fails with "the record declares more than the roadmap's $135
   for the feature". The synthetic fixture, which declares $120, still meets the contract.

- Tests: `test/release-3-run.test.ts`.

## Known gaps

- None. The run's actual spend is still held to the declaration and to every line's limit.
