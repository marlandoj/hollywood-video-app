# HV-031-08 — The one class of invisible character the fold did not remove

epic: HV-031
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

HV-031-05 made `foldForMatching` strip the characters that are not there, because a zero-width
joiner inserted into a word passed every prohibition this package has — seventeen of seventeen. It
strips `[\p{M}\p{Cf}\p{Cs}\p{Co}]`. It never stripped `\p{Cc}`: the C0 controls, `\u007f`, and the
C1 block. Those are invisible in exactly the same way, and they were measured on this repo's own
gate:

```
Cc code points: 65 | whitespace: 5 | invisible: 60
invisible controls that evade EVERY listed name: 60 of 60   (185 of 185 names, each)
prohibition battery: 17 of 17 prompts passed, with one invisible control per word
```

Sixty single characters, each of which defeats the gate **completely**. `T\u0001aylor Swift` renders
to a person as the name, tokenizes at a provider as the name, and `namesPublicFigure` returned
false. `\u0001` before each word of a prohibited prompt and `checkPrompt` returned `allowed`.

The repo already knew. `motion-graphics.ts` refuses `[\p{Cc}\p{Cs}\p{Cf}]` in every string a title
carries, and so do the graphic library and the composite plans — and HV-031-05's own note in this
file cites them as the reason the fold is the right place for it. The fold then took two of that
class's three members. That is the same shape as HV-031-05 and HV-031-07 and HV-029-07: not a wrong
list, but a second description of a set that disagreed with the set.

This was recorded as an unbuilt finding at the end of HV-031-07 and is the whole of it.

## What this increment does

- **`foldForMatching` removes the control characters that are not whitespace**, with the class
  subtracted rather than written out: `/[[\p{Cc}]--[\s]]+/gv`.
- **The five whitespace controls stay.** Tab, newline, vertical tab, form feed and carriage return
  are `\p{Cc}` and are `\s`. `namePattern` already joins a name's parts with `[\s.\-]*`, so
  whitespace between them folds into a match; and removing a newline would join the end of one line
  to the start of the next, taking the word boundary `(?<![\p{L}\p{N}])` away from a name that
  begins a line. That is a false negative bought to close an evasion that is visible on the page.
- **`\p{Cf}` is not subtracted from.** `﻿` is both `Cf` and, to JavaScript, `\s`; subtracting
  `\s` from the format class would have undone HV-031-05 in the act of extending it. The two
  replaces stay separate for that reason, and the test says so.
- **The whole of `\p{Cc}` is the test's subject**, not a chosen character: every code point, against
  every name in `PUBLIC_FIGURES` and every prompt in `PROHIBITED_PROMPT_BATTERY`.

## Acceptance criteria

1. **The class is the whole of `\p{Cc}`** — 65 code points — and splits into 60 invisible and
   exactly the five whitespace ones, named.
2. **The fold removes every invisible control**, and **removes no whitespace control** — both
   directions, so the class cannot widen into whitespace or narrow away from a control.
3. **No invisible control hides a listed name from the gate**: 60 × 185, none missed.
4. **No invisible control hides a prohibited prompt from `checkPrompt`**: 60 × 17, none allowed —
   and each refusal names the category the battery declares, so a control cannot shift a prompt onto
   a different rule.
5. **HV-031-05 and HV-031-07 still hold**: `﻿`, `‍` and `­` still fold away, the
   Cyrillic and accent folds still hold, and `ԁ` and `ı` still refuse.
6. **The control class is derived, not written out** — asserted against the source — and ordinary
   screenplay text with a newline and a tab in it passes through the fold unchanged.
7. Reverting `public-figures.ts` fails criteria 2, 3, 4 and 6 (measured: 4 of the 6 tests fail).

- Test: `packages/safety/test/invisible-controls.test.ts`.

## Known gaps this leaves

- **A *visible* character inserted into a word still evades.** `Tay lor Swift` and `Tay-lor Swift`
  are not matched, because `namePattern` splits a name into parts and only the separators *between*
  parts are optional. The five whitespace controls fall under this too, by the argument above. This
  is the documented limit of a keyword list rather than a likeness detector — `PUBLIC_FIGURES`' own
  header says so — and the difference that matters is that a visible edit is visible to the person
  reading the script, while `\u0001` is not.
- **The fold is not a validator.** Nothing refuses a control character in a prompt; the fold makes
  the gate see through it. A screenplay carrying `\u0001` still reaches a provider carrying it. The
  graphics path refuses them outright, and whether the prompt path should too is a wider change than
  a matching fold and is not made here.
- **`\p{Cn}` — unassigned code points — is not in any of the four classes.** They are not invisible
  by definition, but a future Unicode assignment could make one so, and nothing here would notice.
- **This is still a keyword list.** Nothing in this increment claims the gate is Unicode-complete,
  and `PUBLIC_FIGURES`' header already denies it.
