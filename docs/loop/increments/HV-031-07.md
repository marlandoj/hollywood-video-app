# HV-031-07 — Two characters the gate's own table lists, that the gate never looked at

epic: HV-031
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

A critic pass over `packages/safety` and `packages/parser`.

`foldForMatching` folds a homoglyph — a Cyrillic "а" drawn as a Latin "a" — by looking the character
up in `HOMOGLYPHS`. It offered the lookup only the characters matching a hand-written class:

```ts
.replace(/[Ѐ-ӿͰ-Ͽɐ-ʯ‐‑⁄]/gu, c => HOMOGLYPHS[c] ?? c)
```

**Two of the table's thirty-four entries fall outside it.** `ԁ` is one codepoint past the
Cyrillic range's end; `ı` is Latin Extended-A, in none of the three ranges. The table said they
fold. The class said they never reach it. The class won:

```
table entries: 34   never applied: 2
  U+0501 — table says "d" — fold gives it back unchanged
  U+0131 — table says "i" — fold gives it back unchanged

ԁ for "d":  62 of the 185 listed names pass the gate
ı for "i": 105 of the 185 listed names pass the gate
union:          134 of 185
```

Through both entry points:

```
namesPublicFigure(<a listed name>)                    -> refused
namesPublicFigure(<the same name, one "i" swapped>)   -> allowed
checkPrompt(<the same name, one "i" swapped>)         -> {allowed: true}
```

A name written that way renders to a person as the name and tokenizes for a provider as the name.
The refusal was the only thing that saw a difference, and it did not.

This is a **safety refusal that stopped firing**, which CLAUDE.md names as the thing that must never
happen: *"Safety refusals in packages/safety may grow, never shrink."* It never fired for those two
characters — the table was written with entries the guard could not reach — so this is a hole that
was there from the day the table was, rather than one this loop opened.

And it is a shape the repo has already written about twice. `provider-kinds.ts` opens with:

> Six copies of one closed set is how a widening goes half-applied, and the half that matters fails
> silently.

HV-029-07 said the same thing about twenty hand-written project filters. Here the second copy is a
character class describing what a table holds, and it disagreed with the table by two entries.

## What this increment does

- **The pattern is derived from the table's own keys.** `HOMOGLYPH_PATTERN` is built by escaping
  every key of `HOMOGLYPHS` into a character class, so adding an entry adds its character and the
  two descriptions cannot disagree. The lookup's `?? character` fallback goes with it: every
  character the pattern matches is in the table, by construction.
- **It costs nothing.** A set of thirty-four is not a per-character callback over the string:
  0.03 ms at 25,000 characters and 0.21 ms at 200,000, the same as the range it replaces.

Nothing else about the fold changes. Case still folds before homoglyphs (HV-031-05's ordering),
accents and `\p{M}\p{Cf}\p{Cs}\p{Co}` are still stripped, and a character the table does not list is
still left exactly as it is.

## Acceptance criteria

1. **Every character the table lists is a character the fold folds** — read from the source, so the
   test cannot be looking at a different table. This is the structural claim: not that two entries
   now work, but that no entry can be dead.
2. **No listed name is allowed with one of them standing in for a letter**, over the whole cross
   product — 185 names × 34 entries, each substitution applied at every occurrence, in either case.
   Built from the module's own declarations, so this file contains no ready-made evasion string.
3. **The gate the studio actually calls refuses them too**: `checkPrompt`, not just the predicate,
   with `category: "named_public_figure"`.
4. **Folding a character the table does not list still leaves it alone** — a fold that removed what
   it did not recognise would refuse far more than the list, which is the same defect facing the
   other way.
5. **The fold is still linear**, asserted as a growth ratio, since a character range became a set.
6. Reverting `public-figures.ts` makes 1, 2 and 3 fail.

- Tests: `packages/safety/test/homoglyph-table.test.ts`.

## Known gaps this leaves

- **The table is still thirty-four entries, and the module says so.** Its own comment already denies
  being Unicode-complete: *"a list of thirty is worth having and is not the same as claiming the
  gate is Unicode-complete"*. What changed is that the list it does have is now fully applied. A
  confusables table from Unicode's own data would be the complete answer and is a dependency and a
  size decision, not a line.
- **`\p{Cc}` is not stripped.** The fold removes marks, format characters, surrogates and private
  use, and the docstring cites `motion-graphics.ts` refusing `[\p{Cc}\p{Cs}\p{Cf}]` — but control
  characters are not in the fold's own strip. The same pass could not establish that any route
  admits a raw control character into a gated field, so it is recorded here rather than claimed.
- **This is the gate, not the list.** 185 names is a list someone maintains; nothing here changes
  what is on it or how it grows.
- **The parser findings from the same pass are not in this increment.** A Fountain note or a
  one-line boneyard discards the whole line silently; a note on a scene heading deletes the scene and
  reports the wrong line as unparseable; a boneyard that closes and reopens on one line leaks the
  writer's deleted material into spoken dialogue; and a Fountain parenthetical is spoken and
  captioned where the Final Draft importer refuses it by name. Each is proven and each is its own
  increment — they are correctness in the parser, not a refusal that stopped firing, and this one
  went first because of that difference.
