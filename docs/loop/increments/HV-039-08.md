# HV-039-08 — The take desk locked every control for each 2.5-second status check

epic: HV-039
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

While a take group renders, `poll` checks it every 2.5 seconds, and it did so through `run`:

```js
const poll=()=>{if(panel.hidden)return;timer=setTimeout(()=>busy?poll():run(()=>load(false)),2500);};
```

`run` sets `busy` and disables every button, input and select in the panel until the request
returns. Three alternatives render for minutes, and the take draft sits on the same panel. So every
2.5 seconds:

- **The field the creator was typing a take label or seed into was disabled.** Keystrokes were
  dropped, and a browser that moves focus off a disabled control sent it to the page body.
- **A click on Estimate preview takes, Render, or Adopt selected take direction was dropped** if it
  landed during a check. It reached `run`, hit `if(busy)return`, and nothing said so. The more
  alternatives there were, the more often that happened.
- **The Saved take group list was rebuilt**, which closed it if it was open.

## What this increment does

- **The status check no longer goes through `run`.** It changes only what it reports, and it waits
  while the creator's own action is running rather than blocking it. A failed check says so and
  points to **Refresh take groups**, which is how a failure inside `run` would have been reported.
- **`poll` clears the previous timer** before setting a new one. A user action and a check can now
  both finish a `load`, and each `load` schedules the next check.
- **The group list keeps its options** when the groups are the same and in the same order. Only a
  label whose words changed is written.

## Acceptance criteria

1. **While a status check is in flight, the take draft's fields stay enabled**, and they are still
   enabled after it.
2. **Estimate pressed during a status check is carried out.** The quote is requested and Render
   preview takes appears.
3. **A status check keeps the group list's option elements**, and updates the label from "running"
   to "done".
4. Reverting `takes.js` fails all three.

- Tests: `packages/frontend/test/take-poll.test.js`. The test runs the 2.5-second check by hand and
  holds its request open to act while it is in flight.

## Known gaps this leaves

- **The group viewer is still redrawn when a group's progress changes** (`showGroup` when
  `renderedKey` moves). That replaces the progress line and, once the group finishes, draws the
  player. It happens on a change, not every 2.5 seconds, and the finished player has to be drawn.
- **Other desks' polls** (sound, voice, lip sync) have not been checked for the same pattern in this
  increment.
