# HV-039-15 — Reordering an assembly's ranges dropped keyboard focus to the page body on every move

epic: HV-039
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

The assembly studio builds a trailer or 60-second cut from ranges of a saved parent. It redraws on
every change except typing, and `render` begins:

```js
controls=[];top.replaceChildren();recovery.replaceChildren();library.replaceChildren();form.replaceChildren();actions.replaceChildren();
```

Every button that changes something therefore destroyed itself when pressed: **Move range 2 up**,
**Duplicate range 2**, **Remove range 2**, **Add parent range**, the pager, and **Save proposal and
review**. A keyboard user reordering five ranges had to find their way back from the top of the page
after every single move. They could not simply press the same button again.

## What this increment does

- **The pressed control is named before its action runs.** A range button is named by its range and
  its job, not its words, because after "Move range 2 up" that range is range 1 and its button says
  so. Other buttons are named by their words.
- **The first render that is not busy focuses the new copy of that control**, and then forgets it.
  If the new copy is disabled, focus goes to the nearest control still standing:
  - a range moved to the top or bottom keeps focus in its own row;
  - a removed range hands focus to the range that took its place, or to the one before it;
  - anything else lands on the draft heading.
- The name is cleared when the action finishes, so a failed action can't redirect a later redraw.

## Acceptance criteria

1. **Moving range 3 up focuses its Move up button, which now reads "Move range 2 up"**, in the
   range's new row, so pressing it again moves the same range again.
2. **A range moved to the top keeps focus in its own row, on a button that still works.**
3. **Removing a range hands focus to the range that took its place.** Duplicating a range focuses
   the same range's Duplicate button.
4. **A button outside the ranges returns to its own new copy.**
5. Reverting `edit-assemblies.js` fails all four.

- Tests: `packages/frontend/test/edit-assemblies-focus.test.js`, on the assembly fixture. The
  existing assembly suites pass unchanged (28 / 0).

## Known gaps this leaves

- **Typing is untouched.** Typing never re-rendered the panel; the existing test "typing preserves
  raw field DOM, invalidates exact review, …" pins that.
- **The render panel below** has its own rebuild; HV-039-12 fixed its status messages, not its
  focus.
- **Two buttons with the same words** would resolve to the first usable one. None exist in the panel
  today.
