# HV-038-01 — Sanitized structured logs, trace-correlated
epic: HV-038
spend_usd: 0

## Goal
Close the "structured logs" half of the observability pillar. Traces exist (`packages/observability/src/index.ts`, `StudioTelemetry`), metrics are partial, and there is no logger: the API prints one free-text line with its own URL (`packages/api/src/server.ts`), the worker prints five ad hoc `console.log(JSON.stringify(...))` lines carrying ids but no trace context (`packages/queue/src/worker.ts`), the sweeper prints its own JSON status and error lines (`scripts/sweep-expired.ts`), and nothing states what may or may not appear on stdout. This increment adds a small, dependency-free JSON log emitter in `packages/observability/src/logs.ts` (`StudioLogger`, `loggerFromEnv`) used by the API, the worker and the retention sweeper. Every line is one JSON object with a fixed schema (`ts`, `level`, `service`, `event`, then a bounded, allow-listed context: `op`, `stage`, `outcome`, `code`, `traceId`, `spanId`, `durationMs`, `projectId`, `jobId`, `attemptId`, `provider`, `worker`, `method`, `route`, `status`, `jobStatus`, `leaseReason`, `costUsd`, `shots`, `files`, `retryInSeconds`, `port`, `tls`, `storage`, `release`, `dropped`). Values pass the same validators traces use (`safeAttributes`) or an equally strict log-only enum/pattern; anything else is dropped and counted in `dropped`, never silently. A final line-level guard refuses any serialized line that contains a URL, a `Bearer` marker, a signed-token shape or a long opaque blob. Trace and span ids come from the active `SpanHandle` so every log line joins the trace it belongs to. Level and sampling are env-controlled (`HV_LOG_LEVEL`, `HV_LOG_SAMPLE`) with safe defaults. The identifier rule under ADR-0018 is stated and tested: operational ids that traces already carry (project, job, attempt UUIDs minted by the service; the operator-assigned worker name) may appear; identity and tracking signals (client address, headers, tokens of any kind, URLs, filenames, screenplay text, error messages, provider bodies, credentials) never do. No route, migration, dependency, budget default, provider or frozen path changes; spend is 0 and providers stay `mock`.

## Acceptance criteria
1. **A bounded JSON log emitter exists and is the only log path in API, worker and sweeper.** `packages/observability/src/logs.ts` exports `StudioLogger` (`debug|info|warn|error` methods taking an `event` from a fixed `EVENTS` set and a `LogFields` object), `safeLogFields`, `guardLine`, `loggerFromEnv(service, telemetry?)` and the `LogEvent` type. Each emitted line is `JSON.stringify` of an object whose keys are exactly the fixed fields `ts` (ISO-8601), `level`, `service` (`api|worker|retention`), `event`, plus only allow-listed context keys that passed validation; the line is at most 2048 bytes; lines at `warn`/`error` go to stderr and `info`/`debug` to stdout (the supervisor's per-program log files). Every `console.log`/`console.error` in `packages/api/src/server.ts`, `packages/queue/src/worker.ts` and the PostgreSQL branch of `scripts/sweep-expired.ts` is replaced by a logger call, except the sweeper's per-minute `sweptAt` status line, which `scripts/storage-wave-a-evidence.ts` parses and which stays byte-for-byte unchanged. No entry is added to any `package.json` or lockfile. Satisfies FULL-SCOPE §3 P15 "Observability: OpenTelemetry traces from session action to provider attempt to export; metrics; structured logs; cost dashboards." and CLAUDE.md "Never add keys, accounts, or vendors."
2. **Allow-list only; unknown, invalid and oversized fields are dropped and counted.** `safeLogFields` maps `projectId`, `jobId`, `attemptId`, `op`, `outcome`, `code`, `provider`, `method`, `route`, `status`, `costUsd`, `shots`, `files` onto the existing trace validators in `safeAttributes`, so a log can never carry a value a trace could not; log-only keys have equally closed validators: `stage` ∈ the `JobStage` union, `jobStatus` ∈ `queued|running|done|failed|cancelled`, `leaseReason` ∈ `not_running|wrong_worker|lease_expired|fence_changed`, `worker` matches `^[A-Za-z0-9_.:-]{1,40}$`, `durationMs`/`retryInSeconds`/`shots`/`files` are finite integers in `[0, 1e9]`, `port` in `[1, 65535]`, `tls` boolean, `storage` ∈ `json|postgres|local|s3`, `release` 40 lowercase hex, `traceId` 32 non-zero hex, `spanId` 16 non-zero hex. Any other key, any value that fails its validator, and any string longer than 128 characters is omitted and `dropped` (integer count) is added to the line; `dropped` is absent when nothing was dropped. An `event` outside `EVENTS` produces a single `log.dropped` line at `warn` instead of the requested line and never throws. Satisfies §3 P15 "structured logs" read with §10 "Evidence before promotion: tests, benchmarks, post-flight evals, gap audits."
3. **No secret, text, URL, header, credential or error body can reach a line, on any path.** `guardLine` rejects the serialized line if it matches `://`, `/\bBearer\b/`, the signed-token shape `[A-Za-z0-9_-]{16,}\.[A-Za-z0-9_-]{16,}` (`packages/api/src/tokens.ts` wire format) or a run of 64+ base64 characters, and emits `{ts, level:"error", service, event:"log.suppressed", dropped:n}` in its place. The logger API accepts no `message`, `error`, `reason`, `url`, `path`, `headers` or free-text key; `Error` objects are never serialized; `failureCode(error)` is the only thing derived from an exception. The API never logs the raw pathname (only `routeTemplate`), the `Authorization` header, a request or response body, or the client address computed for rate limiting. Satisfies §3 P15 "structured logs", §8 "Security: capability isolation, signed URL scope, IDOR" and ADR-0018 "privacy-preserving abuse controls".
4. **Identifier rule under ADR-0018, stated and enforced.** Log lines may carry `projectId`, `jobId` and `attemptId` because they are random UUIDs minted by the service, scoped by capability tokens, bound to no account, device or person, and already present on traces (`docs/OBSERVABILITY.md` "Operational identifiers are allowed in traces"); the operator-assigned worker name (`HV_WORKER_ID`) may appear. The per-incarnation `workerId`, the provider request id, tokens of every kind, client addresses, forwarded headers, user agents and cookies are excluded from the schema. `docs/OBSERVABILITY.md` states this rule and its justification. Satisfies ADR-0018 "Visitors do not provide identity or payment information. Revocable capability tokens … privacy-preserving abuse controls … replace accounts and billing." and FULL-SCOPE §10 "Free and anonymous for every end user; no billing code reachable."
5. **Trace correlation from the active span, in both processes.** When a line is emitted inside `StudioTelemetry.run`/`http` (or with an explicit `SpanHandle` argument), `traceId` and `spanId` are the ids of that span (parsed from `SpanHandle.carrier()`). `StudioTelemetry` gains one optional public field, `onOperation?: (report: OperationReport) => void`, invoked from the finished callback in `start()` with `{operation, failed, attributes, durationMs, carrier}`; `loggerFromEnv(service, telemetry)` attaches it so every completed `provider.attempt` yields an `info` line and every other non-`http.request`/`job.process` operation yields a `debug` line, with no new call sites in the worker. When telemetry is disabled the logger still works and omits `traceId`/`spanId`; the doc says so. Satisfies §3 P15 "OpenTelemetry traces from session action to provider attempt to export; … structured logs" and §10 "Evidence before promotion".
6. **Emit sites cover the lifecycle.** API: `api.started` (`port`, `tls`, `storage`) replacing the URL-printing line, and one `api.request` per completed request (`method`, `route`, `status`, `durationMs`, `outcome`, `code` on a thrown error) emitted inside the `telemetry.http` callback so it is in-span. Worker: `worker.started` (`worker`, `storage`), `worker.stopped`, `worker.heartbeat_failed` (`warn`), `worker.job_started` (`projectId`, `jobId`, `stage`, `worker`) at the top of the `job.process` span in `processNextJob`, `worker.lease_lost` (`warn`, `leaseReason`) on both `LeaseError` branches, and `worker.job_finished` in the job's `finally` (`jobStatus`, `code`, `costUsd`, `shots`, `durationMs`, `outcome`; level `info` for `done`, `warn` for `cancelled`, `error` for `failed`). Provider attempt outcomes and stage transitions come from the hook of criterion 5. Sweeper: `retention.failed`, `retention.cache_cleanup_failed`, `retention.incomplete_uploads_failed` (`error`, `retryInSeconds`). `processNextJob` uses `context.logger ?? quietLogger`, mirroring `quietTelemetry`, so existing tests and callers are unchanged. Satisfies §3 P15 "structured logs" and "Render farm: … job classes with leases, retries, idempotency, dead-letter".
7. **Level and sampling are env-controlled and safe by default.** `HV_LOG_LEVEL` ∈ `error|warn|info|debug`, default `info`; `HV_LOG_SAMPLE` is a number in `[0, 1]`, default `1`, applied only to `debug` lines and to `api.request` lines with `status < 400`; `warn`/`error` lines and every `worker.*`, `retention.*` and `provider.attempt` line are never sampled out. The sampling decision is trace-consistent (derived from the last 8 hex digits of `traceId` when present, `Math.random()` otherwise). Unparseable values fall back to the defaults and emit one `log.configuration_invalid` `warn` line; nothing throws. Below-level and unsampled lines cost one comparison, not a serialization. Satisfies §3 P15 "structured logs" and §9 Wave A exit "Staging runs on PostgreSQL + S3 with the existing E2E passing" (the hot path stays cheap and quiet by default).
8. **A real request and a real job with canaries prove non-leakage.** `packages/observability/test/log-leakage.test.ts` runs `createApiServer` and `processNextJob` with injected loggers and `InMemorySpanExporter`s, pushes a screenplay containing a sentinel, obtains a project token, calls a signed review link and an artifact URL, triggers a 400 whose response message contains user text, and makes a job fail through an adapter whose error message contains a sentinel and a `https://` URL. It asserts every captured line parses as JSON, its keys are within the schema, and no line contains the token, the token secret, the sentinels, `://`, `Bearer`, `127.0.0.1`, or the `failureReason` stored on the job; that `api.request` and `worker.job_*` lines carry the trace ids of the exported spans; and that `dropped` never appears on a production emit site. Satisfies §10 "Evidence before promotion" and CLAUDE.md "Every criterion gets a real test."
9. **No frozen path, dependency, budget default, account, vendor, migration, provider, route or telemetry-contract change.** The diff touches nothing under `docs/legal/**`, `docs/adr/**`, `.github/workflows/**`, `packages/safety/**` or `infra/drizzle/**`; `scripts/telemetry-explorer-smoke.ts`, `packages/observability/src/explorer.ts` and every exported symbol and behaviour of `index.ts` used by the `telemetry-contract` job are unchanged (one optional field is added); no `package.json` or lockfile entry; no key, account, tier, cookie or tracking; no HTTP route change; the `sweptAt` status line is unchanged. Satisfies §10 "Free and anonymous for every end user; no billing code reachable.", "Safety refusals expand only." and the EXECUTION-LOOP frozen list.
