# HV-016-04 — The bound on the screenplay was not a bound on the work

epic: HV-016
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

HV-016-03, merged today, fixed a quadratic whitespace normalizer in the **Final Draft importer**
and quoted HV-016-02's own header while doing it:

> *"Every search here is a linear `indexOf`, and the bound on the input is therefore also a bound
> on the work."*

The Fountain parser — which every route in the studio runs, on every read — has the same defect,
and it is worse, because nothing has to be imported to reach it.

```ts
const PROTECTED_SPAN = /\[\[[^\]]*\]\]|\/\*[\s\S]*?\*\//;
```

Tested once per line. On a run of `[`, `\[\[` matches at every offset, `[^\]]*` runs to the end of
the line, `\]\]` fails, and the engine gives back one character at a time. `parseFountain` bounds
the *document* at thirty pages of parsed lines; it has never bounded a **line**. So the payload is
one line, the page estimate is 1, and `rejected` is `false`:

| screenplay characters | `parseFountain` | `PUT /script` | `GET /direction` |
|---|---|---|---|
| 12,500 | 27 ms | 31 ms | 103 ms |
| 25,000 | 111 ms | 101 ms | 400 ms |
| 50,000 | 416 ms | 390 ms | 1,517 ms |
| 100,000 | 1,640 ms | 1,411 ms | 5,926 ms |
| **200,000** | **6,048 ms** | **5,880 ms** | **24,635 ms** |

Fourfold per doubling. 200,000 is the limit `PUT /api/projects/:id/script` enforces, and the body
is 200,012 bytes against a 250,000 default — so the screenplay **saves**, and every later read
parses it again. `GET /direction` parses it four times. `GET /audio-takes` twice.

The server is single-threaded, so this is not one slow request, it is the studio. A second,
unrelated project's `GET /health` measured **25,038 ms** while one attacker's `/direction` ran.

And the worst reach is the media path. `artifactPermission` parses `job.scriptText` for take stages
and character sheets, and it runs on `/artifacts/:token/...` — a route that carries no bearer token
(the signed token is a path segment, FR-053), is meant to be shared, and sits in the **600/min**
artifacts bucket rather than the 120/min api one. Three consecutive frame fetches from a project
whose script is 200,000 poisoned characters measured 6,476 ms, 6,044 ms and 5,587 ms. Six hundred
permitted requests a minute at six seconds each is sixty minutes of blocked event loop per minute
of attack, from one address, with a URL the owner handed out on purpose.

Everything above needs one anonymous `POST /api/projects` and no credentials (ADR-0018).

## What this increment does

- **`holdsProtectedSpan(line)` replaces the pattern with a left-to-right scan.** Two cursors, both
  monotone: for each `[[` the first `]` after it is the only place `[^\]]*` can end, so the question
  is whether that `]` is doubled, and the `]`-searches are disjoint because the cursor is only
  recomputed once the opener has passed it. The boneyard half is one `indexOf` pair, because if the
  first `/*` finds no `*/` after it, no later `/*` can.
- **The replacement is proved equal to the pattern, not argued to be.** Every arrangement of
  `[`, `]`, `/` and `*` up to length eight — 87,380 strings — plus 200,000 seeded pseudo-random
  strings over those four plus ordinary text, a backslash, a tab and a newline. Zero disagreements.
  A false positive here would silently take a line of a real screenplay out of the film, which is
  the failure this epic exists to prevent, so equality is asserted rather than assumed.
- **A guard over the parser's own regex declarations**: none of them may pair two things across an
  unbounded `[\s\S]*` or `[^…]*`. Taken from the source, so a new constant is covered on the day it
  is written.

Measured after: every 200,000-character shape parses in **0–5 ms**.

## Acceptance criteria

1. **Exhaustive equality** over the four-character alphabet to length eight (87,380 strings), with
   the old pattern kept in the test as the oracle.
2. **Equality over mixed text**, 200,000 seeded strings including backslash, tab and newline.
3. **Six adversarial 200,000-character shapes parse in under 500 ms each**, and each still returns
   `rejected: false`, which is what made the original reachable more than once.
4. **The growth is linear**: four times the input is not sixteen times the work.
5. **Notes and boneyards are still excluded from the film**, in the multi-line form the existing
   suite covers and in the one-line forms, with the near misses (`[[a] b]`, `/*/`, `[single]`)
   still unprotected.
6. **No parser regex pairs two things across an unbounded gap**, asserted over the source.

- Tests: `packages/parser/test/protected-span.test.ts` (1–6).

## Known gaps this leaves

- **No line bound was added.** The scan makes the document's bound a bound on the work, which is
  the principle; a per-line limit would additionally refuse screenplays, and refusing a creator's
  script is a product decision rather than a build one. If it is wanted, the importer's
  `paragraphCharacters: 20000` is the number that already exists.
- **The amplification is untouched.** `GET /direction` still parses the same screenplay four times
  (`server.ts:934`, `:936`, and twice at `:955`) and the viewfinder loop parses each candidate
  job's script *before* the permission check that discards most of them. Both are now four times a
  small number instead of four times a large one, so nothing is unsafe; both are still waste.
- **Screenplay version history is still uncapped.** `VersionStore.commit` pushes and never trims,
  while `castingHistory`, `directionHistory` and `dialogueSelections` are all capped. Every
  authenticated request reloads and re-serializes the whole project, so 129 retained versions of a
  legal 200,000-character screenplay measured 25.8 MB of state, 208 ms per `PUT /script` and 93 ms
  per `GET /spend`, growing linearly with no ceiling — about 1.4 GB/hour from one address at the
  120/min limit. It is **not fixed here**: capping it would make an old version unrestorable, which
  changes what `restoreScript` promises and interacts with the living-screenplay acceptance rule
  that every consecutive version be retained. That is a decision for the operator, not a build
  session, and it is written down here so it is a decision rather than an oversight.
- **This says nothing about the other packages' patterns.** The guard reads `packages/parser/src`
  only. `packages/safety` was swept in HV-031-05; the rest have not been.
