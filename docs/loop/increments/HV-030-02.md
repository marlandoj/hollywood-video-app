# HV-030-02 — The crew applies the creator's answers

epic: HV-030
release: 1 "Studio" (build order step 2)
gate: G13-202609192200
spend_usd: 0 (no live model is called)

## Goal

The crew's questions lead somewhere. The creator's answers become the studio's own cast and shot direction, set by the persona that owns each department, through the same validators a creator's edit meets.

## What this increment does

**`packages/planner/src/crew/production-plan.ts`**

- **Strict, gated answers** (`planInput`).
- **The plan prompt.** It is given the script's own character names and the planner's own shot ids.
- **`validateCrewPlan`.** It refuses:
  - a character not in the script, or one cast twice;
  - a shot not in the plan, or one planned twice;
  - a size, angle or movement outside `DIRECTION_CHOICES`;
  - any string the gate refuses.
- **A deterministic stand-in plan.**
- **`crewChanges`.** It adds cast only for uncast speaking roles, with permission pending, and direction only for undirected shots. Both are checked with `characterRecord` and `directionSettings`, and each change carries a note naming the persona that made it.

**`ProjectService.applyCrewChanges`**, plus the PostgreSQL wrapper:

- It checks the expected script, cast and direction versions.
- It refuses to replace an existing cast member or directed shot.
- It writes one cast version and one direction version.

**`POST /api/projects/:projectId/crew/plan`:** owner only. A stale version is a 409. It meters crew spend, and stops at the ceiling.

**`docs/CREW.md`** gains "The production plan".

## What this increment does not do

- **It does not permit a cast member.** The creator attests at the look approval, in HV-030-03.
- **It does not render or spend on generation.**
- **It adds no music.** The Composer's music bed comes with step 7. Here Sound sets each shot's sound intent.
- **It adds no interface.** That is HV-030-03.

## Acceptance criteria

1. **Answers are strict and gated.** Unknown persona, duplicate answer, gated reply and bad format are refused. Tests: `packages/planner/test/crew-plan.test.ts`.
2. **The stand-in plan.** It casts every speaking role and directs every shot, passes the validator, and every string passes the gate.
3. **A plan outside the script is refused.** That covers a name or shot outside the script, an unknown size, a lookalike description and a duplicate shot.
4. **The crew never overwrites the creator.** It adds only uncast roles, with permission pending, and directs only undirected shots.
5. **Fallback.** The model's plan is used when valid. When it is unusable, the crew falls back with the cost recorded.
6. **Over HTTP** (`packages/api/test/crew-plan-route.test.ts`):
   - One cast version and one direction version, with the cast pending.
   - A second pass changes nothing.
   - Stale versions get a 409.
   - Owner only.
   - Malformed answers get a 400.
   - The stand-in spends nothing.
