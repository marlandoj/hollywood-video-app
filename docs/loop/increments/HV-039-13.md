# HV-039-13 — Choosing a frame anchor's image destroyed the list being used

epic: HV-039
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

In **Shot direction → Frame anchors**, each anchor row has a "Private image" list:

```js
select.onchange=()=>{frame.asset=…;changed();render();};
```

`render` starts with `list.replaceChildren()` and rebuilds every anchor row, so the list the creator
had just used was replaced by a new one and keyboard focus fell to the page body. On Windows, the
arrow keys on a closed list change its value and fire `change` on each press. A keyboard user
therefore lost the list at the first arrow and couldn't step through to a second image without a
mouse. **Remove anchor N** also rebuilt the rows, and its own button was destroyed along with them.

## What this increment does

- **Choosing an image redraws only that anchor's thumbnail.** Each row has its own thumbnail
  holder. A newer choice or render makes an older image load moot, so a late load can't overwrite a
  newer thumbnail.
- **Removing an anchor moves focus to a surviving control:**
  - the image list of the anchor that took the removed one's place;
  - if the last anchor was removed, the one before it;
  - if no anchors are left, **Add frame anchor**.

## Acceptance criteria

1. **Choosing an anchor's image keeps the list, the row and the other anchors in place.** The rows
   and the list are the same elements as before, and the thumbnail and the draft both follow the
   choice.
2. **Removing a middle anchor moves focus to the image list of the anchor that took its place.**
3. **Removing the last anchor moves focus to the one before it. Removing the only anchor moves
   focus to Add frame anchor.**
4. Reverting `frame-anchors.js` fails all three.

- Tests: `packages/frontend/test/frame-anchors-focus.test.js`.

## Known gaps this leaves

- **Add frame anchor still rebuilds the rows.** Its own button survives, so focus stays on it, but
  the new row isn't focused.
- **Store anchor image rebuilds the rows** after an upload. The button is in the upload section and
  survives.
