# HV-037-01 — Make the benchmark's metric set self-guarding, and give the cost gate a floor so it can fire

epic: HV-037
spend_usd: 0

## Goal

Fix the two defects that make the merge gate weaker than its own documentation claims, before any metric is added to it.

**1. `compareDeterministic`'s cost gate could never fire.** It guarded its lower-is-better comparison with `if (before > 0 && …)`, and `runBenchmark` constructs `new DeterministicMockProvider({ costPerShotUsd: 0.0 })`. The committed baseline records `"costPerShotUsd": 0`. So that gate was inert on the only record it ever reads — it could not have failed a candidate that made every shot cost twelve dollars. FULL-SCOPE §8 asks for "cost variance (≤ 5 % or $0.05)"; the absolute half is precisely what makes such a gate work from a zero baseline, and it was not implemented. *(An earlier draft of this doc called it "the only cost check in the program". That was wrong: `packages/benchmarks/src/animatic.ts` exact-compares `costUsd` against its own baseline and can fire, and `packages/operator` is a runtime cost ledger with caps. The defect is real; the totality claim around it was not.)*

**2. Two records were closed sets in their own files, gated by hand-written key lists elsewhere, with nothing linking them.** `scripts/benchmark/compare.ts` had **four** such arrays — `LOWER_IS_BETTER`, `HIGHER_IS_BETTER`, `LATENCY_KEYS` and `GATED_LATENCY_KEYS` — naming **eight** distinct fields of the fourteen `BenchmarkMetrics` records. `packages/benchmarks/src/animatic.ts` had one, naming six of its seven. Nothing checked either for coverage, so a field added to either record shipped **silently ungated** — and every remaining §8 metric (identity similarity, palette match, composition, caption alignment, loudness compliance, QC pass rate, provider success rate, determinism) is a field added to one of them. Loudness compliance would most plausibly land in the animatic file, which is why leaving that half alone was not an option.

**How this increment was found.** The program-wide re-verification of the pre-loop credit ran one auditor per epic across all 22 epics that had never had the pass `docs/loop/STATUS.md` says the first planner is supposed to run. HV-037 came back `partially-delivered` with a correction to the board in the *understating* direction: the frozen 24-shot corpus, the merge-blocking deterministic gate, the same-host latency A/B that checks the merge base out into a worktree, the ffprobe-backed animatic gate and the adapter-conformance suite are all real, merged and CI-enforced, and the row credits `(none)`. Both defects above were verified against the source before any code was written.

## The shape of the repair

**One classification per record, in the file that owns it.** `BENCHMARK_FIELDS` in `packages/benchmarks/src/run.ts` names **every** key of `BenchmarkMetrics`, and `ANIMATIC_FIELDS` in `packages/benchmarks/src/animatic.ts` names every key of `AnimaticMetrics`, in the same shape: `exact`, `lower` (a proportional limit *and* an absolute floor), `higher` (the same), `latency-ab` (gated only by the same-host A/B), `latency-note` (advisory) or `note`. Both gates derive their key lists from their own table via the shared `benchmarkFieldsOf`, and neither names a metric field in a literal any more.

**Three independent readings of each closed set, so no single copy can drift.** The table's keys are compared to the keys of a record from the **real** `runBenchmark`, to the keys of the **committed baseline read from disk**, and to the field names parsed out of the **interface in the source**. An earlier draft compared the table to a fixture defined in the test file and described that as evidence about the baseline; it was a fixture testing itself, and deleting a field from `baseline.json` passed.

**The derivation is checked at the source, because equality cannot check it.** A literal list that happens to agree with the table today is indistinguishable from a derived one by any equality assertion. So a test reads `compare.ts` and asserts that **no** key of `BenchmarkMetrics` appears in it as a string literal, and reads `animatic.ts` and asserts its gate has no hand-written key array. An earlier draft offered a perturbation as proof of the link; that perturbation only showed that a literal which *disagreed* failed.

**`note` cannot hide a metric.** Every field classified `note` must be a **string** in the real record. Without that, the escape hatch for a new numeric metric was one word wide.

**The §8 floor, implemented as §8 words it, in both directions.** A regression now fires when the movement exceeds `max(before × limit, floor)` — the allowance is the larger of the proportional limit and the absolute floor, which is what "≤ 5 % **or** $0.05" means. From a zero baseline the floor is the whole allowance, so the cost gate fires at 5.1 cents per shot and passes at 5. Above the floor the proportional limit takes over, so a real paid baseline is not held to five cents for ever. The higher-is-better side gets the same shape and loses the same `before > 0` guard: keeping that guard on one side of a repair whose entire subject is that guard would have been an undeclared asymmetry.

**A missing number is a failure, not silence.** Both old loops treated a non-number as nothing to check: `before > 0` is false for `undefined`, and the latency loop `continue`d on `typeof before !== "number"`. A record that lost a gated field passed the gate. It now reports the field as missing.

**A malformed environment override refuses the gate rather than turning it off — at the gate, not at import.** `LATENCY_LIMIT` was `Number(process.env.HV_BENCHMARK_LATENCY_LIMIT ?? 0.05)`. `Number("loose")` is `NaN`, and `delta > NaN` is `false`, so a typo in that variable silently disabled a merge gate — a fail-open override on the thing whose job is to fail. `limitFromEnv` and `roundsFromEnv` now refuse anything that is not a usable fraction or a positive integer, and both take the environment as a parameter so the refusal is testable without mutating `process.env`. An earlier draft computed the constant at module load, so a malformed value made *importing* the comparator throw and took down the very test that checks the refusal; the module now exposes `latencyLimitOverride()` and `defaultRounds()`, read at call time.

**Each gated latency field is held to its own limit.** `compareLatency` took a single `limit` and never read the table's per-field one, so that field of the rule was scaffolding — and the assertion offered as its justification pinned `DETERMINISTIC_LIMIT`, a different constant entirely. The gate now uses `override ?? rule.limit`, and a test drives both paths: with no override each field uses its table limit; with one, the override replaces every limit and the advisory line says which was applied.

**Two riders in the same files.** `runBenchmark` resolved its fixture with `new URL(…).pathname`, which is percent-encoded, so a checkout under a path containing a space resolved to a file that does not exist; it now uses `fileURLToPath`. And `packages/benchmarks/package.json` declared `"main": "src/index.ts"`, a file that has never existed in that directory; it now names `src/run.ts`.

## Acceptance criteria

1. **Every recorded field of both benchmarks is classified, and nothing is classified that is not recorded.** For `BenchmarkMetrics`: the table's keys equal the keys of a record from the real `runBenchmark`, the keys of `baseline.json` read from disk, the keys of this file's own fixture, and the field names parsed from the interface in the source. For `AnimaticMetrics`: the table's keys equal the field names parsed from its interface, and `animatic-baseline.json`'s keys equal exactly the table's `exact` fields — the wall-clock one is classified `latency-note` and is deliberately absent from the baseline. The **whole** table is pinned with literals: every `kind`, every `limit` and every `floor`, so a limit cannot be widened from 0.05 to 0.5 unnoticed. Every `note` field is a string in the real record, so a new numeric metric cannot be classified as ungated.

2. **Both gates derive their field lists from their own table, checked at the source.** No key of `BenchmarkMetrics` appears as a string literal anywhere in `scripts/benchmark/compare.ts`; `packages/benchmarks/src/animatic.ts` contains no hand-written key array and calls `benchmarkFieldsOf("exact", ANIMATIC_FIELDS)`.

3. **The cost gate fires from a zero baseline, and the same allowance applies in the other direction.** Against `costPerShotUsd: 0`, a candidate at 0.051 is a regression with the allowance named in the message; 0.05 and 0 pass. Against a paid baseline of 4, 4.19 passes and 4.21 fails, and cheaper is never a regression. Against `visualQualityProxy: 1`, 0.96 passes and 0.94 fails, and a zero-to-zero comparison passes.

4. **An exact field that changes is a regression, and a lost number is not silence.** Every `exact` field fails the gate when it differs — including `provider` and `model`, which were ungated — and every `lower` and `higher` field fails the gate when absent, with a message naming it.

5. **Each gated latency field is held to its own table limit, and an override replaces every one.** With no override, 104 passes and 106 fails against a base of 100, per field; with `0.35`, 130 passes, 140 fails, and the advisory names the applied limit.

6. **A malformed limit or round count refuses the gate.** Through both the parser and the accessor the gate actually calls: `HV_BENCHMARK_LATENCY_LIMIT` of `loose`, `NaN`, `-0.1`, `2`, `5%` or `Infinity` throws; `HV_BENCHMARK_ROUNDS` of `loose`, `0`, `-1`, `2.5` or `NaN` throws. Absent and blank yield `undefined` — which is what lets each field keep its own limit — and valid values parse.

7. **The two riders are covered rather than asserted.** `packages/benchmarks/src/run.ts` contains no `new URL(…).pathname` and does use `fileURLToPath`; `packages/benchmarks/package.json`'s declared `main` names a file that exists.

8. **Nothing frozen is touched, and no new dependency, vendor, key, route, account, tier, payment path, budget default or migration appears.** `.github/workflows/ci.yml` is **not** in the diff. The root `package.json` and `bun.lock` are not in the diff; `packages/benchmarks/package.json` is, for its `main` field. `docs/loop/STATUS.md` and `docs/PROGRAM-EXECUTION.md` are not in the diff; RECORD owns both.

Eleven perturbations, each applied on this branch, measured against the final test file, and reverted:

| perturbation | result |
|---|---|

| P3 — drop `continuityAvg` from the classification table | `5 pass / 1 fail` |

| P6 — accept a malformed latency limit again | `5 pass / 1 fail` |

**Four of these rows are corrections to an earlier draft, and each one passed it.** P4, P5, P8, P10 and P11 all passed the first draft: the table pinned only `kind`, `note` had no type rule, the derivation was checked by equality, the animatic half was compared against a list written in the test, and the per-field latency limit drove nothing. P8 and P10 are the two that matter most — they are the shapes in which the defect comes back, and P2 is the shape of every remaining §8 metric.

## Tests added

- `packages/benchmarks/test/metric-classification.test.ts` (new; offline, no provider network) — six cases covering criteria 1–7. The first runs the real 24-shot benchmark and carries a 180-second budget for it.
- `packages/benchmarks/test/benchmark.test.ts` gains one line: `LATENCY_LIMIT` no longer exists as a module constant, so the existing suite now reads the A/B limit from the classification table.

## What this increment does **not** do

- **It adds no metric.** Identity similarity, palette match, composition, caption alignment (p95 ≤ 250 ms), loudness compliance, QC pass rate, provider success rate and determinism are all still absent. This increment makes the *next* one safe to write, which is why it comes first.
- **It does not expand the corpus.** The frozen fixture is still 24 shots, not §8's 240, and `run.ts` still refuses any other count.
- **It does not touch the studio-benchmark half of the promotion claim.** `packages/generator/src/performance-registry.ts` says every provider "must pass the adapter conformance suite **and** the studio benchmark before promotion". The conformance half is real; the benchmark half is claimed-but-unproven, because `run.ts` hardwires one mock provider and nothing can run the benchmark against a registered adapter at all. That is a bigger increment and a claim that should be narrowed or delivered, not left as it is.
- **It delivers none of §8's blinded human rubrics, public leaderboard, chaos suite or security suite.** Five of the seven §8 clauses have no implementing code.
- **It does not change the latency A/B's design or its numbers.** The limit is still 5% and the measurement is still the same-host interleaved floor across rounds; what changed is where the limit comes from and that an override is legible in the advisory line.

## Declared changes beyond the two defects

- **`provider` and `model` are now `exact`.** They were ungated, so a candidate that swapped `DeterministicMockProvider` for a faster or cheaper provider passed the deterministic gate in silence. Both are hardcoded in `run.ts` and in the baseline today, so this fails nothing now and is a deliberate wall for the increment that first runs the benchmark against a registered adapter.
- **`fixtureVersion` is now compared exactly**, which it was not; `run.ts` and `baseline.json` both hardcode `"1.0.0"`.
- **`LATENCY_LIMIT` and `DEFAULT_ROUNDS` are gone**, replaced by `latencyLimitOverride()` and `defaultRounds()`. This removes an import-time throw on a malformed override, and it is why `packages/benchmarks/test/benchmark.test.ts` changed.
- **The higher-is-better comparison lost its `before > 0` guard and gained an absolute floor**, matching the lower-is-better side.
