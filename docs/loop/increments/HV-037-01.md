# HV-037-01 — Make the benchmark's metric set self-guarding, and give the cost gate a floor so it can fire

epic: HV-037
spend_usd: 0

## Goal

Fix the two defects that make the merge gate weaker than its own documentation claims, before any metric is added to it.

**1. The cost gate could never fire.** `compareDeterministic` guarded its lower-is-better comparison with `if (before > 0 && …)`, and `runBenchmark` constructs `new DeterministicMockProvider({ costPerShotUsd: 0.0 })`. The committed baseline records `"costPerShotUsd": 0`. So the only cost check in the program was inert on the only record it ever reads — a gate that could not fail for any candidate, including one that made every shot cost twelve dollars. FULL-SCOPE §8 asks for "cost variance (≤ 5 % or $0.05)"; the absolute half is precisely what makes such a gate work from a zero baseline, and it was not implemented.

**2. `BenchmarkMetrics` was a closed set in one file, gated by three hand-written arrays in another, with nothing linking them.** `LOWER_IS_BETTER`, `HIGHER_IS_BETTER` and `LATENCY_KEYS` in `scripts/benchmark/compare.ts` named nine of the fourteen recorded fields between them. Nothing checked that they covered the record, so a field added to the interface shipped **silently ungated** — and every remaining §8 metric (identity similarity, palette match, composition, caption alignment, loudness compliance, QC pass rate, provider success rate, determinism) is a field added to that interface. The gate would have grown weaker with every metric the pillar delivered.

**How this increment was found.** The program-wide re-verification of the pre-loop credit ran one auditor per epic across all 22 epics that had never had the pass `docs/loop/STATUS.md` says the first planner is supposed to run. HV-037 came back `partially-delivered` with a correction to the board in the *understating* direction: the frozen 24-shot corpus, the merge-blocking deterministic gate, the same-host latency A/B that checks the merge base out into a worktree, the ffprobe-backed animatic gate and the adapter-conformance suite are all real, merged and CI-enforced, and the row credits `(none)`. Both defects above were verified against the source before any code was written.

## The shape of the repair

**One classification, in the file that owns the record.** `BENCHMARK_FIELDS` in `packages/benchmarks/src/run.ts` names **every** key of `BenchmarkMetrics` and how the gate treats it: `exact`, `lower` (with a proportional limit *and* an absolute floor), `higher`, `latency-ab` (gated only by the same-host A/B), `latency-note` (advisory against the baseline) or `note` (deliberately ungated, and named so that "not gated" is a decision on the record rather than an omission). `compare.ts` derives its three arrays from that table and nothing else. A test asserts the table's keys equal the keys of a record produced by the **real** `runBenchmark`, so a field added to the interface and written by the benchmark cannot escape by a fixture simply not mentioning it.

**The §8 floor, implemented as §8 words it.** A lower-is-better regression now fires when `after - before > max(before × limit, floor)` — the allowance is the larger of the proportional limit and the absolute floor, which is what "≤ 5 % **or** $0.05" means. From a zero baseline the floor is the whole allowance, so the gate fires at 5.1 cents per shot and passes at 5. Above the floor the proportional limit takes over, so a real paid baseline is not held to five cents for ever.

**A missing number is a failure, not silence.** Both old loops treated a non-number as nothing to check: `before > 0` is false for `undefined`, and the latency loop `continue`d on `typeof before !== "number"`. A record that lost a gated field passed the gate. It now reports the field as missing.

**A malformed environment override refuses the gate rather than turning it off.** `LATENCY_LIMIT` was `Number(process.env.HV_BENCHMARK_LATENCY_LIMIT ?? 0.05)`. `Number("loose")` is `NaN`, and `delta > NaN` is `false`, so a typo in that variable silently disabled a merge gate — a fail-open override on the thing whose job is to fail. `limitFromEnv` and `roundsFromEnv` now refuse anything that is not a usable fraction or a positive integer, and both take the environment as a parameter so the refusal is testable without mutating `process.env`.

**Two riders in the same files.** `runBenchmark` resolved its fixture with `new URL(…).pathname`, which is percent-encoded, so a checkout under a path containing a space resolved to a file that does not exist; it now uses `fileURLToPath`. And `packages/benchmarks/package.json` declared `"main": "src/index.ts"`, a file that has never existed in that directory; it now names `src/run.ts`.

## Acceptance criteria

1. **Every recorded field is classified, and every classification is a recorded field.** The table's keys equal the keys of a record from the real `runBenchmark` **and** the keys of the committed-baseline shape. Each field's classification is pinned by name, so adding a metric requires a deliberate edit here. Satisfies FULL-SCOPE §8 "Gates in CI" and CLAUDE.md "Every criterion gets a real test."

2. **The cost gate fires from a zero baseline.** Against `costPerShotUsd: 0`, a candidate at 0.051 is a regression with the allowance named in the message; 0.05 and 0 pass. Against a paid baseline of 4, 4.19 passes and 4.21 fails, and cheaper is never a regression. Satisfies FULL-SCOPE §8 "cost variance (≤ 5 % or $0.05)".

3. **An exact field that changes is a regression, and a lost number is not silence.** Every `exact` field fails the gate when it differs; every `lower` and `higher` field fails the gate when it is absent, with a message naming it.

4. **A malformed limit or round count refuses the gate.** `HV_BENCHMARK_LATENCY_LIMIT` of `loose`, `NaN`, `-0.1`, `2`, `5%` or `Infinity` throws; `HV_BENCHMARK_ROUNDS` of `loose`, `0`, `-1`, `2.5` or `NaN` throws. Absent, blank and valid values still yield the documented defaults, so refusing a malformed value has not made either variable mandatory. Satisfies ADR-0020 fail-closed.

5. **Nothing frozen is touched, and no new dependency, vendor, key, route, account, tier, payment path, budget default or migration appears.** `.github/workflows/ci.yml` is **not** in the diff: the gate is already invoked there and this increment only changes what it computes. The root `package.json` and `bun.lock` are not in the diff; `packages/benchmarks/package.json` is, for its `main` field. `docs/loop/STATUS.md` and `docs/PROGRAM-EXECUTION.md` are not in the diff; RECORD owns both.

## Demonstrated, not asserted

Seven perturbations, each applied on this branch, measured against the final test file, and reverted:

| perturbation | result |
|---|---|
| P1 — restore the proportional-only cost guard (`before > 0`) | `3 pass / 1 fail` |
| P2 — add an `identitySimilarity` metric the table does not classify | `3 pass / 1 fail` |
| P3 — drop `continuityAvg` from the classification table | `3 pass / 1 fail` |
| P4 — reclassify the cost field as informational | `2 pass / 2 fail` |
| P5 — accept a malformed latency limit again | `3 pass / 1 fail` |
| P6 — treat a missing gated number as nothing to check | `3 pass / 1 fail` |
| P7 — compare the exact fields from a hand-written list instead of the table | `3 pass / 1 fail` |

P2 is the one the epic needs: it is the shape of *every* remaining §8 metric, and before this increment it passed. P7 shows the link is load-bearing rather than decorative — a list that happens to agree today still fails, because the table is the source.

## Tests added

- `packages/benchmarks/test/metric-classification.test.ts` (new; offline, no provider network) — four cases covering criteria 1–4. The first runs the real 24-shot benchmark, so it carries the same 120-second budget the existing suite uses for that run.

## What this increment does **not** do

- **It adds no metric.** Identity similarity, palette match, composition, caption alignment (p95 ≤ 250 ms), loudness compliance, QC pass rate, provider success rate and determinism are all still absent. This increment makes the *next* one safe to write, which is why it comes first.
- **It does not expand the corpus.** The frozen fixture is still 24 shots, not §8's 240, and `run.ts` still refuses any other count.
- **It does not touch the studio-benchmark half of the promotion claim.** `packages/generator/src/performance-registry.ts` says every provider "must pass the adapter conformance suite **and** the studio benchmark before promotion". The conformance half is real; the benchmark half is claimed-but-unproven, because `run.ts` hardwires one mock provider and nothing can run the benchmark against a registered adapter at all. That is a bigger increment and a claim that should be narrowed or delivered, not left as it is.
- **It delivers none of §8's blinded human rubrics, public leaderboard, chaos suite or security suite.** Five of the seven §8 clauses have no implementing code.
- **It does not change the latency gate's limit or its A/B design.** `compareLatency` still takes a single limit for every gated latency field; the table carries a per-field limit so a later metric can differ, and a test asserts that every gated latency field currently agrees with that single limit, so the signature is honest rather than an accident.
