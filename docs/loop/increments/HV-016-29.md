# HV-016-29 — Snapshots and portable archives that keep a mixed film's originals and proof (`hv-state/16`)

epic: HV-016
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

PR #83 ("Run mixed films with owned proof and atomic recovery") is being rebuilt on main as small
HV-016 increments. HV-016-27 and HV-016-28 let a mixed (V3) film's originals, adopted takes and
proof be held and published. Anything held has to survive a state snapshot and a portable project
archive, and an older reader must refuse such a snapshot rather than quietly drop what it cannot
read. Otherwise a restore would lose the only owned copy of an original, and nothing would say so.

The PR raised the state schema twice: 14 for mixed films and 15 for their proof. Main has since used
14 for deliverables and 15 for the delivery picture check. So on main both become a single new
version, **`hv-state/16`**. Admission still refuses V3.

## What this increment does

- **The snapshot schema is `hv-state/16`.**
  - Any mixed or proof marker selects it. That includes orphaned, abandoned or absent-valued
    markers, and a mixed film without proof.
  - Every older version refuses such a snapshot: "requires state schema 16".
  - The check comes after main's delivery-picture-check check, in both the TypeScript validator
    (`packages/storage/src/snapshots.ts`) and the Python packager (`scripts/archive-package.py`).
  - Every "this version or newer" list gains 16, and the delivery-picture-check check now accepts
    15 or 16.
  - Registries: `STATE_SNAPSHOT_SCHEMAS` (`archive-schema.ts`), the `hv-state.1.schema.json` enum and
    title, and the Python `STATE_SCHEMAS`.
- **Recovery validation for V3** (`packages/storage/src/current-screenplay-snapshots.ts`, ported
  from the PR; held back from HV-016-28).
  - Each marker's exact owning path is registered: V3 plans, checkpoints, outputs, originals and
    prepared proof.
  - A proof's frozen historical jobs are validated as their own scopes, and never become
    top-level jobs.
  - Pending-screenplay recovery (`snapshots.ts`) takes its authority from those scopes.
  - V3 jobs skip the legacy camera-path, anchor and picture-receipt projections.
- **Archives** (`archives.ts`):
  - export does not look for a clip manifest for V3;
  - import no longer skips a job whose only content is originals or proof. This is added to main's
    HV-040-07 list.
- **The Python packager** keeps V3 originals and proof carriers, and verifies V3 media through
  `scripts/verify-current-film-mixed-archive.ts`. Only an exact measured V3 MP4 or proof-preview MP4
  may exceed the 8 GiB per-file limit, and the archive total stays 64 GiB.
- **The PR's Python cases** (`scripts/test_current_film_mixed_archive.py` and
  `test_current_film_proof_archive.py`) are folded into `scripts/test_archive_package.py` as
  `MixedArchiveTests` and `ProofArchiveTests`. The existing CI step runs them, and no CI step is
  added.

Adapted to main:

- **Renumbering.** Every schema number the PR's code and tests use (14 and 15) is now 16, for the
  mixed and proof bridges, the large-output exception, the source-job loop and the Bun bridge
  number.
- **The Python bridge for the current screenplay** keeps main's mapping and passes 16 only for
  `hv-state/16`.
- **The Python test helper** now writes a full hv-state/1 manifest with a digest map, because main
  validates `snapshot.json` before it reads the version.
- **The unsupported-version probes move from 16 to 17:** the golden `rejections.json` row,
  `archive-schema.test.ts` (which now expects 16 versions), `snapshots.test.ts` and the Python
  conformance test.
- **The mixed-artifacts test** passes a real `assembledAt` (HV-016-26).

## Acceptance criteria

1. **Schema selection.** Every nested mixed-runtime marker selects `hv-state/16`, even beside
   retained V2 sources. Versions 1 to 15 refuse it, and promoting an orphan marker grants no
   ownership. Accessors are refused before any read. Legacy empty state stays byte-identical, and
   versions 14, 15 and 16 round trip.
2. **Proof snapshots.** A proof-only snapshot keeps its historical source and target preview
   contexts with no synthetic top-level jobs. A mixed film without proof is also 16. Older schemas
   refuse a proof downgrade. A re-sealed missing preview, a changed owned file, a changed execution
   time or a foreign nested source is refused. Proof-only media needs its complete owned inventory.
3. **Ownership.** V3 recovery registers exact generated and original capture owners, including
   zero-shot preparation. Origins need their exact owner, inventory, execution time and counters.
   Orphans, aliases, getters and hidden origins are refused without being read.
4. **Artifact custody end to end.** This runs on the in-memory PostgreSQL and S3 transport.
   - Originals, prefix and proof are published and restored from owned bytes only.
   - The export completes atomically. A rollback, a lost response and a completed holder are each
     handled.
   - An independent import works, and so does a proof-only independent restore.
   - Refusals: a foreign fence, partial uploads, corrupt or missing indexed roles, changed segments,
     and accessor inputs.
   - Only the exact measured V3 final MP4 may be large.
5. **Archive bounds.** The size allowance applies only to the exact measured mixed final MP4.
6. **Python packager.**
   - Every older schema refuses orphan V3 and proof markers, abandoned ones included.
   - The schema-16 bridge replays the whole snapshot and fails closed without Bun.
   - Origins-only and proof-only jobs use the fixed media bridge, never a clip manifest.
   - Original and proof carriers restore unselected roles, and refuse missing, changed or foreign
     copies.
   - A re-indexed ZIP cannot omit required media, and unpack cleans up after itself.
7. **Conformance.** The TypeScript and Python version lists, the JSON schema enum and the golden
   rejection row agree on 16 versions, and 17 is refused.
8. **V3 is still refused at admission.** The HV-016-24 admission test still passes.
