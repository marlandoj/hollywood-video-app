# HV-016-15 — Every studio film offered "Wait for my rough cut", for a job called `undefined`

epic: HV-016
release: 2 "Voice and crew depth"
gate: none new
spend_usd: 0

## Why

`state.pending` meant two things in `studio.js`:

- **HV-016-11** used it for the render a resumed project left running, `{stage, jobId, status}`.
  `render` puts "Wait for my rough cut" (or "Wait for my final film") above any step whose state has
  one.
- **The look step** used it for the cast still waiting for the creator's permission. That is an
  array, and usually an empty one.

An empty array is truthy, and every later step carries the look step's state forward. So every
creator who planned a film saw "Wait for my rough cut" at the top of the look, the rough cut and the
final. Pressing it requested `/api/jobs/undefined` and showed the error where the film had been.

## What this increment does

- **The look step's cast list is now `pendingCast`.** `pending` means only a running render.

## Acceptance criteria

1. **No wait button without a render.** A film planned in the studio offers no "Wait for…" button on
   the look or the rough cut. Its state has no `pending`, and nothing requests
   `/api/jobs/undefined`.
2. **Permission is still asked for.** A cast member still waiting for permission still needs the
   attestation before the storyboard is drawn. With the attestation, the studio asks the server to
   approve the cast.
3. Reverting `studio.js` fails criterion 1.

- Tests: `packages/frontend/test/studio-pending-cast.test.js`.

## Known gaps this leaves

- **The final step isn't driven through the UI here.** It needs the scoring, sound and graphics
  passes stubbed. It inherits its state from the rough cut, which the test checks has no `pending`.
