# Mixed current-film assembly and custody

The V3 plan can combine generated slots with explicitly selected successful takes from completed V2 films. The assembler, original-media copier, output verifier, queue/worker dispatch and storage adapters are implemented. **End-to-end worker and recovery qualification is still in progress.** Historical V2 entry points retain their strict version boundary; a separate runtime dispatcher handles V3 envelopes and rejects mismatched markers.

## Original identity and target identity

An adopted slot retains its original render record, execution capture, native speech samples and selected repair attempt. Its target slot, physical screenplay correspondence and owned paths are separate metadata. Adoption does not manufacture a new provider attempt, render record or cost receipt. Generated slots require actual target-owned records and captures whose routing decisions exist in the held journal.

The target retains each direct origin's complete file inventory once, including unselected media and original provenance. Selected role copies have separate target-owned paths. Neither catalog metadata nor a copy helper's returned receipt alone establishes durable custody.

## Assembly and verification

`assembleCurrentFilmMixedAsync` accepts the explicit mixed checkpoint, an artifact root and a current-access callback. It verifies owned roles and native line PCM, measures decoded frames, assembles with the admitted overlap policy, and returns a V3 clock. Recorded performance and target intent remain separate in the compact `hv-provenance/3.0` manifest. Private source catalogs, complete captures and routing journals are excluded.

`verifyCurrentFilmMixedMedia` validates a prepared prefix or completed export from target-owned bytes. It checks every complete direct original, generated/adopted role, native speech report, final picture, caption digest, decoded output clock and compact provenance. It does not require an old carrier directory or local clip manifest. HLS playlists must be bounded and refer to present, nonempty, owned segments; exact HLS and segment digests additionally belong to the held artifact-index publication/restore check.

Completed output binds its complete original inventory, immutable checkpoint, measured assembly and bounded continuity outcome IDs. A review binds that exact output. A V3 final can consume an explicitly reviewed V2 or V3 preview of the same canonical target, with the exact saved decision, cast, direction and lifetime.

## Storage phases

Before proof or originals are durably prepared, `assertCurrentFilmMixedTransaction` requires current source/carrier availability. After preparation, it uses only the authoritative saved target plus its complete exact artifact index to select the owned-custody phase. A claimed marker cannot select that phase. Missing or inconsistent saved index entries fail without falling back to a carrier. Both phases require fresh target and original-source permissions, and final jobs require the exact preview decision.

The transaction guard verifies metadata and index custody. The artifact adapter verifies actual bytes before atomic publication of the held job, artifact index and outbox event. `completeCurrentFilmMixedExport` freezes its inputs before awaiting transport and commits delivery rows, the completed domain Job and both completion events in one held transaction. The worker does not perform a second completion. Origins-only jobs retain their original start time across retry and restore. Selected reuse slots bypass provider generation and new cost records; the provider ledger refuses attempts for those slots.

New V3 admission resolves the saved historical screenplay and source dependencies, including the target final's own approved preview, locks exact selected Job bodies and artifact inventories, and compiles a complete bounded copy specification before reservation and enqueue. Exact request replay retains its earlier return path. This is an index and metadata gate; it neither persists a proof marker nor establishes that remote objects exist. Copy preparation uses a distinct proof namespace, preserves original relative paths, and checks existing job files plus missing copies before reading carriers.

The worker now saves a separate `currentFilmProof` checkpoint before preparing direct originals or dispatching selected slots. Its specification binds the target job, explicit target approval envelope, frozen historical context and complete owned proof inventory. The artifact adapter verifies the bytes and atomically publishes the marker, artifact rows and event. Exact preparation retries use the saved proof and owned inventory; they do not rediscover an old carrier. Provider admission requires both proof and originals preparation. Snapshot ownership and archive verification include the proof-only phase without inventing a target clip manifest or top-level historical jobs.

`verifyCurrentFilmProofMedia` independently checks these owned historical copies, including source facts, native line PCM, preview captions, decoded picture/HLS clocks, the exact playlist segment inventory and normalized reference images. Five media tests passed after copying a real bootstrap, V2 final and historical preview and removing the original workspace. Missing/corrupt media, a resealed segment inventory, changed reference bytes and revoked access refuse. The verifier is integrated into proof preparation, checkpoint restoration and archive verification; actual worker resume and service qualification remain separate gates.

`currentFilmMixedSourceClock` derives target physical line identities and film-global timing from completed V3 evidence. Reused records and captures keep their original identities. Native 22,050 Hz positions translate to the target span before a single conversion to 48 kHz; equal dialogue text never substitutes for physical correspondence. Five tests passed with actual original/fresh records, mixed assembly, repeated lines and final dissolves. The clock is private historical metadata and does not yet create an editable V3 receipt or public navigation index.
