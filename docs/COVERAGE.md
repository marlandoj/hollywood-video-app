# Coverage and continuity review

The shot editor now records coverage roles, subjects, a scene-local axis label, camera side A/B or on-axis, a looking subject/target and horizontal eyeline, plus an explanation for deliberate axis changes. These declarations become generation instructions and travel with the existing source-bound direction snapshot. They do not derive geometry from screenplay prose or inspect generated images.

Use **Save screenplay and check coverage** for an advisory report before rendering, or **Coverage findings and inventory** inside the shot editor. The creation flow also refreshes the report before submitting its preview. The report never adds a generation approval requirement. Edit a finding's source shot, save, then create and approve a fresh preview as usual. Unsaved character/shot edits must be resolved before checking coverage. Screenplay edits hide the old report; saving a new direction invalidates it and any earlier preview approval.

## Checks and interpretation

- The inventory lists master, single, over-shoulder, two-shot, insert, reaction, establishing and cutaway roles. Unclassified shots remain explicit unknowns. No declared master or speaker single/over-shoulder produces a coverage suggestion; if unclassified roles could fill the gap, its severity is unknown. Speakers come from parsed dialogue and match declared subjects by whitespace-normalized, case-insensitive names. Cast aliases and action-only subjects are not inferred. A master role describes intended scene coverage; assigning it does not expand the source action or prove full scene coverage in the media.
- A dialogue scene with no declared reaction/cutaway receives an optional edit-coverage note. Every scene need not contain every shot type. Deliberate alternative coverage remains permitted.
- Within one named axis in one scene, differing declared sides A/B produce a potential 180-degree warning. Unspecified/on-axis positions do not establish a side comparison. Unknown intervening shots are not analyzed; the warning identifies the last two comparable declarations, not a proven defect in the intervening edit.
- Reciprocal subject/target pairs on the same axis and camera side compare declared left/right looking directions. The same horizontal direction produces a potential eyeline conflict. Different axes, sides, subjects or targets do not pair. Centered/on-axis and incomplete declarations remain unknown for this check. Vertical gaze, subject depth and lens geometry are outside its scope.
- An explicit axis reestablishment requires both a named axis and an explanation. It clears earlier comparisons for that axis and leaves a visible note requiring preview inspection; it does not certify that a generated camera move crossed the line coherently.
- Changed/missing source shots are excluded from checked metadata and identified as stale. The existing direction rules require their review/removal before generation. Removed scenes retain a report finding for the old source.

Warnings, unknowns, notes and actual comparison counts are separate. Zero warnings is never reported as proof of coverage or continuity. The report is a deterministic planning aid, not a cinematic quality score.

The conventional axis check follows [Columbia's 180-degree glossary](https://filmglossary.ccnmtl.columbia.edu/term/180-degree-rule/), which also discusses intentional crossings. [Adobe's 180-degree guide](https://www.adobe.com/creativecloud/video/discover/what-is-the-180-degree-rule.html) describes keeping related dialogue coverage on one side and making deliberate exceptions. The optional master suggestion draws on [Adobe's master-shot guide](https://www.adobe.com/uk/creativecloud/video/production/cinematography/camera-shots-and-angles/master-shot.html). These references motivate advisory checks; they do not validate model output.

## Persistence, API and release

`settings.coverage` is optional inside `hv-direction/1`. Absent coverage remains absent when old snapshots are validated, preserving their hashes. New coverage records are normalized and bounded (up to eight subjects; 80-character names/axis; 400-character explanation). Existing source/version compare-and-swap, ownership, approval and safety boundaries apply. All prompt-bearing metadata passes the existing content gate before dispatch.

The private `GET /api/projects/:id/direction?maxShots=24` response adds `coverageDefaults`, `coverageChoices` and a `hv-coverage/1` report. The report records its rules version, direction revision and original source-plan hash. The optional 60-shot API plan remains available without changing operator authorization. Only the project owner can read this route. Reports in film export provenance are recomputed from the admitted immutable direction snapshot and original shot sources, so current project edits cannot rewrite historical evidence. JSON state, PostgreSQL backup and portable archive paths retain coverage within direction history and job snapshots. The full report also survives durable media restore as part of provenance.

No SQL migration is required. Deploy API, frontend and workers together. Code from before this change rejects the new coverage field; retain current storage before rollback and use a coverage-aware release to resume these projects/jobs. Historical snapshots without coverage continue to validate.

## Verification and remaining scope

Domain tests exercise unknowns, inventory gaps, isolated axes/scenes, reciprocal eyelines, deliberate reestablishment, stale/removed sources, validation and legacy hash preservation. API tests render a multi-shot preview and final, check exact report provenance, change coverage and reject old approval, and refuse stale source admission. Closed FLUX.2/Kling O3 fixtures verify coverage instructions reach both provider request bodies without paid inference. PostgreSQL tests reuse actual project locks/RLS; slow backup and isolated S3/archive restore preserve new metadata and report provenance.

Browser verification covers manual declarations, conflict correction, required explanation, reload/draft preservation, advisory preflight, preview approval/final export, and mobile layout. Local fixtures use synthetic media; live Zo deployment and paid optical/continuity evaluation remain pending. This does not implement automatic full-scene coverage generation, proposal acceptance/replay, selective regeneration, physical viewfinder/lens simulation, native camera paths, grouped takes or synchronized comparison. Those remain within HV-020/full-studio scope.
