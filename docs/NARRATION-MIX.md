# Reviewed narration and voice-over

The voice studio supports separate owner-authored narration text, bound to a saved character and screenplay scene. Narration auditions use the existing authorized Cartesia or Azure voice, direction, scene memory, phrase controls, provider journal and invoice path. The original screenplay stays unchanged. A separate reviewed source and audio-take schema distinguish narration from dialogue, even when both texts happen to match. A narration take cannot replace a screenplay dialogue line.

The owner reviews the text and scene before the audition quote, then reviews the voice settings and reserved cost before generation. Current screenplay, character permission, scene memory and voice policy are checked at admission and execution. Completed takes retain their original context and audio evidence. Translated narration uses the existing source-bound translation review and explicit language policy.

In Dialogue replacement, the owner can assemble up to 64 narration or voice-over cues from saved auditions, set their start times, and review gain and dialogue ducking. Every complete read, including its pauses, must fit within its reviewed scene. The narration language matches the selected dialogue/caption language. Cue and mix changes invalidate the render review. Existing tracks can be continued or explicitly cleared in a new version. No provider request or new provider charge occurs when applying a retained read; its original invoice remains separate.

The deterministic mix uses the existing 22050 Hz mono dialogue timeline. Narration gain ranges from -24 to 0 dB and dialogue duck level from -36 to 0 dB, in 0.1 dB steps. Attack runs for 0–1000 ms before measured speech; release runs for 0–3000 ms afterward. Leading/trailing pauses remain in the retained read. Overlapping narration cues sum once; overlapping duck envelopes use the lowest dialogue gain. Fixed-point gain coefficients and a final integer rounding define the recipe. Sample overflow rejects the render with a correction message. No automatic limiter, time stretching or loudness normalization is added here.

Each version owns the original dry `dialogue.wav`, separate `narration.wav`, `ducked-dialogue.wav`, `mix.wav`, each converted cue WAV, and the original 48 kHz audition WAV/report. The mix is muxed into MP4/HLS while retaining the encoded picture stream and frame count. Combined captions include measured narration speech windows and are sorted by cue start time. Mix receipts retain source, language, cue settings, conversions, hashes and measured integer sample peaks. Verification rebuilds all mix stems from the dry dialogue and retained converted cues. These are sample-peak measurements, not EBU R128/ATSC A/85 loudness certification.

Lip-sync continues to send only the selected dry dialogue waveform to the provider. Its derived picture version carries the reviewed narration mix, captions, original audition evidence and stems forward unchanged. Saved exports and review links bind the selected version. Current permission gates apply to its narration voices as well as dialogue voices. The independent archive and original provider journal remain authoritative for recovery and settlement.

Compatibility: previous audio-take, dialogue-plan/report/baseline and lip-sync source/preparation records preserve their existing forms when narration is absent. New records use additive versions. Narration is currently added through original clean picture or retained dialogue versions; the existing lip-sync workflow can run afterward. Broader editorial assembly and editing sound after arbitrary picture transformations remain P8/P9 work.

Validation covers review/source/cue rejection, cue overlap and envelope levels, clipping and cancellation, actual mixed exports and captions, dry media preservation, continued variants, tamper detection, original audio in lip-sync preparation, and independent narration stems in lip-sync output. PostgreSQL/S3 coverage exercises voice admission before reservation, one recorded dispatch, checkpoint recovery without redispatch, archive restoration, original-invoice settlement and policy withdrawal. Browser and final-source CI evidence are recorded with the increment's integration checkpoint.

Fixtures use explicitly synthetic tones and closed provider transports. No production voice catalogue, licence, paid inference, listening qualification, loudness compliance or Zo deployment is established by those fixtures. Music/ambience/SFX, production listening, measured loudness, limiters, broader stems/interchange and full program acceptance remain open.
