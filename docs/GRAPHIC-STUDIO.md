# Saved graphics and durable rendering — integration in progress

The owner API saves title, lower-third, credits, slate, watermark and kinetic-text plans independently of the screenplay. `GET /api/projects/:id/graphics` returns defaults, saved history and graphic render jobs. `PUT` accepts an expected library version and a save or availability change; save plans omit the derived revision. Text and layout validation use the same compiler as rendering. Owners can hide and restore a graphic without deleting its history. Saving another text revision preserves earlier render receipts and does not reactivate a hidden item.

`POST /api/projects/:id/graphics/:graphicId/renders` requires the displayed saved revision, generation approval and a recoverable request key. Project rights, current availability and existing content policy apply. Jobs use the normal fair queue with zero provider dispatch or cost. They have a dedicated `motion-graphic` stage, an empty screenplay context, their original owned plan and separate graphic outputs. They do not masquerade as films or audio takes.

Capture, encode, verify and retain progress is separate from the durable checkpoint. A checkpoint contains the complete verified PNG sequence, fonts, licence, composition, decoded frame evidence and lossless alpha master. A fresh worker verifies that checkpoint and completes without needing Chrome. Incomplete captures restart; per-frame capture resumption is not implemented. Worker leases, current project access and availability remain checked during processing. The configured `HV_GRAPHICS_CHROME_PATH` must point to the pinned browser for new captures.

Completed jobs expose scoped frame, master and receipt URLs. Hiding the graphic revokes those URLs; restoring it permits retained versions while their project and export remain valid. Composition, fonts and other non-image files download as attachments with a restrictive sandbox policy. Executable compositions are not served as interactive owner pages.

Migration `0013_motion_graphics` admits the new job stage. State schema **hv-state/5** retains graphic histories, jobs and checkpoints; older schemas reject those records. PostgreSQL/S3 checkpoint and independent archive contracts run in the dedicated graphics CI job. They must pass on the final source before storage qualification is claimed.

Local evidence includes a real alpha render, interrupted completion, recovery with Chrome deliberately unavailable, duplicate render response recovery, immutable saves, stale write rejection, hidden-history preservation, download revocation and schema-5 snapshot round trips. The archive writer also handles Windows file flushing: contents are flushed before publication, while POSIX directory-fsync and permission-bit guarantees remain specific to POSIX filesystems. Windows destinations use their existing ACLs. The local archive suite exercises all applicable cases; creating source symlinks requires a Windows privilege unavailable on this host and is covered in Linux CI.

## Owner workspace

**Titles and graphics** opens a focused workspace within an existing project. All six graphic types have editable text, timing, layout, colors and background transparency. Credits have removable role/name rows. Saved graphics can be reopened, hidden or restored. Rendering requires review of the saved version; edits must be saved or discarded first.

Uncertain save, availability and render responses retain the original request in project-scoped browser storage. Fields and navigation stay locked until recovery resolves that request. Reloading restores a submitted save's fields. A definitive rejection permits returning to the draft; stale writes show the latest saved graphic for comparison and Discard loads that version. Unsubmitted edits remain in memory while the workspace is open; they are not promised to survive a page reload. Browser storage failures limit request recovery to the open workspace.

Rendered versions retain their selection while status polling updates other active renders. Closing, switching graphics or leaving the page stops the corresponding polling and frame playback. The inspector supports exact frame selection, sequential Play/Pause, lossless alpha-master download and the retained receipt. Sequential playback waits for each PNG and may run slower than the authored 30 fps. It is a frame inspector, not a qualified real-time proxy player.

Private browser qualification exercised a lost accepted save, reload recovery without a duplicate revision, lost accepted render recovery without duplicate jobs, real 60-frame transparent lower-third output, frame selection and playback completion, hide/restore, a concurrent stale save with retained draft text, and discard to the newer saved version. A 390-pixel iframe exercised credit-row editing, invalid-duration rejection, corrected saving and a real 90-frame credits render. These are synthetic project fixtures, not production or physical-device qualification.

## Graphics in picture editorial

Completed graphics are available as retained originals in picture editorial. Their `hv-edit-source/2` receipts explicitly retain `graphic-rgba` picture facts, the original FFV1/BGRA master and its full verified bundle. Graphics add a picture lane without invented sound, caption or voice lanes. Insert controls hide audio and caption choices for graphic sources while retaining those field values when returning to a film source.

Saved-cut previews transport graphics as bounded, checksummed RGBA PNG pages under `hv-edit-preview-page/2`. Original film JPEG/PCM pages keep their existing format. Both paths verify exact selected source-frame hashes. Resizing filters premultiplied color separately from the native alpha plane, with precise rounding; an unscaled graphic preserves its pixels. PNG admission checks its dimensions, chunk checksums and supported single-frame encoding before browser decoding.

Full conform verifies graphic frames as RGBA before cropping, fitting or retiming. Graphic padding remains transparent. A clip's opacity and fades multiply its native alpha. Dissolves combine both pictures' weighted premultiplied colors and alpha before applying the result over lower footage. The browser uses the same layer groups and weights. Full conform processes one layer group at a time using three reusable RGBA frame buffers, and converts each completed span to its opaque YUV master once. Source preparation and composition recipes record this behavior; film-only recipe hashes remain unchanged. Storage estimates include the additional alpha and retiming scratch space.

An editorial export retains independent copies of the original graphic bundle. Continued editing can use that carrier after the original job is no longer retained. Current graphic availability and project rights still apply to the copied source. Snapshot schema 5 also protects graphic receipts embedded in sequences and render plans, even when the original graphic job is absent.

Local media checks cover decoded overlay colors, partial alpha, fitted crop padding, held frames, source seeks, span boundaries, film/graphic dissolves, PNG source identities, malformed or disguised packets, and unscaled/resized alpha values. Six native media tests pass with 1,162 assertions. The owner API exercises saved-cut preview, independent rendering and continued editing from retained copies. The existing film recovery test also passes with the unchanged disk reserve; its synthetic workspace uses a separate local volume with sufficient capacity.

A real Chrome decoder/compositor check compares five native-alpha scenarios across eleven frames each against independent pixel formulas: all 168,960 RGBA channel comparisons differ by at most one unit. Cases include partial alpha over film, clip opacity, transparent crop padding and dissolves with unequal clip opacities. The browser also binds PNG versus JPEG packet expectations to saved source facts. These small fixtures do not establish sustained playback performance. Final owner workflow checks, durable PostgreSQL/S3 qualification on the final commit and broader playback qualification remain open.
