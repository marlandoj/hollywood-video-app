# Saved graphics and durable rendering — integration in progress

The owner API saves title, lower-third, credits, slate, watermark and kinetic-text plans independently of the screenplay. `GET /api/projects/:id/graphics` returns defaults, saved history and graphic render jobs. `PUT` accepts an expected library version and a save or availability change; save plans omit the derived revision. Text and layout validation use the same compiler as rendering. Owners can hide and restore a graphic without deleting its history. Saving another text revision preserves earlier render receipts and does not reactivate a hidden item.

`POST /api/projects/:id/graphics/:graphicId/renders` requires the displayed saved revision, generation approval and a recoverable request key. Project rights, current availability and existing content policy apply. Jobs use the normal fair queue with zero provider dispatch or cost. They have a dedicated `motion-graphic` stage, an empty screenplay context, their original owned plan and separate graphic outputs. They do not masquerade as films or audio takes.

Capture, encode, verify and retain progress is separate from the durable checkpoint. A checkpoint contains the complete verified PNG sequence, fonts, licence, composition, decoded frame evidence and lossless alpha master. A fresh worker verifies that checkpoint and completes without needing Chrome. Incomplete captures restart; per-frame capture resumption is not implemented. Worker leases, current project access and availability remain checked during processing. The configured `HV_GRAPHICS_CHROME_PATH` must point to the pinned browser for new captures.

Completed jobs expose scoped frame, master and receipt URLs. Hiding the graphic revokes those URLs; restoring it permits retained versions while their project and export remain valid. Composition, fonts and other non-image files download as attachments with a restrictive sandbox policy. Executable compositions are not served as interactive owner pages.

Migration `0013_motion_graphics` admits the new job stage. State schema **hv-state/5** retains graphic histories, jobs and checkpoints; older schemas reject those records. PostgreSQL/S3 checkpoint and independent archive contracts run in the dedicated graphics CI job. They must pass on the final source before storage qualification is claimed.

Local evidence includes a real alpha render, interrupted completion, recovery with Chrome deliberately unavailable, duplicate render response recovery, immutable saves, stale write rejection, hidden-history preservation, download revocation and schema-5 snapshot round trips. The archive writer also handles Windows file flushing: contents are flushed before publication, while POSIX directory-fsync and permission-bit guarantees remain specific to POSIX filesystems. Windows destinations use their existing ACLs. The local archive suite exercises all applicable cases; creating source symlinks requires a Windows privilege unavailable on this host and is covered in Linux CI.

The owner browser interface, alpha-preserving editorial sources, preview and full conform integration are still required. This increment does not complete P8/P10, qualify long-duration playback, deploy to Zo or complete the full studio program.
