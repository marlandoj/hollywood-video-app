# Phrase pacing, volume and pauses

The voice studio lets an owner select whole source words, add a speed or volume override, and request a pause before or after that phrase. The review shows each exact phrase and its settings. Owners can edit/remove ranges or reuse them from a retained take. Unapplied phrase edits must be applied or discarded before line review; reload and navigation preserve the line draft. These directions belong to an individual audition, not the character's voice defaults.

This is delivery guidance through documented Cartesia `speed`, `volume` and `break` tags. It is not a native emphasis or expressive-intensity control. Cartesia's supported tag list has no emphasis tag, and inline emotion shifts are highly experimental. Speed and volume are also guidance; break tags can reduce context and naturalness. The implementation leaves emotion at line level, refuses stacked pauses between adjacent directed phrases, and requires listening to judge the result. [Supported tags](https://docs.cartesia.ai/build-with-cartesia/capability-guides/ssml-tags), [control semantics](https://docs.cartesia.ai/build-with-cartesia/capability-guides/volume-speed-emotion).

Native word stress is now implemented by the separate Azure audition adapter described in [NATIVE-VOICE-PERFORMANCE.md](NATIVE-VOICE-PERFORMANCE.md); its acoustic qualification remains open. The earlier provider investigation follows. Microsoft's documentation lists word emphasis for a limited set of neural voices and style-degree controls for supported styles; Google's SSML guidance recommends applying emphasis to full sentences to avoid unwanted pauses. Azure now has a separately versioned adapter; Google remains a candidate. Neither this document nor transport fixtures establish acoustic qualification. [Azure voice controls](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/speech-synthesis-markup-voice), [Google SSML](https://docs.cloud.google.com/text-to-speech/docs/ssml).

## Request and source contract

An audition can include up to 16 `phrases`, each with `start`, `end`, exact `text`, and optional `speed` (0.6–1.5), `volume` (0.5–2), `pauseBeforeMs` or `pauseAfterMs` (0–3000, whole milliseconds). Offsets are UTF-16 positions in the original `LineSource.text`; the UI supplies them by word selection. Start and end must coincide with whitespace-delimited source token boundaries. Ranges cannot overlap; repeated words are distinct occurrences. A range must contain at least one effective control. The existing source hash, cast identity, scene performance receipt, owner permission and policy still bind the request.

`GET .../audio-takes` exposes `phraseCapabilityRevision`. Requests containing ranges must echo it. The server builds the provider transcript; owners cannot submit it or raw markup. Pronunciations apply to the selected source content. If a replacement crosses a range boundary, compilation refuses it before reservation and asks the owner to include the whole written phrase or change its pronunciation. The plain spoken text and screenplay text remain separately available.

The compiler inserts only bounded speed/volume/break tags and explicitly restores effective line speed/volume after each overridden phrase. `generation_config` still holds the effective whole-line controls. The complete wire transcript, including markup, must fit the operator policy's character ceiling. This is a conservative input limit, not a provider credit calculation. Dispatched attempts retain unresolved billing until existing invoice reconciliation supplies actual cost.

## Immutable recordings

An additive `hv-audio-capability/2` entry and `hv-audio-line/3` plan retain source ranges and the exact generated provider transcript. The prior capability and `hv-audio-line/1` and `/2` plans keep their original serialization and revisions. Validation recompiles the transcript and rejects forged tags, changed ranges or capability downgrades. Dispatch evidence binds the same capability, plan and request hash.

Leading/trailing line pauses remain exact local silence. Inside a line, requested provider pauses are not inserted again or assumed to match their requested duration. Reports preserve returned PCM and word/phoneme timestamps, including provider normalization. They do not fabricate a mapping between source offsets and normalized timing tokens. Original phrase direction and wire evidence survive retained dialogue application, worker recovery and portable archives.

Tests cover exact generated requests, resets to scene/line defaults, source occurrence and Unicode boundaries, overlapping and empty ranges, cross-boundary pronunciations, raw/forged tags, historical schemas, conservative admission ceilings, current capability review, concurrent idempotent admission, one dispatch, playback and S3 archive preservation. Closed HTTP and browser fixtures use synthetic transport signals. Production acoustic quality, native emphasis/intensity, lip-sync and multilingual qualification remain open; no paid request or active production policy ships here.
