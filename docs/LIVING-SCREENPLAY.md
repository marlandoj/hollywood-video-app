# Living Screenplay implementation

This is an intermediate P1/P8 implementation. The authenticated owner API and browser interface support dialogue review, pending preview/final generation, actual source comparison, explicit recut and atomic screenplay/cut acceptance without saving the proposed screenplay early. Interface integration is implemented and locally tested; complete browser qualification remains in progress. The full requirements in FULL-SCOPE.md remain the completion boundary.

The owner studio retains exact uncertain save, generation, decision and acceptance bodies through browser recovery. Raw invalid fields and authored mapping choices survive reload. The original source-film player is distinct from the complete cut comparison. Acceptance requires preparation of both cuts' picture and sound at the exact recut revision and explicit owner review. Pending films cannot supersede the selected project export during reload. A confirmed acceptance can retry its screenplay refresh without submitting another acceptance.

`living-script-preview-api.ts` registers a bounded, expiring, complete recut review and previews a detached editorial library through the existing shared session/page pool. It does not save a cut, screenplay, settings or acceptance. Reads recheck the current baseline, original/generated carrier identity, permission and reference assets. Closing a review releases its exact captured sessions, including shutdown during admission. Local tests independently compare 48 kHz PCM and decoded PNG samples against a conformed recut. This proves media correspondence for those exercised samples and fixtures, not production performance quality.

`living-script-patch.ts` derives a physical dialogue-line identity from an authenticated retained source receipt. The request binds that source index and the exact current screenplay version and text. The result preserves every unrelated character, original line endings and surrounding whitespace, records the old/new line identities, and explicitly leaves the future rendered-source identity unresolved. Repeated equal dialogue is distinguished by source, scene, beat and physical position. Notes, boneyard and supplied project locks are protected. Changed source/current versions require branch resolution. Original screenplay text remains distinct from performed or localized text.

The initial compiler accepts a single spoken-line replacement that preserves parsed topology. Structural and arbitrary multi-line changes still need their own impact and merge handling; they are not removed from the program scope. A proposed next version in a patch receipt is not a committed screenplay version.

`living-script-generation.ts` compares every before/after shot using the same pinned per-shot input hashes used by normal selective rendering. The report includes regenerated, new, removed and unchanged shots, source receipts, candidate cast/direction/provider bindings and planned duration changes. Additional reviewed changes outside the selected dialogue line remain visible in the changed-shot set. Stale saved direction/coverage cannot be silently reapplied, and foreign-project or wrong-stage bindings are rejected.

Unchanged shot receipts are reuse candidates. Their presence does not authorize media access or prove current carrier availability. Admission, processing and publication must recheck the original permissions, exact source bytes, current bindings and provider/cost limits. The impact compiler does not dispatch generation or commit project state.

The generation integration test uses a real synthetic retained film and the existing owner script-save/selective-render path. It confirms that the compiler's changed-shot set matches fresh rendering, unaffected media is independently copied with matching hashes, captions change, and the previous persisted job and captions remain intact. This test does not establish a linked atomic acceptance workflow.

`living-script-cut-impact.ts` binds the full saved parent, its original receipts, edit-library/history revisions and exact screenplay navigation revision. It separates selected-line occurrences from changed-shot occurrences at their specific evidence windows, including entries shared across shots. All ranges using the related source retain their complete clock/effect review; intervals propagate through matte dependencies without including time-disjoint downstream clips. Review records retain original retiming, masks, transition handles and caption/audio lanes. The compiler does not replace or retime clips. Tests cover immutable parents, duplicates, stale navigation/history, a two-layer matte chain, precise affected intervals and unrelated unchanged-shot coverage; existing sample-accurate projection tests remain applicable.

The new `living-script-source-map.ts` verifies actual before/after shot records, durations, measured speech and caption evidence against the reviewed generation inputs. Unchanged shots retain exact shot-local correspondence; generated material has no inferred old-to-new timing. Overlap regions remain explicit, including cases with more than two contributing shots. This first correspondence implementation supports direct films. Derived dialogue, lip-sync and sound sources still require their own mapping contracts.

`living-script-recut.ts` replays the exact reviewed edit operations into an independent history rooted at the complete frozen parent. Only the generated original is admitted automatically. Existing clip links, ramps, transition handles, masks and capacity limits remain enforced. Every selected-source clip must be replaced or removed explicitly, and unresolved related derived sources require further mapping. Actual media tests verify lossless picture hashes, exact PCM ranges, repeated captions and independently decodable MP4 output while preserving the original cut and unchanged-shot media. This is not atomic project adoption or owner-interface qualification.

`living-script-proposals.ts` retains immutable review requests, complete frozen editorial context and independently reproducible impact. An exact retry returns its original review after a lost response; changed bodies cannot reuse that identity. Historical review data does not grant fresh generation permission. The current cast/direction baseline is separate from explicitly proposed settings: a changed candidate must be the next snapshot. This permits direction to bind to the proposed dialogue without prematurely saving the new screenplay. The internal project service checks the current baseline and original carriers before saving. PostgreSQL uses the existing project transaction and carrier locks, with no body rewrite on exact replay. The local JSON backend retains its existing single-writer limitation; atomic file replacement does not establish cross-process compare-and-swap.

State schema eight retains the complete proposal context and validates its exact original screenplay version, reviewed settings and impact. Older schema declarations cannot silently discard this data. Independent Python archive tests retain original media even when it appears only in frozen proposal context, reject altered media or resealed invalid impact, and preserve the original project JSON. Empty defaults preserve legacy snapshot behavior. New-feature PostgreSQL/S3 concurrency and independent service restoration remain required CI qualification.

`living-script-acceptance.ts` prepares a detached screenplay, independent cut, cast/direction snapshots and linked receipt. The durable `living-script-acceptance-library.ts` retains the complete request, binds its immutable proposal and independently reconstructs the historical acceptance. Exact retries return their original receipt without another mutation bundle. Historical validation checks exact physical-line correspondence, script versions and parent/child history prefixes after later edits; it does not depend on rolling settings history.

The internal project service now adopts the complete bundle with one validated state write. A failed file replacement leaves live state unchanged; an exact retry does not rewrite project state or alter export selection. Candidate artistic settings cannot grant new actor permissions or import unattested references. PostgreSQL wraps adoption in the existing project transaction and locks both original and generated source carriers. The local JSON backend remains single-writer. Restored, increasing noncontiguous screenplay versions advance from their last retained identity rather than array length.

State schema nine retains nonempty acceptance ledgers, including full reviewed requests and generated originals. Independent Python pack/unpack checks preserve the original project JSON and compare decoded frame hashes for both original and generated films. Missing media, altered versions, settings, history prefixes, forged reviews and schema downgrades are rejected. Proposal-only schema eight and absent legacy defaults remain compatible; malformed null metadata is not an absent default. Real PostgreSQL/S3 acceptance races and independent database/bucket restoration have a dedicated CI contract and are not claimed qualified by a local service skip.

`retained-shot-reuse.ts` validates original shot membership and maps its files to the exact copies in a current editorial carrier without rewriting the original render receipt. The copy routine verifies bytes and preserves original provenance even after the original directory is unavailable. Current carrier availability, rights and artifact inventory remain admission/worker responsibilities. Ordinary selective rendering retains its existing behavior.

`living-script-jobs.ts` compiles a pending generation plan bound to the full saved proposal, exact proposed text/settings/providers, original carrier and complete generated/reused shot sets. Final-film proposals have a distinct explicitly pinned animatic preview. Queue, PostgreSQL ledger, worker and artifact publication now carry that context through admission, attempts, checkpoints, reload and completion. Current-state checks reject stale screenplay/cut/settings, missing proposals, unavailable references and changed permissions. Exact admission retries return historical jobs without a new reservation; they do not renew permission to dispatch. A proposed numeric version alone cannot identify approval across different pending proposals.

`living-script-candidate.ts` rebinds only the verified physical line's affected direction, authored scene coverage, line performance and character scene-performance source identities. It retains all artistic controls, references and permissions, advancing cast/direction snapshots only when needed. Every changed source binding appears in the owner impact review. Stale or ambiguous source correspondence is rejected rather than silently discarding performance settings.

Owner routes under `/editorial/screenplay` retain exact proposal requests and generation quotes for retry. Preview approval binds the actual completed output and full proposal. Later decisions remain current while older decisions survive as historical evidence for already admitted films. Provider configuration, capability estimates, budgets, capacity, original custody and current rights are checked before new admission. Ordinary generation cannot consume pending previews or reuse their request identities. Generic job views expose compact proposal summaries rather than the full internal plan.
