# Reviewed multilingual dialogue

The voice studio accepts an owner-reviewed translation of a screenplay line, in a language explicitly authorized by the selected voice policy. The original screenplay, scene intent and character binding remain in the retained take. Translation text, language, review, pronunciation, phrase direction, voice, price and capability revisions are immutable inputs. Editing the text clears translation review and phrase ranges; changing audition settings invalidates the generation review. Earlier takes remain available beside new versions.

The pinned Cartesia Sonic 3.6 snapshot documents 44 base-language codes. This adds a separate multilingual capability and voice/line contract; existing English and Azure records keep their hashes and wire behavior. Non-English requests omit the English-only `generation_config.emotion` field. Their neutral UI value is a placeholder for that omission, not a claim of neutral acting. Word timing is requested; phoneme alignment is not claimed for this contract. Phrase offsets refer to the reviewed translation. Pronunciation substitution and bounded generated tags follow the existing compiler rules. Raw speech markup is rejected.

Operators must explicitly include a `languages` list when compiling a Cartesia audio policy with `audioPolicy`. This creates policy schema 3 and changes the permission revision. Existing policies remain English-only and do not authorize translated auditions. The policy's existing per-request reservation, maximum transcript length, validity and invoice requirements remain in force. No policy, credential or paid generation is installed by this change. A voice's model-level language support is not proof of accent, pronunciation, acting quality or a distribution licence.

In Dialogue replacement, choose a dubbed language and review the selected text and audio for every line. A complete dub requires an available localized take in that language for every audible source line, including inherited baseline reads. Incomplete tracks, mixed languages and unreviewed application requests are rejected before admission. Each language renders as an independent film version with its own WAV, SRT/VTT captions and original audition evidence. Owners can continue a retained language version without changing other reads. Review links and the selected export retain their caption language.

Picture timing and original line starts remain fixed. Each translated read uses its measured duration within the existing line window, with trailing silence where needed. Overlong reads are rejected; revise the translation or direct a faster take. Audio is sample-rate converted without time stretching. Caption cue timing lies inside each measured translated read. The existing lip-sync workflow can use the resulting version's exact audio window, and preserves its dubbed caption files and language. This does not add automatic picture re-editing, arbitrary retiming, automated translation or calibrated language/acting scores.

Validation covers Arabic wire submission through a closed SSE fixture, Spanish/Arabic independent media exports, Japanese source/translation retention, English compatibility, stale review and policy rejection, full-track completeness, owner access and caption review links. PostgreSQL/S3 tests cover native and Cartesia retained applications plus a multilingual application, including admission before reservation, fresh-worker checkpoint recovery, independent archive restore, policy withdrawal and original-invoice settlement. Synthetic tones prove contracts and timing, not spoken-language quality. Browser and exact-source Linux CI results are recorded with the integration evidence.

Production multilingual listening, voice/accent selection, licensed delivery and mouth-quality evaluation remain open. Broader language retiming, narration/voice-over ducking and P8–P9 editorial/sound requirements remain part of the full program. No Zo deployment is claimed.
