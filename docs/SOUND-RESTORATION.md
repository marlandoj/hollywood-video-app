# Per-track noise reduction

In **Edit sound session → Noise reduction by track**, owners can reduce noise in dialogue, narration, music, ambience and effects separately. Each track starts unchanged. Reviewed controls set reduction from 0.1 to 24 dB, an initial noise floor from −80 to −20 dB, automatic floor tracking and spectral smoothing. A continued session inherits these choices. Disabling every track omits restoration and returns to the original mixing contract.

An optional learned profile uses an owner-attested noise-only range from 0.25 to 5 seconds, on a 12.5 ms grid within the film. Dialogue and narration references must avoid all measured voice windows. Silent references fail with a correction message. Learned profiles disable automatic tracking; the initial floor still controls the processor. The range refers to the mixed track before restoration, including its existing cue placement, gains, fades and ducking.

Review presents the exact settings before rendering. Each completed version exposes the original, processed and removed signal for the enabled tracks, plus any noise reference. Comparison playback switches the complete tracks at the current position; the shorter reference starts at zero. Downloads and stereo sample peak/RMS measurements accompany playback. The removed signal may contain wanted sound. If its peak exceeds full scale, comparison playback lowers its volume and says so; its downloadable float waveform remains unchanged. Listening and export selection remain explicit owner decisions.

## Processing and timing

The mixer first retains all seven original 48 kHz stereo 24-bit stems under `restoration/original/`. FFmpeg's `afftdn` processes only enabled tracks, with double precision, bounded parameters and one filter thread. Untreated tracks are copied exactly. The five resulting integer stems are summed to make M&E and the final mix; both individual conversion and summed overload fail instead of silently clipping. This explicit sum can differ by one quantization unit from the older mixer's sum-before-rounding contract. The retained recipe identifies which operation ran.

At 48 kHz the pinned filter uses 600-sample hops, an 1800-sample window and 1200 samples of delay. The worker pads the tail, enforces hop-sized input frames and compensates the delay before retaining exactly the original sample count. A learned profile prepends the selected noise samples and a 2400-sample gap to the processing input, then removes the entire training prefix and filter delay. Original track timing, encoded picture and captions remain intact, including the final sample.

Optional [sound finishing](SOUND-FINISHING.md) runs after restoration. The delivery master is independent of both the original tracks and processed pre-master mix. MP4 and HLS receive the processed mix or finished master. A continued version always resolves to the original non-sound source and regenerates the reviewed mix; it does not repeatedly denoise a prior processed track. Source character performances, recording rights and original provider invoices remain attached. Restoration makes no provider request or charge.

## Evidence and recovery

`hv-sound-restoration/1` settings use version-3 sound sessions and results. Earlier version-1 and version-2 records retain their contracts when restoration is absent. New API, worker and recovery code must be deployed together. Existing state schema 3, fenced PostgreSQL/S3 checkpoints and owned-file archive inventories retain all original stems, processed stems, removed signals, references and the JSON restoration report.

Each report records the exact filter, runtime fingerprint, processing recipe, input/output hashes and stereo before/after/removed sample peak and RMS. Removed audio uses float32 WAV so every difference of two signed 24-bit samples is exactly representable, including differences above full scale. Verification checks that processed plus removed samples reconstruct the original, recomputes meters and sums, reproduces original inputs from saved voices/cues, and checks reference sample ranges. Matching runtimes rerun processing and compare the complete report and outputs exactly. A different runtime retains the original processed waveform and receipts; it does not replace them with new DSP output. Current access and worker fences remain checked during processing; withdrawal and retention cover the additional files.

Actual-media tests cover aligned opening/interior/final impulses, a learned profile on synthetic noise plus a retained tone, fixed/tracking noise floors, silence, exact residual reconstruction, tampering, mix overload, invalid references and cancellation. API and recovery fixtures exercise continued versions, combined restoration/mastering, downloads, clearing settings and recording withdrawal. Synthetic fixtures establish these contracts, not production listening quality or automatic separation of noise from performance.

References: [FFmpeg 8.0.1 filter documentation](https://github.com/FFmpeg/FFmpeg/blob/n8.0.1/doc/filters.texi) and [the pinned afftdn implementation](https://github.com/FFmpeg/FFmpeg/blob/n8.0.1/libavfilter/af_afftdn.c). Production acoustic qualification, generated score/effects and their licences, broader picture editing/interchange and Zo deployment remain open.
