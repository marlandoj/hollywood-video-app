# Native word emphasis and voice style

Owners can select an authorized Azure neural voice, save its speaking style and intensity for a character, and direct exact source words with reduced, none, moderate or strong emphasis. The voice studio reviews these settings before an audition and retains them for comparison, reuse, dialogue application and archive recovery. Existing Cartesia voices and their older records remain supported by their original adapter.

## Qualified contract

This adapter uses Microsoft Speech SDK **1.51.0**, pinned in the dependency lock, and the standard neural service in **eastus**. It admits only `en-US-GuyNeural`, `en-US-DavisNeural` and `en-US-JaneNeural`, the explicit word-emphasis voice list in Microsoft's documentation. The page's broader example names are not treated as support evidence. The supported style set is the published intersection for these voices: neutral, angry, cheerful, excited, friendly, hopeful, sad, shouting, terrified, unfriendly and whispering. Style intensity compiles to `styledegree` 0.01–2 in 0.01 increments; neutral has no style tag and accepts intensity 1 only. These are submitted native controls, with **transport fixture qualification only**; acoustic response and current regional catalogue support still require evaluation. [Voice controls](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/speech-synthesis-markup-voice), [voice/style support](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/language-support?tabs=tts).

Azure manages the neural model version; the application does not claim a pinned model snapshot or deterministic acting. Operator catalogue, account, licence and price evidence must identify this service and region. The worker uses `HV_AZURE_SPEECH_KEY`; no key or active policy ships. The existing operator-owned `HV_AUDIO_POLICY_FILE` may contain separate Azure `hv-audio-policy/2` entries produced by `audioPolicy({provider:"azure", ...})`. A voice is never silently switched to another provider or cloned. Current policy withdrawal blocks admission, dispatch, publication and playback.

Line speed and volume retain the application's bounded ranges and compile to documented relative SSML prosody. Up to 16 nonoverlapping source-word ranges can carry native emphasis, speed and requested pauses. Azure phrase volume is refused; line volume remains available. Owner markup, unsupported style/voice combinations, incompatible Cartesia emotions, phoneme requests and pronunciation substitutions crossing range boundaries are rejected. XML text is escaped; only the compiler produces tags. Existing scene notes and pace/volume defaults remain source-bound. A scene emotion from the other adapter must be replaced by an explicit supported line style.

## Durable execution and evidence

The additive records are `hv-audio-capability/3`, `hv-audio-voice/2`, `hv-audio-line/4`, `hv-audio-dispatch/2` and `hv-audio-line-delivery/2`. Canonical validation reconstructs source ranges, effective controls and the full SSML request. Older discriminants and hashes are unchanged. The reviewed capability is required at API admission, and the complete SSML must fit the operator's character ceiling before a positive reservation. This conservative input bound is not an invoice calculation.

The adapter authorizes and persists one original dispatch intent before creating the SDK request. It checks permission immediately before dispatch and after validation, bounds time/audio/timing events, closes on cancellation, and records the original outcome even after lease or permission loss. Application code schedules one `speakSsmlAsync` call with no synthesis retry or fallback. The pinned SDK can establish/re-establish transport; it does not resubmit the SSML after a synthesis failure. A saved checkpoint resumes without synthesis, and an intent without a checkpoint requires reconciliation rather than redispatch.

Raw mono signed 16-bit PCM stays at 48 kHz. SDK word-boundary offsets and durations are converted from 100 ns ticks to seconds; punctuation/sentence events are not manufactured into words. The report explicitly records `provider-word-boundary-events`, with empty phonemes. There is no viseme, lip-sync or forced screenplay-token alignment claim. SDK result IDs are separate from local attempt IDs, and HTTP status remains null because the transport does not supply an HTTP synthesis status. Local leading/trailing silence is exact; provider-requested internal pauses retain actual returned timing. [SDK boundary events](https://learn.microsoft.com/en-us/javascript/api/microsoft-cognitiveservices-speech-sdk/speechsynthesiswordboundaryeventargs?view=azure-node-latest), [synthesis methods](https://learn.microsoft.com/en-us/javascript/api/microsoft-cognitiveservices-speech-sdk/speechsynthesizer?view=azure-node-latest).

Dispatched billing stays unresolved until an operator invoice allocation supplies actual USD. PostgreSQL attempts, cost events and restored snapshots retain the actual provider and account. Azure completion does not create a fabricated zero charge. Applying a retained audition preserves its original report and explicitly converts a separate copy to the film timeline rate; picture and the original audition remain intact.

## Validation and remaining scope

Tests exercise the real pinned SDK over a closed WebSocket, canonical emphasis/style compilation, escaping and source boundaries, malformed timing, timeout, revocation, withheld delivery and outcome persistence failures. API tests save native character profiles; PostgreSQL/S3 tests cover concurrent admission, one dispatch, provider-specific invoice settlement, playback, restore, retained dialogue application, interrupted-worker recovery, portable archives and permission withdrawal. Browser fixtures use clearly labelled synthetic audio and verify editing, bounds, provider switching, saved defaults, retained settings and responsive layout.

No paid inference or production licence/listening evaluation was performed. Native-control submission does not prove a convincing performance. Lip-sync scoring/fallback, multilingual dubbing, narration ducking, video performance intensity/gestures and the wider P7/P8/P9 scope remain open. Zo rollout and Linear reconciliation await restored access.
