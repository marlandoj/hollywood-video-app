# Character and scene performance direction

Azure reads can now inherit a scene-specific speaking style and intensity. In **Scene performance direction → Scene vocal overrides → Azure scene voice direction**, choose a style and intensity, or inherit both from the character. Explicit line settings take precedence. Neutral uses intensity 1; other admitted styles accept 0.01–2 in steps of 0.01. The line review shows the effective delivery, while retained takes show their original scene style even after later edits. Narration inherits the same scene defaults.

The optional `nativeVoice: {style, intensity}` field uses `hv-scene-performance/3`, alongside existing notes, vocal controls and optional picture direction. It applies only to Azure; Cartesia continues to use scene emotion. When an Azure scene style is present, it supersedes that other provider's emotion for Azure reads. Shared speed/volume and explicit line controls retain their existing precedence. Omitting `nativeVoice` when replacing a scene record removes the override and restores character inheritance. Saving scene intent does not authorize any provider or voice.

The API returns the admitted style vocabulary as `sceneNativeStyles`, including when audition services are disabled. Scene writes, stale-source review, cast history, immutable auditions, retained dialogue application and archives preserve the new receipt. Records without native scene settings retain their original schema and hash; old schemas cannot conceal the new field. Deploy API, workers and archive tools together. The closed real-SDK transport test verifies inherited SSML; PostgreSQL/S3 fixtures exercise application and restoration. These checks do not establish acoustic quality or production voice licensing.

Picture emotion, creative intensity and gesture suggestions are supported by the additive schema-2 scene record and per-character shot overrides; see PICTURE-PERFORMANCE.md. The schema-1 vocal and note behavior below remains unchanged for existing records.

The voice studio saves performance intent for a character in a screenplay scene, including silent scenes. Character defaults initialize the read, scene emotion/speed/volume override those defaults, and explicit line settings take precedence. A blank scene control inherits the character default; explicit neutral/1 values reset it. Scene notes initialize line notes; an explicit empty line note clears them. Pronunciations and voice identity remain character or line settings.

The owner can read the current scene, save/rebind/remove its intent, review the effective line settings, and compare earlier takes. Scene edits and line drafts are separate; refresh, navigation and take reuse preserve unsaved changes. A retained read shows its original scene intent even after later changes. The scene editor remains available when expressive audition services are disabled.

`PUT /api/projects/:projectId/cast/:characterId/scene-performance` accepts `expectedVersion`, `expectedScriptVersion`, `sceneNumber`, the current scene `sourceHash`, and `notes`/partial `controls`. Removal uses `remove:true` without replacement settings; a removed scene has `sourceHash:null`. The service resolves the character and entire ordered scene. It never accepts an owner-supplied memory receipt. Cast history provides restoration; ordinary character edits preserve scene records, and actor imports strip them because they belong to the source project. Up to 60 ordered scene records can be stored per character.

Each `hv-scene-performance/1` receipt contains character ID, scene number, heading, the hash of ordered screenplay beats, notes, controls and its content revision. Harmless source-line shifts preserve the binding. Changes to action, speaker, dialogue, order or scene identity require review/rebinding or removal. New shot coverage of the same scene retains the intent. Stale records block new film planning until reviewed, including records for removed scenes.

`GET .../audio-takes` returns current scenes, per-character records, and each line's `performanceRevision`. An audition request must echo the reviewed revision when scene intent exists. The server compiles current permitted character voice defaults, scene controls and explicit line overrides, saving the receipt in `hv-audio-line/2`. Plans without scene intent retain the original `hv-audio-line/1` serialization. The PostgreSQL admission transaction compares current intent again before reserving funds. Existing idempotent requests return their original admission; later intent edits do not change admitted takes. Current character and voice permission still gates generation and playback.

Picture prompts receive scene intent alongside character descriptions, with explicit shot and line direction taking precedence. Temporary local speech retains scene notes as metadata; expressive emotion/speed/volume are not mapped to unrelated eSpeak controls. The Cartesia request receives effective supported vocal controls and plain dialogue. Free-form scene and line notes are retained in the audio report and are **not sent as a voice prompt**. No acting quality, emphasis, lip-sync or production licensing is inferred from these controls or the closed transport fixtures.

Validation covers canonical receipts, precedence and resets, stale scenes and ownership, cast history/snapshot preservation, actor imports, coverage changes, rendered temporary reports, exact closed HTTP voice payloads, concurrent PostgreSQL writes, stale admission before reservation, immutable retained reads, and S3 archive restoration of applied audio provenance. The browser fixture uses a labelled synthetic retained tone and enables audition review only. Production listening/licensing, broader P7 work and Zo rollout remain open.
